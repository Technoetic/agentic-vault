세션 복원 프로토콜을 수행하라.

## 0. 볼트 감지 (필수 게이트)

현재 작업 디렉토리 루트에 `00-meta/vault-config.json`이 존재하는지 확인하라.
- **없으면**: "이 디렉토리는 agentic-vault 볼트가 아니므로 /vault-session-start를 생략합니다." 한 줄만 정중히 안내하고 즉시 종료하라. 에러를 출력하거나 파일을 생성하지 마라.
- **있으면**: 아래의 검증된 훅 실행을 먼저 수행하라. config나 노트 경로가 차단되면 다른 도구로 읽지 말고 진단을 안내하라. 이후 읽는 설정은 검사기의 `validate_config`로 검증한 값을 사용하며, 키 값이 빈 문자열이면 해당 단계를 생략한다.

## 1. 상태 파일 로드

1. SessionStart 훅이 주입한 handoff/hot이 있으면 그 출력을 재사용하라. 생략 표시가 있다고 전체 파일을 다시 읽어 예산을 우회하지 마라. 주입이 없으면 `${CLAUDE_PLUGIN_ROOT}/hooks/session_start.py`를 Python으로 실행해 같은 경로 검증·예산 제한을 적용한 출력을 사용하라(`CLAUDE_PROJECT_DIR`은 현재 볼트 루트). 설정 오류가 보고되면 상태 파일을 다른 도구로 읽지 말고 오류를 안내하라.
2. handoff 상단에 **기준 커밋(anchor)** 해시가 있고 볼트가 git 저장소이면, 7~64자리 16진수이며 실제 커밋으로 해석되는 값인지 먼저 확인하라. 현재 HEAD와 다를 때 `git log --oneline <anchor>..HEAD`로 변경 범위를 확인하되, 파일의 값을 셸 코드로 삽입하지 마라. 조사한 출처에 근거해 최신 변경을 브리핑에 반영하고, 확인하지 못한 변경은 미확인으로 표시하라. 해시 차이만으로 기억이 정확하거나 최신이라고 단정하지 마라.
3. `index_note`는 플러그인 `vault_paths.resolve_note_path(vault, rel_path, deny_zones)`로 경로를 확인한 뒤 읽어 볼트의 전체 지도를 파악하라. 분량이 크면 최상단 구조 섹션만 훑어라.
4. handoff와 hot이 모두 비어 있으면 같은 경로 검증을 거쳐 `log_note` 최상단 5~10줄로 최근 활동을 대신 파악하라.

주제가 정해져 추가 근거가 필요하면 `/vault-recall <주제>`로 관련 노트의 경로·행 번호가 붙은 발췌를 조회하라. 검색은 읽기 전용이고 어휘 일치 기반이므로, 검색 결과 없음과 해당 사실의 부재를 혼동하지 마라. hot/handoff 예산을 0으로 둔 경우 해당 파일을 수동으로 재주입하지 마라.

## 2. 장기 기억 회상 (선택 단계)

장기 기억 MCP 서버(예: `memoryhub`의 `recall_context` 류 도구)가 **연결되어 있으면** 1회 호출해 세션 횡단 기억을 로드하라.
- 연결되어 있지 않거나 unavailable 응답이 오면 그 사실만 한 줄로 보고하고 계속 진행하라. 재시도하지 마라.
- 회상 내용이 볼트 파일과 모순되면 **볼트를 우선**하라 — 볼트가 진실의 원천(Ground Truth)이다.
- 회상에 `[anchor: <해시>]`가 있고 볼트가 git 저장소이면 위와 같은 해시·커밋 검증 후 `git log --oneline <해시>..HEAD`로 그 이후의 볼트 변화를 확인해 낡은 사실을 걸러라.

- **볼트 상태**: (hot_note 또는 index_note 기준 1~2줄)
- **직전 세션 요약**: (handoff 기준. handoff 미설정 시 log 최근 항목 기준)
- **확인 필요**: (handoff의 "인간의 확인이 필요한 사항" 기준)
- **다음 작업 후보**: (handoff의 "다음 세션 지시사항" 또는 hot의 "최우선 미결" 기준)
