# v0.59.0 — 노트 철회·대체 수명주기 감사, 검증 번들 정확 트리 소속·0건 음성 증거 보존 및 커버리지 명세·검토 분리

공개 v0.58.0(커밋 `34db74b437ddca715280f7d934d90204405f87c3`)을 바탕으로, [openai/math](https://github.com/openai/math)(Apache-2.0, 커밋 `3344da59`)의 대규모 AI 연구 아카이브 거버넌스·검증 규율 가운데 `agentic-vault`에 적합한 세 가지 Python 표준 라이브러리 전용 패턴을 선별 흡수했다. 새 런타임 의존성, 외부 모델·네트워크 자동 호출, 기존 볼트 파일 자동 수정은 없다.

## 기본 결과 변경

- **`vault_healthcheck.py` 기본 `enums.status` 확장:** `vault-config.json`에서 `enums.status`를 따로 재정의하지 않은 기본 볼트에서는 기존 `active`·`draft`·`archive`에 더해 `withdrawn`·`superseded`도 유효 상태로 허용한다(기존 `active`/`draft`/`archive` 노트의 판정은 불변).
- **`vault_coverage.py` 출력 필드 추가:** 결과 dict에 `review_status`(기본 `unchecked`)와 `independent_reviewed`(`False` 기본)가 추가되며, 선택 매니페스트 필드를 선언한 경우 `automation_methods`·`spec_bindings`·`solution_files`·`permitted_gaps_used`가 함께 보고된다(기존 키·`counts` 5항목·종료 코드 불변).
- **`scripts/verify_release_claims.py` 선택 플래그 확장:** 기본 10개 주장과 출력은 v0.58.0과 동일하며, `--bundle-dir`·`--require-independent-review`를 넘길 때만 추가 주장을 평가한다.
- **판 메타데이터:** 매니페스트 버전·설치 태그·healthcheck 스탬프(`engine=0.59.0`, 2행)·`ENGINE_VERSION` 및 `vault_install_state.py` 기본 `--engine-version`이 `0.59.0`으로 이동한다. 선택형 `deny-guard.py`·`ps-parse.ps1`은 무변경이므로 `engine=0.58.0`을 유지한다.
- **경고 승격 인증서(`checker_sha256`) 불변:** 인증서가 묶는 일곱 파일은 v0.55.0부터 v0.59.0까지 바이트 단위로 같다(`checker_sha256` = `3754f606efe8d48c55d5a835bf78552dc9deb6379673d883c5cb9eb56010e79d`, harmless corpus 해시 `38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`, `false_positives = 0`). v0.55.0–v0.58.0에서 v0.59.0으로 올릴 때는 인증서를 다시 만들 필요가 없다.

## 하위호환·업그레이드

현재 설치 ref는 `v0.59.0`이다.

기존 볼트 설정 파일은 자동으로 수정·마이그레이션하지 않는다. 공개 준비나 GitHub Release 게시는 활성 호스트 설치나 기존 볼트 사본을 자동으로 갱신하지 않는다. 볼트에 복사된 healthcheck와 helper bundle(`00-meta/scripts/`)은 설치 호스트에서 플러그인을 갱신한 뒤 `/vault-upgrade`(Codex는 `upgrade`)로 별도 갱신한다. 기존 `vault-config.json`에 `enums.status`를 명시한 볼트에서 `withdrawn`·`superseded`를 쓰려면 해당 목록에 두 값을 추가한다.

v0.55.0–v0.59.0 사이는 인증서가 묶는 일곱 파일이 같으므로 경고 승격 인증서 재생성이 필요 없다. v0.54.1 이하에서 경고를 `fatal`로 승격해 쓰던 볼트는 [v0.55.0 업그레이드 안내](https://github.com/Technoetic/agentic-vault/blob/v0.59.0/docs/releases/v0.55.0.md#하위호환업그레이드)와 같이 승격 해제·모든 엔진 사본 정렬·인증서 재생성(`checker_sha256` = `3754f606efe8d48c55d5a835bf78552dc9deb6379673d883c5cb9eb56010e79d`)·재승격 순서를 따른다.

`vault_healthcheck.py` 스탬프가 `engine=0.59.0`으로 이동하며 기존 규칙 6종, `aside-up.ps1`(`engine=0.17.0`), `deny-guard.py`·`ps-parse.ps1`(`engine=0.58.0`) 스탬프는 유지한다.

## 알려진 경계

- `vault_lifecycle.py`는 명시적 프런트매터 필드와 리터럴 위키링크만 검사하는 읽기 전용 감사기이며, `withdrawn_revision`의 Git 객체 실존 조회, 본문 산문 수준의 암묵적 인용 탐지, 또는 자동 파일 수정·아카이브를 수행하지 않는다. `status: withdrawn`은 증명·근거의 철회 표시이지 명제 자체의 거짓 판정이 아니다.
- `vault_coverage.py`의 `review_status`와 `automation_methods`, 그리고 `verify_release_claims.py`의 `--require-independent-review`는 호출자·영수증이 선언한 메타데이터를 구조적으로 구분·강제할 뿐 독립 검토자의 암호학적 서명이나 신원을 인증하지 않는다.
- `check_exact_tree_membership()`은 번들 디렉터리의 정확한 파일·폴더 소속과 0건 음성 증거 파일의 형식적 비어 있음만 검증하며, 그 파일을 생성한 원본 프로그램의 정확성이나 호스트 실행 이력을 증명하지 않는다.
- Antigravity CLI 생성 패키지는 `build_antigravity_package.py check` 및 격리 설치 검증으로 확인하며, 실제 `agy` 대화 세션은 에이전트가 감싸 실행하지 않는다.
