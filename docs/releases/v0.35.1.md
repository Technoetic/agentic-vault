# v0.35.1 — 웹앱 제작 6원칙과 백업 시험 안정화

v0.34.0의 기능과 v0.35.0 후보의 웹앱 공통 스킬·발견 검증을 유지하고 백업 시험의
임시 Git 저장소를 안정화한다. 공개하지 않은 [v0.35.0 실패 후보](v0.35.0.md)의
소스 `35b8543320946736ea0520d648e4a854db260e7c`에서 준비한 패치이며, 이전 태그와
draft는 고쳐 쓰지 않는다. 최종 태그·CI·자산 검증은 새 영수증으로 확인한다.

## 변경

- `test_git_history_bundle_clones_without_source_repository`의 임시 저장소에만
  `maintenance.auto=false`·`gc.auto=0`을 Git 저장소 로컬 설정으로 넣고 add/commit을
  실행한다. commit 뒤 자동 유지보수가 inventory와 겹칠 여지를 줄이는 시험 fixture
  변경이다. 백업 엔진, 제외 구역의 링크 검사, 실패 시 중단과 clone 검증 조건은
  그대로다. 실제 사용자 저장소나 전역 Git 설정을 바꾸지 않는다.
- [webapp-principles 스킬](../../skills/webapp-principles/SKILL.md)과
  [정본 안내](../webapp-principles.md)를 Claude Code·Codex가 함께 사용한다.
  JavaScript 책임별 모듈, CSS 토큰·기본·컴포넌트 분리, 화면/서비스 책임 경계,
  async/await 로딩과 실패·경합 처리, 화면별 URL·딥링크·새로고침·Back/Forward,
  새 배포의 안전한 자동 반영을 다룬다.
- 열린 탭은 로드된 문서의 빌드 식별자를 기준으로 새 배포를 감지하고 다음 안전한
  화면 이동에서 대상 URL을 전체 문서로 자동 로드한다. 작성 중 입력과 저장 요청은
  보호하고, 버전 확인 실패에서는 현재 앱과 초안을 유지한다. 롤백도 다른 빌드 식별자로
  처리한다. 캐시 헤더나 수동 새로고침 안내만으로 이 기준을 충족했다고 보지 않는다.
- Codex의 명시적 진입점은 `$agentic-vault:webapp-principles`다. 볼트 없이도 사용하며,
  기존 프로젝트 지시·프레임워크·작업 흐름을 우선한다. 일반 노트의 웹사이트 언급만으로
  앱 작업을 시작하거나 설치·배포 권한을 추가하지 않는다.
- 격리 홈 [발견 검증기](../../scripts/verify_codex_plugin.py)는
  `agentic-vault:agentic-vault`와 `agentic-vault:webapp-principles`가 각각 하나씩
  활성화되고 서로 다른 예상 설치 파일을 가리키는지 확인한다. 다른 command 스킬은
  허용한다. 기존 `skill` 결과를 유지하고 `skills` 목록을 더하며, core 스킬·새 스킬·정본
  안내를 포함한 설치 리소스 바이트를 대조한다. 세 session-start 훅·compact/end 각
  하나와 `untrusted` 상태, 모델 턴 0 조건을 유지한다.

기존 [v0.34.0의 다섯 선택형 진단·평가 기능](v0.34.0.md), 15명령, 공통 Python 엔진,
기본 훅과 검색 동작을 유지한다. 기본 모델·네트워크 호출, 의존성, 볼트 자동 이행을
추가하지 않는다. 스킬 탐색과 설치 바이트 일치는 전달 검증이며 모델의 선택이나 앱의
실제 원칙 준수를 보장하지 않는다.

## 하위호환·업그레이드

세 버전 매니페스트와 healthcheck의 `engine=0.35.1`·`ENGINE_VERSION` 식별을 맞춘다.
내용이 같은 규칙·git 훅·어댑터 스탬프는 유지한다. Codex의 고정 설치 ref는
`--ref v0.35.1`이며 [설치 안내](../codex.md#설치)를 따른다. 플러그인 게시, 활성 설치본
갱신, 실제 볼트 upgrade, 운영 앱 변경은 각각 별도 작업이다.

실제 `vault_warning_policy.py --certificate` 결과를 v0.34.0 태그와 독립 대조했다.
일곱 bound 파일과 harmless corpus 바이트가 같고, `checker_sha256`는
`be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`,
`corpus_sha256`는 `38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`로
유지된다. 양쪽 replay는 21사례·false positive 0이었다. healthcheck의 버전 식별은
인증서가 묶는 일곱 파일 밖에 있다. 따라서 실제 설치 bound 바이트가 같다면
v0.34.0 ↔ v0.35.1 전환만으로 승격을 해제하거나 인증서를 재생성할 필요가 없다.

다른 bound 바이트를 쓰는 구버전과 오갈 때는 기존
[인증서 업그레이드·롤백 순서](v0.34.0.md#하위호환업그레이드)를 유지한다.
승격을 warning으로 되돌리고, Claude Code·Codex·git 볼트의 엔진 사본을 같은 바이트로
맞춘 뒤 해당 설치본에서 harmless replay를 포함한 인증서를 다시 만들고 승격한다.
이번 안내는 기존 설치를 검사·변경하거나 볼트 upgrade를 실행한 기록이 아니다.

## 검증

이전 v0.35.0 tag CI의 Ubuntu/Python 3.14에서 임시
`.git/objects/maintenance.lock`이 directory listing과 `stat` 사이에 사라져
백업 시험이 오류를 냈다(2,644시험·제외 78·오류 1·591.287초).
같은 소스·Git 2.56.0·Python 3.14의 master 대응 실행은 통과했다
(2,644시험·제외 78·588.809초). 정리/clone assertion 전에 난 오류이며, 해당 시험과
백업 엔진은 v0.34.0과 같았다. 원인이 자동 유지보수라는 설명은 경로·타이밍과 로컬
Git child 관측에 따른 추론이며, CI에서 파일을 지운 프로세스를 직접 관측한 것은 아니다.
진단 뒤 유지관리자가 두 이전 실행을 취소했으므로 이 후보를 전체 통과로 기록하지 않는다.
기존 [후보 검증 기록](../verification/v0.35.0.md)을 보존하고 새 CI를 요구한다.

수정한 fixture는 Windows·Python 3.12·Git 2.55.0.windows.3에서 기존 백업 시험
20개를 모두 통과했다(제외 0·unittest 11.035초). 같은 실제 history/clone 시험을
새 fixture로 20회 반복한 별도 실행도 모두 통과했다(제외 0·프로세스 36.172초).
두 실행의 Trace2에서 자동 maintenance/gc child는 0개였다. 기본 설정의 별도 로컬
Git probe에서는 자동 maintenance child를 관측했다. 이 관측은 Linux에서 과거 lock을
지운 프로세스의 재현이나 새 다중 OS CI 통과를 뜻하지 않는다.

[2026-10-31 소스 통합 기록](../verification/webapp-principles-20261031.md)의
76개 선택 회귀(74 통과·Windows 환경 제외 2), 격리 Codex 발견·바이트 검사와 독립
공유 경로 결함 수정은 릴리스 메타데이터를 올리기 전의 관측이다. 새 스킬을 읽은
에이전트의 세 가지 가상 계획 관측은 실제 앱 시험 결과가 아니다. 날짜가 있는 원본
기록과 당시 해시·버전 표시는 그 시점의 근거로 보존한다.

문서 준비 시점에는 최종 소스의 master/tag CI, 플랫폼별 전체 시험, Claude 검증,
격리 Codex 설치, 재현 ZIP과 Git blob 대조, draft 자산 점검과 공개 후 확인이 별도
게이트로 남아 있다. 실제 명령·결과·고정 소스는 [v0.35.1 검증 기록](../verification/v0.35.1.md)과
게시 전 `verification.json`, 공개 후 외부 `post-publication.json`으로 확인한다.
문서 준비만으로 이 게이트가 통과했다고 주장하지 않는다.

## 알려진 경계

- 호스트가 스킬을 자동 선택할지는 호스트의 탐색에 달려 있다. 네이티브 발견 검증은
  모델의 지시 준수·애플리케이션의 기능 시험을 대신하지 않는다.
- 실제 앱은 A→B 새 배포, 이미 열린 탭의 다음 이동, background/history 복귀,
  작성/저장 중 보호, rollback, 일시적 버전 실패, 딥링크와 데이터 갱신을 각각 시험한다.
  이 릴리스는 운영 앱이나 MES를 수정·배포하지 않는다.
- v0.34.0과 같은 인증서라는 결론은 대조한 bound 바이트에 한정한다. 로컬 수정이나
  더 이전 버전의 다른 bound 바이트까지 호환한다고 단정하지 않는다.
