# agentic-vault v0.11.0 릴리스 노트

날짜: 2026-09-10

파일을 고친 뒤에도 이전 세션의 "검증 완료"가 인계에 남는 문제를 줄이기 위해,
검증한 파일 버전과 보고서·근거 파일을 연결하는 선택 도구를 추가했다. 다음 세션에
연결된 파일이 달라졌으면 인계에서 이전 검증의 보존 조건을 비우고 재검증을 안내한다.

## 변경

- **검증 전 스냅샷:** `snapshot`으로 명시한 산출물의 SHA-256과 크기를 기록한다.
  파일 사본을 만드는 백업과는 별개이며, 검증은 해당 스냅샷을 만든 다음 수행한다.
- **검증 근거 기록:** `record`로 별도 검증자의 보고서와 근거 파일을 연결한다.
  보고서는 verified·gap·failed·regression을 구분하고 유지할 조건과 다음 검사를 적는다.
  파일을 다시 대조한 뒤 한 번만 확정하며, 새 검증은 새 스냅샷으로 남긴다.
- **현재 상태 조회·인계:** 읽기 전용 `check`·`handoff`가 산출물·보고서 원본·근거
  파일의 해시를 확인한다. pending·stale은 종료 코드가 0이 아니며, 인계의 `preserve`가
  비어 있다. current인 보고서에도 미검증·실패·회귀 항목이 있을 수 있다.
- **세션 연결:** 기존 인계에 명시한 ID만 조회하는 절차와 Codex
  `$agentic-vault:agentic-vault evidence <하위 명령과 인자>` 진입점을 제공한다.
  CLI가 hot·handoff를 직접 편집하거나 전체 기록을 자동 스캔하지 않는다.

[보고서 형식·사용 예·파일 경계](../evidence.md)를 따른다.

## 하위호환·업그레이드

Python 3.10+·표준 라이브러리 구성, config 스키마와 자동 훅 정의를 유지한다.
v0.10.0 볼트에는 새 설정 키나 마이그레이션이 필요 없다. 명시적 `snapshot`·`record`
요청이 볼트의 `00-meta/evidence/`에 기록을 만들며, 기존 세션 기본 동작은 유지한다.
새 스킬·명령 문서를 읽으려면 Codex 새 대화 또는 Claude Code 재시작이 필요하다.

Claude Code는 기존 `agentic-vault` 마켓플레이스에서 플러그인을 갱신한다.
Codex 신규 설치는 공개 태그를 등록한다:

```text
codex plugin marketplace add Technoetic/agentic-vault --ref v0.11.0
codex plugin add agentic-vault@agentic-vault-local
```

같은 이름의 로컬 폴더나 이전 Git 태그가 등록돼 있으면 먼저 등록 소스를 교체한다:

```text
codex plugin marketplace remove agentic-vault-local
codex plugin marketplace add Technoetic/agentic-vault --ref v0.11.0
codex plugin add agentic-vault@agentic-vault-local
```

제거 과정에서 캐시·활성화 상태가 보존된다고 가정하지 않는다. `codex plugin list`로
버전과 활성화 상태를 확인하고 새 대화를 연다. 소스 갱신은 훅 신뢰 승인이 아니다.
Windows 실행 정책과 로컬 소스 유지 방법은 [Codex 안내](../codex.md#설치)에 설명한다.

## 검증

배포 후보의 검사 명령·실제 결과·독립 검증과 원격 CI 상태는
[v0.11.0 검증 기록](../verification/v0.11.0.md)에 기록한다. 구현 당시 Windows에서
실행한 406개 테스트(391개 통과·15개 제외)의 범위와 수정 경위는
[이전 구현 검증](../verification/evidence-handoff.md)에 보존한다. 이전 실측을
이번 배포의 원격 CI나 다른 플랫폼 실행 결과로 취급하지 않는다.

## 알려진 경계

- `current`는 파일 연결이 현재와 일치한다는 뜻이다. 주장 정확성, 모든 검사 통과,
  검증자 신원, 명령 실행 사실을 인증하지 않는다. 보고서의 명령 문자열도 실행하지 않는다.
- 명시한 일반 파일만 검사한다. 외부 의존성·실행 환경·선언하지 않은 파일·조회 직후의
  변경은 입증하지 않는다. OS 수준의 고정 복사본 검사나 볼트 전체 트랜잭션은 없다.
- 협조하는 CLI 쓰기에는 잠금과 기록 파일별 원자 교체를 사용한다. 외부 편집기의
  동시 쓰기를 차단하지 않으며, 중단 뒤 남은 잠금을 자동 제거하지 않는다.
- 보고서와 다음 행동은 근거 데이터다. 사용자 권한, 볼트 읽기 경계, 부분 수정 규칙을
  바꾸지 않는다. 자동 planner/developer/QA 실행이나 규칙의 자동 수정은 포함하지 않는다.
- 다중 세션 품질·시간·토큰 절감 효과는 측정하지 않았다. 참고한 HoH 논문의 결과를
  이 구현의 성능으로 주장하지 않으며, 비교 파일럿은 후속 검증 범위다.
