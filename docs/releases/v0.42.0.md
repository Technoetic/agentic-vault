# v0.42.0 — recoverable edits, review planning and generated memory

## Recover interrupted edits forward

`vault_bundle.py` prepares an explicit bounded bundle of edits to existing Markdown
files. A preview digest binds paths, configuration, source dependencies and before/
after bytes. Persisting a journal, applying edits or recovering requires explicit
`--apply` and the externally checked plan digest. Cooperating note/source leases,
current path and policy guards, preflight of all targets and repeated checks prevent
overwriting unknown content. Recovery inspects actual bytes: exact before means
pending, exact after means recognized-applied even when a receipt was interrupted.
Conflicts withhold further writes. There is no automatic rollback, rebase or
multi-file atomic visibility. See [the contract](../recoverable-bundles.md).

## Order declared review work

`vault_review_plan.py` reuses unchanged direct impact checks and validates a complete
caller-declared acyclic graph. Changes propagate to downstream claims even when
their owning Markdown is unchanged. Deterministic topological ordering and bounded
shortest reason paths give a read-only review worklist. No inferred dependencies,
automatic note edits, recapture, new provenance authority or truth judgment is added.
See [review planning](../review-planning.md).

## Persist and revisit generated memories

The checkout-only `evaluate_generated_memory_lifecycle.py` experiment uses disposable
synthetic checksum vaults. Validated authored action memories are persisted through
production proof and lesson-delta helpers, then reopened through retrieval and
compilation in fresh workers. Later tasks consume stored generated memories rather
than a cached model response. Matched clean and bounded adaptive host-poison arms
share the same initial authored snapshot. Selective production revocation is compared
with retained contamination. Repair credit requires exposure, observed bad-plan
adoption, improved subsequent independent behavior and retained benign capability;
missing adoption, empty memory, errors or blanket removal do not earn repair credit.

Defaults are offline scripted controls. Actual local inference requires an explicit
model, literal-loopback endpoint and network opt-in, bounded cumulative requests/
output tokens/time and no retry after transport failure. Workers hold no transport
credentials and recheck a hashed static local source closure. Scripted and mock HTTP
results are not actual-model performance evidence. No new actual-model observation
is claimed. See [scope and controls](../generated-memory-lifecycle.md).

## Inspiration and prior use

- [All File Systems Are Not Created Equal (OSDI 2014)](https://www.usenix.org/conference/osdi14/technical-sessions/presentation/pillai)
  and [ALICE at 6afda210b96baa2b0b277505d72742420ba89b68](https://github.com/madthanu/alice/tree/6afda210b96baa2b0b277505d72742420ba89b68)
  inform interruption-window testing. Their filesystem experiments and guarantees
  are not reproduced or transferred to this Python journal.
- [DVC at 1c06f9860af61d3947adafac99d8206f713dbfdd](https://github.com/treeverse/dvc/tree/1c06f9860af61d3947adafac99d8206f713dbfdd)
  informs explicit dependency work ordering. The former `iterative/dvc` and
  `treeverse/dvc` are the same repository. DVC was already present in general VCS
  research; this is a new application of a known reference, not a new discovery.
- [AgentPoison, arXiv:2407.12784](https://arxiv.org/abs/2407.12784)
  and [code at 7b02e28f5e477052bd16c778fef7c1f78f7c9d7c](https://github.com/AI-secure/AgentPoison/tree/7b02e28f5e477052bd16c778fef7c1f78f7c9d7c)
  motivate persistent-memory poisoning scenarios. The implementation uses a bounded
  host grammar, not AgentPoison's embedding optimizer, attack dataset or attack rates.

These references were checked against the published Reference Atlas and prior notes
before recommendation. A registry miss alone does not establish novelty. Concepts
are independently implemented; no upstream code, dataset or runtime dependency is
copied. Existing source/policy, lease, impact, proof, lesson and revocation primitives
are reused. Their previous APIs and semantics remain intact.

## Compatibility and installation

Current install refs target `--ref v0.42.0`. Python 3.10+ standard-library runtime,
default hooks, rules and configuration retain their contracts. Healthcheck changes
only its `engine=0.42.0` stamp and `ENGINE_VERSION`. Bundled-byte discovery now checks
the new resources as well. Publication does not update active installations or
convert a company vault. Model/network evaluation remains opt-in and checkout-only.

The seven certificate-bound checker files and committed LF harmless corpus remain
unchanged. Expected `checker_sha256`:
`be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`;
`corpus_sha256`:
`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`.
Fresh actual-byte checks and harmless replay remain final release gates. Matching
installed bound bytes alone do not require certificate regeneration for this
transition. Older changed-byte transitions keep warning reset, aligned engine
copies, regeneration with harmless replay and re-promotion, including rollback.

## Verification and limits

The [verification record](../verification/v0.42.0.md) describes pending final gates;
fresh exact-source results belong to release `verification.json` and independent
post-publication evidence. Historical release records are preserved. Hashes and
journals bind bytes, not identity, approval authority or semantic correctness.
Cooperating locks do not exclude hostile same-user writers; per-file replacement
does not make several files appear atomically or promise every filesystem's
power-loss durability. A local evaluator is not an OS sandbox or a production
agent-security benchmark. No live company deployment or actual-model quality gain
is claimed.
