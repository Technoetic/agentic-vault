# agentic-vault v0.17.0

날짜: 2026-09-29

선택형 **도구 어댑터**를 더했다. 첫 어댑터는 Aside(AI 브라우저 CLI)다. 엔진 규칙은 여전히
도구 중립이다. 어느 브라우저를 쓰는지는 볼트 CLAUDE.md가 정하고, 어댑터는 Aside가 설치된
볼트에서 그 결정을 사용자 승인 아래 채워 넣는 템플릿과 도우미다. Aside CLI가 없는 볼트에는
어댑터 파일이 생기지 않는다. 업그레이드하면 모든 볼트에 도구 중립 규칙 9번(약 0.6KB, 생성
AGENTS.md에도 포함)이 추가되고, git 볼트의 healthcheck가 `engine=0.17.0`으로 교체된다. 조항을 채택하면 CLAUDE.md가 약 2.5KB 늘어난다.

## 변경

### 엔진 규칙 (`engine=0.17.0`)

- `vault-browser.md` 9번 **창 기반 앱의 수명과 포커스**: 도구가 떠 있는 앱 창에 묶여 있으면
  (창을 닫으면 CLI 데몬도 종료되는 AI 브라우저 등) 명령 전에 CLAUDE.md가 정한 기동 절차로
  앱을 확인·기동한다. 기동할 때 사용자가 쓰는 창의 포커스를 뺏지 않는 방법을 쓴다. 이미 떠
  있는 창은 최소화·이동·닫기를 하지 않는다. 작업이 끝나도 앱 창을 닫지 말고 연 탭만 닫는다.
  기동 절차가 없으면 앱을 직접 띄우기 전에 사용자에게 알린다.
- 나머지 다섯 규칙은 내용이 같아 스탬프를 올리지 않았다.

### Aside 어댑터 (`assets/adapters/aside/`)

- `browser-clause.md`: CLAUDE.md 사용자 영역(관리 블록 밖)에 넣는 브라우저 도구 조항. 볼트 소유라
  업그레이드가 바꾸지 않는다. 데이터 경로를 두 갈래로 적는다. `exec`는 페이지 내용을 Aside가 쓰는
  클라우드 모델로 보낸다. `repl`은 Aside 안에서 JS를 실행하지만 `console.log()` 출력은 호출한
  에이전트(Claude Code·Codex)의 모델로 간다. 그래서 외부 전송 금지 자료는 `repl`로 열되 원문을
  출력하지 않고, 로컬 파일로 저장한 뒤 건수·합계·해시만 출력한다. Windows는 훅이 있으면 수동
  기동을 생략하고, 없으면 세션의 첫 aside 명령 전이나 "Aside isn't running" 때만 도우미를
  실행한다. macOS·Linux는 도우미가 없으므로 사용자에게 알리고 사용자가 앱을 띄우게 한다.
- `aside-up.ps1`(Windows, `agentic-vault:adapter aside-up engine=0.17.0`, ASCII 전용):
  - Aside가 꺼져 있으면 띄운 뒤 창이 보이자마자 최소화하고, 기동 직전 전경 창에 포커스를 돌려
    달라고 요청한 다음 CLI 응답까지 기다린다. 새 창이 잠깐 포커스를 가질 수 있으며, 결과 줄에
    포커스 복귀 여부를 적는다.
  - 브라우저가 떠 있으면 다시 실행하지 않는다(새 창이 생겨 사용자 창까지 가릴 수 있다).
    브라우저는 파일 속성 ProductName(`Aside`)으로 가려낸다. CLI 실행 파일도 이름이 `aside.exe`
    (ProductName `Aside CLI`)라서 이름만으로는 구분되지 않는다.
  - 이름 있는 뮤텍스로 동시 실행을 직렬화해 병렬 훅이 두 번 띄우지 않게 한다.
  - 실행은 대략 `-TimeoutSec`(1~45초) 안에 끝나고, 기동한 뒤에는 CLI 확인 한 번(최대 5초)과
    짧은 대기가 더해질 수 있다(60초 훅 제한 안). CLI 확인은 시간 제한이 있는 `aside repl`
    왕복이며, 계산값(42)을 stdout 줄로 확인한다.
  - `-Hook`: 훅 입력(stdin)의 명령에서 **명령 위치**(`;` `|` `&` `(` 줄바꿈 뒤의 첫 토큰)에
    `aside`/`aside.exe`가 있을 때만 동작하고 종료 코드는 항상 0이다. `grep -i aside.exe`,
    `Stop-Process -Name Aside`, `git commit -m "aside"` 같은 명령에는 반응하지 않는다.
    훅 입력은 UTF-8로 읽는다(콘솔 코드 페이지로 읽으면 한글이 섞인 명령의 JSON이 깨져 훅이
    아무 일도 하지 않았다). `-CheckOnly`는 판별 결과만 출력하고 기동하지 않는다.
  - 명시 경로(`-AsideExe`·`ASIDE_EXE`)는 그 경로만 쓰며, CLI 실행 파일을 가리키면 거부한다.
- `settings-hooks.json`: Claude Code PreToolUse 훅. `if` 조건 `Bash(aside *)`·`PowerShell(aside *)`
  때문에 aside 명령에서만 실행된다. 명령은
  `powershell -NoProfile -ExecutionPolicy Bypass -Command '& (Join-Path $env:CLAUDE_PROJECT_DIR 00-meta/scripts/aside-up.ps1) -Hook'`
  이다. 작은따옴표 안의 `$env:CLAUDE_PROJECT_DIR`는 바깥 셸이 아니라 안쪽 PowerShell이 풀기 때문에,
  Git Bash·PowerShell 어느 훅 셸에서도 같은 볼트 경로를 가리킨다. 변수가 없으면 경로 결합이
  실패해 아무것도 실행하지 않는다(비차단 오류). 개발 중 형태 `-File "$CLAUDE_PROJECT_DIR/..."`는
  PowerShell 훅 셸에서 경로가 비어 드라이브 루트의 같은 이름 파일을 실행할 수 있었기 때문에
  공개 전에 바꿨다.
- `operations-guide.md`: `20-knowledge/tools/Aside CLI 운영 가이드.md` 뼈대. 엔진 개발 기기의
  실측 표와 빈 「이 볼트의 실측」 표를 둔다. `status: draft`로 만들고, 그 기기에서 실측한 뒤
  `active`로 바꾼다.

### 명령·스크립트

- `vault_adapters.py`(새 스크립트, 읽기 전용): `aside` CLI가 PATH에 있는지, 도우미 상태
  (`missing`·`current`·`outdated`·`newer`·`modified`·`unstamped`·`unreadable`·`unsafe_path`),
  CLAUDE.md 조항 마커(주석 마커만 센다), 훅 설정(`settings.json`·`settings.local.json`,
  `if` 필터 누락과 셸에 묶인 옛 명령 형태를 `hook.problems`로 보고), 운영 가이드 노트를 보고하고
  `actions`로 제안할 일을 적는다. 설치·복사·실행·설정 변경은 하지 않는다. 심볼릭 링크와 Windows
  정션을 거치는 경로는 읽지 않는다(`vault_paths`의 판정을 재사용).
- `/vault-init` 4-1: 진단에 `offer_install`이 있을 때만 어댑터를 제안하고, 승인하면 조항·도우미
  (Windows)·운영 가이드 노트를 넣는다. 훅은 Claude Code·Windows에서 따로 확인받아 이 기기의
  `.claude/settings.local.json`에 병합한다(공유 `settings.json`은 별도 확인). `.gitignore` 템플릿에
  `.claude/settings.local.json`을 추가했다. Codex에서는 훅 단계를 생략한다.
- `/vault-upgrade` 6번: 진단의 `actions`에 따라 구버전 도우미를 diff 확인 후 교체하고, 스탬프가
  없거나 로컬 수정된 도우미는 덮어쓰지 않으며, 옛 훅 명령 형태는 변경안을 보여 주고 승인받아
  바꾼다. 빠진 부분은 제안만 한다. 안전 규칙의 엔진 소유 예외에 스탬프가 있는 도우미를,
  비파괴 원칙의 예외에 사용자가 승인한 어댑터 설치를 명시했다.
- `/vault-doctor` 6번: 어댑터 상태를 함께 보고한다. 기억 주입 판정과 섞지 않는다.

## 하위호환·업그레이드

- Aside CLI가 없는 볼트: 어댑터 파일이 생기지 않고, 진단에 "도구 어댑터 없음" 한 줄만 나온다.
  업그레이드하면 규칙 9번이 추가된다.
- 기존 볼트는 `/vault-upgrade`(Codex `$agentic-vault:agentic-vault upgrade`)로 `vault-browser.md`
  (`engine=0.12.0` → `engine=0.17.0`)와 생성 AGENTS.md를 갱신한다. healthcheck 스탬프는
  `engine=0.17.0`이다.
- 어댑터 이전에 Aside 조항·도우미를 손으로 만든 볼트는 진단이 `review_helper`(스탬프 없음)로
  보고한다. 업그레이드는 그 파일을 덮어쓰지 않는다.
- Telegram Jarvis 세션은 훅을 끈 채(`disableAllHooks`) 읽기 도구만으로 돌기 때문에 이 훅과
  무관하다.
- Codex 설치: `codex plugin marketplace add Technoetic/agentic-vault --ref v0.17.0`.

## 검증과 경계

- Windows 11 실측(Aside 앱 1.0.928.2, CLI 1.26.916.1741, Claude Code 2.1.252), 독립 검토 결과와
  테스트는 [v0.17.0 검증 기록](../verification/v0.17.0.md)에 있다.
- macOS·Linux에는 기동 도우미가 없다. 포커스를 뺏지 않는 기동 방법을 실측하지 않았다.
- 도우미의 창 판별은 Aside 창 클래스(`Chrome_WidgetWin_1`)에 기댄다. Aside가 창 구조를 바꾸면
  최소화가 동작하지 않을 수 있다. 그 경우에도 CLI 준비 확인과 종료 코드는 그대로 동작한다.
- 포커스 복귀는 Windows의 전경 잠금 규칙에 달려 있다. 복귀하지 못하면 결과 줄에
  `focus NOT restored`가 나온다.
- 훅 `if` 조건은 Claude Code 문서의 권한 규칙 문법이다. 조건을 무시하는 호스트에서는 훅이 모든
  Bash·PowerShell 호출마다 실행될 수 있다. 이때도 도우미가 명령 위치를 다시 확인해 aside 명령이
  아니면 곧바로 끝낸다. 다만 호출마다 PowerShell 기동 비용(약 0.3~0.5초)이 남는다. 판별은 따옴표를
  해석하지 않아서 `grep -E "chrome|aside"`처럼 따옴표 안 구분자 뒤의 aside를 명령으로 볼 수 있고,
  `{ aside … }`, `then aside`, `timeout 60 aside`, `powershell -c "aside ..."`는 놓친다. `if` 필터가
  먼저 걸러 주는 정상 호스트에서는 영향이 없다.

## 공개 후 추가 검증 (2026-09-29)

공개 후 최종판 `aside-up.ps1`을 실제 Aside로 한 번 기동했다(태그·자산은 바꾸지 않았다). 실제 Claude Code 훅에 한글이 든
명령 `aside repl "console.log('한글 확인', 6*7)"`을 내렸고, 결과는 다음과 같다.

- 훅이 입력을 UTF-8로 읽어 aside 명령으로 인식했다.
- 9.4초 뒤 CLI가 응답했다. 첫 창은 기동 약 3.2초 뒤 보였고 같은 50ms 감시 주기 안에 최소화됐다.
- 포커스는 기동 전 전경 창으로 돌아왔고, 명령 출력은 `한글 확인 42`였다.

자세한 기록은 [v0.17.0 검증 기록](../verification/v0.17.0.md)에 있다.
