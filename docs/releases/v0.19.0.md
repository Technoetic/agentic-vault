# v0.19.0 — 출처와 공유 상태 보강

로컬 개선 소스다. 원격 tag/GitHub Release는 게시하지 않았다.

## 변경

- 검사 복사본의 Unicode filler/tag/variation selector 정규화를 보강하고 원문 바이트를 보존한다.
- compact 때 source-bound 고정 제약을 원자적으로 먼저 주입한다. 작은 예산은 진단하며 기본 startup/clear/resume 동작과 9,500 UTF-16 상한을 유지한다.
- 64개 한·영 hard query, context claim coverage/nDCG/paired 통계, 명시적인 alias/plain mapping 검색 확장을 제공한다.
- anchor·중복 파일명·날짜·출처·시간 대장·전송 패턴을 경고로 검사한다. 치명 승격에는 현재 checker/corpus 해시와 실제 benign replay가 필요하다.
- 수집 원문 해시와 origin/classification을 보존하고 파생 최소 신뢰·현재 독립 근거를 연결한다.
- 협조 잠금, 파일/config 해시를 바인딩한 UTF-8 부분 편집, handoff 투영과 minimal PreCompact/SessionEnd checkpoint를 제공한다.
- 시간 대장의 명시적인 dry-run/apply, 안정적인 교훈 ID의 ADD/INC/EDIT/RETIRE와 제한시간을 갖는 선언 규칙을 제공한다.
- 격리 전 literal 보존과 명시적인 모델/세대별 토큰 측정·보정·drift를 확인한다. 기본 추정 계수는 유지한다.

## 사용과 업그레이드

`/vault-harden` 또는 Codex `harden` 진입점과 [helper 안내](../hardening.md)를 사용한다.
새 standalone healthcheck는 같은 버전 helper/resources bundle을 함께 설치해야 한다.
단일 파일만 남은 레거시 설치는 원래 fatal 게이트를 유지하며 추가 분석의 incomplete를 표시한다.
기존 사용자 값·노트·Jarvis 일정/프로세스·활성 범위를 보존한다. SSOT/교훈 이행은 명시적으로 선택하고 검토한다.
runtime을 일반 노트 inventory와 Git 추적에서 제외한다. 변경된 Codex hook 정의의 trust를 강제로 설정하지 않는다.

## 검증과 한계

검증 명령과 실제 결과는 [기능 안내](../hardening.md) 및 저장된 개발 검증 기록을 따른다.
합성 검색 labels/토큰 samples의 성능은 실제 업무 품질 또는 제공자 API count 검증을 대신하지 않는다.
원본 해시 현재성은 point-in-time 검사이며 여러 파일의 원자적 스냅샷이 아니다.
잠금은 협조하는 쓰기만 보호한다. 보고서·manifest·approve/verified_by는 권한이나 검증자 신원을 증명하지 않는다.
semantic completeness/기업 사실 확정은 수행하지 않는다. 외부 모델/tokenizer/scanner는 옵션이며 미실행을 실행으로 보고하지 않는다.
