# v0.53.2 — 외부 평가 개선, CI 병렬 실행, 보안·문서 정합성 복구 및 시험 경합 해소

공개 v0.53.0(커밋 `c0f4a3cb4547897ad3e38a8a663e3aaa390db31a`) 외부 평가에서 확인된 7개 항목을 수정하고, 미공개 `v0.53.1` 후보 태그(`7a25c4c5a3880eb4dc2154d4209192fd3aeea47c`, 태그 CI `run #44514277999`에서 시험 저장소의 Git 자동 유지보수 경합과 macOS 동시 잠금 해제 경합이 관측되어 게시하지 않음; 태그는 다시 쓰지 않고 보존)를 대체해 처음 공개한다. 새 런타임 의존성이나 기본 네트워크 호출은 추가하지 않는다.

## 변경

1. 보안 정책의 선택형 BizRouter 외부 송신과 판 번호 정정([SECURITY.md](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/SECURITY.md)).
   `Scope`, `Known limitations`, `한국어 요약`에 선택형 BizRouter Decisions 어댑터(`bizrouter_client.py`, `https://api.bizrouter.ai/v1/decisions`, `BIZROUTER_API_KEY`, `google/gemini-decision-1` 전용, 256 KiB·1,000문항 JSON/텍스트 상한)의 외부 송신 조건과 비밀 마스킹 경계를 명시했다. 또 머리글 줄 무력화 도입 시점 표기를 미공개 후보 `0.52.0` 대신 첫 공개판 `0.52.1`(미공개 `0.52.0` 후보에 최초 포함)로 바로잡고, 영문 `Known limitations`와 한국어 요약의 Antigravity `Stop` 중복 방지 설명을 v0.51.0+ 현행 동작에 맞췄다.
2. Antigravity 안내서의 낡은 `Stop` 문구 정정([docs/antigravity.md](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/docs/antigravity.md)).
   v0.51.0부터 `executionNum`이 생략되거나 `0`인 경우에도 요청 단위 식별자로 `Stop` 체크포인트 중복을 방지하는 실제 구현에 맞게 안내서 설명을 수정하고 설치 주소를 `v0.53.2`로 맞췄다.
3. `vault_doctor` 주입 추정의 비밀 마스킹 일치([skills/agentic-vault/scripts/vault_doctor.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/skills/agentic-vault/scripts/vault_doctor.py)).
   `vault_doctor`가 노트 주입 크기를 추정할 때 `SessionStart` 훅과 같은 순서(`_redact_sensitive_lines` 뒤 `_neutralize_header_lines`)로 변환하도록 맞춰, 비밀 줄이 들어 있는 노트에서도 진단 추정치와 실제 훅 출력 글자 수가 어긋나지 않게 했다.
4. `scripts/first_handoff.py` CLI 인자 지원([scripts/first_handoff.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/scripts/first_handoff.py)).
   `argparse` 기반 `--help`와 `--dir DIR` 옵션을 추가했다. `--help`는 임시 볼트를 만들지 않고 도움말만 출력하며, `--dir`에 이미 비어 있지 않은 디렉터리가 주어지면 덮어쓰지 않고 종료 코드 2로 거부한다. 인자 없는 기본 실행 출력과 실습 볼트 구조는 v0.53.0과 동일하다.
5. 150자 Windows `TEMP`에서의 Hypothesis 상태기 시험 긴 경로 보강([tests/test_stateful_memory_lifecycle.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/tests/test_stateful_memory_lifecycle.py), [tests/test_stateful_revocation_egress.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/tests/test_stateful_revocation_egress.py)).
   상태기 시험이 영수증과 감사 기록을 읽는 원시 `.read_bytes()` 호출에 `tests._winfs.deep_path`를 적용해, `LongPathsEnabled=0`인 Windows의 150자 `TEMP`에서도 `FileNotFoundError` 없이 실행되도록 수정했다.
6. 개인 경로 예시 정리([skills/agentic-vault/scripts/jarvis_bridge.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/skills/agentic-vault/scripts/jarvis_bridge.py)).
   모듈 상단 사용 예에 남아 있던 개인 로컬 경로(`D:/NS`)를 일반 자리표시자(`/path/to/vault`)로 교체했다.
7. 표준 라이브러리 병렬 시험 실행기와 CI 적용([scripts/run_unittest_parallel.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/scripts/run_unittest_parallel.py), [.github/workflows/tests.yml](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/.github/workflows/tests.yml)).
   `windows-latest / Python 3.10` 순차 실행이 60분 시간 제한에 근접하던 문제를 해소하기 위해 외부 패키지 없이 `tests/test_*.py` 모듈을 4개 작업자 프로세스로 병렬 실행하는 `scripts/run_unittest_parallel.py`를 추가했다. `test_000_environment`를 먼저 실행해 환경·긴 `TEMP` 계약을 확인하고, 나머지 모듈을 무거운 순서로 배분하며, 어느 한 모듈이라도 실패하면 0이 아닌 코드로 실패한다. GitHub 분기 보호의 필수 검사 이름 11개와 타임아웃 정책은 그대로 유지한다.
8. `v0.53.1` 후보 태그 CI에서 확인된 두 건의 시험·동시성 경합 해소([tests/test_vault_capacity.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/tests/test_vault_capacity.py), [skills/agentic-vault/scripts/vault_state.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/skills/agentic-vault/scripts/vault_state.py), [tests/test_vault_state.py](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/tests/test_vault_state.py)).
   `test_vault_capacity.py`의 임시 Git 저장소 초기화(`init_repo`)에 `maintenance.auto=false`와 `gc.auto=0`을 설정해 백그라운드 `.git/objects/maintenance.lock` 생성 경합을 제거했다. 또한 `vault_state._guard`가 `FileExistsError` 직후 `lstat()`에서 동시 `unlink` 중인 일반 파일(`S_ISREG`, `st_nlink == 0`, 재확인 시 부재)을 만났을 때만 `FileNotFoundError`와 동일하게 재시도하도록 보강했다(심볼릭 링크·재분석 지점·하드링크 `st_nlink > 1`은 계속 즉시 `unsafe_lock`으로 거부한다).
9. 판 표면과 생성 패키지 갱신.
   세 매니페스트, `antigravity/` 생성 패키지, healthcheck 스탬프(`engine=0.53.2`)와 `ENGINE_VERSION`, `README.md`(Antigravity CLI 배지·부제 포함)·`docs/codex.md`·`docs/README.md`·`docs/antigravity.md`·`docs/release-integrity.md`·`SECURITY.md`를 `0.53.2`로 정렬했다.

## 기본 결과 변경

- 판 메타데이터: 매니페스트 버전·설치 태그·healthcheck 스탬프(`engine=0.53.2`, 2행)와 `ENGINE_VERSION`이 `0.53.2`로 이동한다.
- `vault_doctor.py`: 비밀 패턴(`jev_client.SENSITIVE`) 또는 PEM 개인키 블록이 포함된 노트에서만 주입 추정 글자·토큰 수가 실제 `SessionStart` 훅 마스킹 출력과 일치하도록 달라진다. 비밀 줄이 없는 노트의 출력은 v0.53.0과 같다.
- `scripts/first_handoff.py`: `--help`와 `--dir DIR` 인자를 받으며, 비어 있지 않은 `--dir`은 종료 코드 2로 거부한다. 인자 없는 기본 실행은 v0.53.0과 같다.
- `vault_state.py`(`_guard`): 동시 프로세스가 짧은 guard 파일을 해제하는 순간 POSIX/APFS에서 일시적으로 `st_nlink == 0`이 관측되고 재확인 시 파일이 이미 사라진 경우에만 `unsafe_lock` 대신 대기 후 재시도한다. 심볼릭 링크·재분석 지점·하드링크(`st_nlink > 1`) 거부와 정상 경로 동작은 v0.53.0과 같다.
- 저장소 CI(`unittest` 작업): 순차 `python -m unittest discover -s tests -v` 대신 `python scripts/run_unittest_parallel.py --workers 4`로 같은 시험 모듈 전체를 실행한다. 필수 상태 검사 이름 11개와 `stateful` 작업은 바뀌지 않는다.
- 그 밖의 기본 검색, 훅 출력, `vault_healthcheck.py` 판정과 종료 코드, `jev_ask.py`·`vault_judge.py` 기본 동작은 v0.53.0과 같다.

## 하위호환·업그레이드

현재 설치 ref는 `v0.53.2`이다.

기존 볼트 설정 키는 추가하거나 마이그레이션하지 않는다. 공개 준비나 GitHub Release 게시는 활성 호스트 설치나 기존 볼트 사본을 자동으로 갱신하지 않는다. 볼트에 복사된 healthcheck는 설치 호스트에서 플러그인을 갱신한 뒤 `/vault-upgrade`(Codex는 `upgrade`)로 별도 갱신한다. `v0.53.1`은 게시하지 않은 후보 태그이며 GitHub 릴리스가 없다.

인증서가 묶는 일곱 파일(`vault_lint_extensions.py`·`vault_warning_policy.py`·`vault_provenance.py`·`vault_egress.py`·`vault_ssot.py`·`jev_client.py`·`vault_paths.py`)은 v0.46.0부터 v0.53.2까지 바이트 단위로 같아, 실제 설치 바이트가 같은 경우 기존 경고 승격 인증서가 그대로 유효하다. `checker_sha256`는 `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d` 그대로다. v0.45.1 이하와 오갈 때는 [v0.46.0 업그레이드 안내](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/docs/releases/v0.46.0.md#하위호환업그레이드)를 따른다. healthcheck만 `engine=0.53.2`로 이동하며 기존 규칙·어댑터 스탬프는 유지한다.

## 검증

요구 관문은 [v0.53.2 검증 계약](https://github.com/Technoetic/agentic-vault/blob/v0.53.2/docs/verification/v0.53.2.md)에 적었다. 최종 커밋의 병렬 시험 수·종료 코드, 150자 Windows `TEMP`(`LongPathsEnabled=0`) 실행, 후보 분기·태그·`master` CI(총 36개 작업 모두 게시 전 완료), 독립 검토, ZIP L1/L2 재빌드, 격리된 Codex·Antigravity 설치 확인과 인증서 재생 결과는 GitHub Release의 `verification.json`에 기록한다.

회귀 시험에는 `tests/test_run_unittest_parallel.py`, `tests/test_first_handoff.py`의 `--help`·`--dir` 시험, `tests/test_session_header_lines.py`의 `vault_doctor` 비밀 마스킹 일치 시험, `tests/test_vault_state.py`의 `st_nlink == 0` guard 재시도·하드링크 거부 시험, `tests/test_supply_chain.py`의 CI 명령 검증, 그리고 `tests/test_release_metadata.py`의 `V0532ReleaseMetadataTests`를 추가했다.

## 알려진 경계

- `scripts/run_unittest_parallel.py`는 각 시험 모듈을 별도 `python -m unittest tests.<module>` 자식 프로세스로 실행하므로, 모듈 경계를 넘는 전역 상태 공유는 발생하지 않지만 OS 스케줄링에 따라 완료 순서 출력은 실행마다 달라질 수 있다.
- CI의 Windows 러너는 `LongPathsEnabled=1`이며 기본 `TEMP`만 사용한다. `LongPathsEnabled=0`의 150자 `TEMP` 검증은 로컬 Windows 실행으로 확인하고 결과를 `verification.json`에 남긴다.
- Antigravity CLI 생성 패키지는 `agy plugin validate --strict`와 격리된 설치·바이트 대조로 검증하며, 실제 `agy` 대화 세션은 에이전트가 감싸 실행하지 않는다.
- `vault_doctor`의 토큰 추정은 계속 문자 수 기반 근사치이며 모델 제공자 토크나이저를 쓰지 않는다.
