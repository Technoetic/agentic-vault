# v0.20.0 — 교훈 비교·작업 기록·충돌 복구·연결 진단

Tower의 신뢰성 설계를 기존 파일 기반 엔진에 맞춘 다섯 선택형 기능으로 제공한다.
기존 Markdown/Git 원천, stdlib, 세션 훅과 기본 예산을 유지한다.
공개 설치 ref는 `v0.20.0`이며 [사용법과 입력 스키마](../tower-reliability.md),
[검증 기록](../verification/v0.20.0.md),
[릴리스 자산](https://github.com/Technoetic/agentic-vault/releases/tag/v0.20.0)을 함께 확인한다.

## 변경

- **교훈 전후 비교:** `vault_runs.py`가 호스트의 반복 관찰·근거를 기록하고 같은 시험의
  후보들을 비교한다. 후보/지시문은 바뀌어도 시험·채점·모델·제공자·예산·도구·설정은 고정한다.
- **실행 조건 기록:** 선택한 원문과 시험 조건의 해시를 영수증에 묶고 변경·누락·불완전한
  반복 결과를 거절한다. 모델을 자동 호출하거나 관찰 값을 대신 만들지 않는다.
- **단일 교훈 복구:** `vault_proposals.py`의 rollback-preview/rollback이 현재 대상,
  영수증과 정책을 확인해 원문 바이트를 복원한다. 다른 사람이 바꾼 파일과 공유
  handoff/tasks 전체 복구는 거절한다. 적용·복구 이력을 보존한다.
- **외부 작업 기록:** `vault_operations.py`가 명시적 claim과 소유 토큰을 기록하고 완료 결과를
  재사용한다. 결과를 모르면 불확실 상태로 보류하며 관찰 후에만 명시적으로 정리한다.
- **연결 단계 진단:** `vault_connectors.py`가 설치·설정·키 가용성·인증·연산을 구분한다.
  기본 오프라인이며 누락하거나 안전하지 않은 의존성을 분리한다. 명시적 Jev probe만
  지원하고 Jarvis 실행이나 Telegram 전송을 추가하지 않는다.

## 하위호환·업그레이드

Claude Code와 Codex는 같은 공개 소스와 helper를 사용한다. [Codex 설치 안내](../codex.md)에
태그 등록과 기존 설치 갱신 절차가 있다. 설치본 버전과 해당 스크립트의 존재를 확인한다.
healthcheck stamp/ENGINE_VERSION은 0.20.0으로 정렬하며 내용이 같은 규칙 6종의
마지막 변경 스탬프는 유지한다. 실제 볼트 엔진/자료 이관은 별도 명시적 upgrade다.

검색 제외 폴더는 금지 구역과 구분한다. 기존 정제의 명시적 선택 입력은 검색 제외 폴더에서도
허용하며, 새 복구 경로는 별도로 제외 정책을 검사한다. 기존 deny/link/hardlink/reserved
경로 거절을 유지한다. 기본 네트워크 호출·자동 승격·자동 복구·전역 도구 가로채기는 추가하지 않는다.

## 검증

소스 통합 검사: 1,248개 중 1,220개 통과, 환경 제외 28개, 실패 0개.
독립 재검증은 CLI 오류 비출력, 누락 의존성, 정제/복구의 경로 경계, 중단 복구,
현재 소스/문서/커밋 범위를 확인했다. 릴리스 metadata와 원격 3 OS × 3 Python 결과는
별도 검증 기록과 자산 `verification.json`의 실제 실행 결과를 따른다.
ZIP의 파일과 SHA256SUMS도 최종 Git commit의 blob과 대조한다.

## 알려진 경계

관찰·해시·영수증·approve/verified_by는 권한, 검증자 신원이나 실제 업무 효과의 인증이 아니다.
비교의 eligible은 관찰 쌍의 hard/error 조건이며 자동 적용 추천이 아니다. 음수 score_delta는 퇴행이다.
구판 복구 영수증은 preview 이후 정책을 묶을 뿐 기록하지 않은 과거 설정을 인증하지 않는다.
협조 잠금은 외부 편집기의 동시 쓰기를 OS 수준으로 잠그지 않는다.

Windows의 고부하 동시 요청은 안전하게 거절되거나 잠금 잔류 때문에 후속 요청을 막을 수 있다.
독립 부하 시험은 120회 중 claim 1/blocked 70/error 49/효과 1이었으며 고부하 가용성 보장은 아니다.
기록을 사용한 호출자 범위에서만 중복 실행을 보류한다. 모든 도구나 원격 exactly-once는 보장하지 않는다.
키가 있어도 시험 전 인증/연산은 미확인이다. 실제 제공자·업무 효과·모델 턴 훅 실행은 이번 검증 범위 밖이다.
