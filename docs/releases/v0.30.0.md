# v0.30.0 — 평가기 식별·개선 비용 근거

개선 실험의 평가기 코드·설정을 실행 조건에 연결하고, 생성부터 선택·기록까지 호출자가 보고한 비용을 원문 근거와 묶는다. 기준 공개판은 v0.29.0 `c72580603fdf0ca4309ba4c9849b848f7144adcc`, 구현은 `47930e64203a8a1c0ef136bc455ca9ecf933b20f`다. Python 3.10+ 표준 라이브러리를 사용한다.

## 변경

- **선택형 평가기 연결:** `vault_runs.py prepare --evaluator-source PATH`를 반복 지정하고 선택적으로 `--evaluator-config PATH`를 더한다. 코드·지원 파일과 JSON 객체 설정의 지문을 manifest에 연결한다. 원문 변경, 평가기 불일치 또는 지정 여부가 다른 실행의 비교를 거부한다. 후보·지시문·시험·도구 계약·보고서·관찰 근거와 경로를 공유하지 않는다. 선택한 스냅샷을 실행하지 않는다.
- **개선 비용 영수증:** 새 `vault_run_costs.py`의 `record`, `inspect`, `summarize`, `compare`로 생성·평가·선택·기록 자원과 근거를 보존한다. 실패·폐기 항목도 합산한다. 미측정은 `null`이며 `known_subtotals`·`unknown_counts`로 부분합을 구분한다. 명시한 영수증만 읽고 중복 실행·같은 근거 경로의 중복 합산을 거부한다.
- **보고된 비용 비교:** 네 단계·전체 범위 선언·모든 수치와 동일한 청구/추산 기준이 있을 때만 자원 차이를 계산한다. 성능 비교의 완료·동일 조건·hard 실패 의미를 유지한다. `compare`는 native 성능 비교 영수증을 기록하므로 읽기 전용이 아니다. 비용 계산 가능 여부는 성능의 `eligible`이나 적용 권한이 아니다.
- **원문 연결의 수치형 검증:** 보고서 재계산값과 저장된 정규화 JSON을 바이트로 대조해 Python의 `True == 1`, `100 == 100.0` 동등성 때문에 잘못된 형식의 영수증이 통과하던 경우를 거부한다.
- **합성 예제·패키지:** 네 후보 역할에 같은 평가기를 연결하는 `scripts/evaluate_improvement_accounting.py`와 CI 단계를 추가했다. Codex 격리 설치 검사는 비용 도구·사용법·예제의 존재와 바이트 일치를 확인한다. 기본 slash command는 15종이다.

## 하위호환·업그레이드

평가기 옵션을 지정하지 않으면 기존 run manifest와 ID를 유지한다. 정상적인 기존 관찰·비교 결과는 같은 형태이며 `--help`에는 새 옵션이 표시된다. 불변 영수증을 수동으로 고쳐 형식이 달라진 입력은 더 엄격히 거부한다.

healthcheck 스탬프와 `ENGINE_VERSION`은 0.30.0이다. 그 파일의 변경은 버전 표면뿐이며 내용이 같은 기존 규칙 6종은 스탬프를 유지한다. 기본 세션 훅·검색·모델/네트워크 호출·자동 적용·승격·런타임 의존성을 추가하지 않는다. 코드·로그를 읽는 권한과 비밀/금지 경로·크기 한도는 기존 정책을 따른다.

경고 검사기 일곱 파일과 corpus는 v0.29.0과 같다. 인증서는 설치본의 실제 바이트를 묶으므로 줄바꿈·설치 차이까지 자동 호환을 보장하지 않는다. v0.25.0 이하에서 올라오면 [v0.26.0 이행 조건](v0.26.0.md#하위호환업그레이드)의 경고 인증서 재작성과 `via_bot` 수집 출처 조건을 따른다. Jarvis API 인증 조건도 유지한다.

Codex 설치 ref는 `--ref v0.30.0`이다. [설치 안내](../codex.md)에 따라 등록 소스·기존 캐시를 확인한다. 공개 릴리스, 활성 설치 캐시 갱신과 실제 볼트 upgrade는 별도 작업이다.

## 검증

구현 커밋에서 새 평가기14·비용21·통합1, 총36개를 독립 재실행했다. 구현 당시 Windows/Python3.12 전체는 2,025개(1,991통과·환경 제외34·실패/오류0)였고, 오프라인11·컴파일·격리 Codex 설치도 통과했다. 이 수치는 버전 표면을 바꾼 최종 릴리스 트리의 검증을 대신하지 않는다.

최종 metadata·README·CI·패키지·ZIP/blob·재빌드·설치와 독립 검토는 고정 소스의 게시 전 `verification.json`에 기록한다. [릴리스 검증 범위](../verification/v0.30.0.md)를 함께 본다. 자산은 `agentic-vault-0.30.0.zip`, `SHA256SUMS`, `verification.json`이며 게시 후 증명·공개 재다운로드 확인은 별도 `post-publication.json`에 남긴다.

## 알려진 경계

- 지문은 선택한 바이트의 현재성만 확인한다. 실제 채점기 실행·정확성·독립 평가자·로그 진실을 인증하지 않는다.
- `instrument_log`, `host_report`, `unknown`, `recorder`와 `scope_complete`는 호출자가 제출한 설명/선언이다. 해시로 직접 계측이나 숨은 시도 없는 완전한 회계를 인증하지 않는다.
- 동일 근거 경로의 중복은 거부하지만 이름을 바꿔 복사한 중복·보고하지 않은 비용을 자동 탐지하지 않는다. 선언한 토큰 상한은 실제 사용량이나 상한 강제가 아니다.
- 청구액과 추산액을 섞어 절감률을 만들지 않는다. 자원 차이가 계산돼도 성능 hard 실패를 상쇄하거나 효율·적용을 자동 판정하지 않는다.
- 예제는 합성 호스트 보고서다. 실제 모델·업무 성능·절감액이나 재귀적 자기 개선을 측정하지 않는다. DGM·AIDE²의 평가 원리만 참고했으며 모델·코드·자율 실행기를 가져오지 않았다.
