# agentic-vault 0.9.0-local.2

2026-09-05 · 로컬 개선판 · 기준 `fd2718f` (`0.9.0-local.1`)

Claude Code 플러그인에 Codex 진입점을 추가했다. 두 클라이언트가 같은 볼트와
Python 엔진을 사용하며, 기존 Claude 명령과 config 형식은 유지한다.

## 변경

- `.codex-plugin/plugin.json`과 저장소 내부 `.agents/plugins/marketplace.json`을 추가했다.
  기존 스킬과 `hooks/hooks.json`을 공유하고 엔진을 복제하지 않는다.
- 세션 스크립트가 `--vault`와 작업 디렉터리를 지원한다. 명시적 경로,
  비어 있지 않은 `CLAUDE_PROJECT_DIR`, 작업 디렉터리 순서로 선택한다.
- Codex 공유 스킬에서 세션 복원·회상·마감·검사·노트 작업·스냅샷 작업을 연결한다.
  설치된 스킬 파일을 기준으로 경로를 구하고 인자를 셸 코드로 해석하지 않는다.
- `init`·`upgrade`가 중립적인 AGENTS 스텁과 기존 규칙 다섯 개로 계약을 생성한다.
  수제 계약과 사용자 수정은 보존하며 Claude 권한을 Codex 설정으로 옮기지 않는다.
- 임시 Codex home에서 실제 설치와 스킬·훅 검색을 재현하는 검증기를 추가했다.

## 설치와 호환성

[Codex 설치·명령 대응·기존 볼트 전환](../codex.md)을 따른다. 이 변경은 원본
GitHub에 게시하지 않았으므로 현재 로컬 배포본의 경로를 지정해야 한다.
Codex 자동 훅은 `/hooks`의 신뢰 검토가 필요하다. 신뢰 전에는 스킬에서 수동으로
세션을 복원할 수 있다. Jarvis는 계속 Claude CLI에 의존한다.

기존 경로 검증·토큰 예산·복구 제약은 유지한다. standalone 건강 검사기의
내용이 바뀌지 않았으므로 engine stamp는 `0.9.0`을 유지한다. 이전 버전의
[변경 내용](v0.9.0-local.1.md)과 [검증 기록](../validation.md)은 해당 버전의 기록이다.

## 검증

Windows · Python `3.12.10`에서 다음을 실행했다.

- 전체 unittest: 303개 중 293개 통과, 10개 환경별 skip, 실패 0.
  skip은 Windows 심볼릭 링크 생성 권한 6개, POSIX FIFO 2개, POSIX 프로세스 그룹 2개다.
  정션 회귀는 통과했다.
  Claude 환경변수가 없는 세션 복원·검색·스냅샷 복구도 포함한다.
- 한국어 8개·영어 8개 검색 fixture: recall@3 `1.0`, MRR `1.0`, 실패 질의 0.
- Claude CLI `2.1.252`: plugin·marketplace·commands·skills strict 검사 통과.
  Codex plugin validator와 공통 skill validator, Python 컴파일도 통과.
- Codex CLI `0.150.1`: 임시 home에 로컬 marketplace·플러그인 설치 성공.
  활성 스킬 `agentic-vault:agentic-vault`와 SessionStart 훅 2개 발견, 검색 오류 0.
  설치된 공통 엔진·참조·템플릿 내용이 원본과 일치했고 훅은 `untrusted` 상태였다.
- 독립 리뷰에서 발견한 Windows 검증 런처의 자식 프로세스 잔류를 수정했다.
  네이티브 실행 파일 선택·알 수 없는 배치 런처 거부·시간 초과 후 자원 정리 회귀를
  실제 subprocess로 검증했다. POSIX 프로세스 그룹 테스트는 이번 Windows 실행에서 skip했다.
- README·설치 안내·릴리스·공통 스킬의 로컬 링크 45개가 모두 존재했다.

실제 모델 대화, 신뢰 후 자동 훅 실행, Telegram 송수신, 원격 CI는 이번 로컬
검증 범위에 포함하지 않는다. 설치 검증은 모델 턴 0회이고 사용자 전역 설정을
변경하지 않는다. 검색 fixture 점수는 어휘 검색 회귀 지표이며 모델 답변 품질 점수가 아니다.
