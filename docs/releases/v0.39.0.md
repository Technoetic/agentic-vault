# v0.39.0 — 단계별 기억 개입과 새로운 한국어 응답 관측

v0.39.0 adds two optional checkout-only evaluators over **original fixtures**.
They extend the existing evaluation tools without changing installed hooks,
configuration, search defaults or the earlier evaluators' contracts.

## Stage-specific memory interventions

[`scripts/evaluate_memory_stages.py`](../../scripts/evaluate_memory_stages.py)
compares `writing`, `management` and `retrieval` interventions separately on
matched clean/poison ASCII and Korean sources. Writing changes origin review,
management changes whether persisted roles survive, and retrieval changes actual
source eligibility and returned consumer context. Other stages are held fixed.
Storage, context and local source hashes expose what each comparison consumed.
Clean-task preservation, poison exposure, observable bad-plan adoption, errors
and incomplete pairs remain separate. These metrics are not the existing strict
four-phase selective-repair score.

Generation is `deterministic_experimental_intervention`, not model-generated
memory or a model summary. Default `scripted-control` runs are offline. See the
[stage guide](../memory-stage-evaluation.md) for commands and interpretation.

## Fresh paired Korean answer observations

[`scripts/evaluate_model_korean_memory.py`](../../scripts/evaluate_model_korean_memory.py)
uses the existing original Korean question fixture and unchanged strict answer
grader. Default and annotate-only retrieval arms retain withdrawal exclusions
and receive separate fresh requests, including when their prompts match.
Only question, options and evidence enter the public payload; labels, arm and
expected values remain outside model messages. Identical prompts do not establish
annotation efficacy.

Strict JSON answer/abstain parsing, valid provider usage on invalid output,
content-free errors and bounded opt-in local transport distinguish completed
observations from failures. Source-bound replay checks the exact sample order,
labels, actual evidence/completeness, policy, model/prompt/limits and local code
closure. A replay receipt records an observation claim; it does not authenticate
inference. See the [Korean observation guide](../model-korean-memory.md).

```text
python scripts/evaluate_memory_stages.py
python scripts/evaluate_model_korean_memory.py
```

Both commands default to offline controls. Actual inference requires an explicit
model, literal-loopback endpoint and network opt-in. No server discovery, secret
file reading, real vault input or automatic policy application is added.

## Research scope and limits

The first research batch takes stage separation ideas from MemGauge, Korean
answer/abstention evaluation ideas from NoMIRACL and input/scoring separation
ideas from Inspect. This is **not an official Inspect SDK integration**;
the **NoMIRACL dataset is not copied**. Original controlled fixtures are not an
official benchmark reproduction. Scripted controls and local HTTP test services
are **not actual-model performance evidence**. No actual-model result is claimed
by this preparation record. Other research candidates remain out of scope.

## Compatibility and upgrade

Installation uses `--ref v0.39.0`. Python 3.10+ standard library requirements
remain unchanged. CI adds two offline smoke steps to the existing nine unit-test
matrix cells; it adds no inference job or runtime call. Checkout-only tools do
not imply new installed-resource requirements. Publication, active installation
updates and company-vault configuration are separate operations.

The seven certificate-bound checker files and committed LF harmless corpus are
unchanged from v0.38.1. Expected `checker_sha256`:
`be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`;
`corpus_sha256`: `38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`.
The healthcheck release stamp is outside those bound files. Matching installed
bound bytes need no certificate regeneration for this transition alone. Older
changed-byte transitions still require warning reset, aligned engine copies,
certificate regeneration with harmless replay, then re-promotion, including
rollback. Verify actual LF bytes in old Windows checkouts.
