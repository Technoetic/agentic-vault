# v0.40.0 — optional multi-skill routing evaluation

v0.40.0 adds an optional checkout-only evaluator for caller-supplied, ordered
skill observations. Existing v0.39.* release and candidate records remain history.
This preparation record makes no actual-model routing or performance claim.

## Scope

[`scripts/evaluate_skill_routing.py`](../../scripts/evaluate_skill_routing.py)
provides three explicit commands:

- `catalog`: collect manifests from caller-selected owned roots; optional
  same-name, description and vocabulary-overlap diagnostics are advisory.
- `evaluate`: check required multi-skill composition, forbidden and unexpected
  calls, neutral helpers, invocation order and entrypoints.
- `compare`: list improved, regressed, unchanged and unmeasured cases from
  compatible trusted grader outputs.

The 32 original AI-assisted KR/EN synthetic cases include vault and non-vault,
read-only and implementation, authorized Jev-first, negative, ambiguous and
composed-skill requests. Frozen pass/faulty traces are `scripted_control`, not
live host observations. Unavailable, error and missing observations stay
unmeasured, including negative cases. A self-report is never an invocation;
file reads require explicit selection and retain that evidence label.

The evaluator does not call models, Jev, a network service or subprocesses.
There is no live Codex observation adapter. It installs nothing, adds no hooks,
changes no SKILL descriptions or configuration defaults, and executes no skill
bodies. The scanner accepts a strict bounded frontmatter subset rather than
general YAML and scans only explicitly selected roots without following links.

Reports bind the full suite, catalog, raw inputs and evaluator source. Comparison
requires compatible suite, source, owned IDs, evidence kind and runtime. It checks
internal consistency, cannot regrade expectations omitted from reports, and does
not authenticate caller-authored grades or host observations. A caller can alter
grades and recompute hashes. Filling missing evidence is not an improvement.

See the [routing guide](../skill-routing-evaluation.md) for executable catalog,
evaluation and comparison examples, expected control results and evidence limits.

## Compatibility and upgrade

Installation refs target `--ref v0.40.0`. Publication does not update active
installations or a company vault. Checkout-only developer tools add no installed
resource requirements, runtime dependencies or default discovery ambiguity.
Python 3.10+ and the standard library remain the runtime requirements. Earlier
evaluators, search, skill descriptions, default hooks and configuration retain
their contracts. CI uses offline controls within the existing matrix; no live
inference job is introduced.

The healthcheck release stamp and `ENGINE_VERSION` become `0.40.0`; these are
metadata-only changes outside the seven certificate-bound checker files. Those
files and the committed LF harmless corpus retain their prior bytes. Expected
`checker_sha256`: `be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`;
`corpus_sha256`: `38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`.
Actual-byte checks and harmless replay remain release gates. Matching installed
bound bytes need no certificate regeneration for this transition alone. Older
changed-byte transitions retain warning reset, engine alignment, certificate
regeneration with harmless replay and re-promotion, including rollback.
