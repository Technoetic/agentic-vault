# agentic-vault v0.15.1

날짜: 2026-09-23

v0.15.1은 선택 기능인 Telegram Jarvis 브리지의 Claude 실행 경로를 고친 보안 패치다.
데몬 내구성, 경로·비밀 규칙 통합, 문서·메타데이터 정정을 함께 담았다. 공개 v0.15.0
(`84f0cb6`) 이후 변경이며, 미공개 로컬 커밋 `8fdaa5f`(Windows 콘솔 창 숨김)를 포함한다.
Jarvis를 켜지 않은 설치에서는 보안 수정 두 건의 코드 경로가 실행되지 않는다.

## 보안 수정

### Windows 배치 런처를 통한 명령 주입 (high)

- **영향 조건(모두 충족):** ① Windows에서 Jarvis 브리지를 실행한다. ② `jarvis.claude_cmd`
  (기본 `claude`)가 `.cmd`·`.bat` 런처로 해석된다. 대표적인 경우가 npm 전역 설치의
  `claude.cmd`다. ③ 화이트리스트에 있는 Telegram 사용자 ID가 비공개 채팅으로 Q&A 메시지를
  보낸다. 따라서 외부 공격자는 소유자의 Telegram 계정(또는 로그인된 기기·웹 세션)을
  제어해야 한다. 화이트리스트 밖 발신자의 메시지는 이전 버전에서도 폐기됐다.
- **영향 없음:** macOS·Linux, 네이티브 설치(`claude.exe`)로 해석되는 Windows, Jarvis를 켜지
  않은 볼트. `기억해:` 캡처와 집사 보고는 claude를 실행하지 않는다.
- **증상:** v0.3.0부터 v0.15.0까지 브리지는 질문을 `claude -p <질문>` 인자로 넘겼다.
  Windows는 `.cmd`를 cmd.exe로 실행하고, cmd.exe는 따옴표와 `&`·`|`·`>`를 다시 해석한다.
  그래서 메시지에 섞인 명령이 브리지를 실행한 사용자 권한으로 실행될 수 있었다. 가짜
  `claude.cmd`로 로컬에서 재현했다. 공격이 아니어도 `"R&D" 예산은?` 같은 질문이 실패했다.
  cmd.exe는 첫 줄바꿈에서 명령줄을 자르므로, 여러 줄인 정기 브리핑 프롬프트는 첫 줄만
  전달됐고 그 뒤의 도구 제한·가드 인자가 빠진 채 실행됐다.
- **수정:** 질문과 브리핑 프롬프트는 표준 입력으로만 넘긴다. argv는 고정값이라 Telegram
  텍스트가 들어가지 않고, `-`로 시작하는 메시지도 옵션으로 해석되지 않는다. Windows에서는
  `.cmd`·`.bat`과 `.exe`가 아닌 대상을 실행하지 않는다. 네이티브 실행 파일을 추측해서
  찾지 않는다. 확장자 없는 이름이 현재 폴더에서만 발견되면 거부한다. 제어문자가 든
  `jarvis.claude_cmd`·`deny_zones`·`hot_note`·`language` 값으로는 claude를 실행하지 않는다.

### 읽기 전용 Q&A의 도구 제한 (medium)

- **이전:** `--allowedTools Read Grep Glob`만 넘겼다. 이 옵션은 나열한 도구를 묻지 않고
  승인할 뿐 다른 도구를 없애지 않는다. 사용자·볼트의 Claude 설정에 느슨한 allow 규칙이나
  `defaultMode`가 있으면 쓰기·명령 도구가 열릴 수 있었다. 조건부 위험이며 실제 실행으로는
  확인하지 않았다.
- **수정:** `--tools Read,Grep,Glob`로 세션이 쓸 수 있는 내장 도구를 셋으로 줄이고,
  `--strict-mcp-config`로 MCP 서버를 불러오지 않는다. `--allowedTools`는 유지한다.
- **경계:** Claude CLI의 도구 가용성과 프롬프트 정책이며 OS 샌드박스가 아니다. 세션은
  볼트 디렉터리에서 시작하므로 볼트의 Claude 설정을 읽는다. 사용자가 직접 설정한
  Claude Code 훅은 이 도구 제한의 대상이 아니다. 알려진 한계는 [SECURITY.md](../../SECURITY.md)에 정리했다.

## 동작 변경

- **npm으로 설치한 Windows 사용자:** claude가 `claude.cmd`로만 잡히면 Jarvis Q&A와 `/brief`는
  답 대신 오류 안내("claude가 Windows 배치 런처(.cmd/.bat, npm 설치 방식)로 잡혀 실행하지
  않습니다…")를 보낸다. 예약 브리핑은 전송되지 않고 로그에 `claude 실행 거부: batch-launcher`가
  남으며 60초에서 1시간 사이 간격으로 다시 시도한다. 해결하려면 네이티브 설치로 `claude.exe`를
  쓰거나 `vault-config.json`의 `jarvis.claude_cmd`에 `claude.exe` 전체 경로를 지정한다.
  캡처와 집사 보고는 계속 동작한다. `--self-test`의 claude 탐지 경고도 배치 런처를 제외한다.
- 제어문자가 든 `jarvis.claude_cmd`는 설정 오류로 데몬을 시작하지 않는다.
- Claude CLI가 `--tools`·`--strict-mcp-config`를 지원해야 한다. 지원하지 않는 구버전에서는
  Q&A·브리핑이 "응답 생성에 실패했습니다"로 끝난다. 두 옵션의 존재는 평가 때
  Claude Code 2.1.252의 `claude --help`(모델 호출 없음)로 확인했다.
- `vault_judge`가 보내기 전에 거르는 비밀 패턴이 `jev_ask`와 같은 범위로 넓어졌다. AWS 키,
  `github_pat_`, JWT, 짧은 비밀번호, `client_secret`, `access_token`이 든 발췌는 이제 거부된다.
- 검사기 config 경로에 `?`·`|`·`<`·`>`·`"`·`*`·제어문자가 있으면 `validate_config`가 바로
  거부한다. 이전에는 노트 경로 해석 단계에서 거부되던 값이다. `vault_paths`와 백업도
  `clock$` 장치명을 거부한다.
- full 모드 리포트에 **§14b**가 생겼다. 따라가지 않은 심볼릭 링크·정션 아래 디렉터리와
  노트, rules 파일을 볼트 상대 경로로 보고하고 관리성 이슈로 센다. 링크 대상과 내용은
  기록하지 않는다. deny zone과 `exclude_dirs` 안은 보고하지 않는다. 종료 코드 규칙은 같다.
- full 모드도 노트를 `utf-8-sig`로 읽는다. BOM이 붙은 노트가 staged 모드와 같은 판정을 받는다.
  Jarvis config 로더와 recall 노트 읽기도 같다.

## 내구성

- 업데이트 하나에서 예상 밖 예외가 나도 데몬이 멈추지 않는다. 본문 없이 로그를 남기고
  소유자에게 알린 뒤 그 업데이트를 건너뛴다. config 오류는 여전히 데몬을 멈춘다.
- 재시도 간격이 연속 실패마다 두 배로 늘어난다. 수신은 5초에서 60초까지, 실패한 정기
  브리핑·집사 보고는 60초에서 1시간까지다. 이전에는 실패한 작업을 쉬지 않고 다시 실행했다.
- 배치 처리 중간에 실패하면 메모리의 offset을 마지막으로 저장한 값에 맞춘다. claude·검사기
  실행의 `OSError`와 시간 초과를 잡는다. 예상 밖 치명 오류는 종류와 위치만 기록하고 종료한다.
- Windows에서 Q&A·브리핑용 claude 자식 프로세스를 `CREATE_NO_WINDOW`와 `STARTUPINFO`
  (`SW_HIDE`)로 실행해 콘솔 창이 뜨지 않는다(`8fdaa5f`).

## 규칙 통합

- 비밀 필터는 `jev_client.SENSITIVE` 하나다. 이전 두 사본의 합집합이라 어느 쪽이 막던
  값도 통과하지 않는다.
- 경로 세그먼트 규칙, deny·exclude 구역 판정, 링크·재분석 지점 격리는 `vault_paths.py`가
  단일 출처다. pre-commit 훅이 단독 실행하는 `vault_healthcheck.py`는 같은 규칙의 글자 그대로
  사본을 담고, `tests/test_rule_sources.py`가 두 사본의 불일치를 막는다.

## 문서·메타데이터

- README 배지를 실제 파일 수에 맞췄다: 명령 14개, 템플릿 14개, 엔진 rules 6개.
  `tests/test_readme_truth.py`가 배지·본문 숫자, 검사기 스탬프, 매니페스트 버전을 대조한다.
- README 상단에 영어 개요를 추가했다. [SECURITY.md](../../SECURITY.md)와
  [문서 색인](../README.md)을 새로 만들었다.
- CI 공백 검사가 커밋된 트리 전체를 검사한다(`git diff --check <빈 트리> HEAD`). 이전 명령은
  체크아웃 직후의 작업 트리와 인덱스를 비교해 항상 통과했다.

## 하위호환·업그레이드

- config 스키마와 명령은 바뀌지 않았다. rules와 git 훅 스탬프도 그대로다.
- 검사기 내용이 바뀌어 `agentic-vault:healthcheck engine=0.15.1`로 올렸다. `ENGINE_VERSION`과
  같은 값이다. `/vault-upgrade`는 볼트의 `00-meta/scripts/vault_healthcheck.py`(0.14.0 이하)를
  교체 후보로 잡고, diff를 보여준 뒤 로컬 수정이 없을 때만 교체한다.
- 실행 중인 Jarvis 브리지는 플러그인을 갱신한 뒤 재시작해야 새 코드가 적용된다.
  Windows에서는 `where.exe claude`로 `claude.exe`가 잡히는지 먼저 확인한다.
- 릴리스 태그 설치는 `--ref v0.15.1`을 사용한다. 플러그인 갱신 후 새 호스트 세션을 연다.

## 검증

[검증 기록](../verification/v0.15.1.md)에 명령과 결과를 남겼다. 모든 테스트는 가짜 실행
파일과 목으로 돌렸다. 실제 Claude·Telegram·Jev 호출은 하지 않았다.

## 알려진 경계

- 도구 제한은 OS 경계가 아니다. 프롬프트 인젝션은 완화할 뿐 막지 못한다.
- Telegram 계정을 제어하는 사람은 화이트리스트 사용자로서 캡처와 읽기 전용 Q&A를 쓸 수 있다.
- 내부 작업 기록(`docs/plans`·`docs/superpowers`·`docs/verification`)은 아직 옮기지 않았다.
  [문서 색인](../README.md)이 사용자 문서와 구분한다.
