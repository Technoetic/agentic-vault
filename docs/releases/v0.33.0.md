# v0.33.0 — 합성 기억 경계 평가와 선택형 행 진단

## 변경

- [`scripts/evaluate_state_revisions.py`](../state-revision-evaluation.md): 독립 작성한 합성 사례 4개·스냅숏 9개로 현재 값, 이전 값, 섞인 상태와 선언한 산술 의존성 재계산을 구분한다. 구조화한 관측의 digest-bound replay를 지원한다.
- [`scripts/evaluate_evidence_insufficiency.py`](../evidence-insufficiency-evaluation.md): 독립 작성한 한국어 합성 사례 5개에서 근거 부족 인정과 근거 없는 전제 부정을 구분한다. 명시한 슬롯·완전성·긍정/부정 근거를 대조하며 구조화한 관측을 재생한다.
- [`check-support --row-references --bind-subject`](../support-row-diagnostics.md): 두 옵션은 따로 켤 수 있다. `--row-references`는 파싱한 모든 사실 행(지원·미지원·미해결·건너뜀)의 내용 없는 참조와 `audit_population`을 내보낸다. `--bind-subject`는 같은 물리 줄의 주어·값 관측과 별도 `binding_warnings`를 더한다. 기존 `warnings`·지원 판정은 유지한다.
- Codex 설치 검증은 두 평가기, 두 합성 fixture와 세 안내 문서의 설치 바이트도 대조한다. healthcheck 식별 스탬프·`ENGINE_VERSION`과 세 매니페스트는 `0.33.0`이다. 내용이 같은 규칙·어댑터 스탬프는 유지한다.

평가기와 진단은 오프라인 Python 3.10+ 표준 라이브러리 도구다. 기본 훅·검색·15명령을 유지하며 모델·네트워크 호출이나 실제 볼트 자동 갱신을 추가하지 않는다. Codex 고정 설치 ref는 `--ref v0.33.0`이다.

## 하위호환·업그레이드

새 옵션을 끈 기존 출력 56건은 v0.32.0과 같았다. 다만 선택형 기능이 `vault_ssot.py`를 바꾸므로, 경고 승격 인증서의 `checker_sha256`는 v0.32.0의 `9bca12a79bfa87ff2bf44afecb2e5527e19c199b95fc1435d9513d2be73b3563`에서 `af8f4c5ab9fc809a4998e55870e769d5f617d6742a53d0c5c2844df7ff3d7b92`로 바뀐다. 기존 harmless corpus는 같다. 인증서는 버전 이름이 아니라 실제 바이트를 묶는다.

Claude Code와 Codex의 플러그인 설치본, 그리고 git 볼트에서 pre-commit 훅이 실행하는 볼트 안 엔진 사본(`00-meta/scripts/`)이 그 대상이다. 그래서 경고를 `fatal`로 올린 볼트는 갱신 전에 다음 순서를 따른다. 이전 버전으로 되돌릴 때도 같은 순서다.

1. 볼트 설정 `warning_policy.levels`에서 `fatal`로 올린 단계를 `warning`으로 되돌린다.
2. 볼트를 읽는 엔진을 모두 같은 버전(되돌릴 때는 이전 버전)으로 바꾼다. Claude Code와 Codex 설치본을 함께 바꾸고, git 볼트의 엔진 사본은 갱신할 때 `/vault-upgrade`(Codex `upgrade`)로 바꾼다. `/vault-upgrade`는 사본을 이전 버전으로 내리지 않으므로, 되돌릴 때는 그 사본도 이전 버전의 파일로 직접 되돌린다.
3. 바꾼 설치본에서 `vault_warning_policy.py --certificate`로 인증서를 다시 만들어 볼트 설정의 `warning_policy.certificate`에 넣는다. 이 명령은 harmless replay를 실행하므로 실행 결과와 설치 바이트를 확인한다.
4. 단계를 다시 `fatal`로 올린다.

맞지 않는 인증서를 유지하면 healthcheck는 종료 코드 1로 멈추고 SessionStart는 주입하지 않으며 `--staged`는 커밋을 막는다. doctor·recall은 `invalid_config`, `check-support`를 포함한 SSOT 명령은 `ssot_operation_unavailable`로 멈춘다. 게시만으로 활성 설치 캐시나 실제 볼트 엔진이 갱신되지는 않는다.

## 검증

구현 커밋 `e9d382a6877411c377ccb49c0d7f3fba604ba1f8`의 Windows Python 3.12 전체 시험은 2,537개(환경 제외 43·실패/오류 0), 1,407.344초였다. CLI 검사 15건, 독립 구성요소·최종·집계 검증과 기존 출력 56건 비교를 통과했다. 이는 구현 시점의 관측이며 버전 문서·설치 검증을 바꾼 최종 릴리스 트리의 전체 시험 결과는 아니다.

최종 소스·전체 시험·CI·설치 확인·ZIP 재현·draft 자산·공개 게이트는 별도 절차다. 실제 명령·결과·고정 소스와 게시 전 상태는 `verification.json`, 공개 후 내려받기·해시·Latest/immutable 확인은 외부 `post-publication.json`에 남긴다. 문서를 준비한 것만으로 완료를 주장하지 않는다. [검증 기록](../verification/v0.33.0.md)을 함께 본다.

## 알려진 경계

합성 대조군은 평가기의 구분 동작을 시험하며 실제 모델 효능이나 실제 볼트 오류율을 측정하지 않는다. 근거 부족 평가는 명시한 구조화 슬롯 안에서만 판단하고 보편적 부재를 증명하지 않는다. 주어·값의 같은 줄 동시 출현은 의미 귀속·권위·진실을 입증하지 않는다. 미완전·실패 자료는 보수적으로 `unassessed`가 될 수 있으며 행 모집단은 원자적 파일시스템 스냅숏이 아니다.
