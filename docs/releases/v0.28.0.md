# v0.28.0 — 기억 형성 대조군·현재값 근거 조립·절차 후보 검색

선택해서 실행하는 기억 신뢰성 도구 세 종류를 더한다. 임시 합성 볼트에서 기억 형성의
오염 경로를 비교하고, 호스트가 별도로 승인한 출처와 현재 원문에 묶인 값을 조립하며, 호스트가
작성한 절차 목록에서 현재 실행 영수증에 연결된 후보를 찾는다. 기준 공개판은
v0.27.0 `5dd5d38cb9ad6cbecfe265dd9d755df2d74d9bbc`, 구현 커밋은
`c1cf33b2e503cd45150d72e0cad971c4dd394113`이다. Python 3.10+ 표준 라이브러리를 사용한다.

## 변경

- **기억 형성의 다섯 대조군:** [formation 평가](../memory-formation.md)는 Content·Evidence·Scope·
  Selection·Path의 clean/poisoned 쌍을 임시 볼트에서 실행한다. 실제 capture·provenance·
  구조화 단위·ADD/EDIT 교훈 경로와 기존 결정론 작업 실행기를 사용한다. P4는 같은 경험 풀과
  같은 선택 수에서 선택만 바꾸고, P5는 같은 선택된 경험에서 통합 순서만 바꾼다. 정상 업무
  성공, 최종 오염과 중간 저장 오염, 후속 행동 실패, 정상 업무 손실을 분리한다. 이는
  MemForm을 참고한 합성 기능 시험이며 실제 모델의 공격 내성이나 공식 벤치마크 재현이 아니다.
- **현재값 근거 조립:** [assembly](../memory-assembly.md)의 `extract`는 호스트가 선택한 원문
  path/line에서 필드를 다시 읽고, `assemble`은 별도로 지정한 승인 출처 집합 안에서 값을
  고른다. confirmed 상태, 명시적 scope/polarity, 주체·관계와 반열린 유효기간을 확인한다.
  동시 유효한 서로 다른 값, 불명확한 기간·상태·부정, 관련 현재행의 선택 누락은 보류한다.
  최신 날짜·mtime이나 문서 스스로의 권한 주장은 선택 근거가 아니다. 기존 v2 대장에
  scope/polarity가 없으면 수정하지 않고 `abstain/missing_scope_or_polarity`를 반환한다.
- **읽기 전용 절차 후보 검색:** [procedures](../procedural-recall.md)는 명시한 JSON catalogue의
  task class·cue·전제조건·단계를 BM25로 검색한다. 단계의 순서 DAG와 원문 substring,
  현재 완료된 native run의 후보·지시문·모델·제공자·도구·토큰 조건을 묶는다. 실행순서
  DAG는 기존 개선 후보의 계보와 별개다. 성공 관찰과 문자열 일치는 전체 절차 실행이나
  사람 검토를 증명하지 않으며, 반환된 전제조건도 충족됐다는 뜻이 아니다. 단계는 실행하지 않는다.
- **명시적 routing과 통합 예제:** 공유 스킬의 선택형 진입점과 패키지 resource 검증을 연결한다.
  `python scripts/evaluate_memory_reliability.py`는 임시 볼트에서 native 영수증과 실제 합성
  조작을 사용해 일곱 사례를 검사한다. 모델·네트워크 호출이나 운영 볼트 반영은 없다.
- **기존 명령 메타데이터 수정:** `vault-harden.md`의 `argument-hint`를 문자열로 인용한다.
  인용하지 않은 두 대괄호 묶음은 YAML 파싱 오류를 내며 Claude가 명령 메타데이터를
  비우는 원인이었다. 명령 본문과 안내 문자열은 그대로이고 슬래시 명령 수는 15종이다.
  `claude plugin validate .`의 marketplace 검사와 별도로
  `claude plugin validate .claude-plugin/plugin.json`을 직접 실행해 검사한다.

## 하위호환·업그레이드

기존 slash command 15종, 기본 세션 훅·회상·설정·모델 호출 경로는 그대로다. 새 도구는
명시적으로 선택할 때만 실행한다. 자동 제안 적용·교훈 승격·절차 실행·권한 변경이나 새
런타임 의존성을 추가하지 않는다. formation의 쓰기는 폐기하는 합성 볼트 안의 시험에 한정하며,
assembly와 procedure 조회는 읽기 전용이다.

이번 릴리스의 버전 표면과 healthcheck 스탬프/`ENGINE_VERSION`은 0.28.0을 사용한다.
내용이 같은 기존 규칙 스탬프는 유지한다. 경고 인증서의 일곱 검사기 파일·harmless corpus와
기존 명령 수 15종은 유지하며 `vault-harden`의 YAML 인용만 수정했다. 최종 소스의 기본 동작·resource 비교 결과는
[릴리스 검증](../verification/v0.28.0.md)과 최종 `verification.json`에서 확인한다.

**경고 승격 인증서:** 검사기와 corpus가 같아도 인증서는 설치본의 실제 바이트를 묶는다.
줄바꿈·설치 파일이 달라지면 자동 호환을 보장하지 않으므로 실제 설치본에서 재검증한다.
v0.25.0 이하에서 올라오면 v0.26.0의 via_bot 변경으로 기존 인증서가 맞지 않는다.
갱신 전에 승격 단계를 `warning`으로 되돌리고 새 설치본의
`vault_warning_policy.py --certificate`로 다시 만든 뒤 승격한다. 인증서를 자동 갱신하지 않는다.
[v0.26.0 이행 조건](v0.26.0.md#하위호환업그레이드)과
[v0.25.0의 바이트·corpus 조건](v0.25.0.md#하위호환업그레이드)을 유지한다.

v0.26.0 이전 엔진은 `content_origin: via_bot` 수집을 `provenance-invalid`로 보고한다.
같은 볼트를 읽는 Claude Code·Codex 설치본을 함께 갱신하고 이전 판으로 되돌릴 때도 해당
수집의 처리와 경고 단계를 확인한다. Jarvis의 API 인증 조건은 그대로다. 구독 로그인만으로
Q&A·예약 브리핑을 실행할 수 없다.

게시 후 Codex 설치 대상 ref는 `--ref v0.28.0`이다. 등록 소스·캐시 보존 절차는
[Codex 설치 안내](../codex.md#설치)를 따른다. 게시, 활성 설치 캐시 갱신, 실제 볼트 upgrade는
서로 다른 작업이며 릴리스 준비만으로 운영 환경이 갱신되지는 않는다.

## 검증

[구현 검증 기록](../verification/memory-reliability-20261022.md)은 초기 실패와 후속 수정을
함께 보존한다. Windows/Python 3.12 초기 전체 실행은 **1,950개, 환경 skip 34개, 문서 링크 실패
1개**였다. 실패한 검사는 아직 작성되지 않은 구현 검증 기록을 README가 가리킨 경우다.
이후 해당 문서와 다섯 formation 회귀 검사를 추가했고, 최종 formation 26개와 문서 검사를 재실행했다.

수정 후 **실제 시험 ID 합집합은 1,955개 = 통과 1,921개 + skip 34개, 미해결 실패·오류 0개**다.
이는 초기 전체 실행·최종 formation 실행·문서 재실행을 합친 감사 결과이며, 1,955개 전체를 한 번에
실행한 단일 PASS로 표시하지 않는다. 구현 단계의 assembly 44개(1 skip), procedures 36개와
일곱 사례 통합 예제, 기존 오프라인 게이트도 같은 기록에 명령별로 구분돼 있다.

이 수치는 버전 표면을 바꾼 최종 릴리스 트리의 검증을 대신하지 않는다. 최종 metadata·CI·독립 검토·
패키지·ZIP/blob 대조·재빌드와 설치 검증은 준비 시점에 대기 상태다.
[v0.28.0 검증 기록](../verification/v0.28.0.md)에 각 gate를 적고, 고정 소스의 실제 결과는 게시 전
`verification.json`에 연결한다.

불변 릴리스 자산은 `agentic-vault-0.28.0.zip`, `SHA256SUMS`, `verification.json`이다.
최종 태그를 고정한 뒤 `TZ=UTC0`과 prefix `agentic-vault-0.28.0/`으로 ZIP을 만들고
`rebuild_spec` 및 Git member/blob·L1/L2 결과를 기록한다. 세 자산을 초안에서 확인한 뒤 게시한다.
게시 후 증명·공개 재다운로드 결과는 잠긴 자산 밖의 별도 `post-publication.json`에 보관한다
([릴리스 무결성](../release-integrity.md)). 아직 수행하지 않은 gate를 완료로 읽어서는 안 된다.

## 알려진 경계

- 합성 기능 시험은 실모델·실제 업무 효과·일반 공격 내성·인과관계·총비용 절감을 측정하지 않는다.
  bounded formation도 근거를 거부한 두 poisoned 사례에서 정상 작업을 잃는다.
- assembly는 literal identity와 수동 구조화 scope/polarity만 지원한다. 자유문장의 의미·부정·동의어·
  단위 변환이나 인용의 의미적 뒷받침을 자동 판정하지 않는다. source hash와 별도 authority 인자는
  진실·인증·행동 권한을 보증하지 않는다.
- 절차의 성공 관찰·원문 substring·DAG는 전체 절차 실행 증명이 아니다. 카탈로그와 출력은 검토할
  데이터이며 다음 행동을 승인하지 않는다. 준비 시점의 Linux/macOS 신규 경로 실행은 대기이며
  최종 CI 관찰은 `verification.json`에 기록한다. 실제 업무 효과는 미측정이다.
- 현재성 재검사는 시점별 확인이며 다중 파일 트랜잭션이나 비협조적 편집을 막는 OS 경계가 아니다.
