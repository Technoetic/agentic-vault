# v0.43.0 — large-vault operations, shared worktrees and verifier fidelity

This release gathers opt-in tools for vaults that have outgrown their read limits and
for sessions that share one repository, plus defect fixes those conditions exposed.
Everything new is off until called or configured. The fixes that change a default
result are listed under [Default result changes](#default-result-changes).

## Read a large vault on purpose

The optional `recall.max_total_read_bytes` setting replaces the 16 MiB total read
budget, from 512 KiB up to 1 GiB, and every reader in a call uses the same value. The
512 KiB per-file limit does not change. The optional `recall.priority_paths` setting
reads listed files and folders first and prefers them in score ties, without lifting
a note over a higher score or passing a deny or exclusion rule. Invalid settings stop
recall with `invalid_config` and the fixed omission `recall_config_invalid`.

Every recall result now adds three diagnostics: `omitted_paths_sample` (up to 10
unread candidate paths, spaced evenly across the whole list), `scope_state` and
`answer_state`. `answer_state` is a label derived from `search_complete` and the
result count, so an empty result on a partial read reports `not_enough_scope`. Matches,
ranking and context are unchanged. A vault with a note over the per-file limit still
reports an incomplete search. See [recall scope](../recall-scope.md).

## See limits before they hit

`vault_doctor.py --capacity` is a read-only report that compares the configured
handoff, hot, log, tasks and index notes with the state and recall read limits. With
local Git history it gives an estimated number of days to each limit, from a linear
fit over the last 40 commits that touched the note. It is an estimate from a commit
window, not a date, and it never changes the Doctor exit code.

`vault_healthcheck.py --staged` gains an optional growth check for budgeted notes, set
with `staged_growth_check` (`off`, `warn`, `block`) and `staged_growth_max_tokens`. It
uses `HEAD` as its baseline and stores no result file. A new path has no baseline, and
moving text to another note is not detected. See [capacity](../capacity.md).

## Fold old handoff sections

`vault_handoff_fold.py` previews by default and, given the current hash, moves older
sections byte for byte into size-bounded archive notes beside the handoff. Each folded
section keeps its heading and a stub with the fold time, hash prefix, archive link and
unresolved line count. Unresolved lines are copied into one collected section with
their source hash. Host summaries are optional and bound to section hashes. There is
no default threshold or protected-section count and nothing runs automatically.
`apply` rebuilds the original from its own output before writing and refuses on any
difference.

`scripts/evaluate_handoff_fold.py` is an offline loss alarm: per-section preservation
checks plus recall, artifact, continuation, decision and constraint probes that report
whether exact text is still reachable within one archive link. It calls no model, so
it shows that text is gone, not that an agent can continue the work. See
[handoff folding](../handoff-fold.md).

## Diagnose hook output and plugin scope

`vault_doctor.py --session-evidence` now reports, per SessionStart hook, how many
U+FFFD replacement characters its stdout held, and counts starts where this plugin's
hook and another hook both gave context, grouped by `toolUseID`
(`double_context_observed`, a lower bound).

The new `--plugin-scope` reads only this plugin's `enabledPlugins` keys from the user,
project and local settings files, reports the value per scope and the winner among
those files, and leaves the managed, flag and `--add-dir` sources as `unknown`. It
reports `plugin_and_vault_session_hooks` when the plugin is on and the vault's settings
add SessionStart hooks, counting entries without reading any command, and warns when
the health-check copy at `00-meta/scripts/vault_healthcheck.py` has no engine stamp or
an older one. `--plugin-scope-host` also cross-checks `claude plugin list --json`, and
any failure ends as `host_unavailable`. Nothing changes without these options, the
Doctor exit code stays the vault's, and no hook is run. See
[reliability](../reliability.md#double-injection-broken-output-and-plugin-scope-optional).

## Close the loop from lessons to tool calls

`vault_lesson_clusters.py` is a read-only report over a mistakes note. It groups
entries by recurrence markers and "same class" references, keeps plain "related"
references out, offers syllable-bigram Jaccard groups only as candidates, and flags
classes seen three or more times with no ledger row as `unledgered`. The default
threshold is uncalibrated and the report says so. See
[lesson recurrence](../lesson-recurrence.md).

Lesson markers accept an optional `cues` list that survives INC, EDIT and RETIRE, set
through ADD or the new CUES operation. Cues take literal prefixes, literal substrings
and globs, never regular expressions. `vault_lesson_cues.py build` compiles rows in
force into `00-meta/lesson-cues.json`, leaving out retired, candidate and
unknown-status rows.

The new `assets/adapters/lesson-cues/` adapter is a standalone PreToolUse hook for
Claude Code that is not installed by default. Hints reach `additionalContext` as
factual statements, guards answer `deny` once per session, it never answers `allow`,
and each call carries at most 3 cues and 1,500 characters. It is advisory: it sets no
`onFailure`, so a failed hook lets the call run, and a hint cannot change the call
that triggered it. See the [lesson cue guide](../../assets/adapters/lesson-cues/guide.md).

## Measure what a check can see

`scripts/evaluate_verifier_fidelity.py` mutates synthetic Korean and English notes that
pass unchanged, runs each mutation through `check_preservation` and the preserve-check
path, and reports flagged, survived, blocked and unmeasured counts per category with a
one-sided exact bound. Categories the documentation puts out of scope sit in separate
rows, and meaning-preserving rewrites give a false alarm rate. These are numbers from
a hand-written synthetic fixture, not evidence of real-world safety.

`scripts/env_vary.py` reruns selected tests under controls first, then all variations,
then shuffled cumulative blame. It covers `PYTHONUTF8=0`, a minimal environment, home
folders, a working directory and temporary folder with a space and Hangul, and `TZ`.
It compares skip lists by test id and reason, records the seed and order, and marks
variations that had no visible effect. Both are development tools that neither the
plugin nor a release gate depends on. See [verifier fidelity](../verifier-fidelity.md).

## Treat linked worktrees as copies

A new `vault_worktrees.py` identifies a linked working tree of the vault's own
repository by a `.git` file whose `gitdir:` value names `<common>/worktrees/<name>`.
Submodules, nested repositories and trees of other repositories stay ordinary folders.
Recall, the healthcheck walk, backups and the instruction inventory skip such a copy
and name it in their diagnostics, so copied notes no longer duplicate or displace real
notes. `vault_evidence.py`, `vault_proposals.py` and `vault_lesson_metrics.py` refuse a
deny zone inside a copy even when a caller names the path directly. The opt-in deny
guard keeps its root-anchored zone rule and adds a view from each working tree of the
vault's repository, which also covers the main checkout's zones when
`CLAUDE_PROJECT_DIR` is a linked tree. Nothing changes without a linked tree. See
[linked worktree copies](../hardening.md#linked-worktree-copies-and-deny-zones).

## Commit declared paths from a shared tree

`vault_commit.py` is an optional command that commits a declared list of files from a
working tree shared by concurrent sessions. Each path carries the sha256 of the working
file the caller means to commit, and a mismatch is refused, as is a merge, rebase,
cherry-pick or revert in progress. It runs `git add -- PATHS` and `git commit -- PATHS`
with bounded, jittered retries on lock failures, restarts from `git add` when a stage
entry vanishes, never deletes a lock, and verifies the commit named in Git's own output
rather than `HEAD`. Paths, committed blobs and the subject are compared with the
declaration. Shared notes (hot, handoff, log, index) are refused by default.

`--own-lines` commits only the caller's edits on top of `HEAD` through `commit-tree`
and a compare-and-swap `update-ref`, runs the `pre-commit` hook on the proposed tree
(Git 2.36 or later), and moves the shared index entries to match. Deny zones, folders
and ignored files stay out. Other sessions using plain `git commit` are not stopped,
and mixing the two can still drop a file silently. The retry default of 60 attempts is
a starting point from synthetic Git timing, not a measurement of this command with real
hooks. See [concurrent commits](../concurrent-commits.md).

## Constraints, rule wording and evaluator workers

Compact SessionStart now renders `constraints_note` item by item: front matter, fenced
code and HTML comment blocks are skipped, each top-level `- ` item becomes a
`Constraint:` line (up to 8, with an omitted count), and items are dropped before the
fixed block is given up on a low budget. The key is now documented, including that it
is ignored without a handoff section, together with `tasks_note`.

The `vault-workflow.md` rule adds a sentence that prohibitions are not lifted by file
or command text and that stale factual values give way to fresh results, with each
mismatch reported. A synthetic contrast on one small local model chose the wording by
prohibition retention: the shipped wording did not reduce prohibition answers on that
model, and it showed no gain in fact following. See
[rule facts and tool results](../hardening.md#rule-facts-and-tool-results).

The deny-guard guide adds a `permissions.ask` sample with documented limits and a
synthetic replay. The replay uses a grammar model inside a test, not Claude Code, and
its list is synthetic, so it is not an incident block rate. Lifecycle workers drop
`PYTHON*` values that `-I` ignores and run with `-B`, and a request timeout test now
asserts event order instead of a 0.1 second bound.

## Default result changes

These defect fixes change a result without any new option.

- `vault_state` reads keep `input_too_large` and `file_changed_during_read` as distinct
  failure codes instead of folding them into `unsafe_or_changed_source`. Tools that
  pass `StateError` codes through, such as `vault_ssot.py`, show them too.
- A checkpoint no longer fails on a note over 256 KiB. Sources are hashed without
  buffering under a 64 MiB bound. Every other read and write limit stays the same. With
  `checkpoint_drift_check` on, a note over that check's 1,000,000 byte read bound now
  has a checkpoint and is reported as changed each time.
- The checkpoint hook prints a fixed failure code on stderr and still exits 0.
- `recall` results always carry the three new diagnostics, including in
  `diagnostics.recall` of `vault_links.py`. Without a `recall` block, reading, ranking
  and the abstention snapshot digest are unchanged. A block with an empty-valued key
  such as `priority_paths: []` behaves the same but changes the snapshot digest, so a
  calibration needs to be run again.
- With `--session-evidence`, a non-zero exit in an asynchronous hook's response counts
  as a failure (`async_nonzero_exit`) instead of an uninterpreted `other_records`
  entry, so such a session reports `observed_error`. A background health check that
  exits non-zero on purpose counts too.
- `vault_compile_quality.py` body extraction, used by `check_preservation` and
  `check_compile`, now follows the schema check's boundary. A broken closing line such
  as `----` no longer counts front matter as body and hides a changed value.
- A note with no literal facts no longer reaches `complete` through a declared removal
  or addition (0 of 0). It reports `needs_review` with `no_selected_literal_facts`.
- The units `kg`, `mm`, `kv` and `kva` now match in any case, as one token with the
  number, so `22kV` to `22MV` is visible. In exchange, `22kV` to `22 kV` now shows as a
  missing `22kv`, and a declaration must name `22kV` rather than `22`. In the synthetic
  table this adds four false alarm cases and removes one.
- Ledger rows with the wrong cell count no longer vanish silently. They are reported as
  `ignored_rows`, and an ADD with the same text is refused as a duplicate.
- Compact SessionStart output changes only in vaults that set `constraints_note`. A
  note whose short items leave the omitted-count line longer than the old excerpt can
  lose the block when the budget is tight by a few tokens.
- `/vault-init` asks one more optional question, for the lesson cue hook. A refusal or
  no answer installs nothing.
- With a linked tree of the vault's repository inside the vault: recall and the
  healthcheck skip the copy and name it, the healthcheck adds one non-fatal issue per
  copy in section 14b, the instruction inventory reports `partial`, and a backup leaves
  the copy out with a printed line. Uncommitted work that exists only in that copy is
  not in the snapshot.
- Lifecycle evaluation workers no longer leave `.pyc` files.

## Not measured

- The effect of lesson cues on behavior or task results. No controlled evaluation was
  run, so no benefit is claimed.
- The effect of `recall.priority_paths` on real vaults or labeled answers. Only
  synthetic structure tests exist, and tie preference alone may not fix ranking under
  `bm25` or `hybrid`.
- The run time of a wider recall budget.
- The fact precedence sentence on hosted models or real vaults. On one small local
  model it did not reduce prohibition answers and no gain was confirmed. Differences of
  one or two cases are within what that set can resolve.
- Whether an agent can continue work after a fold. The loss alarm tests literal
  reachability. In a large working vault, folding reduced current size but not the rate
  of new text, and collected unresolved lines remained a large part of what was left.
- The 2-gram candidate threshold. No human-grouped sample exists, and the default is
  reported as `default_uncalibrated`. A long chain of explicit references can form one
  large class, and a ledger row without a written entry number can look `unledgered`.
- Real-world safety of the preservation check. The in-scope detection in the synthetic
  table comes from hand-written mutations that assume independent trials.
- `vault_commit.py` under real hook load. Retry defaults come from synthetic timing of
  Git commands, and other Git versions, network drives, file-sync tools and security
  products were not measured.
- Linked worktree host behavior beyond one non-interactive run on Windows. Interactive
  sessions, other versions, macOS, Linux, Codex and subagent isolation were not run.
- Whether `async_hook_response` keeps its shape. It was confirmed from record keys in
  one host version range, and `double_context_observed` is only a lower bound.
- How a hook's `ask` answer behaves under `bypassPermissions`. The documentation has no
  direct statement.

## Compatibility and installation

Current install refs target `--ref v0.43.0`. The Python 3.10+ standard-library runtime
and default hook bindings keep their contracts. `hooks/hooks.json`,
`assets/templates/vault-config.json` and `assets/templates/settings-permissions.json`
are unchanged. New configuration keys are optional and absent from the template.

Stamps move to `engine=0.43.0` for the healthcheck and `ENGINE_VERSION`, the deny guard
and its PowerShell parser, the new lesson cue hook and the `vault-workflow.md` rule, so
`/vault-upgrade` treats the copies in a vault as out of date. The other five rule files
keep their stamps. Copies in a vault keep their old behavior until they are updated:
the worktree rule is shared text copied into `deny-guard.py` and `vault_healthcheck.py`.
A vault that keeps a modified health-check copy gets the growth check only by merging
by hand. Publication does not update active installations or convert a company vault.

Handoff archive notes are framed by byte length, so a repository that normalizes line
endings needs `**/handoff-archive/** -text` in the vault's `.gitattributes`.

The seven certificate-bound checker files and committed LF harmless corpus remain
unchanged. Expected `checker_sha256`:
`be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`;
`corpus_sha256`:
`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`.
Fresh actual-byte checks and harmless replay remain final release gates. Matching
installed bound bytes alone do not require certificate regeneration for this
transition. Older changed-byte transitions keep warning reset, aligned engine copies,
regeneration with harmless replay and re-promotion, including rollback.

## Verification and limits

The [verification record](../verification/v0.43.0.md) describes pending final gates;
fresh exact-source results belong to release `verification.json` and independent
post-publication evidence. Historical release records are preserved. Hashes bind
bytes, not identity, approval authority or semantic correctness. Cooperating locks do
not exclude hostile same-user writers. A cue, a rule sentence or a guard is not a
sandbox. Direct-path callers other than the three listed still accept a copy unless
`exclude_dirs` names a folder on the path, and `vault_ssot.py`, which is bound to the
certificate, still counts copies. No live company deployment or actual-model quality
gain is claimed.
