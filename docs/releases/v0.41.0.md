# v0.41.0 — optional source-bound ontology contracts

## Explicit definitions and narrow readers

This release adds an optional host-authored JSON sidecar for types, entities,
relations, typed links and metric definitions. Markdown remains the source;
labels, aliases and definitions are annotations bound to exact physical source
spans and current file hashes. `vault_ontology.py` captures a registry or checks
its declaration, configuration, source and registry bindings without writing a
file. Definition edits are detected even when the version label stays the same.

`vault_ontology_query.py` provides exact reviewed-term lookup and preflight of a
host-authored structured plan. Lookup compares NFC/casefold exact labels, aliases
and IDs; overlapping terms remain ambiguous. Candidate records and links with an
unreviewed dependency closure provide no usable context. A plan must name explicit
entity IDs, directed triples and metrics with the required literal dimensions and
a canonical half-open date period. Gaps withhold all usable context.
`ready_for_evidence` means reviewed definitions and valid slots are ready for the
next evidence-gathering step. It does not prove answer data exists or is correct,
compute a value, supply SQL or authorize execution.

The read-only CLI, `vault_ontology_cli.py`, exposes `capture`, `check`,
`search-terms`, `get-term` and `check-answerable`. Inputs are explicit relative
JSON paths under the existing vault policy. Strict JSON decoding, bounded input
and output, source/input rechecks, current revocation policy and unconditional
engine-runtime path rejection apply. A failed registry or final binding check
invalidates the whole result rather than silently trimming definitions. See the
[ontology contracts guide](../ontology-contracts.md) for schemas and examples.

## Inspiration and difference from existing tools

The public inspiration is NVIDIA's October 21, 2026 article,
[NVIDIA Agent Toolkit Expands, Grounding Enterprise Agents in Company Data](https://blogs.nvidia.com/blog/enterprise-platforms-agent-toolkit/),
and [NVIDIA/auto-ontology at commit 2a24f5d34ef6b6e168a7f22d308504d3ab36a198](https://github.com/NVIDIA/auto-ontology/tree/2a24f5d34ef6b6e168a7f22d308504d3ab36a198).
Pinned design references include its
[semantic models](https://github.com/NVIDIA/auto-ontology/blob/2a24f5d34ef6b6e168a7f22d308504d3ab36a198/auto_ontology/semantic/models.py),
[MCP tools](https://github.com/NVIDIA/auto-ontology/blob/2a24f5d34ef6b6e168a7f22d308504d3ab36a198/mcp/auto_ontology_mcp/tools.py)
and [entity-coverage agent](https://github.com/NVIDIA/auto-ontology/blob/2a24f5d34ef6b6e168a7f22d308504d3ab36a198/auto_ontology/retrieval/entity_coverage/agents/coverage.py).
These are prior research references reused for a new application, not newly
discovered projects. The inspiration is conceptual; no NVIDIA code or dependency
is copied into this implementation.

Reused agentic-vault features include source proofs, strict path/stable reads,
revocation and data-only evidence encoding. Existing impact analysis already
tracks explicit claim/source dependencies; OKF export already packages selected
notes; support checks and retrieval already inspect bounded source evidence.
The new difference is a single explicit definitions contract with typed directed
links, literal metric dimensions, exact reviewed lookup and structured plan
preflight. Existing hooks and recall do not automatically consume the sidecar.

## Compatibility and installation

Installation refs target `--ref v0.41.0`. Python 3.10+ standard-library requirements,
default configuration, hooks, rules and installed skill descriptions keep their
contracts. The healthcheck changes only its release stamp and `ENGINE_VERSION`
to `0.41.0`; its behavior remains unchanged. New helpers and the guide are included
in installed-byte verification. Publication does not update active installations
or install anything in a company vault. Existing historical release and failed
candidate records remain intact.

The seven certificate-bound checker files and committed LF harmless corpus are
preserved. Expected `checker_sha256`:
`be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`;
`corpus_sha256`:
`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`.
Actual-byte checks and harmless replay remain final-source release gates.
Matching installed bound bytes alone do not require certificate regeneration for
this transition. Older changed-byte transitions retain warning reset, aligned
Claude Code/Codex/vault engine copies, regeneration with harmless replay and
re-promotion, including rollback.

## Limits and verification

No NLP extraction, model/network/database calls or runtime dependency is added.
The CLI is not an MCP server. Review labels and hashes authenticate neither
semantic truth, reviewer identity nor approval authority. There is no automatic
ontology inference, real-world identity merge, natural-language query planning,
database execution or promotion into trusted instructions. No new model-performance
observation or company deployment is claimed.

The [v0.41.0 verification record](../verification/v0.41.0.md) separates scoped
implementation checks from final-source gates. At preparation, full regression,
independent review, master/tag CI, native discovery, reproducible assets, draft
inspection and immutable publication checks are pending, not passes.
