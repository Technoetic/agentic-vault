# v0.39.3 — align the existing CI time-budget policy test

v0.39.3 supersedes the **unpublished v0.39.2** candidate by aligning one existing
test expectation with the approved CI policy. Earlier v0.39.0 and v0.39.1
candidates were also unpublished. Preserve all candidate tags and failed CI;
the last published release remains v0.38.1 until new publication.
No actual-model inference or new model-performance result is asserted here.

## Candidate failure and correction

Candidate source `4ec90172b6a67da01d0a0f58ee4aa111fd65c8f3` failed CI run
41671850228, job 126042012584, on Ubuntu / Python 3.14. That full unit job
ran 2,823 tests in 455.178 seconds with 82 skips and one failure:
`SupplyChainAuditJobTests.test_blocking_jobs_keep_a_time_limit_with_margin`
still expected a 35-minute unit-job cap, while the approved workflow used 45.
No formal v0.39.2 release was published. This is a stale policy expectation,
not a runtime or timing bug and not an observed CI job timeout.

`tests/test_supply_chain.py` now expects exactly 45 minutes for `unittest`.
Its strict finite-cap assertion remains intact; the stateful and advisory jobs
retain 10 minutes. The test is neither disabled nor relaxed to accept any cap.
Its explanatory comment now matches the approved policy. The workflow itself
is unchanged from v0.39.2, including the matrix, commands, permissions and caps.

The 45-minute policy remains based on the observed 1,964-second Windows unit
step plus measured 93-second post-unit work and 52-second setup: a 2,109-second
planning envelope above the old 2,100-second cap. That cross-job envelope is
not a measured whole-job duration. No tests are omitted, retries introduced
or model-request deadlines changed.
