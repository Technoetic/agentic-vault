# v0.44.0 — authored record preservation and configured revocation at egress

This release adds optional source-bound record checks and applies existing configured
revocations to two context consumers. It keeps the Python 3.10+ standard-library
runtime. No model, vector store, production dependency or automatic edit is added.

## Authored record preservation

The optional `relation_probes` field in preservation and compile checks selects a
source-body record by a literal anchor and a `line` or `paragraph` scope. The source
must select exactly one record. A missing, ambiguous or changed candidate record
requires review. Comparing the whole anchored record can expose quantity swaps,
appended negation and a removed exception within that scope even when independent
words and numbers remain elsewhere.

Manifests contain 1..64 probes with bounded unique IDs and anchors of at most 256
characters. Compile probes name source and target paths already selected and bound
by the existing request hashes. They cannot discover more files or supply a regular
expression. Reports retain counts, hashes and reasons rather than copying source
records. Existing path policy and pre/post source checks still apply.

The comparison is conservative, anchored literal preservation. Unicode NFC and
line-ending normalization do not establish semantic equivalence; meaningful
case and unit distinctions remain. A valid paraphrase can require review, and an
exception outside the selected record is outside the check. A passing report neither
establishes truth nor authorizes an edit. Omitting the new option preserves existing
results. See [the record guide](../relation-preservation.md).

`scripts/evaluate_relation_preservation.py` compares legacy literal observations and
record probes on the same immutable, independently authored synthetic pairs in
`tests/fixtures/relation_preservation/pack.json`. It reports confusion counts and pack
and source fingerprints. The fixture expectations are authored assertions, not a
model judge or a claim of real-world safety. Final measured output belongs to the
verification evidence; no paper result is transferred to this implementation.

## Configured revocation at two egress readers

When `memory_revocation_file` is configured, Jev file-grounded judgments and Jarvis
generation filter complete raw UTF-8 source text through the existing
`RevocationPolicy` before BOM/CRLF display normalization or prefix truncation. Raw
source hashes remain the source binding. Jev excerpts bind to projected source text.
Jarvis carries the exact prompt policy/source envelope through dispatch rather than
rebuilding a different policy afterward and treating it as proof of the earlier prompt.

Both paths recheck their original bindings before dispatch and after completion. A
stale or malformed configured policy cannot silently fall back to unfiltered context
or a successful report. With no revocation configuration, the existing prompt/result
behavior stays unchanged. See [the egress guide](../revocation-egress.md).

This is the scope of the two named consumers and explicitly declared derivative
relationships. It does not discover unregistered semantic copies, inspect every
external program, erase source files, or withdraw information already sent. A check
after completion can reject a stale result but cannot reverse a completed send. No
universal poisoning defense or OS isolation is claimed.

## Generated lifecycle coverage

The existing development-only `hypothesis==6.168.5` dependency is reused for relation
mutation and revoke/declared-derivative/rebuild/fresh-retrieve/prepare/simulated-send
sequences. This extends the shipped proposal and operation lifecycle machines; it is
not a new stateful testing framework. Missing observations do not count as safety.
Benign retention, stale evidence and an unfiltered negative control remain separate
observations. Inputs are synthetic and tests use no live model/API or company vault.

There is no persistent engine index or real outbox in this scope. Fresh reads, rebuilt
derived context and the simulated sink are named as such. The required stateful CI
job installs `requirements-dev.txt` and explicitly runs all three modules:

```sh
python -m unittest tests.test_stateful_memory_lifecycle tests.test_stateful_relation_probes tests.test_stateful_revocation_egress -v
```

The normal unit matrix may skip generated tests when optional development packages
are absent; that does not replace the required stateful job. Actual runs and skips
are recorded separately in the release verification receipt.

## Research and reuse boundaries

The following pinned primary sources informed the design. They are v1 preprints, not
verification of this plugin. The published Reference Atlas and bounded prior notes
were checked before recommendation; absence from that registry is not proof of novelty.

- [Compaction, decay and reinforcement in a two-tier conversational memory: a paired
  evaluation against retrieval-augmented generation, arXiv:2611.09807v1](https://arxiv.org/abs/2611.09807v1):
  motivates preserving source wording and comparing the same original/candidate
  pairs. This release does not implement automatic fact compaction or decay ranking.
  The associated [NMAFC research repository at `fe0dc4e62065c590b3c8ed7dd264b0bf6336c735`](https://github.com/BigBrown10/nmafc-paper/tree/fe0dc4e62065c590b3c8ed7dd264b0bf6336c735)
  had no verified reuse license. It is public research code, not described here as
  licensed open source; no code or data was copied or executed.
- [MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory,
  arXiv:2611.09721v1](https://arxiv.org/abs/2611.09721v1): motivates tracing later exposure
  and benign utility through memory stages. Earlier MemoryGraft and formation tests
  already covered source boundaries and withdrawal examples here; the extension is
  generated declared-derivative and configured-consumer egress sequences. The original
  benchmark and its model behavior are not reproduced. No official code/data license
  was verified, and none was imported.
- [How Much Conversation History Does an AI Agent Need?,
  arXiv:2611.09662v1](https://arxiv.org/abs/2611.09662v1): exploratory guidance for future
  fixed-ranker, fixed-reader budget experiments. Its scoring limits preclude a general
  quality claim. This release neither chooses an optimal budget nor changes the
  existing 512 KiB read ceiling or introduces a streaming redesign.
- [Hypothesis license at `9ab0be61aaaa27396fc1bbf4b34e7925cc68d1e2`](https://github.com/HypothesisWorks/hypothesis/blob/9ab0be61aaaa27396fc1bbf4b34e7925cc68d1e2/LICENSE.txt):
  MPL-2.0 with upstream-noted exceptions. Hypothesis was already referenced by
  [agentic-vault](https://github.com/Technoetic/agentic-vault/blob/89ce65a7c90e202c601ec50ef7cfa4ada0539c79/docs/memory-evaluation.md#L1097)
  and [semantic-crosscheck](https://github.com/Technoetic/semantic-crosscheck/blob/05046875791e50403837d9ff30d6b852196b6763/skills/semantic-crosscheck/references/counterexamples.md#L255).
  The new application is the scoped invariant coverage above, using the existing
  development dependency. No upstream implementation source is copied into runtime.

No benchmark accuracy, latency, token saving or poisoning-resistance result from
these sources is claimed as an agentic-vault result.

## Compatibility and installation

Current install refs target `--ref v0.44.0`. Existing default hook bindings and
configuration templates stay unchanged. New preservation probes are opt-in;
configured revocation users receive the stricter behavior in the two named paths.
No active installation or company-vault migration is performed by publication.

The healthcheck stamp and `ENGINE_VERSION` move to `engine=0.44.0`; this is a version
update only. Unchanged rules and adapters retain their content stamps. Native Codex
verification adds explicit installed-byte checks for the new helpers, guides and
evaluation assets and still makes zero model turns.

Certificate validity depends on the seven actual bound checker files and the LF
harmless corpus, not on this release number. Their fresh fingerprint and replay are
final release gates. For a changed-byte transition, before upgrading or rolling back,
return promoted levels to `warning`, align every engine copy (Claude Code and Codex
installations and the git vault's `00-meta/scripts/`), regenerate the certificate on
that installation with harmless replay, then promote again. Historical fingerprints
and instructions remain in earlier release records.

## Verification and limits

The [verification record](../verification/v0.44.0.md) defines the final-source,
independent review, master/tag CI, isolated native installation and immutable asset
gates. Actual measured results belong in the release's `verification.json` asset;
public download and attestation checks belong in separate post-publication evidence.
The contract here is not itself a passing measurement. No inherited test count, CI
success or performance measurement is substituted for this release's evidence.

Hashes bind bytes, not identity, approval or truth. These checks cannot exclude a
hostile writer with the same filesystem access or guarantee the absence of every
change between observations. General semantic correctness, universal poison removal,
real-model efficacy and conversation-budget optimization remain unverified.
