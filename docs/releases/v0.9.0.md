# agentic-vault v0.9.0 릴리스 노트

날짜: 2026-09-05

v0.9.0은 `0.9.0-local.1`(신뢰성 개선)과 `0.9.0-local.2`(Codex 진입점) 두 사전 릴리스를 정식 승격한 판이다. 기준 upstream은 v0.8.4(태그 커밋 `50cd144`) 직후의 master `74890f6`. **Claude Code, Codex 겸용** — 같은 Markdown 볼트·Python 엔진·명령 문서를 두 클라이언트가 사용하며, 기존 Claude 명령과 config 형식, Python 3.10+·표준 라이브러리 구성은 유지한다. 세부 변경·검증 원문은 [v0.9.0-local.1](v0.9.0-local.1.md)·[v0.9.0-local.2](v0.9.0-local.2.md)에 있다.

## 변경

### Claude Code · Codex 겸용 (local.2)

- `.codex-plugin/plugin.json`과 저장소 내부 `.agents/plugins/marketplace.json`을 추가했다. 기존 스킬과 `hooks/hooks.json`을 공유하고 엔진을 복제하지 않는다.
- 세션 스크립트가 `--vault`와 작업 디렉터리를 지원한다(명시적 경로 → 비어 있지 않은 `CLAUDE_PROJECT_DIR` → 작업 디렉터리 순).
- Codex 공유 스킬 `$agentic-vault:agentic-vault`에서 세션 복원·회상·마감·검사·노트 작업·스냅샷 작업을 연결한다. 설치된 스킬 파일 기준으로 경로를 구하고 인자를 셸 코드로 해석하지 않는다.
- `init`·`upgrade`가 중립적인 AGENTS 스텁과 기존 규칙 다섯 개로 계약을 생성한다. 수제 계약과 사용자 수정은 보존하며 Claude 권한을 Codex 설정으로 옮기지 않는다.

### 신뢰성 (local.1)

- **세션 주입:** config와 읽기 경로를 주입 전에 검증한다 — 볼트 밖·deny zone·심볼릭 링크·정션 경로 거부. hot/handoff의 토큰 예산을 헤더·생략 표시까지 포함해 실제 출력에 적용하고, 큰 파일의 읽기량도 제한한다.
- **훅 실행:** `resume`에서도 주입하며, 사용 가능한 Python을 한 번 골라 한 번만 실행한다.
- **건강 검사:** 전체 스캔의 config·노트·index·rules·보고서 경로에서도 외부 링크·정션 접근을 차단한다. 검사기 스탬프 `agentic-vault:healthcheck engine=0.9.0`.
- **백업:** 삭제 동기화 미러 대신 독립 스냅샷·SHA-256 manifest·Git history bundle을 보존한다. 검증과 새 디렉터리로의 복구를 추가했고 이전 사본을 자동 삭제하지 않는다.
- **로컬 검색:** `/vault-recall`이 한국어·영어 질의에 출처 경로·행 번호가 붙은 발췌문을 반환한다(어휘 일치 기반 결정론, 검색·읽기·컨텍스트 크기 제한과 진단).
- **검증 인프라:** 실제 임시 파일·Git 저장소를 쓰는 회귀 테스트, 이중 언어 검색 fixture, Windows/Linux/macOS CI.

### 이월 항목 정리

v0.8.2·v0.8.3 노트의 "미포함 v0.9.0 항목" 중 **healthcheck·SessionStart 훅 전체 경로 containment**(`vault_paths.py`·검사기·`session_start.py`), **backup sentinel·bundle verify·restore drill**(비공개 staging 후 공개 + `.backup.lock`, `history.bundle`을 포함한 SHA-256 manifest 검증, `--restore` 새 디렉터리 복구), **hosted CI**(GitHub Actions 3 OS × Python 3종 — master `534df7f` run 33950041799 9/9 성공)는 이 판에 포함됐다. hook doctor, index 서술 누락 센서 승격, 성공 패턴 노트 스키마는 계속 이월한다.

## 하위호환·업그레이드

- config 스키마 유지(키 추가·삭제 없음). 예산 **0은 주입 비활성화**이며 절대경로·상위 경로·링크 경로는 허용하지 않는다 — 그런 설정을 쓰던 볼트는 일반 볼트 내부 노트로 옮기고 config를 고쳐야 한다.
- 백업의 기존 `--vault`·`--target` 인자는 그대로다. 기존 `mirror/`·`bundles/`는 삭제하지 않으며, 복구는 기존 경로를 덮어쓰지 않는다.
- rules 템플릿 5종은 내용 무변경이라 기존 스탬프(vault-workflow `engine=0.8.3`, 나머지 4종 `engine=0.6.0`)를 유지한다. 검사기 스탬프는 `0.9.0`이므로 `/vault-upgrade`가 구판 검사기를 교체 대상으로 잡는다.
- `/vault-recall`은 플러그인 안의 `vault_recall.py`·`vault_paths.py`·`vault_healthcheck.py`를 함께 쓴다 — 스크립트 하나만 볼트에 복사하지 마라.
- 🔴**세션 주입이 config 검증을 통과해야만 동작한다.** `session_start.py`가 검사기의 `validate_config` 전체를 게이트로 쓰므로, 무관한 키 하나의 형식 오류(정수 키에 문자열·실수, `null`, `./` 접두·끝 슬래시 경로, 빈 enum, pattern 없는 `ssot_facts` 등)만으로도 handoff·hot이 **둘 다 주입되지 않고** stderr 한 줄(`invalid session context configuration`)만 남는다 — exit 0이라 화면에는 보이지 않는다. v0.8.4는 파일 존재만 확인했다. 업그레이드 직후 healthcheck 또는 `/vault-session-start`로 config 오류부터 확인하라.
- 볼트 루트가 정션·심볼릭 링크이거나 OneDrive 온디맨드 자리표시자(reparse 속성) 아래에 있으면 주입·검사가 거부된다 — 정규 경로와 "항상 이 기기에 보관"으로 전환하라.
- Windows에서 훅 실행은 `sh`(Git Bash)를 요구한다(Claude Code Windows 기본 구성; Codex Windows 사용자는 별도 확인).
- Codex 자동 훅은 `/hooks`의 신뢰 검토가 필요하다. 신뢰 전에는 스킬에서 수동으로 세션을 복원할 수 있다. Jarvis는 계속 Claude CLI에 의존한다.

## 설치

Claude Code: `/plugin marketplace add Technoetic/agentic-vault` → `/plugin install agentic-vault@agentic-vault`. Codex: `codex plugin marketplace add Technoetic/agentic-vault --ref v0.9.0` → `codex plugin add agentic-vault@agentic-vault-local`. 자세한 대응표는 [docs/codex.md](../codex.md).

설치 정책: Claude Code 마켓플레이스 설치(`source: ./`)는 **master HEAD를 따른다**. master에는 릴리스 상태만 두고 개발은 브랜치에서 진행해 태그 시점에 병합한다. 특정 판을 고정하려면 방법 3(로컬 클론에서 태그 체크아웃) 또는 Release ZIP을 쓴다.

## 검증

- 2026-09-05 Windows · Python 3.12 · 환경변수 없는 깨끗한 워크트리(`534df7f`): `python -m unittest discover -s tests` **303개** — 1차 실행에서 `test_concurrent_same_content_captures_converge_without_temp_residue`가 `BrokenBarrierError`로 ERROR, 재실행 2회 연속 **OK(skipped=10)**. skip은 Windows 심볼릭 링크 권한 6·POSIX FIFO 2·POSIX 프로세스 그룹 2.
- 승격 커밋 후 같은 워크트리에서 전체 스위트 재실행 4회: 1회 FAIL(`test_concurrent_conflicting_captures_keep_one_complete_winner`, `0 != 1`), 이후 3회 연속 **304개 OK(skipped=10)**(v0.9.0 릴리스 노트 계약 테스트 1건 추가). 승격 전후 전체 7회 실행 중 실패 2회는 모두 아래 캡처 동시성 테스트 2건이다(수렴 1회 ERROR, 충돌 1회 FAIL).
- 독립 검증(별도 에이전트 3렌즈, 읽기 전용): unittest 304 OK 재현, `claude plugin validate --strict`(plugin·skills·commands) 통과, Codex 임시 home 설치 검증(`scripts/verify_codex_plugin.py`, codex-cli 0.150.1) 통과, 검색 fixture ko/en recall@3 1.0, 로컬 링크 53개 누락 0, 잔재(TODO·디버그·하드코딩 경로) 0건. 이 검증이 README 설치 절의 잔존 프리릴리스 링크와 아래 한계 절의 인과 오기를 적발해 정정했다.
- 원격 CI: release/v0.9.0 브랜치 push와 태그의 GitHub Actions(`tests.yml`) 결과는 릴리스 페이지에 인용한다.
- local.2 시점의 Claude CLI strict 검사·Codex CLI 임시 home 설치·검색 fixture(recall@3 1.0)·링크 45개 검사는 [v0.9.0-local.2](v0.9.0-local.2.md) 검증 절의 기록이다.

## 알려진 한계

- `tests/test_jarvis_bridge.py`의 캡처 동시성 테스트 2건(`test_concurrent_same_content_captures_converge_without_temp_residue`·`test_concurrent_conflicting_captures_keep_one_complete_winner`)은 **비결정적**이다 — Windows 단독 20회 반복에서 각 4회·5회 실패. 원인: 동시 첫 캡처에서 한 스레드가 제품 코드 `_resolve_capture_directory`의 `capture directory escapes vault`(인박스 디렉터리 생성 경합 중 경로 확인 실패)로 링크 전에 종료하면, 상대 스레드가 테스트의 5초 `threading.Barrier` 타임아웃으로 `BrokenBarrierError`를 내 수렴 테스트는 ERROR, 충돌 테스트는 `0 != 1` FAIL이 된다. 근본 원인은 컨테인먼트 검사와 동시 `mkdir`의 경합이며, 자비스 데몬은 순차 폴링이라 운영에서 같은 경로는 재현되지 않으나 **후속 조사 항목**이다. 원자 교체·소유자 경합 테스트 2건은 20/20 안정.
- 전체 스위트 실행 중 subprocess 리더 스레드에서 비치명 `UnicodeDecodeError`(cp949 자식 출력) 트레이스백이 1회 출력된다 — 테스트는 통과하며 후속 정리 항목(`PYTHONUTF8=1` 또는 `errors="replace"`).
- 실제 모델 대화, 신뢰 후 자동 훅 실행, Telegram 송수신은 검증 범위에 포함하지 않는다.
- 경로 검증은 실행 중 경로 구조가 바뀌지 않는 신뢰할 수 있는 파일시스템을 전제한다.
