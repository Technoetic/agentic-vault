# v0.51.0 — 독립 평가 결함 수정과 선택형 BizRouter Decisions 어댑터

사전 맥락 없는 독립 평가(v0.50.0 기준)가 확인한 Windows `MAX_PATH` 초과 시 오류·오분류, `SessionStart` 비밀 마스킹 공백, Antigravity `Stop` 훅 중복·누락, 신규 `/vault-init` 관리성 이슈 13건, 시험 격리 결함 4종, `README.md` 영문 개요 절단·구버전 표기 잔류를 바로잡고, `google/gemini-decision-1`을 지원하는 선택형 BizRouter Decisions 어댑터와 저확신 에스컬레이션을 더한다. 기준은 공개 v0.50.0 커밋 `39e5177de416dd056fad99f77c074415c42f6f89`다.

## 변경

1. 선택형 BizRouter Decisions 어댑터와 저확신 에스컬레이션(`bizrouter_client.py`, `jev_ask.py`, `vault_judge.py`).
   기본 공급자(TypeSafe Jev `https://api.typesafe.ai/v1/systemone`, `TYPESAFE_API_KEY`, `jev-1.13.0`)는 그대로 유지한다. 명시적으로 `--provider bizrouter`를 주면 고정 주소 `https://api.bizrouter.ai/v1/decisions`(`BIZROUTER_API_KEY`)로 요청하며 기본 모델은 `google/gemini-decision-1`(`typesafe/jev-1.13.0`도 선택 가능)이다. `google/gemini-decision-1`에서는 요청당 최대 1,000개 질문과 2~255개 Choice/Score 단계(페이로드·응답 상한 256 KiB, 텍스트·JSON 전용)를 지원한다. `jev_ask.py run --escalate-bizrouter`는 기본 Jev 배치 응답 중 보류(`abstained`)가 아닌 `low_confidence`·`low_decisiveness` 문항만 추려 `google/gemini-decision-1`로 1회 재평가하며, `BIZROUTER_API_KEY`가 없거나 추가 호출이 실패해도 Jev 원응답을 보존하고 `escalation.status: "unavailable"`만 남긴다. 비밀 필터(`jev_client.SENSITIVE`)와 `vault_judge.py`의 `O_NOFOLLOW`·금지 구역·TOCTOU 재확인은 두 공급자에 똑같이 적용된다([Jev 판단 안내](https://github.com/Technoetic/agentic-vault/blob/v0.51.0/docs/jev-judgments.md)).
2. Windows `MAX_PATH`(260자) 초과 경로 지원과 `path_too_long` 오류 분리(`vault_evidence.py`, `vault_state.py`, `vault_runs.py`, `vault_task_contracts.py`, `vault_improvements.py`, `backup_vault.py`).
   Windows `LongPathsEnabled=0` 환경에서도 깊은 런타임 락·계약·영수증·백업 스테이징 경로가 동작하도록 시스템 호출 경계에서 확장 경로 접두어(`\\?\`) 헬퍼(`fs_path`)를 적용하고, OS 경로 길이 초과 예외(`ENAMETOOLONG`·`WinError 206` 등)를 `unsafe_lock`이나 `unsafe_or_invalid_input` 같은 보안·무결성 위반 코드와 분리해 `path_too_long`으로 보고한다. 작업 트리 경로 판정(`vault_worktrees.py`)과 인증서가 묶는 `vault_paths.py`는 바꾸지 않는다.
3. `SessionStart` 비밀 마스킹과 Antigravity `Stop` 훅 중복·누락 보완(`hooks/session_start.py`, `hooks/antigravity_hook.py`, `hooks/session_checkpoint.py`).
   대화형 `SessionStart`(`startup`·`resume`·`clear`·`compact`)와 `--host antigravity`(`injectSteps[].systemMessage`)가 읽는 상태 노트 본문에서 `jev_client._matches_sensitive`에 걸리는 자격 증명 줄과 다중 줄 PEM 개인키 블록을 마스킹한다(비밀 패턴이 없는 일반 노트는 기존과 바이트 단위 동일). Antigravity `Stop` 훅은 양의 정수 `executionNum`에서 기존 120초 잠금 키를 유지하고, `executionNum == 0`이면 턴 필드 요약을 잠금 키에 보태 120초 안의 후속 턴 체크포인트가 누락되지 않게 하며, `executionNum`이 생략되거나 정수가 아니면 원시 이벤트 SHA-256으로 잠금을 걸어 3중 처리기(`sh`·`py -3`·`python`) 중 하나만 기록하게 한다.
4. 초기 `/vault-init` 청결성, 시험 격리, 엔진 폴더 정리, 볼트 사본 방어, 줄바꿈 통일.
   `vault_healthcheck.py`가 이미 섹션 10(`scan_rules_integrity`)에서 검사하는 `rules_dir` 행동 계약 파일을 고아·인덱스 미등록 집계에서 제외하고 `assets/templates/index.md`에 `[[lessons]]`를 기본 등록해, 정석 `/vault-init` 직후(미니볼트 포함·미포함 모두) 첫 `vault_healthcheck.py` 실행이 `issues: 0, critical: 0`이 되게 한다. 또한 비볼트(`not_vault`)·경로 부재(`vault_not_found`) 조기 종료 시 `--worktree-heads --json-summary`가 검사하지 않은 `"unreachable_worktree_heads": 0`을 내보내지 않게 고친다. 라이브 `claude` CLI를 호출하는 수동 프로브 `skills/agentic-vault/scripts/test_rules_inheritance.py`는 `scripts/manual_rules_inheritance_probe.py`로 옮겨 엔진·`antigravity/` 패키지에서 제외하고, 볼트 `00-meta/scripts/`로 복사된 `vault_doctor.py`·`vault_adapters.py`가 플러그인 트리 밖에서 임포트 시 죽지 않도록 `CLAUDE_PLUGIN_ROOT` 폴백과 안전 종료 진단(`session_hook_not_bundled`)을 더한다. 비-TTY `stdin` 파이프 행(`test_memory_recovery.py`, `test_vault_doctor.py`), 단독 모듈 임포트(`test_run_evaluator_binding.py`), 줄바꿈 고정(`test_vault_healthcheck.py`), 병렬 부하 타임아웃 여유(`test_codex_verification.py`)를 고치고 `.gitattributes` 최상단에 `* text=auto eol=lf`를 두어 Windows 기본 체크아웃에서도 루트와 생성 `antigravity/` 텍스트 줄바꿈을 일치시킨다.
5. 문서·판 표면 복구와 생성 패키지 갱신.
   `README.md` 첫 화면에 30초 개요·영문 개요·현재 판 요약을 배치하고 이전 판 이력을 접힘 블록으로 내렸으며, 영문 `Core commands` 문단 한복판에 끼어들었던 구버전 이력 194줄을 복구하고 현행 안내문의 `0.48.0` 잔류 표기(`README.md`, `docs/antigravity.md:23`)를 모두 `0.51.0`으로 바로잡았다. `.codex-plugin/plugin.json` `longDescription` 앞머리에 제품 소개를 보강하고 Antigravity CLI 생성 패키지(`antigravity/`)를 다시 생성해 일치를 확인했다.

## 기본 결과 변경

- 판 메타데이터: 매니페스트 버전·설치 태그·healthcheck 스탬프(`engine=0.51.0`)와 `ENGINE_VERSION`이 `0.51.0`으로 이동한다.
- `SessionStart` 주입: 비밀 패턴이 없는 일반 노트의 출력은 바이트 단위로 같으며, `jev_client._matches_sensitive` 또는 PEM 개인키 블록을 포함한 줄만 마스킹 문구로 치환된다.
- `vault_healthcheck.py`: `rules_dir`(기본 `.claude/rules`) 아래 행동 계약 파일이 섹션 6(고아/준고아)·섹션 6c(인덱스 미등록)에서 제외되고(섹션 10 검사는 그대로 유지), `not_vault`·`vault_not_found` 조기 종료의 `--worktree-heads --json-summary`에서 `"unreachable_worktree_heads": 0`이 빠진다.
- Antigravity `Stop` 체크포인트: `executionNum`이 생략되거나 `0`으로 유지되는 호스트 이벤트에서도 단일 턴 1회 기록으로 수렴한다.
- Windows 긴 경로 오류 코드: `MAX_PATH` 초과 OS 오류 시 `unsafe_lock`·`unsafe_or_invalid_input` 대신 `path_too_long`을 반환한다.
- Jev 판단 도구(`jev_ask.py`, `vault_judge.py`): 새 플래그(`--provider bizrouter`, `--model`, `--escalate-bizrouter`)를 주지 않으면 기본 TypeSafe Jev 동작·출력은 v0.50.0과 같다(`--help`에 새 옵션이 표시된다).

## 하위호환·업그레이드

현재 설치 ref는 `v0.51.0`이다. 기존 볼트 설정 키는 추가하거나 마이그레이션하지 않는다. 공개 준비 자체가 활성 설치나 운영 볼트를 자동으로 갱신하지 않는다. git 무결성 게이트가 있는 볼트에서 helper bundle을 갱신할 때는 `bizrouter_client.py`를 함께 둔다(`bizrouter_client`는 지연 임포트되므로 기존 Jev 전용 사본도 깨지지 않는다).

인증서가 묶는 일곱 파일(`vault_lint_extensions.py`·`vault_warning_policy.py`·`vault_provenance.py`·`vault_egress.py`·`vault_ssot.py`·`jev_client.py`·`vault_paths.py`)은 v0.46.0부터 v0.51.0까지 바이트 단위로 같아, 실제 설치 바이트가 같은 경우 기존 경고 승격 인증서가 그대로 유효하다. v0.45.1 이하와 오갈 때는 [v0.46.0 업그레이드 안내](https://github.com/Technoetic/agentic-vault/blob/v0.51.0/docs/releases/v0.46.0.md#하위호환업그레이드)를 따른다. healthcheck만 `engine=0.51.0`으로 이동하며 기존 규칙·어댑터 스탬프는 유지한다. `checker_sha256`는 `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d` 그대로다.

## 연구 출처와 기존 기능의 차이

| 출처 | 준 것 | 이번 적용 |
|---|---|---|
| [BizRouter Decisions API 문서](https://bizrouter.ai/docs/decisions) | `POST https://api.bizrouter.ai/v1/decisions`에서 `noul`·`choice`·`score` 세 유형으로 `google/gemini-decision-1`·`typesafe/jev-1.13.0`을 호출하는 정형 판단 계약 | 기존 TypeSafe Jev(`jev_client.py`)를 대체하지 않고 `bizrouter_client.py` 선택형 어댑터(`--provider bizrouter`) 및 저확신 문항 재평가(`--escalate-bizrouter`)로 추가했다. 동일 비밀 필터(`jev_client.SENSITIVE`)와 파일 근거 바인딩(`vault_judge.py`)을 그대로 재사용한다 |
| [Google Gemini Decision 1 공개 벤치마크 색인](https://artificialanalysis.ai/evaluations/decision-index) | 정형 판단 지수(Decision Index v2.1)와 모델별 보정·불변성 특성 공개 지표 | 참고 맥락으로만 확인했으며 외부 벤치마크 수치를 이 플러그인의 자체 성능으로 주장하지 않는다 |

## 알려진 경계

- BizRouter Decisions(`https://api.bizrouter.ai/v1/decisions`)는 텍스트·JSON 입력만 지원하며 이미지·첨부 파일 입력은 거부한다(`HTTP 400`). 기본 공급자는 계속 TypeSafe Jev이며, 두 공급자 모두 명시적 `--allow-network`와 환경변수 키(`TYPESAFE_API_KEY` 또는 `BIZROUTER_API_KEY`) 없이는 네트워크를 호출하지 않는다.
- `SessionStart` 비밀 마스킹은 `jev_client._matches_sensitive` 패턴과 PEM 개인키 블록 기반이므로 알려지지 않은 임의 형식·인코딩된 비밀까지 모두 찾아내지는 못한다([보안 정책](https://github.com/Technoetic/agentic-vault/blob/v0.51.0/SECURITY.md)).
- Windows 긴 경로 헬퍼(`fs_path`)는 Python 표준 라이브러리 파일 입출력 경계를 처리하며, 외부 셸 도구·서드파티 프로그램 자체의 `MAX_PATH` 한계까지 바꾸지는 않는다.
- 생성 Antigravity CLI 패키지의 사본 일치와 `agy plugin validate --strict`는 검사하지만 소비자 계정 약관 경계에 따라 에이전트가 실제 `agy` 대화 세션을 감싸 실행하지는 않는다.
