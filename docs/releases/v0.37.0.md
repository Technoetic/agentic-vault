# v0.37.0 — 선택형 기억 철회·세션 간 복구 검사

선택한 기억의 사용을 거두고 다른 기억은 보존하는 선택형 기능을 추가한다.
원문을 지우거나 자연어가 같은 뜻인지 자동으로 판정하는 기능은 아니다.

## 변경

- [기억 철회](../memory-revocation.md): 원문 SHA-256·물리 줄 구간과 명시적 파생 관계를
  등록한다. 선언한 부모의 철회는 연결된 자식으로 전파하고 순환 관계는 유한하게 처리한다.
  원문과 줄 번호·출처 해시는 보존하고, 철회한 줄은 원래 개행만 남겨 가린다.
- 검색(lexical/BM25/hybrid/wiki graph), 기억 단위, 절차, 대장 선택,
  SessionStart 시작/재개/compact 문맥, 링크 제안, 새 선택 OKF 출력이 같은 정책을 사용한다.
  무관한 줄은 유지하며, 영향을 받는 원문 diff는 철회 내용 노출·물리 삭제 제안을 막기 위해 거부한다.
  낡은 출처 연결은 전체 출처 제외/거부, 잘못되거나 바뀐 설정은 출력 거부로 처리한다.
- `vault_revocation.py capture|check`: 경로·형식·크기·원문 연결을 검증하며 파일을
  저장하거나 설정을 활성화하지 않는다. 호스트가 선택 범위를 검토하고 별도로 저장·설정한다.
  64 KiB 상한의 compact JSON이 저장 후 다시 검증되도록 성공 출력에는 끝 개행을 넣지 않는다.
- [세션 간 합성 평가](../memory-lifecycle.md): 두 언어 사례의 11단계를 각각 새 Python
  프로세스에서 실행한다. 실제 저장·조회·교훈 교정 경로를 이용해 오염, 교정, 정상 기억 보존,
  재주입, 새 사실 학습을 따로 잰다. 취약 대조군과 전체 삭제 대조군을 함께 검사한다.
- 대소문자를 구별하지 않는 파일시스템의 별도 경로 표기가 철회 범위를 우회하지 않도록
  안전하게 검증한 파일 동일성을 사용한다. 대소문자를 구분하는 환경의 다른 파일은 합치지 않는다.
  테스트의 적용 여부도 운영체제 이름 대신 실제 파일시스템 동작으로 정한다.
- 격리 Codex 설치 검증에서 새 핵심 모듈·평가기·두 문서의 실제 설치 바이트까지 대조한다.
  모듈/문서가 빠지거나 달라지면 검증을 거부하며 실제 사용 설치본을 자동 갱신하지 않는다.

## 하위호환·업그레이드

설치 ref는 `--ref v0.37.0`이다. `memory_revocation_file`이 없거나 빈 문자열이면
기존 기본 동작을 유지하며 설정 키를 자동으로 추가하지 않는다. 원본 노트·Git 이력·이전 출력은
변경하지 않는다. 기본 훅 이벤트·모델/네트워크 호출·Python 3.10+ 표준 라이브리 런타임을 유지한다.

인증서가 묶는 검사기 일곱 파일과 커밋된 LF harmless corpus는 v0.36.1과 같다.
`checker_sha256`는 `be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`,
`corpus_sha256`는 `38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`다.
실제 설치된 bound 바이트가 같으면 이번 전환만으로 인증서를 다시 만들 필요가 없다.
기존 CRLF corpus는 깨끗한 git 상태에서도 남아 있을 수 있으므로 실제 바이트를 확인한다.
더 오래된 바이트가 다른 설치와 오갈 때는 [기존 전환 순서](v0.35.1.md#하위호환업그레이드)를 유지한다:
경고 승격 해제 → 엔진 사본 정렬 → harmless replay 포함 인증서 재생성 → 재승격.

공개와 활성 플러그인 설치 갱신, 실제 회사 볼트의 철회 설정 활성화는 별도 작업이다.

## 검증

구현 체크포인트 `1f0d5a4015cc0b2cb9e72064192db68440218083`의 로컬 전체 2,731개는
2,685개 통과·플랫폼 조건 제외 46개·실패/오류 0개였다. 이후 릴리스 준비에서 발견한
경로 별칭 경계 보완과 설치 자원 검증의 새 소스 결과를 이 이전 집계로 대신하지 않는다.

최종 소스·master/tag CI·각 플랫폼 전체 시험·격리 설치·ZIP/Git blob 대조·초안 자산과
공개 후 확인은 [릴리스 검증 기록](../verification/v0.37.0.md)의 별도 게이트다.
문서 준비 시점의 대기 항목은 통과가 아니다. 최종 게시 전 근거는 `verification.json`,
게시 후 새 다운로드·증명 확인은 별도 `post-publication.json`에 남긴다.

## 알려진 경계

철회 단위는 선언한 물리 줄 전체다. 같은 줄의 다른 사실을 따로 분리하지 않으며
미등록 사본·바꿔쓴 문장·자연어 의미 동치를 찾지 못한다. 임의 호스트 도구의 직접 파일 읽기,
감사/이력/diff, 외부 기억 서비스, 백업·Git 이력과 이미 밖으로 나간 출력은 경계 밖이다.
설정/선언의 편집 권한과 철회 범위의 정당성은 호스트 책임이며 해시는 진실·승인을 증명하지 않는다.

두 사례의 작은 결정론적 합성 평가는 실제 LLM의 강건성·개인정보 삭제·완전 망각이나
업무 성과를 측정하지 않는다. 외부 벤치마크의 코드/데이터를 복사하거나 공식 점수를 재현하지 않았다.
