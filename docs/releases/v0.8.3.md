# agentic-vault v0.8.3 릴리스 노트

날짜: 2026-09-02

v0.8.3은 WikiSkill 논문([arXiv 2608.27454](https://arxiv.org/abs/2608.27454), Google Research — 이 플러그인과 같은 Karpathy LLM Wiki 계보의 스킬 진화 프레임워크)에서 3건을 흡수한 릴리스다. 전부 마크다운 계약(템플릿·커맨드·rules) 변경이며 Python 코드·훅은 건드리지 않는다. 흡수 판정은 후보별 3렌즈 적대 검증(이미 존재하는가 / 파일 기반 아키텍처에 맞는가 / 논문에서 실증됐는가)을 통과한 것만 반영했다.

## index 서술 규격

- index 등록 서술은 **설명만 읽고 노트를 열지 말지 결정할 수 있어야 한다**(제목 재진술 금지). 실패·교훈형 노트는 `문제+근본 원인+처방`, 그 외는 `핵심 결론+범위+언제 열어볼지` 1~2문장.
- 반드시 **한 물리적 줄** — `- [[노트 이름]] — 설명` 단일 줄 grep 계약을 보존한다.
- 등록 경로 4곳에 일관 적용: SKILL.md 체크리스트 ④, `/vault-ingest` 기록 단계, `/vault-trace` 영구화 단계, `/vault-lint` 6c(신규 등록 + 처리 중 발견된 bare 항목은 관리성 표로 올려 승인 후 보강).
- 근거: WikiSkill p.27 E.2 — Proposer는 index만 초기 제공받아 페이지를 선택 개방하므로 색인 서술이 실작동 게이트다. 서술이 빈약하면 grep 전수 탐색으로 후퇴한다.

## 기각 대장 (rejected-proposal ledger)

- `lessons.md`에 `## 기각 대장` 섹션 신설 — 기각된 승격 초안의 **전문**과 사유를 보존한다(기각 1건 = 소제목 1개, 최신이 위).
- 재제안 규칙 완화(동기 수정): 종전 "기각되면 다시 제안하지 않는다" → **"같은 접근 재제안 금지, 기각 사유를 해소한 개선안은 허용"**. `/vault-session-end`는 승격 초안을 쓰기 전에 기각 대장을 읽는다.
- 범위: 자기개선 제안(승격안·규칙 초안)의 기각만. 전략·아키텍처급 기각 대안은 ADR 소관이며 링크로 가리켜 이중 보존을 피한다. decisions 템플릿은 행동 계약·엔진 규칙 변경 ADR에 기각 대안 **원문** 보존을 권고한다.
- 근거: WikiSkill p.27-28 E.3 — skill-impact.md가 기각 제안 전문을 보존하고, 기각 사유를 해소한 개선 재제안이 수락되는 사례(p.12-13 Figure 3). 제안 과반이 기각되므로(p.13 Table 4) 기각이 곧 주 데이터다.

## 승격 검증 게이트 + 가역 롤백

- 승격은 확정이 아니라 검증의 시작이다: 승격 시 상태를 `승격완료(검증중→대상, 승격일, anchor)`로 기록하고, `/vault-session-end` §5에 신설된 0단계(검증 게이트)가 세션마다 준수·역효과를 점검한다.
- 관찰 기간(기본 **3세션**, config `promotion_review_sessions` 키로 조정) 무이상이면 `승격완료(→대상)`으로 확정. 경과 세션 수는 `log_note`의 session-end 기록 수 또는 anchor 이후 세션 종료 커밋 수로 센다(결정론적 도출 — 별도 상태 파일 없음).
- 역효과·미준수 반복 시 **롤백을 제안**한다(사용자 승인 필수). 승격 대상 파일(CLAUDE.md 조항·rules·명령 문서)에서 조항을 제거하되, 대장 줄은 삭제하지 않고 `롤백(사유)`로만 바꾼다 — **조항은 가역, 대장은 영속**.
- 승격 이후 재발한 교훈은 근거에 `(재발)` 마커를 붙여 계속 갱신한다 — 검증 게이트가 읽는 미준수 신호다.
- 근거: WikiSkill p.6 §3.2.4 + p.19 Algorithm 1 16행 "Roll back skills only; wiki retained" — 스킬은 검증 성능으로 게이팅·롤백하되 위키는 영속하는 비대칭.

## 하위호환

- 구판 상태 표기 `승격완료(→대상)`(승격일·anchor 없음)는 검증을 통과한 확정분으로 간주한다 — 기존 대장은 수정 없이 유효하다.
- `promotion_review_sessions`는 선택 키다 — 없으면 기본값 3세션. config 스키마 변경·필수 키 추가 없음.
- index 서술 규격은 커맨드에서 "index 노트 헤더 규격 우선, 없으면 기본값" 순서로 적용된다 — 구판 index 노트도 그대로 동작한다.
- 기각 대장 섹션이 없는 기존 `lessons.md`도 동작한다 — session-end가 필요 시 템플릿 구조로 만들거나 `/vault-upgrade`가 멱등 추가한다.

## 업그레이드

1. `/vault-upgrade` 실행 — 기존 `lessons.md`에 `## 기각 대장` 섹션이 없으면(v0.8.2 이하 생성분) 템플릿의 해당 섹션을 파일 끝에 멱등 추가한다. 기존 교훈 줄은 건드리지 않는다.
2. `.claude/rules/vault-workflow.md`는 `engine=0.8.3` 스탬프로 통째 교체된다(index 서술 규격 반영) — 로컬 편집분이 있으면 기존 절차대로 diff를 보여주고 CLAUDE.md 이동을 제안한다.
3. 그 외 파일(healthcheck·훅·config)은 이 릴리스에서 변경 없음.

## 검증

릴리스 후보는 저장소 루트에서 다음 명령으로 검증한다.

```powershell
python -m unittest discover -s tests -v
python -m json.tool .claude-plugin/plugin.json > $null
python -m json.tool .claude-plugin/marketplace.json > $null
git diff --check
git status --short --branch
git log --oneline origin/master..HEAD
```

## 알려진 경계

- 검증 게이트의 준수·역효과 판정은 LLM의 정성 판단이다 — 관찰 기간·상태 전이는 결정론이지만 판정 자체는 아니며, 그래서 롤백은 자동이 아니라 제안이다.
- 기각 대장의 전문 보존은 lessons.md를 길게 만든다. 대장이 비대해지면 오래된 기각 건을 아카이브 노트로 분리하는 것은 사용자 결정 사항이다(자동 정리 없음).
