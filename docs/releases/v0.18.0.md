# v0.18.0 — 파일·전송 경계와 무인 Jarvis 보강

2026-10-04. 사용자 제공 *OWASP Top 10 for LLM Applications 2026* PDF와 기존 코드의
경계를 대조하고, 읽기 우회·비밀 전송·과대 입력·무인 모델의 도구 접근을 보강했다.
제공 문서에는 발행 정보 자리표시자가 남아 있다. 이 릴리스는 OWASP 준수 인증이나 공식
2026 최종본의 모든 권고를 구현했다는 주장이 아니다.

**호환성 변경: Jarvis Q&A·예약 브리핑의 `--bare` 실행은 API 인증이 필요하다.
구독 OAuth 로그인만으로는 실행되지 않는다.** 이 변경 때문에 0.17.x 패치 대신 0.18.0으로 낸다.
일반 Claude Code·Codex 세션의 로그인 방식과 Jev 인증은 바뀌지 않는다.

## 변경

### 파일 읽기와 출처

- SessionStart·recall과 이를 이용하는 doctor는 내용을 읽기 전에 일반 파일 여부와
  `st_nlink == 1`을 검사한다. 여러 이름으로 연결된 하드링크는 config까지 포함해 거부한다.
  기존 경로 포함·deny zone·심볼릭 링크·Windows junction 검사도 유지한다.
- recall의 제목 메타데이터는 512자로 제한한다. 검색 순위는 전체 제목을 계속 사용하며,
  원문 경로·행 번호와 잘림 표시는 남는다. 이 제한은 전체 recall JSON의 바이트 상한이 아니다.

### Jev 전송 전 검사

- `password`·`client_secret`·`API_KEY` 등 명시적 자격 증명 키에 비어 있지 않은 스칼라 값이
  있으면 거부한다. 일반 질문에 쓰이는 `secret`·`token` 키는 이 키 규칙으로 차단하지 않는다.
  기존 문자열 패턴 필터와 전송 승인 경계는 유지한다.
- 순환 컨테이너를 거부하고, 정상적인 공유 컨테이너는 허용한다. 8,192개 노드·깊이 64·
  합계 문자 65,536·직렬화 64KiB·큰 정수 변환 한도를 검사한다. 입력이 거부되면 전송하지 않는다.
- 전체 객체를 무제한 펼치지 않는 순회와 점진적 JSON 인코딩을 사용한다. 필터는 모든 비밀을
  찾아내는 DLP가 아니며, 라벨이나 알려진 형태가 없는 비밀·인코딩된 비밀에는 한계가 있다.

### Jarvis의 무인 생성

- 호스트가 허용 경로에서 읽은 제한된 근거만 JSON으로 공급한다. 질문·파일 본문·출처 경로와
  최종 입력에 알려진 비밀 패턴 검사를 적용하고, 생략·잘림·검색 불완전 상태를 모델에 알린다.
  브리핑에는 설정된 hot/handoff와 최근 로그·git 활동을 포함한다.
- 모델 직접 파일 탐색을 제거한다. 고정 argv의 `--bare`, `--tools ""`, `--setting-sources ""`,
  `--disable-slash-commands`, `--no-session-persistence`, `--strict-mcp-config`와
  `--settings '{"disableAllHooks":true}'`로 도구·자동 컨텍스트·설정·스킬·훅·세션 저장을 제한한다.
  지원하지 않는 CLI 옵션은 실패하며 넓은 권한으로 재시도하지 않는다.
- 질문과 근거를 합친 stdin은 64KiB, stdout/stderr는 스트림마다 64KiB다. 초과 결과는
  버리고 직접 자식 프로세스를 종료한다. 파일 기반 stdin과 취소 가능한 파이프 읽기로
  시간 초과·출력 초과 후 reader가 남는 문제를 막는다. 자식이 파이프를 잡고 있어도 정리한다.
- 기존 private chat·숫자 사용자 ID 화이트리스트, 봇 토큰의 자식 환경 제외, stdin 전달,
  Windows `.cmd`·`.bat` 런처 거부와 네이티브 `claude.exe` 요구는 유지한다.

## 하위호환·업그레이드

- Jarvis를 사용한다면 갱신 전에 API 인증을 마련하거나 Q&A·예약 브리핑 생성을 중지한다.
  설치된 Claude CLI의 `--bare`는 OAuth/키체인·CLAUDE.md 자동 검색·자동 기억을 건너뛴다.
  `ANTHROPIC_API_KEY` 또는 선택한 타사 제공자의 인증이 필요하다. 이 브리지는 별도 API-key
  helper를 공급하지 않는다. 기존 구독 로그인을 자동으로 API 인증으로 바꾸거나 비밀을 복사하지 않는다.
- 플러그인의 새 훅·Python 코드·명령 문서는 플러그인을 갱신한 뒤 새 세션에서 사용한다.
  git 볼트의 healthcheck를 복사해 쓰고 있다면 `/vault-upgrade` 또는
  `$agentic-vault:agentic-vault upgrade`로 `engine=0.18.0`을 적용한다. healthcheck 판정 논리는
  이번 릴리스에서 바뀌지 않았고 버전 식별자만 배포 메타데이터와 맞췄다.
- 규칙 템플릿 6종은 내용이 같아 이전 스탬프를 유지한다. 사용자 소유 CLAUDE.md·AGENTS.md·
  Aside 설정을 이 릴리스의 코드 보강을 이유로 일괄 덮어쓰지 않는다. `gates`는 여전히 설정 검증이며
  행동 승인을 실행 시 자동 집행하는 엔진이 아니다.
- Codex 설치: `codex plugin marketplace add Technoetic/agentic-vault --ref v0.18.0`.
  등록된 이전 소스의 교체 절차는 [Codex 설치 안내](../codex.md#설치)를 따른다.

## 검증과 경계

- 원 보강 커밋 `aa31663`은 Windows에서 전체 663개 테스트를 실행해 641개 통과·22개 환경
  제외·실패 0개였다. 독립 실행과 영향받은 문서 검사 재실행, 실제 로컬 자식 프로세스·NTFS
  하드링크 fixture로 경계를 확인했다. 이는 버전 메타데이터 변경 전의 보강 근거다.
- 0.18.0 릴리스 대상의 최종 명령·테스트·CI·설치 결과는
  [v0.18.0 검증 기록](../verification/v0.18.0.md)에 기록한다. 실행 전 상태를 통과로 표시하지 않는다.
- 위험 10개별 코드·테스트·남는 한계는
  [OWASP 제공본 기준 보강 기록](../security/owasp-2026-hardening.md)을 참고한다.
  그 기록은 버전 변경·설치·공개 전 `aa31663` 시점의 작업 기록이다.
- 모델 오답, OS 권한, 임의의 프로세스 트리·CPU·디스크 제한, 공급자 전체 비용 한도와
  완전한 비밀 탐지는 보장하지 않는다. 학습·파인튜닝 파이프라인과 벡터/임베딩 DB는 이
  플러그인에 없으므로 해당 구성요소의 조치는 적용 대상이 아니다.
- 검증에는 합성 파일·가짜 전송·실제 로컬 프로세스를 사용했다. 라이브 제공자 인증·모델 응답과
  실제 Telegram 전달은 이 보강 검증에 포함되지 않는다. CLI 바이너리·플러그인 파일·OS는 신뢰한다.
