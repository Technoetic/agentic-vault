# v0.29.0 — 응답률·회수 성공률 하한·제안 유지 문구 확인

선택해서 실행하는 읽기 전용 측정 세 가지를 더한다. 한국어 기억 평가에서 답한 것 중 틀린 비율을
따로 보고하고, 회상 평가의 '모두 찾음' 비율에 단측 하한을 붙이며, 교훈 수정안의 원문과 후보에서
바뀌면 안 되는 문구와 의도한 정정을 등장 횟수로 대조한다. 설계 원리만
[AgentOnto](https://arxiv.org/abs/2610.23317)(arXiv 2610.23317)의 갱신 관문(정정·유지 검사)과
'조용한 의미 오류' 지표에서 가져왔고 논문 수치는 근거로 쓰지 않는다. 기준 공개판은 v0.28.0
`7f7f98ece3626f8706003fd4a50085bf1d4a414a`, 구현 커밋은 `4f97a9f8d5114c5da3f8e90ff47f2ca40dcb9172`이다.
Python 3.10+ 표준 라이브러리를 사용한다.

## 변경

- **응답률과 조용한 오류율(`evaluate_korean_memory.py --answer-rates`):** `summary` 바로 뒤에
  `answer_rates`를 더한다. 응답률(답한 문항/전체), 조용한 오류율(답한 문항 중 틀린 비율)과 단측 95%
  상한(Wilson·Clopper-Pearson), 답할 문항과 답하지 말 문항(답 없음·철회)의 정확도, 항상 답하는 방법의
  상한(`always_answer_ceiling`), 시나리오별 값을 분자·분모와 함께 싣는다. 혼합 정확도
  `answer_accuracy_all_cases`는 두 모집단 정확도의 가중합으로 정수 개수에서 정확히 분해된다. 예를 들어 답할
  문항 30건을 모두 틀리고 답하지 말 문항 20건만 보류해도 혼합 정확도는 0.4지만, 조용한 오류율은 30/30이다.
  [사용법](../memory-evaluation.md)
- **회수 성공률 하한(`evaluate_recall.py --success-bounds`):** 헤드라인 요약(전체·언어별·시나리오별,
  비교 모드의 각 팔)마다 '기대 출처를 모두 top_k 안에 찾은 답할 질의 비율'의 단측 95% 하한을 더한다.
  recall@k의 하한이 아니다. 분자·분모는 그 요약과 같은 행에서 다시 세고, `answerable_query_count`와
  다르면 오류로 멈춘다. 56/56이면 Clopper-Pearson 하한 0.9479, Wilson 0.9539(계산값)다.
  `--rate-bounds`의 세 상한과 게이트는 그대로다. [사용법](../memory-evaluation.md)
- **제안 유지 문구 확인(`vault_proposals.py preserve-check`):** 제안 기록에 저장된 원문과 후보의 본문
  (프런트매터·BOM 제외)에서 숫자·날짜 토큰, 이름 라벨·위키링크 대상, `--claim` 문구의 **등장 횟수**를
  비교한다. 줄어든 것 가운데 선언하지 않은 것은 `unexpected_removals`로 보고한다. `--expect-removed`로
  선언했는데 줄지 않은 것과 `--expect-added`로 선언했는데 늘지 않은 것은 검토 대상이다. 모순된 선언은
  `conflicting_declarations` 오류다. 검토 대상이 있으면 `needs_review`와 종료 코드 1이다. 볼트 파일과
  제안 기록은 바꾸지 않고 `apply`와 사람 승인 절차도 그대로다. 라이브러리 함수는
  `vault_compile_quality.check_preservation`이다. [사용법](../lesson-proposals.md)
- **문서:** 평가·제안 사용법, 문서 색인, Codex 참조의 읽기 전용 명령 목록, `vault-session-end` §5.1의
  선택형 안내 한 문장, README 영감·출처 표(AgentOnto)를 고쳤다.

## 하위호환·업그레이드

새 플래그와 하위 명령을 쓰지 않으면 기존 출력과 종료 코드는 그대로다. 각 기능의 시험이 플래그 유무에
따른 보고서·종료 코드·내보낸 관측의 차이가 새 키뿐임을 확인하고, v0.28.0과의 기본 출력 대조는 게시 전
`verification.json`에 기록한다. 기존 slash command 15종, 기본 세션 훅·회상·설정·모델 호출 경로는 바뀌지
않는다. `vault-session-end` 명령은 선택형 안내 한 문장만 더했다. 게이트·자동 적용·승인·승격을 추가하지
않으며 새 런타임 의존성도 없다.

이번 릴리스의 버전 표면과 healthcheck 스탬프/`ENGINE_VERSION`은 0.29.0을 사용한다. 내용이 같은 기존
규칙 스탬프는 유지한다. 경고 인증서의 검사기 일곱 파일과 harmless corpus는 바꾸지 않았다.

**경고 승격 인증서:** 검사기와 corpus가 같아도 인증서는 설치본의 실제 바이트를 묶는다. 줄바꿈·설치 파일이
달라지면 자동 호환을 보장하지 않으므로 실제 설치본에서 재검증한다. v0.25.0 이하에서 올라오면 v0.26.0의
via_bot 변경으로 기존 인증서가 맞지 않는다. 갱신 전에 승격 단계를 `warning`으로 되돌리고 새 설치본의
`vault_warning_policy.py --certificate`로 다시 만든 뒤 승격한다. 인증서를 자동 갱신하지 않는다.
[v0.26.0 이행 조건](v0.26.0.md#하위호환업그레이드)과
[v0.25.0의 바이트·corpus 조건](v0.25.0.md#하위호환업그레이드)을 유지한다.

v0.26.0 이전 엔진은 `content_origin: via_bot` 수집을 `provenance-invalid`로 보고한다. 같은 볼트를 읽는
Claude Code·Codex 설치본을 함께 갱신한다. Jarvis의 API 인증 조건은 그대로다. 구독 로그인만으로
Q&A·예약 브리핑을 실행할 수 없다.

v0.28.0 이하 설치본에는 `preserve-check`가 없다. 그때는 `inspect`의 diff를 직접 검토한다. 게시 후 Codex
설치 대상 ref는 `--ref v0.29.0`이다. 등록 소스·캐시 보존 절차는 [Codex 설치 안내](../codex.md#설치)를
따른다. 게시, 활성 설치 캐시 갱신, 실제 볼트 upgrade는 서로 다른 작업이며 릴리스 준비만으로 운영 환경이
갱신되지는 않는다.

## 검증

구현 단계의 결과는 [v0.29.0 검증 기록](../verification/v0.29.0.md)에 명령별로 적는다.

- 새 시험 33개(응답률 10, 성공률 하한 10, 유지 문구 확인 13)가 구현 전에 실패하는 것을 먼저 확인했다.
- 4갈래 독립 검토와 각 지적의 반박 검증에서 25건을 확인했다(차단 0, major 6). 가장 중요한 것은
  `preserve-check`의 '조용한 통과' 3건이었다. 있음/없음으로 대조해 ① 같은 값이 여러 번 나오는 문서에서 한
  곳만 바꾼 수정, ② `90일`을 `130일`로 잘못 고친 수정을 `30일` 추가로 확인한 경우, ③ `승인 필요` 뒤에
  `없음`을 붙인 부정을 놓쳤다. 등장 횟수·숫자 토큰·단어 경계 대조로 고치고 회귀 시험을 더했다. 25건은
  모두 고치거나 사유를 적어 수용했다. 읽기 전용 최종 확인이 찾은 minor 1건·nit 8건은 문서로 보강했다.
- 수정 후 Windows/Python 3.12 전체 실행은 **1,988개 OK, 환경 skip 34개**(931초)였다. 컴파일과 CI 오프라인
  관문 10개 명령은 모두 종료 코드 0이었다. 수정 전 1차 전체 실행은 1,979개 OK였다.

이 수치는 버전 표면을 바꾼 최종 릴리스 트리의 검증을 대신하지 않는다. 최종 metadata·CI·패키지·ZIP/blob
대조·재빌드·설치 확인과 독립 검토는 고정 소스에 묶인 게시 전 `verification.json`에 기록한다. 불변 릴리스
자산은 `agentic-vault-0.29.0.zip`, `SHA256SUMS`, `verification.json`이다. `TZ=UTC0`과 prefix
`agentic-vault-0.29.0/`으로 ZIP을 만들고 `rebuild_spec`과 L1/L2 결과를 기록한다. 게시 후 증명·공개
재다운로드 결과는 잠긴 자산 밖의 별도 `post-publication.json`에 보관한다
([릴리스 무결성](../release-integrity.md)). 아직 수행하지 않은 gate를 완료로 읽어서는 안 된다.

## 알려진 경계

- 응답률·조용한 오류율·하한은 고른 평가 결과의 서술 값이다. 기본 픽스처와 결정론 대조군은 실제 모델·업무
  성능을 측정하지 않는다. 실제 모델에 관한 값은 그 모델의 출력을 `--observations`로 재생했을 때만 의미가 있다.
- 하한은 기대 출처를 '전부' 찾았는지를 센다. 질의가 서로 독립이고 한 비율을 공유한다고 가정하며, 여러
  요약을 함께 볼 때의 다중 비교는 보정하지 않는다.
- `preserve-check`는 위치를 보지 않는다. 맞바꾸거나 다른 곳에 같은 값을 더해 가린 변경은 잡지 못한다.
  표현만 바꾸거나 조사가 달라진 수정은 누락으로 보일 수 있다. 리터럴 일치는 의미 보존이나 사실을 뜻하지
  않으며, 결과는 `apply`를 막거나 허락하지 않는다.
- 논문에서는 설계 원리만 가져왔다. 논문의 수치나 결론은 이 도구의 효과 근거가 아니다.
