# v0.27.0 — 후보 계보·기본안 유지와 판단 보류·수정별 근거를 연결하는 개선 실험

선택형 [개선 실험 도구](../improvement-experiments.md)를 더한다. 기본안·공통 개선안·작업 특화안·합성안을
기존 실행 영수증에 연결하고, 비교 결정과 수정별 관찰·교훈 후보를 기록한다. Harness²의 후보 대비·합성과
NO_ENTRY를 참고했으며 기존 agentic-vault의 경로·현재성·실행 비교 경계를 사용한다. 별도 모델·명령 실행기나
새 의존성을 넣지 않고 Python 3.10+ 표준 라이브러리만 사용한다.

## 변경

- **네 조건의 후보 계보:** `vault_improvements.py prepare`는 baseline·general·specialized·composed를
  각각 하나씩 받고 부모 관계, 중복 ID와 run, 같은 실행 조건을 검사한다. 원본 계획·고정 입력과 실행 영수증을
  묶어 현재성이 맞지 않으면 거절한다. 네 실행을 도구가 생성·수행하는 것은 아니다.
- **기본안 유지와 판단 보류:** `compare`는 기존 `vault_runs.compare`의 쌍별 비교 영수증 세 개를 만들고
  ID를 반환한다. 미완료는 `pending / abstain`, 유효한 양의 개선 없음은 `keep_base`, 양의 최고점 동률과
  기본안의 hard 실패·오류는 `abstain`이다. 실패·부적합 후보도 결과에서 숨기지 않는다. 유일한 양의 최고점도
  검토할 `candidate`이며 적용 권한은 없다.
- **수정별 관찰과 NO_ENTRY:** `record`는 무엇을 바꾸고 어떤 차이를 관찰했는지 현재 완료 관찰의
  `{run_id, case_id, repetition}`로 기록한다. helped/hurt에는 기본안과 후보의 서로 다른 관찰 두 쌍 이상이
  필요하다. 여러 요소가 섞인 관찰은 `confounded`로 둔다. 교훈이 없으면 `lesson: null`로 NO_ENTRY를
  기록하며 빈 교훈을 꾸며내지 않는다. 교훈 후보는 실제 도움을 관찰한 격리된 행을 인용하고 해당 후보에도 유효한
  양의 비교가 있어야 한다.
- **조회와 비교의 분리:** `inspect`·`inspect-record`는 읽기 전용이다. 기록과 기록 조회는 현재 호환되는 완료
  실행 영수증에서 점수 차이와 적합성을 다시 계산하므로 별도로 저장한 비교 영수증이 선행 조건은 아니다.
  `compare`를 실행하면 기존 비교 영수증을 별도로 남긴다. 두 경로 모두 근거·정책·입력의 현재성을 확인한다.
- **실행 가능한 오프라인 예제:** `python scripts/evaluate_improvement_experiments.py`는 임시 합성 볼트에서
  다섯 시나리오를 검사한다. 총 20개 논리 실행(준비 20개+완료 20개 영수증)과 비교 영수증 15개를 사용한다.
  CI에도 이 명령을 더한다. 이 결과는 데이터 흐름 검사이며 실제 모델 성능·업무 효과·총비용 절감의 측정이 아니다.
- **검토 전용 출력:** 성공 응답은 `authority=advisory_host_observations_only`, `requires_review=true`,
  `applies_changes=false`를 명시한다. 입력·최종 영수증 64 KiB, 수정 행 16개 등 한도를 검사하며 민감 문자열과
  기존 deny/exclude·링크/정션 정책도 적용한다. CLI 오류는 입력을 되비추지 않는 오류 코드만 반환한다.

## 하위호환·업그레이드

기존 slash command 15종과 기본 세션 훅·검색·설정은 그대로다. `hooks/hooks.json`, 훅 스크립트, git 훅·규칙
6종·볼트 설정 템플릿은 v0.26.0과 같다. 새 helper는 명시적으로 선택할 때만 사용하며 자동 모델·네트워크 호출,
명령 실행, 제안 적용·교훈 승격, 실제 볼트 마이그레이션을 추가하지 않는다. healthcheck 스탬프와
`ENGINE_VERSION`은 0.27.0으로 올리고 내용이 같은 규칙 스탬프는 유지한다.

**기존 경고 승격 인증서:** v0.27.0은 `checker_sha256`가 묶는 일곱 파일과 harmless corpus를 바꾸지 않는다.
다만 인증서는 설치본의 실제 바이트를 묶으므로 줄바꿈 등이 달라지면 같은 버전의 인증서도 맞지 않을 수 있다.
설치 경로를 바꾼 뒤에는 실제 설치본에서 검증한다. v0.25.0 이하에서 올라오는 볼트는 v0.26.0의 via_bot 변경으로
인증서가 맞지 않으므로, 갱신 전에 승격 단계를 `warning`으로 되돌리고 새 설치본의
`vault_warning_policy.py --certificate`로 다시 만든 뒤 승격한다.
[v0.26.0 업그레이드 안내](v0.26.0.md#하위호환업그레이드)와
[줄바꿈·corpus 조건](v0.25.0.md#하위호환업그레이드)을 보존한다. 인증서를 자동으로 다시 쓰지 않는다.

v0.26.0 이전 엔진은 `content_origin: via_bot` 수집을 `provenance-invalid`로 보고한다. 같은 볼트를 읽는 Claude
Code·Codex 설치본을 함께 갱신하고, 이전 버전으로 되돌리기 전에는 해당 수집을 정제·격리하거나 경고 단계를
확인한다. Jarvis의 API 인증 조건도 유지한다. 구독 로그인만으로 Q&A·예약 브리핑을 실행할 수 없다.

Codex 설치 ref는 `--ref v0.27.0`이며 등록 소스·캐시 보존 절차는 [설치 안내](../codex.md#설치)에 있다.
플러그인 게시, 활성 설치 캐시 갱신과 실제 볼트 upgrade는 별도 작업이다. 릴리스 준비는 활성 설치본이나 운영
볼트 엔진을 자동 갱신하지 않는다.

## 검증

기능 구현 커밋 `cff88e66b86031cb7117a539692d954741052722`에서 Windows/Python 3.12 전체 시험
1,846개 중 환경 제외 33개, 실패·오류 0개였다. 새 기능 시험 26개와 독립 검토자의 같은 26개·추가 경계 검사가
통과했고 기존 오프라인 회귀 명령 일곱 개도 종료 코드 0이었다. 이는 기능 구현 시점의 결과이며 버전 메타데이터와
CI 단계를 바꾼 최종 릴리스 소스의 시험 결과를 대신하지 않는다.
[구현 검증 기록](../verification/improvement-experiments-20261021.md)과 구조화된 JSON을 함께 보존한다.

[이번 릴리스 검증 기록](../verification/v0.27.0.md)은 준비 시점의 결과와 대기 항목을 구분한다. 최종 소스의
메타데이터·CI·독립 검토·ZIP/blob 대조·재빌드 결과는 게시 전 자산 `verification.json`에 기록한다.
GitHub 불변 릴리스 절차로 `agentic-vault-0.27.0.zip`, `SHA256SUMS`, `verification.json`을 초안에 모두
올린 뒤 게시한다. ZIP은 `TZ=UTC0`과 `--prefix agentic-vault-0.27.0/`을 써서 만들고 `rebuild_spec`을 남긴다.
게시 후의 릴리스 증명·공개 재다운로드 확인은 잠긴 자산 밖의 별도 `post-publication.json`에 보관한다
([릴리스 무결성](../release-integrity.md)).

## 알려진 경계

- 합성 점수와 호스트 관찰은 실제 모델 성능, 인과관계, 외부 효과, 통계적 유의성이나 총비용을 보증하지 않는다.
  격리 표시는 호스트가 입력하며 도구가 누락한 변경까지 찾아내지는 못한다.
- 해시는 현재 입력을 묶는 표지다. 위변조 서명·진실·쓰기 권한이 아니며 협조적 잠금도 모든 동시성 상황의
  가용성을 보장하지 않는다.
- 선택·반영·교훈의 실제 효과 관찰은 기존 제안·근거·교훈 관측 경로에서 별도로 수행한다. 새 기능은 온라인
  자율 개선이나 자동 권한 변경을 제공하지 않는다. 원 Harness² 코드·런타임·벤치마크를 복사하지 않았다.
