# v0.39.2 — clock-independent timeout stop contracts

v0.39.2 supersedes the **unpublished v0.39.1** and v0.39.0 candidates with a
test-fixture correction. Both candidates' tags and failed CI records are retained;
the last published release remains v0.38.1 until a new release is published.
Runtime scripts, limits, error accounting, installed defaults, dependencies and
installed-resource requirements are unchanged. CI maintenance raises only the
unit-job cap from 35 to 45 minutes; the matrix and smoke steps stay unchanged.
No actual-model inference or new model-performance result is asserted here.

## Candidate failure

Candidate source `fb92f7e79bd2c37a815df1a25b297323e20e4a1a` failed master CI
run 41664026652, job 126014409284, on Windows / Python 3.12. The Korean timeout
test required one received HTTP request but observed zero. That full unit job
ran 2,823 tests in 1,621.381 seconds, with 18 skips and one failure. This was
an assertion failure, not a CI job timeout. No formal v0.39.1 release was published.

A 100ms deadline does not guarantee server acceptance: the bounded attempt may
expire before the handler sees it. Expecting one server receipt coupled a stop
contract to scheduling speed. The runtime already stops after the first failed
attempt. The earlier v0.39.0 failure and preparation records remain in their
[historical release record](v0.39.0.md); v0.39.1's record is
[also unpublished history](v0.39.1.md), not v0.39.2 verification.

## CI time budget

The v0.39.1 tag run's Windows / Python 3.12 job 126014408786 also failed the
same server-receipt assertion: 2,823 tests in 1,956.182 seconds, 18 skips and
one failure. Its unit step took 1,964 seconds (32.7 minutes), followed by four
seconds of cleanup. The successful Windows / Python 3.10 job measured 93 seconds
of post-unit work and 52 seconds of setup. Combining the slow unit step with
those measured overheads gives a 2,109-second planning envelope, exceeding the
old 35-minute cap of 2,100 seconds. This combined envelope is not a measured
whole-job duration; the observed candidate failure was a test assertion, not
a job timeout.

The unit-job cap rises to a finite 45 minutes to allow the full suite and smoke
steps to finish with margin while keeping hung jobs bounded. No tests are
omitted, retries introduced or model-request deadlines changed. Stateful and
advisory job caps remain unchanged.

## Test correction and evidence boundary

Stage and Korean timeout fixtures now use **clock-independent** deterministic
bounded-call contracts. They require exactly one attempt, no later calls after
either `request_timeout` or `transport_error`, and no successful abstention from
errors. Deterministic stop tests assert the control flow and error accounting;
they do not claim an HTTP request reached a server.

Normal-budget actual HTTP contract tests remain separate, including the stage
transport test and Korean 100-request contract coverage. A local HTTP test service
is not a model-inference observation. Attempt counters do not establish server
receipt, completion or inference. No runtime classification is loosened, no
duration is fabricated, and no model result or performance claim is added.

The [stage guide](../memory-stage-evaluation.md) and
[Korean observation guide](../model-korean-memory.md) explain the original
optional tools and counters. Original synthetic fixtures, offline scripted
defaults, strict answer/replay scoring and explicit literal-loopback inference
opt-in remain unchanged. This is not an official Inspect SDK integration or a
copied NoMIRACL benchmark. Stage metrics remain distinct from strict four-phase
selective repair, and identical Korean prompts do not establish annotation efficacy.
