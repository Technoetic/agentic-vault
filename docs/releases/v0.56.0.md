# v0.56.0 — 사전 등록 평가 계획·사후 개정 이중 판정, 설치 상태 자체 다이제스트·기능 커버리지 표 및 사일런트 노옵 방지 감사

공개 v0.55.0(커밋 `ed6cc1362600f0edf44e6ab049705d9208c0f895`)을 바탕으로 [`ai3inc/foldboost`](https://github.com/ai3inc/foldboost)(`v0.3.0`, 커밋 `ff7ad2208cf52d7692d5d016ba5b788d782256c7`, Apache-2.0)에서 선별한 세 가지 비(非)중복 평가 규율·무결성·진단 패턴을 Python 표준 라이브러리만으로 구현해 공개한다. 생체분자 추론·GPU/CUDA 어댑터, `site-packages` `.pth` 몽키패치, Unix 소켓 상주 서버, NumPy 의존성은 도입하지 않으며, 새 런타임 의존성과 모델·네트워크 자동 호출은 없다.

## 변경

1. **사전 등록 평가 계획 봉인 및 사후 규칙 변경(Post-hoc Amendment) 이중 판정 검증기 (`scripts/verify_eval_plan.py`)** ([scripts/verify_eval_plan.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/scripts/verify_eval_plan.py), [tests/test_verify_eval_plan.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/tests/test_verify_eval_plan.py)).
   `v0.54.0`의 사후 릴리스 원장 검증기(`scripts/verify_release_claims.py`)를 넘어, 측정 전에 `plan_id`·`frozen_utc`·`claim_limit`·`gates`를 동결하는 `agentic-vault/eval-plan/v1` 스키마와 `seal`·`verify`·`evaluate` CLI를 추가했다. `frozen_core_sha256`(사전 등록 핵심 불변 해시)과 `plan_sha256`(문서 전체 정규화 해시)을 분리해, 사후 개정(`amendments[]`, `timing: pre_measurement | post_hoc`)을 덧붙여도 원 게이트 변조를 fail-closed로 탐지한다. 측정 시각(`measured_utc`) 이후로 적힌 `pre_measurement` 개정은 거부하며, `evaluate`는 사후 개정이 있더라도 원래 사전 등록 판정(`original_verdict`)을 지우지 않고 개정 판정(`amended_verdict`) 및 `post_hoc_rescued_failure` 표식과 나란히 출력한다(`--strict-original`은 원 판정이 통과해야만 종료 코드 0).
2. **설치 상태 매니페스트 자체 다이제스트·구조화 드리프트 진단 및 호스트×OS×어댑터 커버리지 표 (`vault_install_state.py`, `vault_coverage_matrix.py`, `vault_doctor.py --coverage`)** ([skills/agentic-vault/scripts/vault_install_state.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/skills/agentic-vault/scripts/vault_install_state.py), [skills/agentic-vault/scripts/vault_coverage_matrix.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/skills/agentic-vault/scripts/vault_coverage_matrix.py), [skills/agentic-vault/scripts/vault_doctor.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/skills/agentic-vault/scripts/vault_doctor.py), [commands/vault-doctor.md](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/commands/vault-doctor.md), [tests/test_vault_install_state.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/tests/test_vault_install_state.py), [tests/test_vault_coverage_matrix.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/tests/test_vault_coverage_matrix.py)).
   `vault_install_state.py`가 `00-meta/.vault-install-state.json`에 정규화 JSON 자체 해시(`manifest_sha256`)를 기록·검증하고 중복 JSON 키를 거부하도록 보강했다. 해시 불일치 시 `status`는 `invalid_state`(`manifest_digest_mismatch`), `uninstall`은 `refused`로 fail-closed 차단한다(기존 `v0.54.0`–`v0.55.0`의 해시 없는 매니페스트는 `manifest_integrity: unsealed_legacy`로 하위호환 유지). 또한 드리프트 사유를 `near_misses` 배열(`missing_file`·`missing_engine_stamp`·`sha256_mismatch`·`untracked_managed`)로 구조화해 보고한다. 아울러 읽기 전용·무누출 `vault_coverage_matrix.py`와 선택 플래그 `vault_doctor.py --coverage`(종료 코드 불변)를 추가해 Claude Code·Codex·Antigravity CLI 및 Windows·Linux·macOS별 각 기능의 `supported`·`opt_in_available`·`unsupported`·`not_measured` 상태와 근거를 한 번에 보여 준다.
3. **처치군 발동·대조군 비발동 사일런트 노옵(Silent No-Op) 차단 감사 (`scripts/eval_activation.py`, `--check-activation`)** ([scripts/eval_activation.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/scripts/eval_activation.py), [scripts/evaluate_retrieval_backends.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/scripts/evaluate_retrieval_backends.py), [scripts/evaluate_tool_matrix.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/scripts/evaluate_tool_matrix.py), [tests/test_eval_activation.py](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/tests/test_eval_activation.py)).
   평가 비교군에서 실험군 기능이 실제 1회 이상 발동했는지(`silent_noop` 차단)와 대조군에 기능이 0회 누출됐는지(`control_leakage` 차단)를 감사하는 `eval_activation.py`(`agentic-vault/activation-audit/v1`, 실패 시 전용 종료 코드 `INACTIVE_EXIT = 70`)를 추가하고, `evaluate_retrieval_backends.py`와 `evaluate_tool_matrix.py`에 선택 플래그 `--check-activation`으로 연결했다. 플래그를 주지 않은 기본 출력과 종료 코드는 바뀌지 않는다.
4. **판 표면 및 생성 `antigravity/` 패키지 정렬.**
   세 매니페스트, `antigravity/` 생성 패키지, `vault_healthcheck.py`(`engine=0.56.0`), `scripts/verify_codex_plugin.py`, `README.md`, `SECURITY.md`, `docs/README.md`, `docs/antigravity.md`, `docs/codex.md`, `docs/release-integrity.md`를 `0.56.0`으로 정렬했다.

## 기본 결과 변경

- 판 메타데이터: 매니페스트 버전·설치 태그·healthcheck 스탬프(`engine=0.56.0`, 2행)와 `ENGINE_VERSION`이 `0.56.0`으로 이동한다.
- `vault_install_state.py`: 새로 `record`하거나 부분 `uninstall` 뒤 갱신하는 `00-meta/.vault-install-state.json`에 `manifest_sha256`이 추가되고, `diagnose_install_state` 출력에 `manifest_integrity`와 `near_misses`가 포함된다. 기존 v0.54.0–v0.55.0 매니페스트는 `unsealed_legacy`로 그대로 읽힌다.
- `vault_doctor.py`: `--coverage`를 주지 않은 기본 출력과 종료 코드는 v0.55.0과 바이트 단위로 같다.
- `evaluate_retrieval_backends.py`·`evaluate_tool_matrix.py`: `--check-activation`을 주지 않은 기본 출력과 종료 코드는 v0.55.0과 바이트 단위로 같다.
- **경고 승격 인증서(`checker_sha256`) 불변:** 인증서가 묶는 일곱 파일은 v0.55.0과 바이트 단위로 같다(`checker_sha256` = `3754f606efe8d48c55d5a835bf78552dc9deb6379673d883c5cb9eb56010e79d`, harmless corpus 해시 `38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`, `false_positives = 0`). v0.55.0에서 v0.56.0으로 올릴 때는 인증서를 다시 만들 필요가 없다.

## 하위호환·업그레이드

현재 설치 ref는 `v0.56.0`이다.

기존 볼트 설정 파일은 자동으로 수정·마이그레이션하지 않는다. 공개 준비나 GitHub Release 게시는 활성 호스트 설치나 기존 볼트 사본을 자동으로 갱신하지 않는다. 볼트에 복사된 healthcheck와 helper bundle(`00-meta/scripts/`)은 설치 호스트에서 플러그인을 갱신한 뒤 `/vault-upgrade`(Codex는 `upgrade`)로 별도 갱신한다.

v0.55.0과 v0.56.0 사이는 인증서가 묶는 일곱 파일이 같으므로 경고 승격 인증서 재생성이 필요 없다. v0.54.1 이하에서 경고를 `fatal`로 승격해 쓰던 볼트는 [v0.55.0 업그레이드 안내](https://github.com/Technoetic/agentic-vault/blob/v0.56.0/docs/releases/v0.55.0.md#하위호환업그레이드)와 같이 승격 해제·모든 엔진 사본 정렬·인증서 재생성(`checker_sha256` = `3754f606efe8d48c55d5a835bf78552dc9deb6379673d883c5cb9eb56010e79d`)·재승격 순서를 따른다.

healthcheck만 `engine=0.56.0`으로 이동하며 기존 규칙 6종·어댑터 스탬프는 유지한다.

## 알려진 경계

- `scripts/verify_eval_plan.py`의 타임스탬프(`frozen_utc`·`recorded_utc`·`measured_utc`)와 관측 수치는 호출자 선언이며 외부 타임스탬프 권위나 독립 실행을 암호학적으로 증명하지 않는다.
- `vault_install_state.py`의 `manifest_sha256`은 매니페스트 자체의 우연한 손상과 단순 편집을 탐지하는 무결성 해시이며 암호학적 서명이 아니다(공격자가 해시까지 재계산해도 `MANAGED_SURFACES` 허용 목록·엔진 스탬프·파일별 SHA-256 가드가 별도로 사용자 파일을 보호한다).
- `vault_coverage_matrix.py`는 선언된 지원 표와 정적 로컬 파일 존재 표식만 보고하며, 실제 호스트 런타임 훅 실행이나 `agy` 대화 세션은 `not_measured`로 남긴다.
- `scripts/eval_activation.py`는 비교군별 관측 신호의 발동 여부와 대조군 무누출을 점검할 뿐 모델 품질이나 통계적 유의성을 보장하지 않는다.
- Antigravity CLI 생성 패키지는 `build_antigravity_package.py check` 및 패키지 검증으로 확인하며, 실제 `agy` 대화 세션은 에이전트가 감싸 실행하지 않는다.
