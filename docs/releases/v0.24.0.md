# v0.24.0 — Windows 편집 안정성과 선택형 한국어 모델·검색 비교

Windows에서 열린 읽기 핸들 때문에 부분 편집이 일시적으로 거부되는 경우를 제한적으로 재시도한다.
한국어 도구 호출의 언어·문자열 보존 조건과 공개 fixture의 검색 순위를 비교하는 두 선택형 CLI도
포함한다. 핵심 엔진은 Python 3.10+ 표준 라이브러리만 사용하며 기본 모델·네트워크 호출이나
검색 설정을 추가하지 않는다. [사용법](../evaluation-stability.md), [보강 도구](../hardening.md),
[릴리스 검증](../verification/v0.24.0.md), [릴리스 무결성](../release-integrity.md)을 함께 확인한다.

## 변경

- **Windows 부분 편집:** 원자적 교체가 WinError 5/32로 거부되면 최대 6회, 총 대기 0.31초 범위에서
  재시도한다. 매번 lease·설정·대상 revision·관련 출처 해시를 다시 확인한다. 정책이나 원문이 바뀌면
  중단하고 지속적인 잠금·다른 오류도 실패로 남긴다. Python 3.12 `realpath`의 경합에서 남는 DOS
  drive `\\?\` 접두어는 동일한 물리적 root를 확인한 비교에 한해 처리하며 원래 OS 입출력 경로를
  유지한다. UNC/device 경로를 임의로 합치지 않는다.
- **언어·문자열 보존 매트릭스(선택):** `scripts/evaluate_tool_matrix.py`는 요청 언어,
  설명 언어, `--prompt-variant canonical|literal-identifiers`, clean/attacked 조건과 반복 seed를
  묶어 비교한다. 기본 실행은 모델 없는 프로토콜 대조군이다. 실제 모델은 `--backend local-model`과
  명시적 모델·인증 환경변수 이름을 선택해야 하며 루프백 endpoint만 사용한다. 기존
  `evaluate_tool_safety.py`의 canonical 기본 출력은 유지한다. 정상 업무 완료·공격 목표·모델 오류·
  인자 실패를 따로 세고 오류를 분모에서 지우지 않는다. `--receipt-out` 영수증은 크기를 제한한
  응답과 실패 진단을 보관하며 알려진 인증값을 중첩 JSON·응답 본문·props에서도 정제한다.
- **검색 순위 비교(선택):** `scripts/evaluate_retrieval_backends.py`는 공개 `recall`,
  `recall_advanced`, `recall_hard` fixture만 받는다. 기본은 BM25와 한글 bigram을 비교하고,
  `--kiwi`와 `--qmd-mode search|query`로 별도 실험 환경의 Kiwi/qmd를 선택한다. fixture 조상
  링크·junction을 검사하고 허용 노트만 복사하며 qmd 환경·설정·색인·캐시를 격리한다. qmd
  벡터 조건은 `--allow-model-download`를 명시해야 하고, `--qmd-model-cache`로 기존 공개 모델
  하나를 해시 확인 후 사용할 수 있다. 모델이나 패키지를 핵심 설치 의존성으로 추가하지 않는다.

## 하위호환·업그레이드

기본 세션 주입·검색 설정·네트워크/모델 호출·런타임 의존성은 유지한다. Windows 충돌 재시도는
기존 부분 편집의 성공 조건과 실패 시 보존 규칙을 유지한다. `hooks/hooks.json`, 훅 스크립트,
명령 문서와 여섯 규칙 템플릿은 v0.23.0과 같으며 healthcheck stamp/ENGINE_VERSION만 0.24.0으로
맞춘다. 내용이 같은 규칙 스탬프를 일괄 갱신하지 않는다. 평가 CLI는 기본 세션 프롬프트나
실제 볼트에 자동 적용하지 않는다.

**경고 승격 인증서.** `vault_paths.py`는 경고 승격 인증서의 checker 해시에 포함된다.
이번 경로 검사 코드 변경으로 `checker_sha256`가 바뀌므로 v0.23.0 등 이전 설치본에서 생성한
인증서로 `fatal` 승격을 유지하면 설정 오류로 멈춘다. 조용히 경고로 낮추지 않는 fail-closed
동작이다. 갱신 전에 해당 단계를 `warning`으로 되돌리고, 새 설치본에서
`vault_warning_policy.py --certificate`로 bundled benign replay와 현재 해시에 묶인 인증서를
다시 만든 뒤 승격한다. 구체적 설정·실패 사례는 [이전 릴리스의 인증서 안내](v0.23.0.md#하위호환업그레이드)와
[보강 도구](../hardening.md)를 따른다. 실제 사용자 볼트의 인증서는 자동 재작성하지 않는다.

Codex 설치 ref는 `--ref v0.24.0`이다. 기존 소스 교체·캐시 보존 절차는
[Codex 설치 안내](../codex.md#설치)에 있다. 플러그인 게시, 활성 캐시 갱신과 볼트 upgrade는
별도 작업이다. 이번 게시 준비 중 활성 호스트 캐시와 운영 볼트의 엔진은 v0.23.0으로 유지했다.
Jarvis의 기존 API 인증 조건도 유지한다.

GitHub 불변 릴리스 절차를 계속 사용한다. ZIP·`SHA256SUMS`·`verification.json`을 초안에
올린 뒤 게시하며 텍스트 자산은 LF 바이트로 쓴다. `verification.json`은 게시 전 최종 소스·
CI·ZIP/blob 대조·독립 검토 영수증이다. 게시 뒤 릴리스 증명과 공개 재다운로드 확인은 별도
기록에 남긴다. 잠긴 자산 안에 그 자산의 나중 검증 결과를 덧붙이지 않는다.

## 검증

기능 개발 단계의 2026-10-18 실제 관측은 [당시 기록](../verification/eval-stability-20261018.md)과
[JSON 요약](../verification/eval-stability-20261018.json)에 그대로 보존한다. 당시 전체 검사
1,548건은 1,515통과·기존 환경 제한 33 skip·실패/오류 0이었다. Windows 신규 10검사와
두 프로세스 prepare/record 100/100, 독립 검토 83검사, 상태 기반 4검사·두 생성 machine,
기존/신규 CLI 9개, compileall과 whitespace 검사도 통과했다. 이 수치를 버전 메타데이터와
릴리스 문서 변경 후 최종 소스에서 새로 실행한 결과로 표시하지 않는다.

| 실제 관측 | 결과와 범위 |
|---|---|
| 순차 한국어 clean 도구 과제 | 같은 30초 요청·90초 에피소드 예산, 최대 3턴, 조건별 두 반복에서 canonical 0/4, literal-identifiers 4/4; 모델 오류 0 |
| 최초 32에피소드 매트릭스 | 업무 완료 17/32, 인자 언어 불일치 7, 모델 오류 8(시간 초과 7·transport 1), 공격 목표 0/16; 다른 모델 호출과 겹친 부하·10초 제한의 관측 |
| 구조화 기억 답변 pilot | 균형 10문항에서 10/10 정답, 답 있음 근거 6/6·답 없음 보류 4/4·오류 0; 전체 50문항이나 자유형 QA 점수가 아님 |
| 공개 recall_hard 64질의 | BM25 recall@5 0.5714, 한글 bigram 0.7500, Kiwi 0.7143, qmd 키워드 0.5179, typed lex+vec 1.0000; 벡터의 답 없음 후보 오탐은 8/8 |

원 관측은 인증값 정제·검색 환경 격리 보강 전의 실행 소스와 함께 보존했다. 보강 후 네 키워드
방식은 64질의를 다시 실행해 품질·오류 0·바인딩 일치를 확인했고 벡터는 새 색인과 캐시 모델로
한 질의의 같은 다섯 경로를 확인했다. 보강 후 전체 64 벡터 질의의 재실행은 아니다.

릴리스 준비 트리의 disposable Codex home 설치는 0.24.0 리소스 일치와 공통 skill 하나,
sessionStart 3·preCompact 1·sessionEnd 1 훅 발견을 확인했다. 모델 턴은 0이고 훅은 untrusted로
유지했다. 실제 훅 실행이나 운영 캐시 갱신을 검증한 것은 아니다. 최종 소스의 전체 검사·원격 CI·
공개 자산 상태는 [v0.24.0 검증 기록](../verification/v0.24.0.md)과 거기서 지정한 영수증에 남긴다.

## 알려진 경계

합성 fixture와 한 로컬 모델(Qwen3.5-9B-Q8_0)의 작은 반복 관측이다. 한국어 업무 전체·공격
내성·공식 LongMemEval/BFCL 점수를 입증하지 않는다. 최초 매트릭스 오류를 방어 성공으로
재분류하지 않으며 문자열 보존 지시를 기본 프롬프트에 자동 적용하지 않는다. 알려진 인증값
정제는 알 수 없는 모든 비밀의 탐지를 보장하지 않는다.

벡터 검색의 후보 회수율은 답변 품질·출처 철회·시간 유효성을 보장하지 않는다. 이번 qmd 조건은
CPU, typed lex+vec, no-rerank이며 query expansion·생성 모델·reranker와 전체 기본 파이프라인을
평가하지 않았다. 준비 비용과 질의 지연을 분리했고 방식별 측정 범위가 달라 단순 속도 순위를
주장하지 않는다. Kiwi와 qmd는 선택형 실험 의존성이다.

협조 잠금은 참여하는 writer만 보호하며 외부 앱 편집의 완전한 차단·다중 파일 트랜잭션을
제공하지 않는다. 다른 OS/Python 조합의 실제 CI, 대규모 업무 볼트와 자유형 답변은 당시 관측
범위 밖이다. 최종 릴리스 CI는 별도로 기록한다. GitHub 릴리스 증명은 게시 자산과의 동일성을
확인하며 빌드 출처·게시 승인자 신원·내용의 안전성은 증명하지 않는다.
