# v0.25.0 — 선택형 동기화 경고, 실제 볼트 골드셋·소표본 평가와 측정 조건 기록

Claude Code 2.1.295 이상을 권장하고, 기본값이 꺼진 선택형 진단·평가 옵션과 경고 전용 CI 작업의 해시 고정
설치를 더한다. 새 옵션을 주지 않으면 기본 동작은 버전 스탬프를 빼고 v0.24.0과 같다(아래 비교 범위). 핵심
엔진은 Python 3.10+ 표준 라이브러리만 사용하며 기본 모델·네트워크 호출, 런타임 의존성, 훅 정의를 추가하지
않는다. [호스트 버전 확인](../reliability.md#호스트-버전과-sessionstart-실측),
[동기화 경고](../hardening.md#동기화-충돌-사본과-checkpoint-이후-변경-경고-선택),
[골드셋·소표본 평가](../memory-evaluation.md), [측정 조건 기록](../evaluation-stability.md),
[릴리스 검증](../verification/v0.25.0.md), [릴리스 무결성](../release-integrity.md)을 함께 확인한다.

## 변경

- **Claude Code 2.1.295 이상 권장:** 이 플러그인은 `startup|clear|resume`에 비동기 healthcheck SessionStart 훅을
  등록한다. [Claude Code 공식 변경 기록](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)의 2.1.295
  항목이 "Fixed an async SessionStart hook's unchanged context being added to the conversation again on every
  resume"이므로, 그 이전 버전에서는 이 훅의 바뀌지 않은 컨텍스트가 resume마다 대화에 다시 붙을 수 있다(이 저장소에서
  재현하지 않음). 권장일 뿐 낮은 버전의 설치나 훅 실행을 막지 않고 `hooks/hooks.json`도 바꾸지 않았으며, 같은
  버전의 `onFailure: "block"`은 채택하지 않았다. `vault_doctor.py --host-version`은 요청할 때만 PATH의
  `claude --version`을 셸 없이 한 번 실행하고(4초 뒤 종료, 정리 1초) `host_version`에 `ok`·`below_recommended`·
  `unavailable`·`unparsed`와 권장 최소 버전 2.1.295를 남긴다. 종료 코드는 바꾸지 않는다. PATH 실행 파일의
  버전이므로 지금 훅을 실행하는 호스트와 같다고 단정하지 않는다.
- **동기화 충돌·checkpoint 이후 변경 경고(선택):** `00-meta/vault-config.json`에 `sync_conflict_check: true`를
  넣으면 healthcheck full 모드가 Syncthing 충돌 사본·임시 파일과 Obsidian Sync 충돌 파일의 이름을 리포트 §15
  경고로 더한다. `sync_conflict_patterns`(파일 이름 glob, 최대 32개)는 공식 이름 규칙을 확인하지 못한
  Dropbox·OneDrive 같은 클라이언트에 쓴다. `checkpoint_drift_check: true`는 마지막 PreCompact·SessionEnd
  checkpoint 이후 바뀌거나 없어진 hot·handoff·log·tasks 노트를 경고한다. 이름과 해시만 비교하며 노트를 쓰거나
  고치지 않는다. exit code와 치명 집계는 그대로이고 새 경고 코드는 fatal로 승격할 수 없다. 형식이 틀린 키는
  다른 설정 오류처럼 설정을 읽는 구성 요소를 모두 멈춘다.
- **실제 볼트 골드셋 평가(선택):** `scripts/evaluate_recall.py --vault VAULT --goldset GOLDSET.json`은 손으로
  라벨한 질문 묶음으로 실제 볼트의 검색을 제자리에서 잰다. 볼트 설정의 deny zone·제외 폴더를 먼저 적용하고,
  파일을 쓰거나 네트워크·모델을 호출하지 않으며 결과는 표준 출력으로만 낸다. 라벨은 경로나 유일한 파일 이름
  stem으로 맞추고, 같은 이름이 여럿이면 `ambiguous_stem`으로 남긴다. `--redact`는 id·질문·scenario 같은 자유
  텍스트를 sha256 값으로 바꾼다(암호화가 아니다). `--split dev|heldout`·`--split-file`·`--derive-split`은
  (언어, scenario) 층마다 seed 1707로 나눈 분할을 쓰거나 출력하며, `recall_hard`의 분할(dev 32·heldout 32)을
  `tests/fixtures/recall_hard/split.json`으로 포함한다. 문항의 `"inspected": true`는 실패를 본 뒤 고친 문항을
  헤드라인 지표·게이트에서 빼고 따로 집계한다. 그 때문에 헤드라인에 문항이나 답 있는 문항이 남지 않으면
  게이트를 통과로 치지 않고 종료 코드 1로 끝낸다.
- **소표본 통계(선택):** `evaluate_recall.py`는 `--exact-paired`나 `--rate-bounds`를 줄 때만 새 표준 라이브러리
  모듈 `scripts/eval_stats.py`를 읽는다. `--exact-paired`(`--compare` 필요)는 0이 아닌 쌍이 20개 이하인 쌍 비교의
  p값을 부호 패턴 전체 열거로 계산하고 `method`·`nonzero_pair_count`·`minimum_attainable_p_value`(2^(1−k))를
  남긴다. 20개를 넘으면 기존 몬테카를로 값을 쓴다. `--rate-bounds`는 답 없음 오탐·금지 출처 노출·stale top-1
  비율에 단측 95% Wilson·Clopper–Pearson 상한을 붙인다. 게이트와 종료 코드는 관측 비율만 읽고, 상한이 게이트
  최댓값을 넘으면 비차단 알림만 남긴다.
- **llama-server 측정 조건(선택):** `evaluate_tool_safety.py`와 `evaluate_tool_matrix.py`의 `--no-prompt-cache`는
  채팅 요청 끝에 `"cache_prompt": false`를 붙이고, `--slot-snapshots`는 에피소드 앞뒤로 같은 루프백 서버의
  `GET /slots`를 요청해 전체·바쁜 슬롯 수를 남긴다(5초·262,144바이트 제한, 실패해도 실행과 종료 코드는 그대로).
  `evaluate_tool_matrix.py`의 `--repeat-agreement`(`--repeats` 2~5 필요)는 같은 seed로 같은 구성을 반복해 첫
  실행과 응답·도구 호출 해시가 같은 비율을 낸다. 조건을 기록할 뿐 결정성을 만들지 않는다.
- **CI 공급망 점검의 해시 고정 설치:** 경고 전용 `supply-chain-audit` 작업이 pip-audit을
  [`ci/requirements-audit.txt`](../../ci/requirements-audit.txt)(pip-audit 2.10.1과 그 의존성을 합친 29개 패키지,
  sha256 362개, 2026-10-04 이전 업로드만)에서 `--require-hashes --only-binary :all:`로 설치하고
  `--no-deps --disable-pip`로 감사한다. pip-audit을 해시 없이 설치하던 action 단계는 없앴다. 작업과 단계는 계속
  `continue-on-error`이고 차단 작업(unittest·stateful)의 명령은 그대로다. 갱신 절차는
  [릴리스 무결성](../release-integrity.md#갱신-절차)에 있다.

## 하위호환·업그레이드

새 옵션과 설정 키는 모두 기본값이 꺼져 있고, 새 검사는 경고 전용이며, CI 변경은 경고 전용 작업 안에만 있다.
기본 동작은 버전 스탬프를 빼면 v0.24.0과 같다. 근거는 버전 변경 전의 기능 통합 코드를 v0.24.0(`d2b9315`)과 같은
입력으로 비교한 38건이 모두 같았다는 기록이다. 비교는 `d2fc05f`에서 실행했고, 그 뒤의 `4de01be`는 문서 3개만
고쳐 코드가 같다. healthcheck·doctor text·doctor json 30건(fixture 볼트 5개, 동기화 golden 볼트 3개, doctor 준비
볼트, 빈 폴더)은 종료 코드·stdout·stderr·쓴 파일 바이트가 그대로 같았고, 스크립트 8건(recall 기본·recall_advanced
비교 top-3·top-5·recall_hard top-3·top-5, 도구 안전 대조군, 기억 작업 흐름, 한국어 기억)은 경과 시간 값만 정규화한
뒤 같았다. 이 범위 밖의 동작을 이 수치로 보증하지 않는다. 별도의 독립 비교에서 `evaluate_tool_matrix.py` 두 건과
`evaluate_retrieval_backends.py` 한 건의 기본 출력은 내장한 소스 파일 SHA-256과 지연 값만 달랐다. 두 도구는 실행
코드의 지문을 기록하므로 코드가 바뀌면 그 값도 바뀐다.

`hooks/hooks.json`, 훅 스크립트(`session_start.py`·`session_checkpoint.py`·`run_python_hook.sh`), git 훅 템플릿과
여섯 규칙 템플릿은 v0.24.0과 바이트가 같다. 명령 문서는 두 개가 바뀌었다. `commands/vault-doctor.md`에 요청할 때만
쓰는 `--host-version` 항목을, `commands/vault-lint.md`에 §15 동기화·checkpoint 경고의 처리 원칙(자동 삭제·병합 금지)을
더했다. healthcheck 스탬프와 `ENGINE_VERSION`만 0.25.0으로 올리고 내용이 같은 규칙 스탬프는 그대로 둔다. 볼트 설정
템플릿에는 새 키를 넣지 않았으므로 `/vault-upgrade`의 누락 키 보충이 새 경고를 켜지 않는다.

**경고 승격 인증서.** `vault_warning_policy.py`의 `checker_sha256`는 `vault_lint_extensions.py`·
`vault_warning_policy.py`·`vault_provenance.py`·`vault_egress.py`·`vault_ssot.py`·`jev_client.py`·`vault_paths.py`
일곱 파일의 바이트로 만든다. 이번에 바뀐 `vault_healthcheck.py`·`vault_doctor.py`는 여기에 들어가지 않고, 일곱
파일과 benign corpus(`resources/lint-benign-v1.json`)의 Git blob은 v0.24.0과 같다. 2026-10-19에 v0.23.0·v0.24.0·
릴리스 준비 트리의 엔진 파일을 저장소 바이트(LF) 그대로 꺼내 측정하자, v0.24.0과 준비 트리의
`vault_warning_policy.py --certificate` 출력은 일곱 필드가 모두 같았다(`checker_sha256` `2ef4b9d4…`). v0.24.0
인증서로 `missing-anchor`를 `fatal`로 올린 합성 볼트에서 새 healthcheck는 종료 코드 0이었고 SessionStart 훅도
정상 주입했다. 따라서 v0.24.0에서 만든 인증서는 다시 만들 필요가 없다. v0.23.0 이하에서 만든 인증서는
v0.24.0의 `vault_paths.py` 변경으로 맞지 않는다. 같은 측정에서 v0.23.0 인증서(`checker_sha256` `b7138def…`)를
쓴 fatal 승격은 v0.24.0과 새 버전 모두
`warning promotion rejected: promotion certificate checker_sha256 differs from current harmless replay`와 함께
종료 코드 1로 멈췄고 SessionStart 훅은 주입하지 않았다. 단계를 `warning`으로 되돌린 같은 설정은 종료 코드 0이었다.
v0.23.0 이하에서 올라오는 볼트는 [v0.24.0 안내](v0.24.0.md#하위호환업그레이드)대로 갱신 전에 승격 단계를
`warning`으로 되돌리고, 새 설치본에서 `vault_warning_policy.py --certificate`로 인증서를 다시 만든 뒤 승격한다.
실제 사용자 볼트의 인증서는 자동으로 다시 쓰지 않는다.

인증서는 설치본의 바이트에 묶인다. 일곱 Python 파일은 저장소 속성으로 항상 LF로 체크아웃되지만 corpus JSON은
그렇지 않다. `core.autocrlf=true`인 Windows git 작업 트리처럼 CRLF로 체크아웃한 설치본은 같은 버전이라도
`corpus_sha256`이 달랐다(CRLF `4b31a673…`, LF `38efaabd…`). 줄바꿈이 다른 설치본 사이에서는 인증서가
`promotion certificate corpus_sha256 differs from current harmless replay`로 멈췄다(같은 측정). 이전과 같은 방식으로
설치해 줄바꿈이 같으면 v0.24.0 인증서가 그대로 맞고, 설치 방식을 바꿨다면 새 설치본에서 인증서를 다시 만든다.
이 성질은 이번 릴리스에서 생긴 것이 아니다.

**새 설정 키와 되돌리기.** v0.24.0은 세 키를 읽지 않는다. v0.24.0 코드(`d2b9315`)를 저장소 밖에 풀어 같은 합성
볼트에서 키가 없을 때, 올바른 값일 때, 형식이 틀린 값일 때를 비교하자 healthcheck(full)·SessionStart·SessionEnd
checkpoint·doctor(json)·recall(json)의 종료 코드·stdout·stderr·리포트 바이트가 세 경우 모두 같았다(2026-10-19
측정). 그래서 v0.25.0에서 켠 경고는 v0.24.0으로 되돌리면 오류 없이 꺼진다. 반대로 v0.25.0은 세 키의 형식을
검사한다. v0.24.0에서 아무 효과 없이 남아 있던 잘못된 값(예: `"sync_conflict_check": "yes"`)은 갱신 뒤 healthcheck를
설정 오류(종료 코드 1)로 멈추고, SessionStart 주입·checkpoint 기록을 막으며, doctor·recall도 설정 오류(종료 코드 2)로
끝낸다(같은 측정). 갱신 직후 healthcheck로 설정 오류부터 확인한다.

Codex 설치 ref는 `--ref v0.25.0`이다. 기존 소스 교체·캐시 보존 절차는 [Codex 설치 안내](../codex.md#설치)에 있다.
플러그인 게시, 활성 캐시 갱신과 볼트 upgrade는 별도 작업이다. 이번 게시 준비는 활성 호스트 캐시와 운영 볼트를
바꾸지 않았다. Jarvis의 기존 API 인증 조건도 유지한다.

GitHub 불변 릴리스 절차를 계속 사용한다. ZIP·`SHA256SUMS`·`verification.json`을 초안에 올린 뒤 게시하며
텍스트 자산은 LF 바이트로 쓴다. `verification.json`은 게시 전 최종 소스·CI·ZIP/blob 대조·독립 검토 영수증이다.
게시 뒤 릴리스 증명과 공개 재다운로드 확인은 별도 기록에 남긴다. 잠긴 자산 안에 그 자산의 나중 검증 결과를
덧붙이지 않는다.

## 검증

기능 개발·통합 단계의 기록은 [검증 기록](../verification/v0.25.0.md)에 범위와 함께 정리했다. 기능 통합 코드의 전체
검사는 1,703건(v0.24.0의 1,548건과 새 155건)이고 33건은 기존 환경 제한으로 건너뛴다. 같은 코드에서 돌린 전체
실행 6회(통합 2·독립 코드 검증 2·릴리스 호스트 2) 가운데 3회가 통과했고 3회는 아래 기존 불안정 시험 하나씩으로
실패했다. compileall과 `git diff --check`는 통과했다. 이 수치를 버전 메타데이터와 릴리스 문서를 바꾼 최종 소스에서
새로 실행한 결과로 표시하지 않는다.

## 알려진 경계

**Python 3.10 CI 실패(게시 전 해결 필요).** 기능 통합 커밋 `4de01be`의 첫 원격 CI에서 Python 3.10 세 작업
(Linux·macOS·Windows)이 `tests/test_small_sample_stats.py:148`의 같은 단언으로 실패했다(`0.5 != 0.625`). 이 단언은
허용오차 0에서 부동소수 동률이 몇 개 깨지는지를 고정하고, 테스트 도우미는 내장 `sum()`으로 더한다. 릴리스 호스트의
Python 3.12에서 같은 도우미를 내장 `sum()`으로 계산하면 0.625, 왼쪽부터 차례로 더하면 3.10 작업과 같은 0.5가
나왔다(2026-10-19 측정). 같은 테스트에서 그보다 앞선 정확 p값(0.75) 단언과, 허용오차를 쓴 300건 전수 대조 시험은
3.10에서도 통과했다. 기능 코드가 아니라 Python 버전별 float 합산에 의존한 테스트 단언의 문제로 보이며, 이 릴리스
준비 커밋은 그 테스트를 고치지 않았다. 최종 소스의 원격 CI가 통과하기 전에는 게시하지 않는다.

**기존 불안정 시험 세 개.** `tests/test_vault_query_expansion.py:251`

1회 실패했다. 위 전체 실행 6회의 실패 3건은 앞 시험 2건, 뒤 시험 1건이다. `tests/test_vault_instruction_budget.py:258`

**넣지 않은 것.**

- 1번: `context_tokens` 선택 기록과 deny-zone PreToolUse 가드 템플릿은 넣지 않았다. `--debug` 훅 소요 시간 실측은

  경고로 나온다. 실제 볼트의 오탐률·놓침률은 재지 않았고 근거는 합성 임시 볼트뿐이다.

  `/slots` 파싱과 프롬프트 캐시 재사용만 확인했다.

**열린 질문.** `--derive-split`은 `--compare`(`--exact-paired` 포함)·`--rate-bounds`를 오류 없이 무시한다(2026-10-19
확인: 출력과 종료 코드가 플래그 없을 때와 같았다. `--compare` 없는 `--exact-paired`는 사용 오류다). 해시 고정 설치가

합성 fixture와 한 로컬 서버의 작은 관측이다. 실제 업무 볼트의 검색 품질, 동기화 경고의 실제 오탐률, 로컬 모델의
