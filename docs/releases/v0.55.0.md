# v0.55.0 — 검증일 노화·별칭 충돌 린트, URL 쿼리 유출 검사, 클라우드 동기화 경고 및 첫 실행 기능 요약

공개 v0.54.1(커밋 `74a2776cec936cd2cce7274cc9f3cb29bacf0159`)을 바탕으로 [`seulee26/stock-team-harness`](https://github.com/seulee26/stock-team-harness)(`v2.4.0`, 커밋 `d3b716d1`, MIT)에서 선별한 여섯 가지 비(非)중복 운영·위생·보안·온보딩 패턴을 Python 표준 라이브러리만으로 구현해 공개한다. 주식·선물·세무 도메인 기능과 35개 스킬/32개 에이전트 팩은 도입하지 않았으며, 새 런타임 의존성과 모델·네트워크 자동 호출은 없다.

## 변경

1. **검증일 기준 노화·연도 경계 경고 (`checked-at-stale` · `review-by-passed`) 및 별칭 충돌 린트 (`alias-collision`)** ([skills/agentic-vault/scripts/vault_lint_extensions.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/skills/agentic-vault/scripts/vault_lint_extensions.py), [skills/agentic-vault/scripts/vault_healthcheck.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/skills/agentic-vault/scripts/vault_healthcheck.py), [tests/test_vault_lint_extensions.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/tests/test_vault_lint_extensions.py)).
   `vault_lint_extensions.py`에 프런트매터 `checked_at`·`review_by` 날짜 검증 및 재검증 노화 경고를 추가했다. `checked_at_stale_days`(선택형 양의 정수, 기본 비활성)와 `checked_at_annual_rollover`(선택형 불리언, 기본 `false`)로 외부 기준·법령·가격 문서의 재검증 경과와 연도 변경을 감지하고(`checked-at-stale`), 명시적 `review_by` 기한이 지난 노트는 `review-by-passed`로 경고한다(두 코드는 실행 날짜 의존 경고이므로 `PROMOTABLE_CODES`에서 제외해 승격 불가로 유지한다). 또한 프런트매터 `aliases:`(흐름 목록·블록 목록)를 선형 시간으로 파싱해 다른 활성 노트의 파일명 stem 또는 별칭과 겹치는 중복 엔티티 후보를 결정론적 경고 `alias-collision`(승격 가능)으로 보고한다.
2. **URL 쿼리 파라미터 비밀키·서명 유출 검사 (`egress-url-secret`)** ([skills/agentic-vault/scripts/vault_egress.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/skills/agentic-vault/scripts/vault_egress.py), [tests/test_vault_egress.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/tests/test_vault_egress.py)).
   `vault_egress.py`의 경고 전용 스캔에 `https?://` URL 한정 `urllib.parse.urlsplit` + `parse_qsl` 검사를 추가했다. `token`, `sig`, `signature`, `x-amz-signature`, `x-goog-signature`, `accountseq` 등 고신호 자격증명·사전 서명 쿼리 파라미터에 실제 값(4자 이상, `<...>`·`{...}` 템플릿 자리표시자 제외)이 담긴 경우 원문 URL이나 비밀값을 출력하지 않고 `egress-url-secret`(승격 가능) 경고를 낸다. `page_token`·`next_token`·`cursor` 같은 정상 페이지네이션 파라미터는 경고하지 않으며, NFKC·불가시 문자 위장 URL과 민감 경로 마스킹도 함께 적용한다.
3. **읽기 전용 클라우드 동기화 목적지 경고 및 첫 실행 기능 요약 (`vault_cloud_sync.py`, `vault_doctor.py --cloud-sync` · `--summary`)** ([skills/agentic-vault/scripts/vault_cloud_sync.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/skills/agentic-vault/scripts/vault_cloud_sync.py), [skills/agentic-vault/scripts/vault_doctor.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/skills/agentic-vault/scripts/vault_doctor.py), [skills/agentic-vault/scripts/backup_vault.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/skills/agentic-vault/scripts/backup_vault.py), [skills/agentic-vault/scripts/vault_okf.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/skills/agentic-vault/scripts/vault_okf.py), [tests/test_vault_cloud_sync.py](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/tests/test_vault_cloud_sync.py)).
   경로 조각과 환경 변수(`OneDrive`·`OneDriveCommercial`·`OneDriveConsumer`) 휴리스틱만으로 OneDrive·Google Drive·Dropbox·iCloud 동기화 폴더 여부를 판별하고 원시 경로·사용자명·파일 내용은 출력하지 않는 `vault_cloud_sync.py`를 추가했다. `vault_doctor.py --cloud-sync`는 볼트·`backup_target` 동기화 여부와 `.claude/settings.local.json`·`.env` 존재 표식을 보고하며, `vault_doctor.py --summary`는 초기화 여부와 관계없이 "지금 바로 쓸 수 있는 것 vs 선택 준비가 필요한 것"을 2~3줄로 요약한다(두 플래그 모두 선택형이며 종료 코드를 바꾸지 않는다). `backup_vault.py`와 `vault_okf.py` CLI는 대상 경로가 클라우드 동기화 폴더 안일 때만 `stderr`로 비차단 경고 1줄을 출력한다(`manifest.json`과 `stdout`은 불변).
4. **반증 가능한 ADR 템플릿 및 무근거 결론 번복 검토 기준** ([assets/templates/decisions.md](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/assets/templates/decisions.md), [commands/vault-lint.md](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/commands/vault-lint.md), [commands/vault-doctor.md](https://github.com/Technoetic/agentic-vault/blob/v0.55.0/commands/vault-doctor.md)).
   ADR 템플릿에 선택 항목 `- **재검토·무효화 조건:**`을 추가해 결정이 깨지는 조건을 사전에 적도록 했고, `/vault-lint` §4 상태 노트 교차 대조에 이유·대체 표기(`superseded_by`·`대체됨 → ADR-XXX`) 없는 결론 번복 점검과 과거 결론 덮어쓰기 금지 원칙을 명시했다.
5. **판 표면·인증서 전환 기록·생성 `antigravity/` 패키지 정렬.**
   세 매니페스트, `antigravity/` 생성 패키지, `vault_healthcheck.py`(`engine=0.55.0`), `scripts/verify_codex_plugin.py`, `README.md`, `SECURITY.md`, `docs/README.md`, `docs/antigravity.md`, `docs/codex.md`, `docs/hardening.md`, `docs/release-integrity.md`를 `0.55.0`으로 정렬했다.

## 기본 결과 변경

- 판 메타데이터: 매니페스트 버전·설치 태그·healthcheck 스탬프(`engine=0.55.0`, 2행)와 `ENGINE_VERSION`이 `0.55.0`으로 이동한다.
- `vault_lint_extensions.py` 및 `vault_egress.py`:
  - `review_by` 기한이 지난 노트, 다른 활성 노트의 파일명/별칭과 충돌하는 `aliases:`, `https?://` URL의 자격증명·서명 쿼리 파라미터가 있는 노트에서는 각각 경고(`review-by-passed`, `alias-collision`, `egress-url-secret`)가 추가 보고된다.
  - `checked-at-stale`은 `checked_at_stale_days > 0` 또는 `checked_at_annual_rollover: true`를 명시한 볼트에서만 동작한다.
  - 정상 노트의 기본 harmless corpus(`resources/lint-benign-v1.json`) 21건은 여전히 오탐 0건(`false_positives: 0`)이다.
- `vault_doctor.py`: `--cloud-sync`·`--summary`를 주지 않은 기본 출력과 종료 코드는 v0.54.1과 바이트 단위로 같다.
- `backup_vault.py`·`vault_okf.py`: 로컬 일반 경로에 대해서는 stdout·stderr·매니페스트·종료 코드가 v0.54.1과 바이트 단위로 같다. 클라우드 동기화 폴더 대상일 때만 `stderr` 경고 1줄이 추가된다.
- **경고 승격 인증서(`checker_sha256`) 전환:** 인증서가 묶는 일곱 파일 중 `vault_lint_extensions.py`와 `vault_egress.py`가 바뀌어 `checker_sha256`가 v0.46.0~v0.54.1의 `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`에서 `ee421d6f8cc419f9d10017fe7fc3f52084dde4775e4a20ca5fe3271cb6691f98`로 이동한다(harmless corpus 해시 `38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a` 불변).

## 하위호환·업그레이드

현재 설치 ref는 `v0.55.0`이다.

기존 볼트 설정 파일은 자동으로 수정·마이그레이션하지 않는다. 공개 준비나 GitHub Release 게시는 활성 호스트 설치나 기존 볼트 사본을 자동으로 갱신하지 않는다. 볼트에 복사된 healthcheck와 helper bundle(`00-meta/scripts/`)은 설치 호스트에서 플러그인을 갱신한 뒤 `/vault-upgrade`(Codex는 `upgrade`)로 별도 갱신한다.

경고를 `fatal`로 승격하지 않은 볼트는 별도 인증서 절차가 필요 없다. **경고를 `fatal`로 승격한 볼트**는 v0.54.1 이하(또는 v0.55.0에서 이전 버전으로 되돌릴 때)와 전환하기 전에 아래 순서를 따른다.

1. 볼트 설정 `warning_policy.levels`에서 `fatal`로 올린 항목을 `warning`으로 되돌린다.
2. 볼트를 검사하는 모든 엔진 사본(Claude Code, Codex, 그리고 git 볼트의 `00-meta/scripts/`)을 같은 버전 바이트로 맞춘다.
3. 바꾼 설치본에서 `vault_warning_policy.py --certificate`를 실행해 새 인증서(`checker_sha256` = `ee421d6f8cc419f9d10017fe7fc3f52084dde4775e4a20ca5fe3271cb6691f98`, `false_positives: 0`)를 발급받아 설정에 반영한다.
4. 필요한 항목을 다시 `fatal`로 올린다(`checked-at-stale`·`review-by-passed`는 날짜 의존 경고라 승격 불가, `alias-collision`·`egress-url-secret`은 승격 가능).

healthcheck만 `engine=0.55.0`으로 이동하며 기존 규칙 6종·어댑터 스탬프는 유지한다.

## 알려진 경계

- `vault_cloud_sync.py`는 경로 조각과 OneDrive 환경 변수 휴리스틱 기반의 읽기 전용 안내이며, OS 동기화 데몬 API를 조회하거나 동기화를 기술적으로 차단하는 보안 샌드박스가 아니다. 사용자 지정 이름의 동기화 폴더는 감지하지 못할 수 있다.
- `egress-url-secret`은 고정 키 집합과 4자 이상 값 기준의 최선(best-effort) 패턴 경고이며 모든 벤더 전용 쿼리 토큰을 망라하지 않는다.
- `checked-at-stale`과 `review-by-passed`는 실행 시점의 로컬 달력 날짜에 의존하므로 경고 승격 인증서(`PROMOTABLE_CODES`) 대상에서 의도적으로 제외했다.
- `alias-collision`은 프런트매터 `aliases:`의 정준 NFC·casefold 정확 일치만 검사하며 자연어 유의어·의미 중복을 추론하지 않는다.
- Antigravity CLI 생성 패키지는 `build_antigravity_package.py check` 및 패키지 검증으로 확인하며, 실제 `agy` 대화 세션은 에이전트가 감싸 실행하지 않는다.
