# v0.49.0 — 요구 출처·단계별 검증·개선 반복 관찰

사용자 요청·확인 답변·저장소 사실·호스트 기본값을 분리하는 작업 명세, 기존 실행 근거에 연결한
단계별 검토, 고정 명세의 개선 반복 관찰을 선택형 표준 라이브러리 도구로 추가한다.
기준은 공개 v0.48.0 커밋 `8c4b176c9f594ad5c47ea9c12fd561d0432e822f`다.

## 변경

1. [작업 명세](../task-contracts.md): `vault_task_contracts.py`의 capture / inspect / revise.
   각 항목의 정확한 원문 출처와 선언된 origin/status, 미확정 질문, 수락된 완료 조건을 기록한다.
   저장소 사실과 호스트 가정은 확인된 사용자 요구로 자동 승격하지 않는다. 명세 개정은 새 불변
   영수증으로 남고 이전 버전을 사용하는 검토는 현재 결과로 재사용하지 못한다.
2. [단계별 검증](../staged-evaluation.md): `vault_staged_evaluation.py evaluate`.
   기존 `vault_evidence`·`vault_coverage`를 재사용하며 계약의 완료 조건과 기계 검사·의미 검토·독립 검토를 연결한다.
   실패·미실행·건너뜀·근거 없음을 구분하고 모델의 찬성만으로 검사 실패나 근거 누락을 통과로 바꾸지 않는다.
3. [개선 반복 관찰](../improvement-cycles.md): `vault_improvement_cycles.py audit`.
   명시된 순서의 보고서를 다시 계산하고 같은 명세·완료 조건의 결과를 비교한다. 성공·회귀·반복 실패·진동·
   세대 한도·관측 비용 한도 소진을 구분한다. 첫 관측이나 마지막 허용 관측에서도 성공할 수 있다.
4. 공용 스킬·Codex 연결 문서·문서 색인·배포 자원 확인 목록에 새 도구를 연결한다.
   Antigravity CLI 생성 패키지는 원본에서 다시 만들고 사본 일치를 검사한다.

## 기본 결과 변경

- 기존 엔진 명령과 설정 스키마의 판정 경로는 바꾸지 않는다. 새 capture/revise 쓰기와 읽기 전용
  inspect/evaluate/audit는 사용자가 해당 명령을 명시적으로 선택할 때만 수행한다.
- 공용 스킬과 Codex 참고 문서에 새 도구 설명이 들어가므로 호스트가 읽는 안내 문구는 갱신된다.
  단순하거나 이미 확정된 작업에 새 인터뷰나 대기 단계를 강제하지 않는다.
- 현재 버전·설치 태그·healthcheck 식별은 0.49.0으로 이동한다. healthcheck의 버전 안내 출력은 바뀐다.
- 새 엔진 도우미와 문서가 패키지/설치 확인 목록에 추가된다. 기존 볼트의 엔진 사본은 upgrade 전까지 그대로다.
- 규칙·어댑터·권한 템플릿·기본 훅 정의·기본 네트워크/모델 호출 설정은 바꾸지 않는다.

## 하위호환·업그레이드

현재 설치 ref는 `v0.49.0`이다. 기존 설정 키는 추가하거나 마이그레이션하지 않는다.
새 작업 명세와 단계별 보고서의 스키마는 명시적 입력에만 적용한다. 활성 설치와 회사 볼트는 이 릴리스로 갱신하지 않는다.

인증서가 묶는 일곱 파일은 v0.48.0과 같아 v0.46.0 이후 인증서는 실제 바이트가 같은 경우 계속 유효하다.
v0.45.1 이하와 오갈 때는 [v0.46.0 업그레이드 안내](v0.46.0.md#하위호환업그레이드)를 따른다.
healthcheck만 `engine=0.49.0`으로 이동하며 기존 규칙·어댑터 스탬프는 유지한다.

## 검증

[검증 계약](../verification/v0.49.0.md)에 요구 관문을 적었다. 실제 최종 소스의 시험 수·종료 코드·건너뜀·CI·
독립 검토·ZIP 재빌드·설치 자원 바이트·인증서 결과는 릴리스의 `verification.json`에 기록한다.
게시 후 새 다운로드와 릴리스 증명 확인은 별도 기록으로 남긴다. 계약 문서 자체는 통과 결과가 아니다.

체크아웃에서 `python scripts/evaluate_task_workflows.py`로 일곱 합성 통제를 재생한다. 이는 외부 벤치마크가 아니다.

새 합성 시험은 확인되지 않은 가정의 수락, 미해결 질문, 개정된 명세의 이전 검토 재사용,
실패/미실행을 모델 찬성으로 통과시키는 경우, 필수 완료 조건 누락, 정체·회귀·소진을 성공으로
오인하는 경우, 낡거나 위험한 출처·경로·입력 한도를 다룬다. 실제 모델이나 회사 자료로 성능을 측정하지 않았다.

상류는 [MIT](https://github.com/Q00/ouroboros/blob/54dad8e1dd93aee31858bde72493cd7a0f938739/LICENSE)다.
모호성 수치 0.2와 온톨로지 유사도 0.95를 정확도 보증이나 이 플러그인의 기본 문턱으로 가져오지 않는다.

## 알려진 경계

- origin·confirmed·검사 실행 표시는 호출자의 선언이다. 정확한 원문과 해시는 바이트 연결/현재성을 확인하며
  사용자 신원·실제 승인·내용의 진실·독립 실행을 인증하지 않는다.
- `ready_for_execution_review`는 실행이나 배포의 허가가 아니다. 모델 검토는 의미상 이견/보류의 자료이며
  단독으로 실행 근거를 만들 수 없다. 기존 evidence에서 말하는 current 역시 의미상 정답을 뜻하지 않는다.
- 반복 관찰기는 자동 실행·명령 실행·모델 호출·외부 지출 상한 강제·자동 승격·게시를 하지 않는다.
  보고하지 않은 비용/관측은 발견하지 못하며 미확인 비용을 0으로 취급하지 않는다.
- 실제 업무 오류율·비용 절감·자동 자기 개선 성능을 측정하지 않았다. 원문 명세와 검사가 충분한지에 대한
  판단은 호출자와 검토자의 책임이며, 합성 기능 시험은 실업무 효과의 증명이 아니다.
- 생성 Antigravity CLI 패키지의 사본 일치는 검사하지만 실제 agy 대화 세션은 실행하지 않는다.
