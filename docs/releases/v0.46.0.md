# v0.46.0 — 금지 구역 정규화와 검사 빈틈 보강

v0.45.1에 대한 외부 검토가 찾은 결함 일곱 가지를 고친다. 금지 구역(deny zone)이
같은 폴더 이름의 다른 유니코드 정규화 표기를 놓치던 문제, 프런트매터의 따옴표 없는
위키링크 검사가 놓치거나 잘못 보고하던 꼴, 설정 키·노트 경로·`--vault` 경로의 오류를
조용히 넘기던 곳, 템플릿으로 만든 볼트에 나던 거짓 경고, 검사를 다 하지 못했는데도
통과로 보이던 집사 보고다. 새 옵션 없이도 결과가 바뀌는 곳이 있으므로 아래
`기본 결과 변경`을 먼저 보고, 경고를 `fatal`로 올린 볼트는 갱신 전에
`하위호환·업그레이드`의 순서를 따른다.

## 변경

- [금지 구역 비교](../../SECURITY.md)와 [deny zone 가드](../../assets/adapters/deny-guard/guide.md):
  금지 구역과 `exclude_dirs`를 견주는 판정이 경로 단계마다 같은 접기 함수 `fold_path_part`를
  쓴다. 두 이름은 유니코드 정준 대소문자 무시 비교(canonical caseless matching: NFD, casefold,
  NFD)로 같을 때 같은 이름이고, 비교용 결과는 NFC로 낸다. ASCII 이름은 예전처럼 casefold만
  한다. healthcheck, `vault_paths`로 경로를 푸는 도구(recall·세션 시작·doctor·Telegram 브리지 등),
  lint 경고 확장, 선택형 deny zone 가드(Bash·PowerShell 명령과 와일드카드 경로에서 구역 이름을
  찾는 단계 포함)가 모두 이 비교를 쓴다. 설정 파일의 문자열은 고쳐 쓰지 않는다.
- [프런트매터의 따옴표 없는 위키링크](../../commands/vault-lint.md): 줄 단위 정규식 대신
  작은 반복형 스캐너가 YAML이 중첩 목록으로 읽는 꼴을 찾는다. 커밋 게이트(`--staged`)와 full
  검사가 같은 스캐너를 쓰며, 메시지·개수 방식·종료 코드는 그대로다. 표준 라이브러리만 쓰고
  입력 길이에 선형이며 재귀하지 않는다.
- [알 수 없는 최상위 설정 키](../reliability.md): `deny_zone` 같은 오타는 적용되지 않는데도
  조용히 넘어갔다. 이제 health 리포트 §0과 doctor `config_warnings`가 키 이름과 가장 가까운
  알려진 키를 알리고, healthcheck 콘솔 줄은 그 건수를 알린다. 값은 보이지 않고, 키 이름의 제어·줄
  바꿈·방향 제어 문자는 escape해 적는다. 경고일 뿐 종료 코드는 그대로다.
- [`hot_note`·`handoff_note`의 `.md` 요건](../../commands/vault-upgrade.md): 두 키가 `.env` 같은
  임의 파일을 가리키면 SessionStart가 그 내용을 주입할 수 있었다. 이제 비어 있거나 확장자가
  `.md`(대소문자 무관)인 노트만 받고, 다른 값은 설정 오류로 막는다. 메시지는 키 이름만 적는다.
- [`--vault` 경로 오류와 `--require-vault`](../reliability.md): 명령줄에서 준 `--vault` 경로가
  없거나 파일이면 healthcheck와 doctor가 종료 코드 0으로 끝날 수 있었다(아래 9번). 이제 종료
  코드 2로 끝난다.
  새 `--require-vault`는 설정이 없는 폴더도 2로 끝낸다.
- [템플릿의 기준 커밋 자리표시자](../../README.md): 템플릿 그대로의 handoff
  기준 커밋 `(없음)`이 "session-end 계약 위반"으로 보고됐다. 이제 자리표시자를 받아들이고,
  git 볼트에서 볼트 폴더를 바꾼 커밋이 `anchor_drift_threshold`개 이상 쌓였을 때만 알린다.
- [집사 보고와 healthcheck 요약](../../commands/vault-jarvis-setup.md): Telegram 집사는 종료
  코드만 보고 `치명 없음 ✅`를 보냈다. healthcheck에 선택형 `--json-summary`(한 줄 JSON, 개수만
  담고 경로·노트 이름·값은 담지 않는다)를 더했고, 브리지는 이 요약을 읽어 완전하고 깨끗한 검사에만
  ✅를 붙인다.
- Codex 설치 확인(`scripts/verify_codex_plugin.py`)이 `vault_paths.py`·`vault_healthcheck.py`·
  `jarvis_bridge.py`도 설치본과 바이트로 대조한다. 대조하는 리소스는 126개에서 129개가 된다.

## 기본 결과 변경

다음 결함 수정은 새 옵션 없이 결과를 바꾼다. 볼트에 설치된 healthcheck와 deny zone 가드
사본은 `/vault-upgrade`(Codex `upgrade`)로 갱신하기 전까지 옛 동작이며, 그 사이에는 커밋
게이트와 세션 시작 검사의 판정이 다를 수 있다.

1. 금지 구역은 이제 대소문자뿐 아니라 유니코드 정규화 형식도 무시하고 맞춘다(유니코드
   정준 대소문자 무시 비교). healthcheck full 모드, recall, 세션 시작, doctor, Telegram 브리지,
   lint 경고 확장, deny zone 가드(Bash·PowerShell 명령과 와일드카드 경로에서 찾는 구역 이름
   포함), 그리고 `vault_paths`로 노트 경로를 푸는 모든 도구(`jarvis_bridge`, `vault_commit`,
   `vault_connectors`, `vault_context_guard`, `vault_doctor`, `vault_egress`, `vault_evidence`,
   `vault_instruction_budget`, `vault_lesson_metrics`, `vault_links`, `vault_memory`,
   `vault_plugin_scope`, `vault_proposals`, `vault_provenance`, `vault_query_expansion`,
   `vault_recall`, `vault_retrieval`, `vault_revocation`, `vault_runs`, `vault_ssot`,
   `vault_state`, `vault_worktrees`, `session_start`)에 적용된다. 예를 들어 커밋 도우미는 그런
   경로를 `denied_path`로 거부하고, SSOT 도우미는 그런 노트를 더 이상 읽지 않는다. macOS 볼륨과
   거기서 복사한 자료처럼 분해형(NFD)으로 저장된 폴더 이름은 이제 조합형(NFC)으로 적은 구역
   안에 들고, 반대도 그렇다. 기본 구역 다섯 개를 포함해 ASCII 이름의 구역은 예전과 같다. 그런
   폴더의 노트는 healthcheck 대상, recall 결과, 세션 문맥에서 빠진다.
2. `exclude_dirs` 항목도 공유 비교기가 견주는 곳(recall, 브리지의 노트 경로, `vault_paths`를
   쓰는 도구)에서는 같은 방식으로 접힌다. healthcheck 자체의 폴더 순회와 백업은 지금의 정확
   일치를 유지한다.
3. 이름이 정규화 형식만 다른 두 형제 폴더는 이제 한쪽을 적은 구역에 둘 다 든다.
4. 그런 폴더 안을 가리키는 설정 노트(`hot_note`, `handoff_note`, `index_note`, `log_note`,
   `ssot_note`, `health_report`, `rules_dir`)는 이제 설정 오류다. healthcheck 종료 코드 1, 세션
   주입 없음, doctor `invalid_config`(종료 코드 2), recall `invalid_config`이다. 설정을 검증하는
   다른 도구(커밋 도우미, evidence, memory, proposals, revocation과 그 밖의 `validate_config`
   호출자, 설정 바인딩을 거치는 브리지의 Q&A·브리핑)도 멈추고, 볼트의 검사기 사본을 갱신하면
   커밋 게이트가 커밋을 거부한다.
5. 프런트매터 검사는 이제 흐름 목록 안의 따옴표 없는 위키링크(`related: ["[[A]]", [[B]]]`,
   `related: [ [[B]] ]`), 영문자·숫자·`_` 밖의 글자가 든 키 뒤(`see-also: [[B]]`, 따옴표로 감싼
   키), 키 다음 줄, 중첩 목록 항목, 앵커·태그 뒤, 흐름 키로 쓴 링크, 값 맨 앞의 Obsidian 임베드
   (`cover: ![[img.png]]`), 주석으로 끝난 평문 값 다음 줄의 링크도 보고한다. 그런 노트가 있으면
   full 검사가 종료 코드 1로 끝나고(SessionStart 백그라운드 검사도 그렇다. 그래서
   `--session-evidence`는 `observed_error`를 보고한다), 제안(proposals)은 거부되며, 볼트의 검사기
   사본을 갱신하면 그 노트를 스테이징한 커밋도 거부된다.
6. YAML 자체가 블록 스칼라(`|`, `>`)의 내용, 따옴표 문자열(여러 줄 포함), 평문 값의 이어지는
   줄로 두는 줄은 더 이상 보고하지 않는다. v0.45.1은 그 줄들을 한 줄씩 따로 읽었다. 그 밖에
   v0.45.1이 보고한 줄은 프런트매터가 올바른 YAML이 아닐 때(닫히지 않은 따옴표 뒤, `...` 줄 뒤,
   블록 스칼라 내용보다 덜 들여 쓴 줄, 평문 값을 시작할 수 없는 글자로 시작한 값 뒤 등)도 모두
   계속 보고한다.
7. `00-meta/vault-config.json`의 알 수 없는 최상위 키는 이제 health 리포트 §0에 한 줄씩(가장
   가까운 알려진 키가 있으면 함께), healthcheck 콘솔 줄에 알림으로(SessionStart 백그라운드 검사
   줄도 마찬가지), doctor에 `config_warnings` 필드로 나온다. 종료 코드, 커밋 게이트, SessionStart
   주입(`session_start.py`)과 recall은 그대로다. `deny_zone`을 `deny_zones`로 고칠 때는
   `deny_zones`가 기본 구역 다섯 개를 대체한다는 점을 기억하고 그 다섯 개도 함께 적는다.
8. `hot_note`·`handoff_note`는 비어 있거나 확장자가 `.md`(대소문자 무관)인 노트를 가리켜야 한다.
   다른 값은 이제 설정 오류다. healthcheck 종료 코드 1, 두 노트 모두 주입 없음, doctor
   `invalid_config`(종료 코드 2), recall `invalid_config`이고, 설정을 검증하는 다른 도구도 4번처럼
   멈추며, 볼트의 검사기 사본을 갱신하면 커밋 게이트가 커밋을 거부한다.
9. 명령줄에서 준 `--vault` 경로가 없거나 파일이면 healthcheck는 이제 종료 코드 2로 끝난다(전에는
   full 모드에서 없는 경로는 종료 코드 0과 `볼트 아님`, 파일은 Windows에서 0과 `볼트 아님`,
   POSIX에서 1이었고, `--staged`에서는 1이었다). doctor는 종료 코드 2와 `invalid_vault`
   (`vault_path_not_found`)를 낸다(전에는 종료 코드 0과 `not_vault`). `00-meta/vault-config.json`
   없이 존재하는 폴더와 `--vault` 없는 실행(SessionStart 훅 등)은 여전히 0으로 끝나며, 새
   `--require-vault`를 주면 그 경우도 2로 끝난다.
10. 기준 커밋(anchor) 줄이 아직 템플릿 값 `(없음)`인 handoff는 더 이상 "handoff에 기준
    커밋(anchor) 줄이 없음 — session-end 계약 위반"을 받지 않는다. git이 없으면 §12가 검사를
    건너뛰었다고 적고, git 볼트에서는 아직 session-end 기록이 없다고 적으며, 볼트 폴더를 바꾼
    커밋이 `anchor_drift_threshold`개에 이르러야 콘솔 경고("session-end 기록 없음")를 낸다.
    기준 커밋 줄 자체가 없는 handoff는 예전처럼 보고하고, 자리표시자 줄과 함께 16진수 기준 커밋
    줄도 있는 handoff는 예전처럼 그 16진수 줄로 계산한다.
11. 명령줄: healthcheck의 `--help`와 usage 줄에 `--require-vault`·`--json-summary`가, doctor의
    것에 `--require-vault`가 나온다. 사용 오류였던 새 옵션의 접두어(`--r`, `--re`, `--j` 등)는
    이제 그 옵션을 고른다. 전에 통하던 약어는 모두 뜻이 그대로다.
12. Telegram 집사는 완전하고 깨끗한 검사에만 `치명 없음 ✅`를 보인다. 치명 건수를 밝히고, 읽지
    못한 노트가 있거나 링크·정션을 건너뛰었으면 그 수와 함께 `일부 미검사`라고 적는다(연결 작업
    트리 사본과 근거 바이트 예산으로 빠진 노트는 세지 않는다). 근거 바이트 예산 때문에 경고 확장
    분석이 일부 생략됐으면 그 사실과 건수를 덧붙이고, 경고를 `fatal`로 올린 볼트에서는 그때 ✅
    대신 ⚠️를 쓴다. 설정·경로 오류는 치명 발견이 아니라 오류로 보고하고, 검사기가 요약을 내지
    않으면 결과를 확인할 수 없다고 적는다. 볼트 폴더가 사라졌으면 예전처럼 `실행 실패`다. 이전
    플러그인 폴더에서 시작한 브리지는 새 폴더에서 다시 시작할 때까지 옛 문구를 쓴다.
13. `checker_sha256`가 바뀌므로, 경고를 `fatal`로 올린 볼트는 v0.45.1 이하에서 만든 인증서로는
    새 엔진에서 멈춘다(아래 `하위호환·업그레이드`).
14. 참고: `scripts/evaluate_retrieval_backends.py`가 싣는 `vault_paths.py`·`vault_healthcheck.py`의
    `code_sha256` 값이 바뀐다.

바뀌지 않는 것도 적어 둔다. `--json-summary`를 주지 않으면 healthcheck의 콘솔 줄과 리포트
§14는 근거 바이트 예산 때문에 건너뛴 파일을 여전히 읽기 실패로 적고 이슈 합계에 센다. 이번
릴리스는 기본 출력을 일부러 바이트 단위로 유지한다. 커밋 게이트(`--staged`)는 구역의 다른 표기로
스테이징한 노트를 대소문자 변형과 마찬가지로 계속 검사한다(아래 `알려진 경계`).

## 하위호환·업그레이드

금지 구역 비교를 바꾸면서 경고 승격 인증서의 `checker_sha256`는 v0.34.0부터 v0.45.1까지의
`be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`에서 `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`로 바뀐다. 일곱 bound 파일 가운데 바뀐 것은 `vault_paths.py`와 `vault_lint_extensions.py`이고 harmless corpus는 같다. 인증서는 버전 이름이 아니라 실제 바이트를 묶는다.

Claude Code와 Codex의 플러그인 설치본, 그리고 git 볼트에서 pre-commit 훅이 실행하는 볼트 안 엔진 사본(`00-meta/scripts/`)이 그 대상이다. 그래서 경고를 `fatal`로 올린 볼트는 갱신 전에 다음 순서를 따른다. 이전 버전으로 되돌릴 때도 같은 순서다.

1. 볼트 설정 `warning_policy.levels`에서 `fatal`로 올린 단계를 `warning`으로 되돌린다.
2. 볼트를 읽는 엔진을 모두 같은 버전(되돌릴 때는 이전 버전)으로 바꾼다. Claude Code와 Codex 설치본을 함께 바꾸고, git 볼트의 엔진 사본은 갱신할 때 `/vault-upgrade`(Codex `upgrade`)로 바꾼다. `/vault-upgrade`는 사본을 이전 버전으로 내리지 않으므로, 되돌릴 때는 그 사본도 이전 버전의 파일로 직접 되돌린다.
3. 바꾼 설치본에서 `vault_warning_policy.py --certificate`로 인증서를 다시 만들어 볼트 설정의 `warning_policy.certificate`에 넣는다.
4. 단계를 다시 `fatal`로 올린다.

3단계의 명령은 harmless replay를 실행하므로 실행 결과와 설치 바이트를 확인한다. 버전이 섞인
동안에는 한 인증서가 모든 사본에 맞지 않으므로 승격을 끈 채로 둔다. 맞지 않는 인증서를 유지하면
healthcheck는 종료 코드 1로 멈추고 SessionStart는 주입하지 않으며 `--staged`는 커밋을 막는다.
doctor·recall은 `invalid_config`, `check-support`를 포함한 SSOT 명령(`vault_ssot.py`)은
`ssot_operation_unavailable`로 멈춘다. 경고를 승격하지 않은 볼트는 이 순서가 필요 없다.

healthcheck 스탬프와 `ENGINE_VERSION`, deny zone 가드(`deny-guard.py`)와 PowerShell 구문
분석기(`ps-parse.ps1`)의 스탬프는 `engine=0.46.0`이다. 규칙 6종, Aside 도우미, 교훈 단서 훅,
git 훅은 내용이 같아 기존 스탬프를 유지한다. 볼트에 설치된 healthcheck·도우미 사본
(`00-meta/scripts/`)과 deny zone 가드 사본은 `/vault-upgrade`(Codex `upgrade`)로 갱신하기
전까지 옛 동작이며, 가드 스탬프가 올라갔으므로 `/vault-upgrade`가 가드 갱신을 제안한다. 예약
실행 중인 Jarvis 브리지는 등록한 폴더의 코드를 계속 쓰므로, 새 집사 문구를 보려면 새 플러그인
폴더에서 브리지를 다시 시작한다.

## 참고와 기존 활용의 차이

| 자료 | 고정 근거와 이번 활용 | 기존 활용과의 관계 |
|---|---|---|
| [The Unicode Standard, Version 18.0.0, Core Specification, Chapter 3 "Conformance"](https://www.unicode.org/versions/Unicode18.0.0/core-spec/chapter-3/) | "Default Caseless Matching" 절의 정의 D145: X와 Y는 `NFD(toCasefold(NFD(X))) = NFD(toCasefold(NFD(Y)))`일 때 정준 대소문자 무시 일치다. 금지 구역 접기(`fold_path_part`)의 정의로 쓴다. 코드는 실행 중인 Python의 유니코드 자료로 이 정의를 적용하므로(예: Python 3.12는 Unicode 15.0.0), 인용한 판은 정의의 문안을 가리키며 문자 자료의 판이 아니다 | 공개 Reference Atlas 카탈로그에 아직 없으며 이번 릴리스에서 추가한다. 기존 비교(`check-support`의 값 비교, 유출 검사 등)는 노트 본문을 NFKC·casefold로 견준다. 경로 이름에는 호환 분해(NFKC)를 쓰지 않는다. 파일 시스템은 호환 문자를 다른 이름으로 다루기 때문이다 |
| [Unicode Standard Annex #15, "Unicode Normalization Forms", Revision 58 (Unicode 18.0.0, 2026-08-12)](https://www.unicode.org/reports/tr15/tr15-58.html) | 접기가 쓰는 정규화 형식 NFD와 NFC의 정의. 비교용 결과를 NFC로 내며, NFC는 NFD 문자열에서 일대일이라 접은 결과가 같다는 것은 정준 대소문자 무시 일치와 같다 | 공개 Reference Atlas 카탈로그에 아직 없으며 이번 릴리스에서 추가한다. 이전에 쓴 NFKC(호환 정규화)와 달리 정준 정규화만 쓴다 |
| [YAML Ain't Markup Language (YAML) version 1.2, Revision 1.2.2 (2021-10-01)](https://yaml.org/spec/1.2.2/) | YAML 리더가 중첩 목록으로 읽는 프런트매터 꼴(흐름 시퀀스, 블록 스칼라, 따옴표 스칼라)을 정하는 근거. 검사는 이 프로젝트용으로 쓴 작은 줄 스캐너이며 YAML 파서가 아니다 | 공개 Reference Atlas 카탈로그에 아직 없으며 이번 릴리스에서 추가한다. 이전의 프런트매터 검사는 줄 하나에 정규식 하나를 맞췄고 YAML 문맥을 보지 않았다 |

개발 중에는 PyYAML과 ruamel.yaml을 오프라인 비교용 파서로만 썼다. 둘 다 배포하지 않고 CI에서도
실행하지 않으며, 그 일치 수치는 릴리스 근거가 아니다. 저장소의 fixture와 템플릿에는 새로 보고되는
꼴의 프런트매터 줄이 없다.

## 검증

[검증 계약](../verification/v0.46.0.md)에 따라 최종 소스의 전체 로컬 시험, v0.45.1과 오가는
인증서 전환의 양방향 시험, 새 옵션 없이 v0.45.1과 출력을 비교해 모든 차이를 위 `기본 결과 변경`의
항목에 대응시키는 대조, 독립 검토, CI, 격리한 Codex 설치의 바이트 대조, 인증서, 재빌드와 자산을
따로 확인한다. 실제 결과는 공개 `verification.json`에 기록하고 게시 후 확인은 별도 기록으로
보관한다. 과거 릴리스의 성공 수치를 이번 버전의 결과로 옮기지 않는다.

## 알려진 경계

- 커밋 게이트(`--staged`)의 Git 경로 지정은 바이트 단위라, 구역의 다른 정규화 표기로 스테이징한
  노트를 대소문자 변형과 마찬가지로 계속 검사한다. 이 점에서 full 검사보다 엄격하며 의도한
  동작이다.
- 볼트 폴더 자체의 이름은 정규화하지 않는다. ASCII가 아닌 볼트 폴더 이름을 도구마다 다른 표기로
  넘기는 환경(macOS 등)에서는 deny zone 가드의 볼트 경로 비교와 연결 작업 트리 규칙의 볼트 접두어
  비교가 어긋날 수 있다.
- healthcheck 자체의 폴더 순회와 백업의 `exclude_dirs`는 정확 일치 그대로다.
- 볼트에 설치된 healthcheck·도우미·deny zone 가드 사본과, 이전 플러그인 폴더에서 시작한 Jarvis
  브리지는 갱신하거나 다시 시작하기 전까지 옛 동작이다.
- 프런트매터 판정은 YAML 1.2.2의 구조를 기준으로 한 줄 스캐너의 판정이다. Obsidian·Dataview의
  파서 동작은 시험하지 않았다. 프런트매터 끝이나 `...` 줄까지 닫히지 않은 따옴표나 흐름 자체는
  새 발견으로 보고하지 않으며, 그 사이의 줄은 v0.45.1 규칙으로 계속 검사한다.
- `.md` 요건은 `hot_note`·`handoff_note`에만 적용한다(`log_note`·`tasks_note`·`constraints_note`는
  아니다). 기준 커밋은 여전히 16진수 40자까지만 받는다. 알 수 없는 `jarvis` 하위 키와 staged
  모드의 설정 키는 경고하지 않는다.
- 자리표시자 기준 커밋 알림은 볼트 폴더를 바꾼 커밋만 센다. 이력 안에서 볼트 폴더를 옮기거나
  이름을 바꿨으면 더 적게 세어 알림이 늦게 나올 수 있다. 16진수 기준 커밋의 드리프트 계산은
  예전처럼 저장소 전체를 센다.
- `--json-summary` 없이는 콘솔 줄과 리포트 §14가 근거 바이트 예산 생략을 읽기 실패로 적는다(위).
- 종료 코드 2는 argparse 사용 오류와도 겹친다. 사용 오류는 요약 JSON을 내지 않으므로, 브리지는
  요약의 유무와 `status`로 둘을 구분한다.

세 매니페스트와 healthcheck 식별은 `0.46.0`, Codex 고정 설치 ref는 `--ref v0.46.0`이다.
현재 설치 ref는 `v0.46.0`이다. healthcheck·deny zone 가드·PowerShell 구문 분석기는
`engine=0.46.0`이고 규칙·도우미 스탬프는 유지한다. Python 3.10+ 표준 라이브러리 런타임과 기본
훅 정의·설정 템플릿의 바이트를 유지하며, 모델·네트워크 호출이나 런타임 의존성을 더하지 않는다.
공개는 활성 설치 캐시나 볼트 사본의 갱신이 아니다.
