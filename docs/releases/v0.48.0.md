# v0.48.0 — Antigravity CLI 겸용 패키지

Google Antigravity CLI(`agy`)에서도 같은 볼트를 쓰도록, 저장소의 명령·스킬·훅·엔진 스크립트로 만든
Antigravity 전용 플러그인 패키지를 `antigravity/` 폴더에 더한다. 이 플러그인을 Antigravity CLI와 함께 쓰려면
무엇을 고쳐야 하는지 살핀 검토(agy 1.5.7 실측과 공식 문서 대조)의 변경 목록에서 여섯 항목을 다룬다. 세션 시작
훅의 Antigravity 모드, Stop 사건의 체크포인트, 패키지 생성기와 생성 패키지, 격리 설치 확인 도구, 호스트 중립
공용 문구, 문서와 판 표면이다. 저장소 루트는 지금처럼 Claude Code·Codex 플러그인이며 그 훅 정의와 매니페스트
구성은 바뀌지 않는다. 실제 agy 대화 세션은 실행하지 않았다(아래 `알려진 경계`). 새 옵션 없이도 결과가 바뀌는
곳이 있으므로 아래 `기본 결과 변경`을 먼저 본다.

## 변경

- [세션 시작 훅](../../hooks/session_start.py)에 `--host antigravity` 모드를 더한다(공용 도우미는
  [hooks/antigravity_hook.py](../../hooks/antigravity_hook.py)). 생성 패키지의 `hooks.json`만 이 플래그를 쓰며,
  표준 입력의 모양으로 모드를 짐작하지 않는다. 이 모드는 표준 입력의 JSON을 16 MiB까지 읽고, 입력의 `cwd`와
  `workspacePaths` 항목 가운데 `00-meta/vault-config.json`이 일반 파일로 있는 절대 경로가 정확히 하나일 때 그
  볼트를 쓴다. `CLAUDE_PROJECT_DIR`와 훅 프로세스의 현재 폴더는 쓰지 않는다. 볼트가 없거나 둘 이상이면 `{}`를
  내고, 둘 이상일 때는 경로 없는 한 줄을 표준 오류에 남긴다. 같은 사건의 처리기 셋 가운데 하나만 동작하도록
  시스템 임시 폴더에 대화 ID로 정한 표지 파일을 만들며, 표지는 120초 동안만 유효하다. 주입할 글은 기본 경로가 새
  세션(`startup`)에 쓰는 것과 같은 설정 검증·예산·9,500자 상한으로 만들어 `injectSteps`의 시스템 메시지
  하나(`metadata`의 `source`는 `agentic-vault`)로 낸다. 오류가 나면 고정 코드 한 줄과 `{}`를 내며 종료 코드는
  언제나 0이다. 도움말과 줄임 옵션 `--h`(아래 `기본 결과 변경` 5번)를 빼면 플래그 없는 기본 경로(`--host claude`)의
  출력과 표준 입력 처리는 v0.47.0과 같다.
- [체크포인트 훅](../../hooks/session_checkpoint.py)의 `--host antigravity` 모드는 Antigravity의 `Stop` 사건에서
  `fullyIdle`이 참이고 대화 ID(`conversationId`, 128자 이하)가 있을 때만, 같은 방식으로 찾은 볼트에 사건 이름
  `Stop`의 체크포인트를 남긴다. 같은 대화 ID와 실행 번호(`executionNum`)의 Stop이 120초 안에 다시 오면 쓰지
  않는다. 훅 입력의 `lastUserInput`·`transcriptPath`·작업 공간 경로는 저장하지 않고(노트의 볼트 기준 상대
  경로·크기·해시는 Claude Code 체크포인트처럼 남는다), 대화 ID는 해시로만 남기며, 언제나 `{}`를 내고 0으로
  끝난다. `vault_state.py`와 healthcheck가 `Stop` 사건을 `PreCompact`·`SessionEnd`와 함께 받는다.
- [패키지 생성기](../../scripts/build_antigravity_package.py)(`build`·`check`)가 저장소에서 Antigravity CLI 패키지
  `antigravity/`를 만들고, 만든 폴더를 커밋한다. `plugin.json`, Antigravity 형식의 `hooks.json`(SessionStart와
  Stop마다 `sh` 래퍼·`py -3`·`python` 처리기 셋), 스킬 17개(공용 스킬 둘과 명령 15개를 같은 이름으로 바꾼 스킬),
  엔진 스크립트·훅 파일 넷·`assets/`의 바이트 사본, 스킬이 가리키는 `docs/` 문서가 들어간다. 명령 스킬은
  `${CLAUDE_PLUGIN_ROOT}`·`$ARGUMENTS` 대신 `<PLUGIN_ROOT>`·`<ARGUMENTS>` 자리표시자와 그 뜻을 적은 머리말을 쓰고
  `disable-model-invocation: true`를 단다. agy 검사기는 24,000바이트를 넘는 스킬 본문에 경고하므로
  `agentic-vault`·`vault-init`·`vault-upgrade` 스킬의 일부 절을 패키지 안의 `references/` 파일로 옮기고, 본문이
  23,500바이트를 넘으면 생성이 실패한다. 저장소의 원본은 나누지 않는다. 패키지 안에 없는 대상으로 가는 링크는 같은
  태그의 GitHub 주소로 바꾼다. 생성은 결정적이며(정렬한 순회, LF, 시각 없음) `check`는 다시 만든 결과와 커밋한
  폴더의 차이를 하나씩 보이고 차이가 있으면 종료 코드 1로 끝난다. `.gitattributes`는 `antigravity/**`를 LF로
  고정한다.
- [격리 설치 확인 도구](../../scripts/verify_antigravity_plugin.py)는 패키지를 임시 폴더에 복사하고 가짜 홈
  폴더(`USERPROFILE`·`HOME`·`APPDATA`·`LOCALAPPDATA`·`TMP`·`TEMP`)에서 `agy --version`,
  `agy plugin validate --strict --json`(오류·경고 0), `agy plugin install`, `agy plugin list --json`(판, `source`가
  `antigravity`, 활성, 스킬 이름, 훅 묶음)을 실행한 뒤 설치본을 바이트로 대조하고 실제 `~/.gemini/config`가
  그대로인지 확인한다. 대화, `-p` 실행, 로그인은 하지 않는다.
- 공용 문구: [공용 스킬](../../skills/agentic-vault/SKILL.md)의 설명과 본문,
  [`/vault-session-start`](../../commands/vault-session-start.md), [`/vault-lint`](../../commands/vault-lint.md),
  [볼트 AGENTS.md 스텁](../../assets/templates/AGENTS-vault-stub.md)이 Antigravity CLI를 함께 적는다. 수동 세션
  시작 경로와 `/vault-lint`는 볼트 루트를 `--vault`로 넘긴다. 스킬에
  [Antigravity CLI 참고 문서](../../skills/agentic-vault/references/antigravity.md)(설치, 스킬 이름, 자리표시자,
  도구 대응, 훅, 하지 않는 것, 데이터, 확인하지 않은 것)를 더한다.
- 문서: 새 [Antigravity CLI 안내](../antigravity.md)(설치·갱신·직접 해 보는 확인·권한·데이터·약관 메모·한계),
  README, [SECURITY.md](../../SECURITY.md), 문서 색인, [hardening.md](../hardening.md#checkpoint-이후-바뀐-엔진-노트)의
  체크포인트 사건, codex.md, release-integrity.md, 저장소 [AGENTS.md](../../AGENTS.md)(매니페스트 넷과 생성 폴더
  규칙)와 판 표면을 고친다.

## 기본 결과 변경

플러그인을 갱신하면 명령·스킬·훅 코드는 바로 바뀐다. 볼트에 설치된 사본(규칙·healthcheck·생성 AGENTS.md)은
/vault-upgrade(Codex는 upgrade)를 실행하기 전까지 예전대로다.

1. 공용 스킬 `agentic-vault`의 설명(호스트가 스킬을 고를 때 읽는 문구)에서 ` with Claude Code or Codex,`가
   ` with Claude Code, Codex or Antigravity CLI,`로 바뀐다. 본문에는 Antigravity CLI 갈래 줄, 상시 규칙 괄호의
   `Codex·Antigravity CLI의 AGENTS.md`, 명령 표기 문단 끝의 스킬 이름 안내, 훅 출력 상한 괄호의 `injectSteps`
   문장, 참고 목록의 `references/antigravity.md` 줄이 더해진다. 대상: Claude Code와 Codex의 모든 사용자.
2. 볼트 AGENTS.md 스텁의 첫 줄 재생성 안내가 Codex와 Antigravity CLI의 재생성 방법을 함께 적고, "Codex는
   CLAUDE.md를"은 "Codex와 Antigravity CLI는 CLAUDE.md를"로, "Codex 표시 상한에 따른 생략"은 "호스트 표시 상한에
   따른 생략"으로 바뀌며, Codex 줄 뒤에 Antigravity CLI 줄이 더해진다. 새 볼트의 AGENTS.md와,
   `/vault-upgrade`(Codex `upgrade`)가 `agentic-vault:generated` 표지가 있는 AGENTS.md를 다시 만들 때 반영된다.
   표지가 없는 AGENTS.md는 바뀌지 않는다. `/vault-recall`은 AGENTS.md도 읽으므로 그런 볼트에서는 결과의
   `diagnostics.bytes_read`가 달라진 바이트 수만큼 바뀐다. 대상: 새 볼트, 생성 AGENTS.md가 있는 볼트를 업그레이드하는 사용자.
3. `/vault-session-start`는 주입이 없을 때 `session_start.py`에 볼트 루트를 `--vault`로 넘겨 실행하라고 하고,
   `CLAUDE_PROJECT_DIR`을 현재 볼트 루트로 보라는 괄호를 뺀다. 대상: 세션 시작 주입이 없던 세션의 모든 사용자.
4. `/vault-lint`(Codex `lint`)는 건강 검사기에 볼트 루트를 `--vault`로 넘기고, 생략하면 스크립트가
   `CLAUDE_PROJECT_DIR`(Claude Code), 없으면 현재 폴더를 쓴다고 적는다. 넘긴 경로가 없거나 폴더가 아니면 검사기는
   종료 코드 2로 끝난다(v0.46.0부터의 동작). 대상: `/vault-lint`를 쓰는 모든 사용자.
5. 두 훅의 `--help`(usage 줄과 옵션 목록)에 `--host {claude,antigravity}`가 보인다. `--help`를 `--h`로 줄여
   쓰면 이제 `--help`·`--host` 둘에 맞아 인자 오류(종료 코드 2)로 끝난다(v0.47.0은 도움말을 냈다). 줄임 옵션
   `--h`를 빼면, `--host`를 주지 않은 실행에서 바뀌는 것은 도움말과 아래 6번의 `Stop`뿐이고 그 밖의 출력과
   표준 입력 처리는 그대로다. 대상: 훅을 직접 실행하거나 도움말을 읽는 사람.
6. `session_checkpoint.py`의 `--event`가 `Stop`도 받는다(도움말의 `--event` 선택지와 설명 문장에도 `Stop`이
   보인다). v0.47.0은 `--event Stop`을 인자 오류(종료 코드 2)로 거부했다. `--event` 없이 표준 입력으로 온 `Stop`은
   v0.47.0처럼 거부하고 기록하지 않는다. `vault_state.py`가 `Stop` 사건의 체크포인트를 쓰고 읽으며, healthcheck의
   선택형 `checkpoint_drift_check`는 마지막 사건이 `Stop`인 체크포인트도 비교 대상으로 삼고 그 경고의 `details`에
   사건 이름 `Stop`이 나올 수 있다. v0.47.0은 그런 기록을 형식이 맞지 않는 것으로 보고 건너뛰었다. Stop
   체크포인트는 `--host antigravity`(Antigravity 패키지의 훅)나 `--event Stop`을 준 실행에서만 생기므로, 그런
   기록이 없는 볼트의 healthcheck 결과는 그대로다. 보강 helper bundle을 설치한 git 볼트에서는
   `/vault-upgrade`(Codex `upgrade`)가 `00-meta/scripts/`의 `vault_state.py`·`vault_healthcheck.py`를 플러그인
   원본과 다르다(`differs`)고 보고하고 교체를 제안한다. 대상: 훅을 직접 실행하는 사람, `checkpoint_drift_check`를
   켜고 Antigravity CLI로도 쓰는 볼트, helper bundle을 설치한 git 볼트.
7. 새 파일 `hooks/antigravity_hook.py`, `scripts/build_antigravity_package.py`,
   `scripts/verify_antigravity_plugin.py`, `skills/agentic-vault/references/antigravity.md`, `docs/antigravity.md`와
   생성 폴더 `antigravity/`가 저장소와 Claude Code·Codex 설치본의 플러그인 폴더에 생긴다. Claude Code와 Codex가
   읽는 매니페스트와 훅 정의는 바뀌지 않는다. 대상: 모든 사용자(설치 폴더의 파일 목록과 크기).
8. 릴리스 ZIP(태그의 `git archive`)에 생성 패키지 `antigravity/`가 들어가 파일 수와 크기가 늘어난다. 대상: ZIP을
   내려받거나 재빌드로 대조하는 사람.
9. healthcheck 스탬프와 `ENGINE_VERSION`이 `0.48.0`이 된다. `/vault-upgrade`가 `00-meta/scripts/vault_healthcheck.py`
   교체를 제안하고, doctor `--plugin-scope`는 v0.47.0 사본을 더 오래된 것으로 보고한다. 대상: healthcheck 사본이
   있는 git 볼트.
10. `.gitattributes`가 `antigravity/**`를 LF로 고정하므로 `core.autocrlf=true`인 Windows checkout에서도 그 폴더의
    파일은 LF로 받는다. 대상: 저장소를 clone하거나 checkout하는 사람.

## 하위호환·업그레이드

일곱 bound 파일은 v0.46.0·v0.47.0과 같으므로 checker_sha256는 `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d` 그대로다. v0.46.0이나 v0.47.0에서 만든 인증서는 실제 설치 바이트가 같으면 그대로 맞는다. v0.45.1 이하에서 올 때는 [v0.46.0의 순서](v0.46.0.md#하위호환업그레이드)를 따른다.

healthcheck 스탬프와 `ENGINE_VERSION`은 `engine=0.48.0`이다. 규칙 6종, Aside 조항 시작 마커와 `/aside-repl` 명령
원본(`engine=0.47.0`), deny zone 가드와 PowerShell 구문 분석기(`engine=0.46.0`), Aside 도우미
`aside-up.ps1`(`engine=0.17.0`), 교훈 단서 훅, git 훅은 기존 스탬프를 유지한다. 볼트에 설치된 healthcheck 사본은
`/vault-upgrade`(Codex `upgrade`)로 갱신하기 전까지 옛 동작이며, 스탬프가 올라갔으므로 `/vault-upgrade`가 그
사본의 교체를 제안한다.

Claude Code·Codex 설치는 그대로다. 저장소 루트의 `hooks/hooks.json`, `.claude-plugin/`, `.codex-plugin/`의 구성은
바뀌지 않고 판 번호와 Codex 긴 설명만 바뀐다. 줄임 옵션 `--h`를 빼면 두 훅의 기본 경로(`--host` 없음)는 v0.47.0과
같은 출력을 낸다(도움말과 `--event Stop`은 위 `기본 결과 변경` 5·6번).

Antigravity CLI에는 이번 판부터 `antigravity/` 폴더를 태그를 고정한 주소나 로컬 폴더로 설치한다
([Antigravity CLI 안내](../antigravity.md#설치)). 이전에 저장소 루트를 agy로 설치했다면(Claude 플러그인 구조의
자동 변환 설치) 그 설치를 지우고 이 판의 패키지를 설치한다.

v0.47.0 이하의 healthcheck는 `Stop` 사건이 든 체크포인트를 형식이 맞지 않는 기록으로 보고 건너뛰므로, 되돌린 뒤에는
다른 체크포인트와 비교한다. 생성 AGENTS.md는 `/vault-upgrade`가 다시 만들 때 새 문구를 받고, 이전 판으로 되돌린 뒤
upgrade를 실행하면 그 판의 문구로 다시 만들어진다.

홈 폴더에서 로그인이 필요 없는 `agy plugin` 명령으로 직접 실행해 얻었다.

## 검증

[검증 계약](../verification/v0.48.0.md)에 따라 공개한다. 공개 순서는 다음과 같다.

후보 브랜치 CI(최종 커밋) → 로컬 태그·ZIP·재빌드 확인·Codex 설치 확인·Antigravity 패키지 확인과 격리 설치·인증서 → 태그 push → 태그 CI 11/11 → 참고 대장 갱신과 독립 확인 → 독립 릴리스 검토 → master push → master CI 11/11 → 검증 기록(verification.json) → 업로드 → 초안 점검 → 게시 → 게시 후 확인

전체 로컬 시험은 통합한 트리에서 첫 후보 브랜치 push 전에, 그 뒤 트리가 바뀐 후보 push 전마다, 그리고 최종
커밋에서 다시 실행한다. 같은 단계에서 항목별 시험 모듈, 컴파일과 공백 검사, 워크플로의 smoke 명령, 두 Claude
매니페스트의 엄격 검증, 커밋한 생성 패키지와 생성기 결과의 일치 확인(`build_antigravity_package.py check`), agy
1.5.7의 `agy plugin validate --strict`와 격리 홈 설치 확인(`verify_antigravity_plugin.py`), 새 옵션 없이 v0.47.0과
출력을 비교해 모든 차이를 위 `기본 결과 변경`의 항목에 대응시키는 대조, v0.47.0 기준과 함께 재는 항목별 기능
근거, 독립 소스 검토를 거친다. 결과는 공개 `verification.json`에 기록하고 게시 후 확인은 별도 기록으로 보관한다.
과거 릴리스의 수치를 이번 버전의 결과로 옮기지 않는다.

실제 agy 대화 세션은 하지 않았다. agy는 엔진 개발 기기의 격리한 가짜 홈 폴더에서 `agy --version`과 로그인이 필요
없는 `agy plugin` 하위 명령으로만 실행한다. 이유와 확인하지 않은 동작은 아래 `알려진 경계`에 있다.

## 알려진 경계

- 실제 agy 대화 세션(모델 호출)은 실행하지 않았다. Antigravity FAQ는 소비자 요금제에서 agy를 제3자 코딩
  에이전트·앱으로 감싸 쓰는 것을 지원하지 않는다고 하고, 제3자 소프트웨어로 Antigravity 로그인에 접근하면 약관
  위반이라고 적는다. 그래서 에이전트가 agy를 감싸 실행하는 확인은 하지 않았다. `injectSteps`가 실제 대화에
  들어가는지, 압축·재개 뒤에도 남는지, 명령 스킬이 대화에서 어떻게 불리는지는 확인하지 않았다. 훅 시험은 지어낸
  훅 입력을 쓴다. 사용자가 직접 해 볼 수 있는 절차는 [Antigravity CLI 안내](../antigravity.md#직접-해-보는-확인)에
  있다.
- Windows에서 훅 명령을 실행하는 셸은 문서에 없고 확인하지 않았다. 엔진 개발 기기의 레지스트리 PATH로 `cmd /c`를
  거친 재현 실행에서는 `sh`를 찾지 못했다. 그래서 사건마다 처리기 셋(`sh` 래퍼, `py -3`, `python`)을 두고 표지
  파일로 하나만 동작하게 했다. 실행기가 없는 처리기는 실패하고 agy가 그 오류를 기록한다(0이 아닌 종료 코드는
  기록된 뒤 무시된다). 표지 파일을 만들 수 없으면 처리기가 각자 동작하므로 같은 사건이 두 번 이상 처리될 수 있다.
- 표지는 120초 동안만 유효하다. 같은 키(SessionStart는 대화 ID, Stop은 대화 ID와 `executionNum`)가 120초 안에
  다시 오면 처리하지 않고, 그보다 오래된 표지는 낡은 것으로 보아 다시 처리한다. `executionNum`의 범위(대화
  전체에서 이어지는지, 턴마다 다시 매기는지)와 대화를 다시 열 때 SessionStart가 다시 오는지는 문서에 없고
  확인하지 않았다. 그래서 같은 대화를 2분 안에 다시 열면 인계가 다시 주입되지 않을 수 있고, 2분 뒤에는 다시
  주입될 수 있다.
- 공식 문서는 스킬마다 `/<스킬 이름>` 슬래시 명령이 생긴다고 적는다(`/vault-day`). 플러그인 스킬에 이름공간이
  붙는지와, 뒤에 적은 텍스트가 스킬에 어떻게 전달되는지는 문서에 없고 확인하지 않았다. 생성 스킬의 머리말은 그
  텍스트를 `<ARGUMENTS>`로 부르고, 없으면 이번 요청에서 찾으라고 한다. 에이전트가 `<PLUGIN_ROOT>`를 설치 폴더의
  절대 경로로 맞게 푸는지도 확인하지 않았다.
- `injectSteps`의 크기 상한은 확인하지 않았다. 훅은 Claude Code와 같은 9,500자 묶음을 그대로 넣는다.
- Antigravity CLI의 훅 사건에는 압축과 세션 종료가 없다. 압축 뒤에는 인계를 다시 넣지 않으며(필요하면
  `vault-session-start` 스킬로 다시 복원한다), 체크포인트는 Claude Code의 PreCompact·SessionEnd 대신
  Stop(`fullyIdle`)에서 남긴다. 문서는 Stop이 실행 루프가 끝날 때 온다고 적으므로, 그 볼트의 가장 최근 Stop
  체크포인트는 대개 에이전트가 완전히 멈춘 마지막 시점의 해시다. 다만 같은 대화 ID와 `executionNum`의 Stop이
  120초 안에 다시 오면 기록하지 않으므로 그보다 이른 시점의 해시일 수 있다.
- deny zone 가드·교훈 단서 훅·Aside 자동 기동 훅은 Claude Code의 PreToolUse 훅이라 Antigravity 패키지에 넣지
  않았다(Codex와 같다). Claude Code 권한 템플릿의 deny zone 차단도 옮기지 않았다. Antigravity CLI의 Project 범위
  권한이 저장되는 파일 위치는 문서에 없어, 사용자가 `/permissions`에 직접 넣는다. Jarvis 브리지는 Claude CLI로만
  응답을 만들며, agy만 설치한 사용자에게 Jarvis 진단은 Claude CLI가 없다고 보고한다(`jarvis_claude_cli_unavailable`).
- `vault_doctor.py`는 agy 설치와 Antigravity 플러그인 상태를 진단하지 않는다. `--plugin-scope`는 Claude Code
  설정만, `--session-evidence`는 Claude Code 세션 기록만 읽는다. 볼트 안에 생길 수 있는 `.agents/`·`.gemini/`와
  `GEMINI.md`를 검사·색인의 제외 이름에 더하는 일, CI에서 agy를 실행하는 검사, Antigravity 마켓플레이스 제출도 이번
  릴리스에 넣지 않았다.
- Antigravity CLI는 개인 Google 계정에서 상호작용 데이터 수집에 동의한 것으로 보고 설정에서 끌 수 있게
  한다(계정에 저장된다). 비즈니스 계정에서는 이 수집이 늘 꺼져 있다. Antigravity 세션이 읽거나 훅이 주입한 볼트
  내용은 Google로 전송된다.
- `antigravity/`의 엔진 스크립트·훅·`assets/` 사본은 저장소의 고정 경로 검사(규칙 사본 시험 등)가 읽지 않는다.
  생성기의 `check`와 그것을 부르는 일치 시험이 그 사본을 원본과 같게 지키는 유일한 검사다. CI는 agy를 실행하지
  않고 이 일치 시험만 실행한다.
- 패키지 검사와 격리 설치는 Windows의 agy 1.5.7에서만 확인했다. 1.5.6 이상을 권장하며, 그보다 낮은 판과 macOS·Linux의
  agy는 실행하지 않았다. 저장소 루트를 agy로 설치하는 자동 변환 경로는 안내하지 않는다: agy 1.5.7은 루트를 Claude
  플러그인으로 보고 명령을 `agentic-vault-cmd-*` 스킬로 바꿔 설치하지만, 변환된 시작 훅은 플러그인 폴더에서
  실행되어 재현 실행에서 아무것도 출력하지 않았다(실제 agy 세션에서는 재지 않았다). agy가 설치할 때 패키지
  파일의 실행 권한을 보존하는지도 확인하지 않았다. macOS·Linux에서 이 패키지의 스킬로 볼트에 넣은 git 훅이
  동작하지 않으면 `chmod +x`로 실행 권한을 준다([Antigravity CLI 안내](../antigravity.md#확인하지-않은-것)).

네 매니페스트(Claude Code 둘, Codex, Antigravity 패키지)와 healthcheck 식별은 `0.48.0`, Codex 고정 설치 ref는
`--ref v0.48.0`, Antigravity CLI 설치 주소는 `https://github.com/Technoetic/agentic-vault/tree/v0.48.0/antigravity`이다.
현재 설치 ref는 `v0.48.0`이다. healthcheck는 `engine=0.48.0`이고 다른 규칙·어댑터 스탬프는 유지한다. Python 3.10+
표준 라이브러리 런타임과 Claude Code·Codex의 기본 훅 정의를 유지하며, 모델·네트워크 호출이나 런타임 의존성을
더하지 않는다. 공개는 활성 설치 캐시나 볼트 사본의 갱신이 아니다.
