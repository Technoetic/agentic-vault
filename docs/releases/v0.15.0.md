# agentic-vault v0.15.0

날짜: 2026-09-20

승인된 Jev-first 요청은 볼트 밖에서도 직접 질문을 먼저 Jev에 맡긴다. `1+1`을 포함한
자기완결적 질문·선택한 인라인 문맥에 native Noul·Choice·Score를 사용한다.
기존 파일 근거의 선택형 판단은 출처 바인딩·정책·보고서 형식을 유지한다.

## 변경

- `/jev-ask`와 Codex `$agentic-vault:agentic-vault jev-ask <질문>`을 추가했다.
  직접 요청과 승인된 지속 선호는 볼트 감지 전에 연결한다.
- `python skills/agentic-vault/scripts/jev_ask.py prepare|run --input -`는 볼트 없이
  UTF-8 JSON stdin을 받는다. 승인된 전송에는 `run --allow-network`가 필요하다.
- `user_input`·`selected_text`는 인라인 문맥이며 파일 출처 검증을 뜻하지 않는다.
  임시 근거 파일을 만들거나 파일 정책을 인라인 입력으로 우회하지 않는다.
- Choice는 보류 label을 포함한 2~255개 후보, Score는 순서 있는 2~10개 루브릭 수준을
  사용한다. Noul 확률의 파생 판단 강도를 native confidence로 표시하지 않는다.
- 혼합 요청은 지원되는 판단을 Jev에, 생성·환경 관측·도구 실행·종합을 호스트에 배분한다.
  현재 사실은 먼저 확보하며 근거 부족을 부정으로 바꾸지 않는다.
- 같은 질문의 현재 파일 보고서나 정확히 일치하는 직접 요청 결과를 재사용한다.
  바뀌지 않은 요청은 한 배치만 호출하고 실제 Jev 사용과 호스트 대체 사유를 구분한다.

## 하위호환·업그레이드

`vault_judge.py`의 기존 입력·파일 바인딩·정책과 보고서 계약을 유지한다. 기존 권한·
상태 기록기·완료 기록·사용자 설정을 변경하지 않는다. SDK 설치, 볼트 설정 마이그레이션,
시작 시 네트워크 호출은 없다. API 키는 프로세스의 `TYPESAFE_API_KEY`에서만 읽는다.
플러그인 갱신 후 새 호스트 세션을 연다. 릴리스 태그 설치는 `--ref v0.15.0`을 사용한다.

healthcheck의 공개 `ENGINE_VERSION`은 0.15.0이며 실제 검사 내용은 바뀌지 않았다.
마지막 내용 변경을 가리키는 `agentic-vault:healthcheck engine=0.14.0` 스탬프와
기존 규칙 스탬프를 보존해 불필요한 볼트 검사기 교체를 유발하지 않는다.

## 검증과 경계

[검증 기록](../verification/v0.15.0.md)과 [입력·실행 안내](../jev-judgments.md)를 참고한다.
Jev는 유형이 정해진 평가 API이며 자유형 생성·도구 실행·권한 부여를 하지 않는다.
Score는 루브릭 점수로 제한되며 임의 계산값이 아니다. `reviewed`도 `role: advisory`다.
확신도와 공개 합성 점검은 실제 업무 정확도 보증이 아니다. 호스트 라우팅은 전역 훅이나
호출 횟수 강제 장치가 아니며 원문·질문·비밀을 결과에 노출하지 않는다.
