# agentic-vault v0.17.1

날짜: 2026-10-01

세션 시작 주입과 기억 검색의 결함을 고친 패치다. 규칙 6종은 바뀌지 않는다. git 볼트는 업그레이드하면
healthcheck가 `engine=0.17.1`로 교체된다(§11 설명 정정).

## 변경

### SessionStart 주입 — 호스트 출력 상한 (`hooks/session_start.py`)

- **결함.** 훅은 handoff·hot을 추정 토큰 예산으로만 잘랐다. 그런데 Claude Code(2.1.252 실측)는 훅
  출력이 10,000자(JavaScript 문자열 길이, 곧 UTF-16 코드 단위)를 넘으면 출력을 파일로 옮기고 앞 2,000자
  미리보기만 세션에 넣는다. 비한글 비중이 큰 볼트는 템플릿 예산(handoff 4,000·hot 2,500 추정 토큰)만으로
  약 2만 자를 내보내 인계가 미리보기로 떨어졌다. 훅은 성공(rc 0)으로 끝났고 doctor도 이를 잡지 못할 수
  있었다. Windows에서는 `print`가 줄마다 CR을 붙이고 CRLF 노트는 CR이 두 번 붙어, 전송 길이가 잰 값보다
  길었다.
- **수정.**
  - 합친 출력을 상수 `HOST_MAX_OUTPUT_CHARS = 9500`, 곧 9,500 UTF-16 코드 단위(호스트 한계 10,000자에서
    여유를 둔 값) 이하로 묶는다. 설정 키가 아니다. 추정 토큰 예산은 지금처럼 비용 예산이다.
  - 상한 안이면 출력은 이전과 같다. 넘으면 두 섹션에 토큰 예산 비율로 문자 몫을 나누고(짧은 섹션이 남긴
    몫은 다른 섹션으로 넘긴다) 몫을 넘는 섹션만 다시 자른다. 두 헤더와 생략 표식은 항상 남는다.
    예산 0은 지금처럼 섹션을 끈다.
  - 노트의 CRLF·CR은 LF로 정규화하고, 출력은 UTF-8 바이트를 줄바꿈 변환 없이 쓴다. 잰 길이가 호스트가
    받는 길이와 같다.
  - 자르는 위치는 남긴 앞부분의 마지막 줄 경계로 맞춘다(줄이 없으면 글자 경계).
- **잘림 표식.** 잘린 섹션은 먼저
  `[... truncated: <볼트 상대 경로>; omitted headings: A | B (+N more); for a topic run /vault-recall <topic> (Codex: recall) ...]`
  를 시도한다. 생략된 부분의 Markdown 제목을 최대 5개(각 40자 이하, 코드 펜스 안은 제외) 적는다.
  안내는 주제를 찾을 때 쓰라는 것이지 잘린 부분을 통째로 다시 읽으라는 뜻이 아니다. 긴 표식이 예산에
  들어가지 않으면 이전의 짧은 `[... truncated ...]`로 돌아간다.

### `/vault-doctor` (`vault_doctor.py`)

- 훅과 같은 합성 함수(`compose_context`)로 판정해, 훅이 실제로 내보낼 내용을 보고한다.
- 훅 보고에 `estimated_emitted_chars`(실제 출력 길이, UTF-16 단위)와 `host_char_cap`(9500)을 더했다.
  상한 때문에 더 잘린 섹션은 `truncated`(사유 `host_char_cap`)로 보고되고 전체는 degraded(exit 1)다.
- 절단 판정은 표식 문자열 끝 비교가 아니라 명시 플래그로 한다. JSON은 필드만 늘었다(`schema_version` 1).

### healthcheck §11 설명

- v0.9.0부터 훅은 예산을 넘는 뒷부분을 자르는데, §11의 주석과 보고 문구는 "통째로 주입한다"는 옛 설명을
  유지하고 있었다. 이 다섯 곳을 "예산 안의 앞부분만 주입하고 나머지는 자른다 — 초과분은 다음 세션이 보지
  못하는 내용이다. 호스트 전송 상한이 별도로 더 자를 수 있다"로 바로잡았다. 판정 알고리즘과 등급
  (관리성, exit 코드 무관)은 그대로다.

### `/vault-recall` (`vault_recall.py`)

- 파일당 한도(512KiB)를 넘는 파일은 지금처럼 부분 읽기 없이 건너뛰되, 이제 어떤 파일인지 밝힌다.
  `diagnostics.oversized_files`에 `{path, bytes}`를 최대 50개(`MAX_RESULTS`) 싣고, 텍스트 모드는
  `recall skipped (over 512 KiB): <경로> (<크기> KiB)`를 stderr에 쓴다(크기는 올림). 목록에 못 실린
  수는 `recall skipped: N more oversized file(s) not listed`로 적는다. deny zone·exclude·경로 안전 검사를
  통과한 파일만 목록에 오른다.
- `/vault-recall` 명령 문서: 건너뛴 파일 이름을 답변에 밝히고, 필요하면 그 파일만 좁혀 확인한다.
  로그가 한도를 넘으면 오래된 달을 deny zone 밖의 별도 노트로 나누는 것을 제안할 수 있다(나눌지는
  사용자 결정).
- 배경: 추가 전용 로그는 모든 볼트에서 결국 이 한도에 닿는다. 이전에는 개수와 "불완전"만 보고돼,
  로그에만 있는 사실을 물으면 무관한 노트가 답으로 돌아왔다.

## 하위호환·업그레이드

- 규칙 6종의 스탬프는 그대로다. git 볼트는 `/vault-upgrade`(Codex `$agentic-vault:agentic-vault upgrade`)로
  healthcheck가 `engine=0.17.1`로 교체된다(설명 문구만 바뀜).
- 주입 출력: 상한 안이던 볼트는 줄바꿈 정규화 말고는 같다. 상한을 넘던 볼트는 미리보기 2,000자 대신 상한
  안에서 잘린 두 섹션이 들어간다. 잘린 섹션의 표식 문구가 달라졌다(긴 표식 → 짧은 표식 순).
- doctor 텍스트 출력에 두 줄(`estimated_emitted_chars`, `host_char_cap`)이 추가돼 줄 위치로 파싱하던
  소비자는 영향을 받는다. JSON은 필드 추가뿐이다.
- recall JSON은 `oversized_files` 필드 추가뿐이다.
- Codex 설치: `codex plugin marketplace add Technoetic/agentic-vault --ref v0.17.1`.

## 검증과 경계

- 발견 경위: 사용자 볼트에서 논문 흡수 분석을 하며 엔진 코드와 대조하다 찾았다(세 렌즈 독립 검증).
  논문의 메커니즘을 흡수한 것이 아니므로 README 계보표에 올리지 않는다.
- 호스트 한계 10,000자와 미리보기 2,000자는 Claude Code 2.1.252 설치본의 상수로 확인한 값이다(문서화된
  계약이 아니며 버전마다 바뀔 수 있다). 엔진은 500의 여유를 둔다. Codex의 표시 상한은 따로이며, 두
  클라이언트는 같은 훅 출력을 받는다.
- 문자 몫 배분은 토큰 예산 비율을 따른다. 한쪽 섹션이 몹시 길고 예산이 치우치면 다른 섹션은 짧게
  남는다. 줄 경계 맞춤은 아주 긴 한 줄을 통째로 뺄 수 있다.
