# agentic-vault v0.8.4 릴리스 노트

날짜: 2026-09-02

v0.8.4는 2026-08-31 포크 볼트(NS) 교차 검증(`wf_6d8aff64-f1a`, 7에이전트 프로브)에서 확정된 healthcheck 엔진 결함 2건을 수정하는 패치 릴리스다. 마크다운 계약(템플릿·커맨드·rules) 변경 없음 — `vault_healthcheck.py`와 계약 테스트만 변경된다.

## 수정 1 — config 경로 필드의 deny zone 우회 차단 (high)

- 증상: `handoff_note`·`index_note` 등 검사기가 되읽어야 하는 경로 필드가 deny zone 안을 가리키면, pre-commit `--staged` 게이트가 대상 파일을 읽지 못한 채 **조용히 통과**했다(프로브 실증).
- 수정: `validate_config`가 `_PATH_KEYS` 7종(index·log·hot·handoff·ssot·health_report·rules_dir) 전부를 deny zone과 대조해 fail-closed로 거부한다. 비교는 경로 세그먼트 + casefold 기준 — Windows 대소문자 표기 차이는 우회가 아니고, `90-assets-notes` 같은 유사 접두 폴더는 오탐하지 않는다. 배치는 `_PATH_LIST_KEYS` 정규화 이후(deny_zones가 정규화된 뒤에만 비교가 옳다).

## 수정 2 — 노트 읽기 실패 fail-soft + §14 신설 (low)

- 증상: 본 검사 루프의 `read_text`가 OSError 무방비 — 클라우드 하이드레이션 실패·백신 잠금·동시 저장 레이스로 파일 하나만 못 읽어도 전체 검사가 traceback으로 죽었다.
- 수정: 파일 단위 fail-soft — 못 읽은 노트만 건너뛰고 신설 **§14 읽기 실패**(관리성)로 보고한다. 건너뛴 노트는 프런트매터·링크·고아 판정에서 제외한다(읽기 실패를 링크 부재로 오판하지 않는다). 콘솔 요약에 `⚠️읽기 실패 N건(§14)`을 덧붙인다.
- 침묵 통과 방지: **검사 대상 전부가 읽기 실패면 exit 1**이다 — 그건 fail-soft가 아니라 검사 미수행이다.
- §13은 결번 — 포크 볼트(NS)의 루트 allowlist 검사(§13) 번호와 충돌 회피(README 로드맵의 "파일 위치 규율" 이식 후보 자리).

## 하위호환

- config 스키마 변경 없음(키 추가·삭제 없음). 단, 경로 필드가 deny zone 안을 가리키던 볼트는 이제 설정 오류로 거부된다 — 이는 회귀가 아니라 그 구성이 원래 검사 불능이었다는 신호다(경로를 deny zone 밖으로 옮기면 된다).
- 리포트에 §14가 항상 출력된다(0건이면 "- 없음"). 총 이슈 집계에 읽기 실패 건수가 포함되며 치명(exit 코드)에는 반영하지 않는다.
- 엔진 스탬프 `agentic-vault:healthcheck engine=0.8.4` — `/vault-upgrade`의 점 단위 숫자 비교로 구판 설치본이 교체 대상으로 잡힌다.
