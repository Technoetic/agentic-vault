# v0.32.0 — 기본 경로 정규식의 선형 시간, 기간 정규화 변성 시험, 답 없음 쌍둥이와 표본 감사, 선택형 deny zone 가드

기본 lint·healthcheck·`check-support`·recall이 노트마다 읽는 제목·frontmatter 줄과 인라인 코드·링크·frontmatter 블록의 정규식 가운데 특정 입력에서 이차·삼차 시간이 걸리던 것을 같은 결과를 내는 선형 처리로 바꿨다. `check-support`는 표를 뺀 자리, frontmatter가 있는 인용 노트의 줄 나눔, 자기 인용의 BOM에서 본문을 한 규칙으로 읽으며, 이번 버전에서 기본 판정이 바뀌는 곳은 이 경우뿐이다. 선택형 기간 정규화는 생성한 사례로 알려진 실패를 세어 고정하고, 더 보류하거나 v0.31.0의 지나친 보류 일부를 푼다. 저장소 평가 도구에는 답 없음 쌍둥이와 행 토큰 정렬(`scripts/evaluate_recall.py`), 실제 볼트 표본 감사(`scripts/real_vault_audit.py`)를 더했고, Claude Code용 선택형 deny zone 가드 템플릿을 둔다(기본으로 설치하지 않는다). 기준 공개판은 v0.31.0 `21c4b47a436ce7e6619f848ccf73c39d4c777ee1`, 갈래마다 검토와 수정을 마치고 병합한 통합 커밋은 `b85fb5ea5b495ee9cdb2d068a1a41fe82ff6eb56`이며 최종 소스는 게시 전 `verification.json`에 기록한다. 핵심 엔진은 Python 3.10+ 표준 라이브러리만 쓰며 모델·네트워크 호출과 런타임 의존성을 추가하지 않고 플러그인 훅 정의(`hooks/hooks.json`)도 바꾸지 않는다(선택형 가드는 켠 볼트에서 PATH의 `python`을, Windows에서는 Windows PowerShell 5.1도 쓴다). **`vault_ssot.py`·`vault_lint_extensions.py`·`vault_provenance.py`·`jev_client.py`와 설명만 고친 `vault_paths.py`가 바뀌어 경고 승격 인증서의 `checker_sha256`가 바뀐다. 경고를 `fatal`로 올린 볼트는 갱신하거나 되돌리기 전에 [아래 순서](#하위호환업그레이드)를 따른다.**

## 변경

- **기본 경로 정규식의 선형 시간:** 게으른 묶음 뒤에 생략 가능한 공백 꼬리가 오는 줄 정규식(`parse_ledger`의 확정 구역 제목, handoff 투영(`project_handoff`)의 차단 구역 제목, lint의 제목 anchor와 `created`·`updated` 날짜, 출처 frontmatter, healthcheck의 rules 제목 중복 검사, `/vault-recall`의 제목)과, 같은 경로에서 다른 꼴로 느려지던 정규식 일곱 개(lint의 인라인 코드 지우기·위키링크 찾기·제목 키의 Markdown 링크, healthcheck의 `split_frontmatter`·`WIKILINK_RE`, `check-support` 출처 칸의 `CODE_SPAN_RE`, 특권 노트의 링크 찾기)를 같은 결과를 내는 선형 처리로 바꿨다. 켜는 설정·옵션·새 출력 필드는 없고 판정·경고·`issue_id`·출력·종료 코드는 그대로다(근거는 [아래](#하위호환업그레이드)). 2026-10-27 이 PC(Windows 11·Python 3.12.10)에서 `# a` + 공백 64,000개 + `b`인 제목 줄 하나가 예전 식으로 21.15초, 새 처리로 1.4 µs였고, `[`만 32,000개인 노트의 healthcheck 위키링크 찾기는 17.8초에서 167 µs로, 백틱만 16,000개인 줄의 lint 인라인 코드 지우기는 21.7초에서 5.4 µs로, 백틱 4,096개인 출처 칸이 62행인 대장의 `check-support`는 48.6초(v0.31.0, 한 번 잼)에서 0.019초로 줄었다(결과는 같았다). v0.31.0 릴리스 노트가 '공백이 아주 많은 제목 줄'로 적은 느린 꼴은 정확히는 제목 글자 사이의 긴 공백이다. 대장과 handoff 투영이 쓰는 `_atx_heading`은 `vault_ssot.py`에 두고 `vault_state.py`에 바이트가 같은 사본을 둔다(`tests/test_rule_sources.py`가 대조한다). 모듈 이름 `vault_healthcheck.WIKILINK_RE`(대상 목록은 새 `wikilink_targets`)·`RULE_HEADING_RE`, `vault_recall._TITLE_RE`·`_HEADING_RE`, `vault_ssot.CODE_SPAN_RE`는 없앴다. 제목 해석을 CommonMark 쪽으로 고치지 않으며(0.31.2 4.2절 예제 66·73·75·76·79와 유니코드 공백의 차이를 그대로 둔다), v0.31.0에서 늘어난 기본 `check-support`의 비용(인용 노트마다 `parse_ledger`)은 줄이지 않는다. `\s`가 `str.isspace()`라는 것과 atomic·possessive 문법이 Python 3.11부터라는 것(그 문법으로도 이차 시간은 남는다)은 Python `re` 문서에서, 원래 식과 결과가 같은 수리와 시험 사례를 통과하는 수리를 나누는 두 수용 기준은 VULCANBOOST(Yeting Li 외, USENIX Security 2025)에서 판정 틀로만 빌렸다. - **`check-support`의 본문 경계(R10·R11·R12):** v0.31.0의 `check-support`는 본문을 읽는 세 곳이 서로 어긋났다. 사실 표를 뺀 본문은 표 위 글과 아래 글을 이어 붙였고 비교는 줄바꿈을 포함한 공백을 한 칸으로 줄이므로, 표를 사이에 둔 두 글이 하나의 값·기간·기간 수식어로 찾혔다. frontmatter가 있는 인용 노트만 `str.splitlines`로 나눠 U+000B·U+000C·U+001C~U+001E·U+0085·U+2028·U+2029도 줄바꿈이 되었고, UTF-8 BOM으로 시작하는 대장의 자기 인용은 frontmatter를 알아보지 못해 비교에 넣었다. 이제 표 바로 위 줄의 끝(줄바꿈 앞)에 NUL 표시를 남겨 이어 읽지 않고(`parse_ledger`가 NUL이 든 대장을 거절하므로 어떤 대장 값에도 없고, `vault_period`도 건너 읽지 않는다), 인용 노트는 frontmatter가 있든 없든 `parse_ledger`처럼 CR·LF·CRLF에서만 줄을 나누며, 자기 인용은 맨 앞 BOM을 떼고 frontmatter를 정한다. 켜는 옵션과 새 필드는 없다. 이 세 경우가 이번 버전에서 기본 판정이 바뀌는 유일한 곳이며 경우별 변화는 [하위호환·업그레이드](#하위호환업그레이드)에 있다. 줄 나눔 규칙은 이 모듈의 `parse_ledger`(`bytes.splitlines`)와 Python 문서의 `bytes.splitlines`·`str.splitlines` 줄 경계에서, BOM 처리는 `codecs`의 `utf-8-sig`에서 가져왔다. [동작과 시험](../hardening.md#표를-뺀-자리와-줄-나눔)
- **기간 정규화의 변성 시험과 보류·회복(`--normalize-periods`, 선택):** 새 `tests/test_vault_period_metamorphic.py`는 작은 낱말 목록의 데카르트 곱(`itertools.product`)으로 만든 14,775개 사례로 관계 아홉 개를 본다. DIR(방향 기대)은 좁히는 말, 기간 앞의 영문 수식어, 구분 기호 뒤의 기간 단위 항목, 두 회계연도 사이의 표시가 붙으면 기간 전체를 더는 비교하지 않는지, INV(불변)는 기간을 좁히지 않는 말, 구분 기호 뒤의 시각·개수, 회계연도와 표시 사이의 이음 문자, 두 회계연도의 순서가 결과를 바꾸지 않는지 본다. 알려진 실패는 `unittest.expectedFailure`로 숨기지 않고 `KNOWN_FAILURES`·`KNOWN_FAILURE_COUNTS` 톱니로 고정하므로 새 실패가 생겨도, 고쳐서 실패가 사라져도 시험이 실패한다. 2026-10-27에 남은 실패는 목록 밖의 좁히는 말 561건 중 264건, `FY2025/Q3 FY2026/Q1` 꼴의 두 회계연도 사이 표시 74건 중 16건, 낱말 `중`·`기준`·`그리고`로 회계연도와 이은 표시 1,764건 중 108건이다(v0.31.0은 같은 세 관계에서 537·74·864건). 같은 파일의 `PeriodDifferentialTests`는 v0.31.0 태그의 `vault_period.py`와 맞대어, 아래 선언한 회복 말고는 어떤 값·인용 본문도 더 강하게 비교되지 않는지와 회복이 v0.31.0이 기간만 읽은 결과와 같은지 본다. 보류가 느는 꼴: `말` 뒤의 `은`·`는`·`이`·`가`·`도`(`2026년 3분기 말이 되면`), `중`·`내`·`동안` 뒤의 좁히는 말(`2026년 3분기 중 마지막 달`), 기간 안의 달 목록과 `3주째`·`1개월 차`(`2026년 3분기 7·8월`), 날짜가 아닌 기간 바로 앞의 영문 `late`·`early`·`mid`·`end of`·`start of`(`late 2026Q3`), v0.31.0의 이음 문자 밖의 문자나 `및`·`과`·`와`로 회계연도와 이은 표시(`FY2026 & Q3`, `FY2026 [Q3]`, `Q3 및 FY2026`), 표시와 다른 회계연도 사이에 공백·서식 문자만 있는 그 회계연도(`FY2025 Q4 FY2026`의 `FY2026`), 표시처럼 이은 분기·반기 목록 옆의 회계연도(`FY2026 1·2분기`). v0.31.0이 지나치게 보류하던 꼴은 기간 전체로 비교한다: `초과`, `2주 차질`·`차량`·`차례`, 구분 기호 뒤의 시각이나, 단위에서 낱말이 끝나고 바로 뒤나 조사 뒤에 기간 낱말이 오지 않는 개수(`2026-10-07, 10:00`, `2026년 3분기, 120억`, `2026.10.07, 1차 납품`. `4개 분기`·`4개의 분기`는 개수가 아니다). 새 보류 사유는 없고 `period_convention`의 `scope` 문자열도 같으며, 기본 경로는 이 옵션 없이 `vault_period.py`를 불러오지 않는다. CI의 `unittest` 작업은 태그를 받도록 `fetch-depth: 0`으로 checkout해 차분 시험을 실행한다. 관계 시험의 방법은 CheckList(Ribeiro·Wu·Guestrin·Singh, ACL 2020, arXiv 2005.04118) §2.2·§2.3의 INV·DIR에서 빌렸다. [보류 규칙과 실패 목록](../hardening.md#기간-정규화의-알려진-실패-목록)
- **답 없음 쌍둥이와 행 토큰 정렬(`scripts/evaluate_recall.py`, 선택):** 저장소 평가 도구의 새 `--gold-removal-twins`는 inspected가 아닌 답 있는 문항마다 그 답을 담은 노트(`expected_paths`, `relevance` 등급이 0보다 큰 모든 경로, 정규화한 `required_claims` 문장이 든 노트)를 뺀 볼트에서 같은 질문을 한 번 더 실행하고, 팔마다 `gold_removal_twins`를 붙인다. 쌍둥이마다 `refused_empty_complete`(완전한 검색이 아무것도 돌려주지 않음, 지금 recall이 낼 수 있는 유일한 거부)·`stale_only`·`returned_candidates`(답 없음 오탐)·`twin_error`(`twin_error_reason`: `retrieval_not_ok`·`search_incomplete`·`note_scan_incomplete`) 가운데 하나를 고르고, 다른 문항의 등급 라벨이나 주장 문장으로 알 수 있는 근접 중복은 `possibly_still_answerable`로 따로 센다. 2026-10-27 recall_hard(답 있는 56문항, top3)에서 legacy 팔은 쌍둥이 26/56을 거부하고 30/56에서 후보를 돌려줬으며, 질의 확장 improved 팔은 24/56과 32/56이었다(답 있는 문항의 빈 결과는 13/56에서 0/56). 빈 결과라는 한 작동점(`operating_point`)뿐이며 곡선이나 문턱이 아니다. 게이트·종료 코드는 이 절을 읽지 않고, 플래그가 없으면 출력·표준 오류·종료 코드는 바이트 단위로 같다. 새 `--redact-row-order token`(기본 `gold`)은 키 가명화(`--redact-key-file`·`--redact-ephemeral`)와 함께일 때만 받아, 모든 통계·게이트가 끝난 뒤 출력 사본의 `per_query`·`failed_queries`·`evaluation_errors`·inspected id·쌍둥이 행을 키 토큰 순으로 정렬하고 `row_order: "sorted_by_keyed_id_token"`을 남긴다. 키 없는 `--redact`나 가명화 없는 실행에 쓰면 종료 코드 2다. 골드셋만 가진 사람이 위치로 행을 맞추는 일만 막을 뿐 익명화가 아니다. 쌍둥이 절차와 '거짓 거부 예산을 고정한 거부 재현율'이라는 틀은 Search Engines Never Say No(Chandradevan·Ghosh·Selvendran, arXiv 2610.05348 v1, 2026-10-04, 동료 심사 전 프리프린트, 영어 위키백과 QA·BM25)에서 빌렸고 탐지기·거부 문구·수치는 가져오지 않았다. [쌍둥이](../memory-evaluation.md#답-없음-쌍둥이)
- **실제 볼트 표본 감사(`scripts/real_vault_audit.py`, 저장소 도구):** `draw`는 사용자가 실제 볼트에서 뽑아 준 항목 참조 목록(일반 형식, 또는 저장한 `check-support --normalize-periods` 결과에서 `normalized_match`가 `none`인 행)에서 seed와 SHA-256 순위로 k개를 뽑아(seed가 무작위이면 비복원 균등 추출) 표본 파일(seed·N·k·신뢰 수준·`population_sha256`과 참조만, 라벨 없음, 덮어쓰지 않음)을 쓰고 `sample_sha256`을 출력한다. `bound`는 사람이 표본 전체에 붙인 `miss`·`ok` 라벨에서 놓침 수의 단측 정확 상한을 낸다. 새 `eval_stats.hypergeometric_upper_bound`가 P(X ≤ x | N, K, k) ≥ α인 가장 큰 K를 정확한 정수 비교와 이분법으로 찾는다(N=500, k=20, x=0이면 68개, 모집단의 13.6%). 신뢰 수준은 `draw`가 기록한 값만 쓰고 `--confidence`가 다르면 `confidence_mismatch`, `--population`을 주면 추출을 다시 계산해 다르면 `sample_mismatch`로 거절하며 `population_verified`를 남긴다. 출력에는 id·라벨·노트 내용이 없고(`upper_misses`·`upper_miss_share`, `--flagged-true-positives`를 주면 재현율 하한), 사용 오류는 내용 없는 코드와 종료 코드 2다. 볼트를 열지 않고 네트워크·모델을 부르지 않으며 훅·CI 게이트·기본 실행에 연결하지 않는다. 이번 릴리스는 이 도구로 실제 볼트를 재지 않았다. 방법은 Callaghan·Müller-Hansen, 「Statistical stopping criteria for automated screening in systematic reviews」(Systematic Reviews 9:273, 2020, CC BY 4.0)의 초기하 검정(식 7·9·10)을 상한으로 뒤집은 것이다. **기본 동작.** 판정이 바뀌는 기본 출력은 `check-support`의 아래 경우뿐이다. 해당 행의 `rows_supported`·`rows_unsupported`·경고·`issue_id`·`ledger_table_only`·`rows_supported_ledger_table_only`가 v0.31.0과 다를 수 있다. 그 밖에 바뀌는 값은 경고 승격 인증서의 `checker_sha256`이고(아래), 읽기 전용 진단 보고에는 가드 상태가 더해진다(아래 **진단 보고**).

선형 처리는 예전 정규식과 같은 결과를 낸다. 근거는 아래와 같으며 모든 입력에 대한 증명은 아니다([알려진 경계](#알려진-경계)). 예전 정규식은 `tests/test_linear_line_parsers.py` 안에만 대조용으로 남아, 한정된 기호 집합의 모든 문자열과 비교된다(제목 식은 공백 종류 8개와 `#`·`a`·`가`로 만든 길이 6 이하 1,948,717개, 백틱·링크 스캔 넷도 11개 기호의 같은 범위, frontmatter 블록은 7개 기호에 앞붙이 넷, 위키링크 스캔은 9개 기호의 길이 6 이하와 구별 문자만의 길이 9·10까지이며, `AGENTIC_VAULT_SLOW_TESTS=1`이면 더 길게 본다). 호출부 시험은 CR·CRLF·U+2028 등을 섞어 넣어 제목 식에 줄바꿈이 넘어가지 않는지 보고, 예전 식을 끼워 넣은 실행과 lint 경고·`check-support` 결과·healthcheck full 모드와 `--staged`의 출력·링크 제안·recall 순위·경고 승격 replay가 같은지 본다. 제목 식을 바꾼 커밋(`aef13f4`)에서는 v0.31.0과 새 코드의 `git archive`를 같은 합성 볼트에 돌려 healthcheck(full·`--staged`), `vault_ssot.py`의 `check`·`check-support`, recall(`--expand-query` 포함)과 CI recall 평가 네 단계의 출력·종료 코드가 같았다. 검토자가 따로 만든 무작위·전수 입력(제목·frontmatter 줄 함수 700,000개, 코드·링크·frontmatter 스캔 7,591,321개, 위키링크 스캔 3,377,666개)에서도 불일치가 없었다. 통합 커밋 `3e025cc`의 CI 평가 단계 11개 출력은 같은 PC의 v0.31.0 기준 실행과 시간 필드를 빼고 같았다(2026-10-27). 전후 측정은 [위](#변경)와 [hardening.md](../hardening.md#제목frontmatter-파싱과-코드링크-스캔의-선형-시간)에 날짜와 함께 있다.

**선택형 경로.** `--normalize-periods`는 [위](#변경)의 보류·회복으로 일부 값과 인용 본문의 `normalized_match`·`reason`·`via`가 v0.31.0과 다르다. 더 강하게 비교되는 것은 선언한 회복(`초과`, `2주 차질`·`차량`·`차례`, 구분 기호 뒤의 시각·개수)뿐이며 나머지는 보류가 늘거나 인용 본문에서 색인하는 기간이 줄어드는 쪽이다. 릴리스 후보 검토가 찾은 결함(`ㆍ`·`ᆞ`로 표시와 이은 회계연도를 통째로 비교함, 표를 뺀 자리의 NUL을 이음 문자로 읽음, 조사로 기간 낱말과 이은 개수를 개수로 봄)을 고친 `7c98d89`를 v0.31.0과, 그리고 v0.31.0에 선언한 회복만 넣은 기준과 맞댄 차분(2026-10-27, 무작위 낱말 열과 전수 곱·NUL 삽입으로 만든 글 5,873,638개를 `fiscal_start` 없음·1·4·12로 23,494,552번 읽음, `ㆍ`·`ᆞ`·NUL·조사와 회복 포함)에서 선언한 회복 밖의 더 강한 비교는 없었고, NUL이 든 글은 모두 NUL 양쪽을 따로 읽은 것과 같았다([방법과 수](../hardening.md#기간-정규화의-알려진-실패-목록)). 켜도 `rows_*`·경고·`issue_id`·종료 코드가 그대로라는 점은 v0.31.0과 같다. `--primary-text-only`·`--normalize-periods`의 결과는 위 표의 경우에도 다를 수 있다. `evaluate_recall.py`는 새 옵션을 붙일 때만 출력이 바뀌고 `--help`에 두 옵션과 설명 문장이 더해진다.

**진단 보고.** 볼트로 확인된 `vault_adapters.py` 보고(`status: ok`)에는 옵션 없이도 `adapters.deny_guard`가 더해지고(가드가 없으면 `state: absent`, `actions`는 빈 목록), 텍스트 출력에는 Aside 줄 뒤에 `deny_guard.state`·`deny_guard.guard`·`deny_guard.parser`·`deny_guard.hook`·`deny_guard.actions` 줄이 붙는다. `/vault-doctor`가 이 보고를 보여 준다. `adapters.aside`, 볼트가 아닐 때의 답, 종료 코드는 v0.31.0과 같다(합성 조합 97가지 비교). `vault_doctor.py` 파일은 바뀌지 않았다(기본 출력 비교는 최종 트리에서 한다).

**명령 문서의 변화(가드를 켜지 않는 사용자).**

- `/vault-init`(Claude Code): Aside 단계 뒤의 4-2단계가 `vault_adapters.py --offer-deny-guard`를 읽기 전용으로 실행해 `offer_deny_guard`가 있으면 Aside 질문과 따로 한 번 묻는다. 거부하거나 답이 없으면 아무것도 복사·병합하지 않으며, 완료 보고의 선택 단계 목록에 deny zone 가드가 더해진다. Codex는 이 단계를 건너뛴다.
- `/vault-doctor`: 6단계가 `adapters.deny_guard`도 보고한다. 가드가 없으면 `state`가 `absent`이므로 "도구 어댑터 없음" 한 줄로 끝나는 조건은 v0.31.0과 같게 작동한다. Doctor는 가드를 제안하지 않는다.
- `/vault-upgrade`: 6단계가 Claude Code에서 `adapters.deny_guard.actions`도 처리한다. 가드가 없는 볼트는 `actions`가 비어 있어 하는 일이 없고, 업그레이드는 가드를 설치·제안하지 않는다. 엔진 소유 파일 예외에 스탬프가 있는 두 가드 스크립트가 더해졌다(설치한 볼트에만 해당).
- `/vault-process-inbox`·`/vault-lint`·`/vault-session-end`: 가드를 켠 볼트에만 적용되는 문장이 하나씩 더해졌다(격리 이동과 노화 문서 아카이브 이동은 Bash 도구의 `mv -n`, 이미 추적하는 파일은 `git mv`; 구역 안 경로는 구역 밖 상위 폴더로 스테이징하고 `git status`로 확인). 가드가 없으면 절차는 그대로다.

**경고 승격 인증서.** 이번 버전은 `checker_sha256`가 묶는 일곱 파일(`vault_lint_extensions.py`·`vault_warning_policy.py`·`vault_provenance.py`·`vault_egress.py`·`vault_ssot.py`·`jev_client.py`·`vault_paths.py`) 가운데 `vault_ssot.py`·`vault_lint_extensions.py`·`vault_provenance.py`·`jev_client.py`와 설명만 고친 `vault_paths.py`를 바꿨다(선형 처리와 본문 경계, `vault_paths.py`는 가드가 구역 규칙을 그대로 복사해 둔다는 설명). 저장소 바이트(LF)로 다시 계산한 `checker_sha256`는 v0.31.0의 `d8f9559a873ed7cf00f6982a2aeab28880227f403cec358e8e4e5c3fbfcbeb9c`에서 `⟦CHECKER_SHA256⟧`로 바뀐다. benign corpus(LF `38efaabd…`)와 replay 결과(`result_sha256`)는 `b85fb5e`에서 v0.31.0과 같았다. 인증서를 검사하는 `vault_warning_policy.py`는 바뀌지 않았으므로, 다른 버전의 인증서가 남은 볼트에서는 [v0.31.0 안내](v0.31.0.md#하위호환업그레이드)에 적은 도구들이 같은 방식으로 멈출 것으로 본다(healthcheck 종료 코드 1, SessionStart 훅의 주입 생략, staged 검사의 커밋 차단, doctor와 `/vault-recall`의 `invalid_config`, `vault_ssot.py`의 `ssot_operation_unavailable`). v0.31.0(`21c4b47`)과 이번 릴리스 트리를 `git -c core.autocrlf=false archive`로 꺼내, 합성 git 볼트에서 `missing-anchor`를 `fatal`로 올리고 각 엔진에 다른 버전의 인증서를 두는 두 방향 확인은 최종 트리에서 다시 실행해 `verification.json`에 남긴다. 인증서는 그것을 검사하는 엔진 사본마다 맞아야 한다. Claude Code와 Codex의 플러그인 설치본, 그리고 git 볼트에서 pre-commit 훅이 실행하는 볼트 안 엔진 사본(`00-meta/scripts/`)이 그 대상이다. 그래서 경고를 `fatal`로 올린 볼트는 갱신 전에 다음 순서를 따른다. 이전 버전으로 되돌릴 때도 같은 순서다.

1. 볼트 설정 `warning_policy.levels`에서 `fatal`로 올린 단계를 `warning`으로 되돌린다.
2. 볼트를 읽는 엔진을 모두 같은 버전(되돌릴 때는 이전 버전)으로 바꾼다. Claude Code와 Codex 설치본을 함께 바꾸고, git 볼트의 엔진 사본은 갱신할 때 `/vault-upgrade`(Codex `upgrade`)로 바꾼다. `/vault-upgrade`는 사본을 이전 버전으로 내리지 않으므로, 되돌릴 때는 그 사본도 이전 버전의 파일로 직접 되돌린다.
3. 바꾼 설치본에서 `vault_warning_policy.py --certificate`로 인증서를 다시 만들어 볼트 설정의 `warning_policy.certificate`에 넣는다.
4. 단계를 다시 `fatal`로 올린다.

버전이 섞인 동안에는 하나의 인증서가 모든 사본에 맞을 수 없으므로 승격을 켜 두지 않는다. 실제 사용자 볼트의 인증서는 자동으로 다시 쓰지 않는다. 인증서는 설치본의 실제 바이트를 묶으므로 줄 끝 등이 다른 설치본에서도 맞지 않을 수 있다. 이번 버전부터 `.gitattributes`가 benign corpus를 `text eol=lf`로 지정하지만, `core.autocrlf=true`인 Windows git checkout으로 받아 둔 설치본은 갱신해도 이 파일이 CRLF로 남는다(`corpus_sha256` `4b31a673…`). 그런 사본이 있으면 3단계 전에 그 파일을 지우고 `git checkout -- skills/agentic-vault/scripts/resources/lint-benign-v1.json`으로 다시 받는다. 위 해시는 최종 트리에서 다시 계산해 `verification.json`에 남긴다. v0.30.0 이하에서 올라오면 [v0.31.0 안내](v0.31.0.md#하위호환업그레이드)의 혼합 버전 조건도 따른다.

**혼합 버전과 되돌리기.** v0.31.0 이하는 deny zone 가드를 모른다. v0.31.0의 `vault_adapters.py`는 가드 훅(`aside-up.ps1`을 부르지 않는 핸들러)을 Aside 보고에서 무시하고 가드 상태를 보고하지 않으며 `--offer-deny-guard`를 사용법 오류(종료 코드 2)로 거절한다. v0.31.0의 `/vault-doctor`·`/vault-upgrade`는 가드 스크립트를 보고하거나 교체하지 않는다. 가드는 볼트의 두 스크립트와 `.claude/settings.local.json`의 훅이라 플러그인을 되돌려도 계속 실행된다. 끄려면 그 훅 그룹을 먼저 지우고 스크립트를 지운다(훅이 남은 채 `deny-guard.py`가 없으면 python이 종료 코드 2로 끝나 대상 도구 호출이 모두 막힌다). `check-support`와 `--normalize-periods`의 결과는 위 경우에 v0.31.0 설치본과 다르다. Claude Code와 Codex의 플러그인 캐시는 따로 갱신되므로 함께 갱신한다. `--redact-row-order token`으로 만든 보고서와 v0.31.0 이하나 `gold`로 만든 보고서는 행 순서가 다르므로 위치가 아니라 `id` 토큰으로 맞춘다(같은 키 파일이면 토큰이 같다). v0.31.0의 `evaluate_recall.py`는 두 새 옵션을 사용법 오류(종료 코드 2)로 거절한다. `scripts/real_vault_audit.py`는 같은 checkout의 `scripts/eval_stats.py`를 불러오며, v0.31.0의 `eval_stats.py`에는 `hypergeometric_upper_bound`가 없다. 표본·라벨 파일은 이 도구만 읽는다.

**명령줄 약어.** `evaluate_recall.py`에 `--gold-removal-twins`가 생겨 `--goldset`을 줄여 쓴 `--g`·`--go`·`--gold`가 모호해졌다. v0.31.0은 이를 `--goldset`으로 받았지만 이제는 argparse의 `ambiguous option` 오류와 종료 코드 2다. 약어는 문서화한 인터페이스가 아니므로 `--goldset`을 쓴다.

**deny zone 가드는 기본으로 설치하지 않는다.** 플러그인 훅 정의(`hooks/hooks.json`)에는 PreToolUse 항목이 없고, 볼트 템플릿(`vault-config.json`·`settings-permissions.json`)은 v0.31.0과 내용이 같다(시험으로 고정). `/vault-init`이 따로 묻고 답이 없으면 설치하지 않으며, `/vault-doctor`·`/vault-upgrade`와 Codex는 제안하지 않는다. 켤 때는 Claude Code v2.1.295 이상이 필요하다. 그보다 오래된 호스트는 `"onFailure": "block"`을 모르므로 가드가 충돌하거나 시간을 넘기거나 `python`이 없으면 도구 호출이 그대로 진행된다(fail-open).

**그 밖.** healthcheck 스탬프(`engine=0.32.0`)와 `ENGINE_VERSION`은 0.32.0이다. healthcheck의 위키링크·frontmatter·rules 제목 처리도 선형으로 바뀌었으므로(결과는 같다) 볼트의 엔진 사본(`00-meta/scripts/vault_healthcheck.py`)은 로컬 수정이 없으면 `/vault-upgrade`가 교체한다. 규칙 템플릿 6종은 내용이 같아 스탬프를 유지한다. 기본 세션 훅·검색·모델/네트워크 호출·자동 적용·승격·런타임 의존성을 추가하지 않는다. Jarvis API 인증 조건도 유지한다. Codex 설치 ref는 `--ref v0.32.0`이다. [설치 안내](../codex.md#설치)에 따라 등록 소스·기존 캐시를 확인한다. 공개 릴리스, 활성 설치 캐시 갱신과 실제 볼트 upgrade는 별도 작업이다.

## 검증

구현은 갈래 여덟 개(1a·1b 제목 줄과 본문 경계, 1c 코드·링크·frontmatter 스캔, 1d 위키링크 스캔, 2 기간 정규화, 3 쌍둥이와 행 순서, 4 표본 감사, 6 deny zone 가드 세 부분, 정리)로 나눠 각자의 작업 트리에서 했다. 갈래마다 구현, 읽기 전용 검토, 차단·수정 등급 지적의 별도 반증 검토, 수정 순서로 진행했고, 새 시험이 v0.31.0(또는 수정 전 커밋)에서 실패하는지 확인했다. 검토 여덟 번에서 지적 30건(차단 4·수정 8·사소 18)이 나왔고, 반증 검토의 판정 12건 가운데 11건이 확인되고 1건이 반박됐다. 차단 4건은 모두 고쳤다. 기간 정규화의 목록 예외가 단위 뒤에서 낱말이 끝나는지 보지 않아 `2026.10.07, 10.09 시행`·`2026년 3분기, 2027 시점` 같은 두 기간의 목록을 앞 항목만으로 비교하던 문제와 그와 어긋난 문서(`a7d5415`), deny zone 가드의 Bash 예외 단어가 명령 치환을 품어도 예외로 남아 `echo "$(cat 90-assets/x)" > out.txt`가 결정 없이 지나가던 문제와, 값을 받지 않는 제외·무시 옵션 뒤의 피연산자를 예외로 두어 `tar -czf o.tgz --exclude-vcs 90-assets`가 지나가던 문제(`f5f20d9`)다. 수정 등급 8건 가운데 6건은 갈래 안에서 고쳤다(기간 목록 예외의 이차 시간 lookahead, 쌍둥이 문서의 행 모양 부류 수, 표본 감사의 신뢰 수준 사전 고정, MSYS 형식 `CLAUDE_PROJECT_DIR`에서 가드가 설정의 구역 대신 템플릿 구역을 쓰던 문제, 가드와 엔진 작업 흐름의 충돌 문서화, git이 무시하는 작업 트리까지 읽던 `WIKILINK_RE` 시험). 반박된 1건은 쌍둥이 문서의 '질의 확장 팔 56개 중 33개'가 재현되지 않는다는 지적이었고(legacy 팔의 15개와 같은 정의로 재현된다), 남은 1건은 이번 릴리스 준비가 맡은 `checker_sha256` 고정값과 해시 문장 갱신이다. 사소한 지적 18건 가운데 16건을 고쳤고, 문서 색인 줄은 릴리스 메타데이터 작업으로, 정리 갈래의 지적 하나는 검토자의 제안대로 별도 작업으로 넘겼다. 수정 커밋은 수정한 쪽이 시험과 수정 전 커밋에서의 실패로 확인했으며 따로 다시 검토하지 않았다.

갈래들은 통합 브랜치에 차례로 병합했고, 겹친 문서·시험(`docs/memory-evaluation.md`, `docs/hardening.md`, `.github/workflows/tests.yml`, `tests/test_rule_sources.py`, `tests/test_vault_adapters.py`)은 양쪽 내용을 모두 살렸다. 통합 커밋 `3e025cc`(가드와 1d를 병합하기 전)에서 Windows 11·Python 3.12.10으로 로컬 전체 시험 2,297개(통과 2,258·환경 제외 38·실패 1)를 실행했다(2026-10-27). 실패 1건은 이번 릴리스가 갱신하는 v0.31.0 `checker_sha256` 고정값 시험이다. CI 평가 단계 11개와 컴파일·전체 트리 공백 검사도 통과했고, 평가 단계의 출력은 같은 PC의 v0.31.0 기준 실행(2,172개, 실패 없음·환경 제외 34)과 시간 필드를 빼고 같았다. 가드 갈래는 검토할 때 그 작업 트리에서 전체 시험 2,260개를 실패 없이 실행했고(환경 제외 36, 검토 지적 수정 전), 1d 갈래는 관련 시험 모듈만 실행했다. 가드와 1d를 병합한 `b85fb5e`에서 찾는 시험은 2,407개이며 전체 실행은 최종 트리에서 한다. `b85fb5e` 뒤의 릴리스 준비 커밋 `4789c6d`는 버전 표면(매니페스트 세 개, healthcheck 스탬프와 `ENGINE_VERSION`), `vault_paths.py`의 설명, README·Codex·보안·색인 문서와 메타데이터 시험을 바꿨다. 이 수치는 최종 릴리스 트리의 검증을 대신하지 않는다. Python 3.10·3.14와 Linux·macOS는 CI 행렬에서만 확인한다.

## 알려진 경계

- **선형 처리의 같음은 한정된 근거다:** 예전 식과의 비교는 위 기호 집합과 길이 안의 전수 비교, 고정 사례, 호출부 시험이며 모든 문자열에 대한 증명이 아니다. 스캔의 규칙은 예전 식이 되돌아가는 순서에서 손으로 유도했고 시험은 그 범위에서 확인한다. 제목·날짜·출처 frontmatter 키·`title`·대시 꼬리를 읽는 함수는 줄에 줄바꿈이 없다는 조건에서만 같다. 지금 호출부는 모두 줄을 나눈 뒤 넘기지만, 앞으로 줄바꿈이 든 문자열을 넘기는 호출부가 생기면 다를 수 있다. 새 스캔은 Python 반복문이라 예전 식이 빨리 끝나던 입력에서는 더 느릴 수 있다(`` `a ``를 32,000번 이은 64,000자 줄 하나에 약 15 ms, 예전 식은 1.0 ms(lint)·2.4 ms(`check-support`). 코드 span이 둘 있는 보통 줄마다 약 1.5 µs 더). `vault_state.py`의 사본은 `checker_sha256`가 묶지 않으며 원본과 같은지는 시험만 확인한다. 제거한 모듈 이름을 import하던 저장소 밖 코드는 실패한다.
- **남은 비선형 정규식:** 같은 방법(한 글자·두 글자 반복 입력)으로 다시 잰 탐색에서 기본 경로에 하나가 남았다. 기본 lint의 유출 검사(`vault_egress.scan_text`)가 노트마다 줄별로, 그리고 노트 전체(256 KiB 이하)에 쓰는 `jev_client.py`의 `SENSITIVE`는 `a-a-a-…`처럼 단어 경계가 잦은 런에서 이차 시간이다(그런 한 줄 32,000자에 `scan_text` 3.25초, 2026-10-27). 기본 경로 밖에서는 Jarvis 브리지의 위키링크 치환(`jarvis_bridge.py`)이 `[` 런에서 이차 시간이다(4,000자 이하 조각 하나에서 잰 모양 가운데 가장 느린 것이 약 0.07초). 반복 입력 탐색은 남은 것이 이것뿐이라는 증명이 아니며, 실행 중에 만드는 식(`_support_pattern`, 설정의 사실 패턴, `session_start.py`의 이름표 식)은 재지 않았다. - **본문 경계의 남은 꼴:** `--normalize-periods`에서 다른 대장의 사실 표를 모두 빼면 결과가 오히려 강해지는 행의 `via_ledger_table_only`는 더 좁은 경우로 남았다(사실 표 자신의 첫 줄이 앞 `|` 없이 `말`로 시작해 바로 위 줄의 기간을 꾸밀 때). 자기 인용은 v0.30.0 순서대로 표를 뺀 뒤 frontmatter를 정하므로, 첫 줄의 표 바로 아래가 `---`이고 64줄 안에 `---`가 또 있으면 그 사이를 비교에서 뺀다. 경우별 변화의 근거는 유한한 입력 집합의 비교다.
- **기간 정규화의 알려진 실패:** 위 수는 손으로 만든 낱말 목록이 만든 사례의 실패이며 실제 볼트의 오탐률이 아니다. 목록으로 만들지 않은 꼴(`FY2025, Q1 & FY2026`의 `FY2026`, 공백만으로 이은 목록, `;`·`또는` 목록, 가까운 끝이 글자로 끝나는 범위, 괄호 안에 요일이 둘 이상인 범위, 낱말 안의 서식 문자, 다섯 개 밖의 영문 수식어)은 세지 않으며 틀린 `equal`·`contained`를 낼 수 있다. 새 보류는 재현율을 줄인다(`2026년 3분기 말이 되면`은 이제 보류한다). 개수 예외는 단위만 보고 판단하므로 '9일만'의 뜻인 `9만`도 개수로 보고, 숫자 없이 쓴 기간은 읽지 않는다. 조사 뒤에 기간 낱말이 오면 개수로 보지 않으므로 `2026년 3분기, 120억은 연간 목표`도 보류한다. 차분 시험은 git과 v0.31.0 태그가 있어야 돌며 릴리스 ZIP이나 태그를 받지 않는 얕은 복제에서는 이유를 밝히고 건너뛴다. 실제 볼트에서의 오탐률·놓침률은 측정하지 않았다.
- **답 없음 쌍둥이:** 빈 결과라는 한 작동점만 있고 n=56에서 5% 예산은 거짓 거부 2건이라 문턱을 맞출 표본도 아니다. 라벨도 주장도 없는 근접 중복이 남은 볼트에서는 쌍둥이 오탐이 어휘 검색의 오탐을 부풀린다. 쌍둥이는 원래 결과에서 골드 경로만 뺀 것이 아니다(legacy 팔 56개 중 15개는 다음 순위 노트가 빈자리를 채웠고, 질의 확장 improved 팔은 56개 중 33개가 그 밖의 방식으로 달랐다). fixture 쌍둥이는 일부러 만든 사례이고, 출처는 동료 심사 전 v1 프리프린트다.
- **행 토큰 정렬의 남은 누출:** 행 수, 원문으로 남는 언어·기대 유형, `by_scenario`의 시나리오별 개수와 원문 이름 순서의 키, 행의 모양(recall_hard에서 64행이 14개 부류로 나뉘고 그중 2행은 하나로 특정된다), 같은 토큰의 반복과 빈도, 시간 필드, 골드셋 경고의 문항 번호(`queries[3]`)는 남고, 한 행 안의 목록은 원래 순서를 지킨다. 특히 고급 검색 행의 `diagnostics.temporal`은 노트를 볼트 경로 순으로 최대 50개 나열하므로 볼트의 노트 목록을 아는 사람은 그 순서로 경로 토큰을 풀 수 있다. 키를 가진 사람에게는 아무 효과가 없다.
- **표본 감사의 가정:** seed·k·신뢰 수준을 라벨하기 전에 정한 진짜 무작위 추출일 때만 성립한다. 도구는 표본 파일을 덮어쓰지 않고 기록과 다른 신뢰 수준을 거절할 뿐 다시 뽑기를 막지 못하며, `--population`의 재계산은 `k`나 신뢰 수준의 수정을 잡지 못한다(`draw`가 낸 `sample_sha256`을 따로 적어 두고 비교해야 드러난다). 라벨이 맞다고 가정하고, 한 번 고정한 모집단에만 해당하며, 라벨이 적으면 상한이 넓다(20개 중 0건이어도 500개 중 68개까지). `check-support`는 뒷받침된 행의 줄 번호를 내지 않아 그 행들은 아직 모집단으로 열거할 수 없다. 경로·줄 번호도 볼트 메타데이터이며, 상한마다 따로 계산한 값이라 동시 포함은 보장하지 않는다. 게이트가 아니다.
- **deny zone 가드:** 가드이지 샌드박스가 아니다. 실행된 프로그램·스크립트가 스스로 여는 파일, 구역 이름을 글자로 쓰지 않고 조립하는 경로(`Get-Content (Join-Path 90 -assets)`, 문자열 결합, `9?-assets` 같은 와일드카드, Bash의 `$'...'` 이스케이프), 볼트 루트에서 경로 없이 도는 Grep·Glob, 확인 뒤의 정션 바꿔치기, 훅 matcher 밖의 도구(MCP 도구 등)와 도구 호출 없이 실행되는 명령(다른 훅, 플러그인이 저절로 시작하는 monitor)은 보지 못한다. Bash에서는 구역 경로와 같은 검색어나 here-document 본문, `:` 뒤가 구역 경로와 같은 원격 경로(`scp host:90-assets/x .`)도 `deny`될 수 있고, `-n` 없는 `mv`처럼 구역 안 파일을 덮어쓸 수 있는 이동은 `ask`다. git `REV:경로`는 작업 폴더, 볼트 루트, 작업 폴더 위의 첫 `.git` 폴더에서만 풀어 보며(`git -C`·`GIT_DIR`은 따라가지 않는다), 8.3 짧은 이름은 앞부분이 구역·제어 파일 이름과 맞는 것만 보고 실제로 있는 경로만 긴 이름으로 푼다. PowerShell에는 Bash 예외가 없어 `Move-Item`으로 구역에 넣는 격리 이동과 `-Exclude` 값도 `deny`되고(격리 이동은 Bash 도구의 `mv -n`·`git mv`로 한다), 구문 분석은 Windows PowerShell 5.1 파서라 PowerShell 7 전용 문법은 `ask`, Windows가 아니면 구역 이름이 보이는 PowerShell 명령은 모두 `ask`다. 구역으로 옮긴 파일을 이름으로 스테이징하는 `git add`는 `deny`이므로 `git mv`나 구역 밖 상위 폴더로 스테이징한다. 대상 도구를 부를 때마다 Python 시작 시간이 더해지고 병렬 호출은 그 수만큼 프로세스를 띄운다. Claude Code v2.1.295 미만에서는 가드가 실패하면 호출이 진행되고(fail-open), 그 이상에서는 `python`이 깨지면 대상 도구 호출이 모두 막히며, 훅이 남은 채 `deny-guard.py`가 없으면 버전과 상관없이 막힌다. 자기 보호는 `ask`일 뿐이라 볼트의 `.claude/`·`00-meta/vault-config.json`·가드 스크립트를 쓸 수 있는 누구나 가드를 끄거나 구역을 바꿀 수 있다. Codex 세션의 도구 호출은 검사하지 않는다. 실제 Claude Code 세션 안에서 훅으로 실행해 확인하지 않았다(입력·결정 필드와 `onFailure`는 hooks 문서, Monitor의 입력은 도구 참조 기준, 지연은 같은 명령줄의 하위 프로세스 측정). [전체 한계](../../assets/adapters/deny-guard/guide.md)
- **플랫폼:** 로컬 검증은 Windows 11·Python 3.12.10에서만 했다. Python 3.10·3.14와 Linux·macOS는 CI 행렬에서만 확인하며, 새 처리의 시간은 CI에서 시간 상한 시험(함수마다 0.25초)만 본다. 가드의 심볼릭 링크 시험과 POSIX 경로는 이 PC에서 돌지 않았고, macOS의 대소문자 접기는 대역으로 시험했다. 지연 측정은 보안 제품의 실시간 검사가 켜진 이 PC의 값이다.
