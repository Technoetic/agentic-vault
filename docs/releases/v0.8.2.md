# agentic-vault v0.8.2 릴리스 노트

날짜: 2026-08-31

v0.8.2는 Jarvis의 메시지 인가·상태 내구성과 Git index 기반 커밋 게이트를 함께 강화한 릴리스다. 두 변경은 Python 3.10+ 표준 라이브러리만으로 동작한다.

## 보안 수정

- Jarvis는 발신자가 허용 목록에 있고 `chat.type == "private"`이며 `chat.id == from.id`인 private chat에서만 볼트 응답을 생성한다. 그룹 채팅, 발신자와 채팅 ID가 다른 대화, 미허용 발신자는 응답 없이 폐기하고 메시지 본문을 로그에 남기지 않는다.
- Telegram 토큰 원문은 오류, 로그, 상태 경로에 기록하지 않는다. Q&A 세션은 `Read Grep Glob`만 허용하고 deny zone과 `.env`를 탐색하지 않는다.
- 잘못된 설정과 손상된 상태는 부분 활성화하거나 0으로 되돌리지 않고 설명 가능한 오류로 시작을 중단한다.

## 데이터 내구성

- 수신 업데이트는 `process-then-ack` 순서로 처리한다. 라우팅·저장·응답이 성공한 뒤에만 `offset`을 원자적으로 전진시키며, 실패하면 해당 업데이트부터 다음 poll에서 다시 처리한다.
- 상태 파일은 같은 디렉터리의 임시 파일을 `flush`·`fsync`한 뒤 `replace`한다. 볼트 경로 해시와 Telegram bot ID로 상태를 분리해 서로 다른 볼트·봇이 offset과 집사 상태를 공유하지 않는다.
- 캡처 파일명은 Telegram `update_id`를 포함한다. 같은 업데이트를 재처리하면 같은 파일·내용으로 수렴하고 같은 초의 서로 다른 캡처는 충돌하지 않는다.
- 전달 보장은 손실보다 중복을 택하는 at-least-once다. 응답 전송 뒤 offset 저장이 실패하거나 일부 청크만 전송된 경우 다음 시도에서 응답이 중복될 수 있다.

## commit gate

- pre-commit은 `vault_healthcheck.py --staged`를 실행하고 워킹트리가 아닌 Git staged index의 config·파일을 진실의 원천으로 사용한다.
- 추가·수정·복사·개명된 Markdown의 프런트매터, 필수 키, Enum, YAML 위키링크를 검사한다. 삭제·개명된 노트를 가리키는 백링크가 결과 index에 남으면 차단하고 같은 커밋에서 링크를 수정하면 통과시킨다.
- 한글·공백 경로, rename/copy 상태, unborn HEAD를 NUL 구분 Git 출력으로 처리한다. config가 잘못되었거나 Python·설치된 검사기가 없거나 Git 명령이 실패하면 fail-closed로 차단한다.
- staged 모드는 health report를 쓰지 않는다. 기존 관리성 부채와 볼트 전체 상태는 기본 full 모드가 계속 리포트한다.

## 하위호환

- 새 복수 브리핑 설정 `briefing_times`를 우선한다. 기존 단일 `briefing_time`은 `briefing_times` 키가 없을 때만 fallback으로 사용하므로 기존 볼트는 설정 변경 없이 동작한다.
- 기존 `fm_exempt_zones`는 `frontmatter_exempt_paths`의 호환 별칭으로 읽는다. `frontmatter_roots`가 없는 레거시 config의 full 모드는 기존처럼 활성 노트 전체를 검사한다.
- config가 없는 일반 Markdown 디렉터리와 비활성 Jarvis는 기존처럼 조용히 무동작한다.

## 업그레이드

1. 로컬 변경을 커밋하거나 별도로 보존한 뒤 `/vault-upgrade`를 실행한다.
2. 일반 누락 키 보충은 `frontmatter_roots`와 `frontmatter_exempt_paths`가 없을 때 그 부재를 보존한다. `frontmatter_exempt_paths`가 없고 기존 `fm_exempt_zones`가 있으면 호환 alias가 계속 적용되도록 새 키를 자동 추가하지 않는다.
3. 두 범위 키를 추가하려면 full 모드 검사 범위가 어떻게 바뀌는지 먼저 확인하고, 별도의 검사 범위 마이그레이션으로 명시적으로 승인한다.
4. 엔진 소유 healthcheck와 Git 훅은 `engine=0.8.2` 스탬프를 기준으로 갱신한다. 기존 파일에 사용자 수정이 있거나 훅 경로가 예상과 다르면 diff를 확인하고 교체 여부를 명시적으로 결정한다.
5. 기존 `jarvis.briefing_time`만 있는 볼트에는 일반 누락 키 보충으로 `briefing_times`를 추가하지 않는다. 별도 브리핑 일정 마이그레이션을 승인하면 기존 단일 시각을 배열의 유일한 값으로 옮기며, 템플릿 기본 `07:30`으로 바꾸지 않는다. 새 config나 `jarvis` 블록이 없는 config는 계속 새 템플릿의 `briefing_times` 기본값을 사용한다.

## 검증

릴리스 후보는 저장소 루트에서 다음 명령으로 검증한다.

```powershell
python -m unittest discover -s tests -v
python -m py_compile hooks/session_start.py skills/agentic-vault/scripts/vault_healthcheck.py skills/agentic-vault/scripts/backup_vault.py skills/agentic-vault/scripts/jarvis_bridge.py
python -m json.tool .claude-plugin/plugin.json > $null
python -m json.tool .claude-plugin/marketplace.json > $null
python -m json.tool assets/templates/vault-config.json > $null
sh -n assets/git-hooks/pre-commit
sh -n assets/git-hooks/pre-push
python skills/agentic-vault/scripts/jarvis_bridge.py --self-test
python skills/agentic-vault/scripts/vault_healthcheck.py --vault .
git diff --check
git status --short --branch
git log --oneline origin/master..HEAD
```

## 알려진 경계

- 볼트·봇 네임스페이스마다 정확히 하나의 데몬을 실행해야 한다. 예약 브리핑의 at-least-once 보장은 `pending` 커밋 이후에만 성립한다. `pending` 이전에 프로세스가 중단되면 재시작 시 지난 슬롯을 cold-start miss로 건너뛸 수 있고, Telegram 수락 후 응답 유실·일부 청크 전송·전송 성공 후 `fired` 기록 실패에서는 중복될 수 있다.
- Git 훅은 로컬 협업 게이트이지 OS 수준 보안 경계가 아니다. 저장소를 제어하는 사용자는 `--no-verify` 옵션이나 `core.hooksPath` 변경으로 commit·push 검사를 우회할 수 있다. 우회 불가능한 강제에는 별도 원격 CI·서버 정책이 필요하다.
- Jarvis의 deny zone과 허용 도구 규칙은 프롬프트·도구 정책이지 OS 수준 보안 경계가 아니다. 민감 자료에는 파일 권한이나 별도 샌드박스를 적용해야 한다.
