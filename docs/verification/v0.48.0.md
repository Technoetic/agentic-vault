# v0.48.0 verification contract

This document specifies gates, not measured results. Exact-source measurements
and explicit skips belong in the immutable release's `verification.json`; later
public-download/attestation observations belong in separate post-publication evidence.

## Release content and scope

v0.48.0 builds on published v0.47.0 at `1ffc63d125d6ebc2099a4aa28f538b2c9e1b83b7` and
takes up six items ([release note](../releases/v0.48.0.md)) from the change list of a review that
examined what Antigravity CLI (`agy`) support needs, based on agy 1.5.7 measurements and the
official Antigravity documentation:

- Item 1: an explicit Antigravity mode of the session-start hook
  (`hooks/session_start.py --host antigravity`, with its helpers in `hooks/antigravity_hook.py`). It reads the hook input
  from stdin, takes the one vault named by the input's `cwd` or `workspacePaths` and emits the
  handoff and hot context as one `injectSteps` system message; apart from its help text and the
  abbreviation `--h` (which now matches both `--help` and `--host`), the default path is
  byte-identical to v0.47.0.
- Item 2: a checkpoint on Antigravity's `Stop` event when the agent is fully idle
  (`hooks/session_checkpoint.py --host antigravity`); `vault_state.py` and the health check accept
  the `Stop` event.
- Item 3: the generator `scripts/build_antigravity_package.py` (`build`, `check`) and the
  committed generated package `antigravity/`: a manifest, an Antigravity `hooks.json` with three
  handlers per event, 17 skills (the two shared skills and one per command), byte copies of the
  engine scripts, hooks and `assets/`, and the linked documents. `.gitattributes` keeps the folder LF.
- Item 4: the isolated install verifier `scripts/verify_antigravity_plugin.py`.
- Item 5: host-neutral shared texts (`skills/agentic-vault/SKILL.md`,
  `commands/vault-session-start.md`, `commands/vault-lint.md`,
  `assets/templates/AGENTS-vault-stub.md`) and `skills/agentic-vault/references/antigravity.md`.
- Item 6: documents (`docs/antigravity.md`, README, SECURITY, the documentation index,
  `docs/hardening.md`, `docs/codex.md`, `docs/release-integrity.md`, `AGENTS.md`) and the version
  surfaces.

The repository root stays the Claude Code and Codex plugin: `hooks/hooks.json`, `.claude-plugin/`
and `.codex-plugin/` keep their layout, and only their versions and the Codex long description
change. Several changes alter results without a new option; the release note lists each one under
`기본 결과 변경`. Manifests (four, with the generated `antigravity/plugin.json`), install refs and
health check identification advance to 0.48.0; only the health check carries `engine=0.48.0`, and
every rule and adapter keeps its stamp. The number of installed resources that the native Codex
check byte-compares is measured at gate 3 and recorded in `verification.json`; this document does
not carry the v0.47.0 count over.

## Required feature evidence

Each probe runs on the v0.48.0 source and, as its baseline, on the v0.47.0 sources taken from tag
v0.47.0 into a separate folder. Probe IDs follow the release specification: E1 package, E2 install,
E3 SessionStart, E4 Stop and E5 unchanged defaults. Hook probes feed synthetic hook inputs to the hook
scripts and run no model. agy 1.5.7 runs only in fake homes made for the probes (a new one for each
install), with `agy --version` and the `agy plugin` subcommands `validate`, `install` and `list`. The
hook commands of an installed package run from the installed copy through Git for Windows `sh -c`,
because the shell that agy uses on Windows is not documented, with the temporary folder of the hook
set to one of the probe's own, so that the claim files are the probe's.

- Item 1: the Antigravity-mode tests of the session-start hook and of `hooks/antigravity_hook.py`
  (vault from `cwd` or `workspacePaths`, no vault and several vaults give `{}`, the claim that lets
  one handler act per event and lasts 120 seconds, the 16 MiB input cap, invalid input, errors give
  `{}` and exit 0) with the existing session-start tests unchanged. Probe E3: after an install as in
  probe E2, the three SessionStart handlers of the installed `hooks.json` (timeout 30 each) run in
  order with a synthetic Antigravity event that names the fixed vault in `workspacePaths`; all exit 0,
  the first prints one `injectSteps` system message with metadata source `agentic-vault` whose text
  equals the default-mode startup output for the same vault (`CLAUDE_PROJECT_DIR` and stdin source
  `startup`), and the other two print `{}`. For a workspace without a vault the last handler prints
  `{}` and nothing on stderr; for two vaults it prints `{}` and the fixed several-vaults line on
  stderr. Baseline: v0.47.0, installed from its root by agy's automatic conversion, has one
  SessionStart handler, which prints nothing (0 bytes) for these events.
- Item 2: the `Stop` tests of the checkpoint hook, `vault_state.py` and the health check
  (`fullyIdle`, `hookEventName`, the conversation ID bound, one write per conversation and
  `executionNum` within 120 seconds, no input text or workspace path stored, the default path
  refusing a `Stop` read from stdin without `--event`, a `Stop` checkpoint read by
  `checkpoint_drift_check`). Probe E4: `vault_state.py` and the health check accept the events
  `PreCompact`, `SessionEnd` and `Stop`. The three Stop handlers of the installed `hooks.json`
  (timeout 15 each), run with a synthetic `Stop` input with `fullyIdle` true, all exit 0 and print
  `{}`, and leave one checkpoint record whose only event is `Stop`, whose session hash is the SHA-256
  of the `conversationId` and which holds neither the input's `lastUserInput`, its `transcriptPath`
  nor the vault path; the health check reads that record as `Stop`. With `fullyIdle` false they print
  `{}` and write nothing. The hook run directly with `--host antigravity`, and the default path with
  `--event Stop`, each write a record. Baseline: v0.47.0 has no Stop handler and writes no record,
  exits 2 on `--host antigravity` and on `--event Stop`, and its health check does not read a `Stop`
  record.
- Item 3: `tests/test_antigravity_package.py` (two builds identical, manifest keys and values,
  `hooks.json`, the 17 skill folders, body sizes, placeholders, links, byte-equal copies, the
  `.gitattributes` line, and the sync assertion that `check` exits 0 on the committed
  `antigravity/`). Probe E1: `antigravity/plugin.json` names `agentic-vault` at the plugin version,
  `.gitattributes` keeps the package LF, `python scripts/build_antigravity_package.py check` exits 0,
  and `agy plugin validate --strict --json` on a copy of `antigravity/` reports 0 errors, 0 warnings,
  17 skills and 1 hook group, while on a copy of the repository root it still reports one error (no
  plugin.json found). Baseline: v0.47.0 has no package and no generator, and its root gives the same
  single error.
- Item 4: `tests/test_antigravity_verification.py` (with a fake agy: a pass; a validate warning, a
  `claude-code` source, a version mismatch and an installed byte mismatch fail; a missing agy exits
  2; the fake sees the redirected home). Probe E2: a copy of `antigravity/` installed with
  `agy plugin install` into a fresh fake home is listed by `agy plugin list --json` as `agentic-vault`,
  enabled, at the plugin version, with source `antigravity`, hooks `["agentic-vault"]` and 17 skill
  names (the two shared skills and one per command, equal to the package's skill folders), and the
  installed folder is byte-identical to the copy; `scripts/verify_antigravity_plugin.py`, reaching
  agy through the same isolated runner, exits 0 with `passed` and `real_home_unchanged` true and no
  mismatch (inside the probe the real home that the verifier checks is the probe's temporary home).
  Baseline: v0.47.0 can only be installed from its root, which agy converts: source `claude-code`,
  17 skills of which 15 are `agentic-vault-cmd-*`, and an installed folder that differs from the copy
  (the conversion replaces `commands/` and `hooks/hooks.json`); it has no verifier.
- Probe E5, unchanged defaults: on the fixed vault the default-mode (Claude Code) SessionStart output
  for the sources `startup` and `compact` (exit code, stdout and stderr) and the `PreCompact` and
  `SessionEnd` checkpoint records minus their time field are byte-identical between v0.47.0 and
  v0.48.0, and `hooks/hooks.json` and `assets/templates/settings-permissions.json` hash the same as in
  v0.47.0.
- Item 5: `tests/test_antigravity_texts.py` (the replacements in the shared skill, the two commands
  and the `AGENTS.md` stub; the generated `AGENTS.md` within 24,000 UTF-8 bytes). The flags-off
  comparison shows their effect on generated files.
- Item 6 (text only): `V0480ReleaseMetadataTests` and `V0480SharedSurfaceTests` in
  `tests/test_release_metadata.py`, `tests/test_readme_truth.py` (the Antigravity skill count, the
  agy calls of the verifier and the links of the new documents) and `tests/test_contributor_guide.py`
  (the four manifests and the generated-folder rule).
- Flags-off comparison: on the golden fixture vault and a template vault with and without git, the
  health check (full, `--staged`, `--help`), both hooks' `--help` and SessionStart output for each
  source, doctor JSON and text, recall, the `/vault-upgrade` file plan and the generated `AGENTS.md`;
  every difference maps to an entry of `기본 결과 변경`.

## Evidence boundaries

None of the seven bound files changed since v0.46.0, so the certificate CLI must return checker
fingerprint `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`, corpus
`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a` and result digest
`2efeda6adfcbfd1b677159fa9ce59cb61fa011179168740f99bf9d20655dac59`, as for v0.46.0 and v0.47.0,
when run on the tagged commit and from the ZIP.

Antigravity CLI is exercised only through agy 1.5.7 in an isolated fake home, with `agy --version`
and the `agy plugin` subcommands that need no login. No conversation, no `-p` run and no login take
place: Antigravity's FAQ says that wrapping agy inside third-party coding agents is not supported
under consumer plans and that using third-party software with an Antigravity login violates its
terms. What a real session does with the hooks' output is therefore not release evidence; the hook
tests and probes feed synthetic inputs. The verifier's real-home check covers `~/.gemini/config` only:
it compares the names, types, sizes and modification times under that folder before and after the
agy calls, never file contents, and does not look at agy's data folder `~/.gemini/antigravity-cli`.
The review that listed the changes is a reason for them, not measured benefit. No earlier release's
counts, timings or CI results are reused for this release.

## Final release gates

At documentation preparation time the following gates are pending; this document does not
assert they passed.

1. **Local gates on the integrated tree and on the final commit.** Before the first
   candidate-branch push, again before any later candidate push whose tree changed since these
   gates last ran, and again on the final commit: full fresh local unittest (head unchanged, source
   clean afterwards), the focused item modules, compile, the whole-tree whitespace check against
   the empty tree, the workflow's smoke commands, `claude plugin validate --strict` on the two
   Claude manifests, `commands` and `skills`, `python scripts/build_antigravity_package.py check`
   on the committed `antigravity/`, `python scripts/verify_antigravity_plugin.py` with agy 1.5.7 on
   that folder (its `agy plugin validate --strict` with no error and no warning, the isolated
   install and listing, the byte comparison and the unchanged real `~/.gemini/config`), the
   flags-off comparison against v0.47.0 on fixed temporary vaults with every difference mapped to
   an item of `기본 결과 변경`, the feature evidence probes with their v0.47.0 baseline, and an
   independent source review. A failure is fixed with a failing regression first and the gate is
   repeated.
2. **Candidate-branch CI on the final commit.** Nine OS/Python unit jobs and two stateful jobs
   succeed; the advisory supply-chain job is recorded separately.
3. **Local tag, release ZIP, rebuild check, native Codex check and certificate.** An annotated
   local tag on the final commit; the UTC0 ZIP from the tag with its rebuild specification; an
   independent rebuild from a separate clone (L1 bytes when the git build matches, otherwise L2
   member and blob identity); disposable native Codex discovery from a clean detached worktree of
   the tag and from the extracted ZIP with the installed resources byte-compared, their number
   recorded, and zero model turns; the Antigravity package check and the isolated install from the
   extracted ZIP; the certificate on the tagged commit and from the ZIP. No tag and no master push
   happens before this gate passes; only candidate branches have been pushed.
4. **Tag push.** Release immutability is confirmed enabled and remote master still at the v0.47.0
   commit; the tag alone is pushed.
5. **Tag CI.** Eleven of eleven required jobs on the tag.
6. **Reference catalog update and its independent check.** The Reference Atlas entries for the
   sources this release cites, pinned to the pushed tag, checked by a separate reviewer.
7. **Independent release review.** A reviewer who did not run gates 3-5 re-checks the tag, ZIP,
   rebuild, native Codex and Antigravity package results, certificate, tag CI and the default-result
   list against the final diff and the flags-off comparison.
8. **Master push.** Master fast-forwards to the tagged commit; branch protection requires the
   eleven status checks for that commit.
9. **Master CI.** Eleven of eleven required jobs on master.
10. **Receipt.** LF `verification.json` from the runs above, checked against the ZIP with
    `--spec`, and `SHA256SUMS`.
11. **Upload.** A draft release of the tag whose body is `docs/releases/v0.48.0.md` as stored in
    the tag, with the three assets.
12. **Draft inspection.** The three draft assets are downloaded and compared by hash before
    publication.
13. **Publication.** The draft becomes the immutable Latest release.
14. **Post-publication checks.** Anonymous downloads and hashes, Latest and tag identity, release
    and asset attestations, in a separate record. A public tag is never rewritten.

## Limits

No real agy conversation was run. Whether a session receives the `injectSteps` system message,
whether it survives compaction or a resumed conversation, the size limit of `injectSteps`, the shell
that runs hook commands on Windows, whether the slash command of a plugin skill carries a namespace
(the skills documentation names one slash command per skill) and how the text after it reaches a
skill, and whether an agent resolves `<PLUGIN_ROOT>` to the install folder were not run or measured.
Each hook event has three handlers (`sh` wrapper, `py -3`, `python`) so that one of them finds an
interpreter; a claim file in the system temporary folder lets one of them act per event, a handler
whose interpreter is missing fails and agy logs it, and when the claim file cannot be created more
than one handler can act. A reproduction on the release machine that went through `cmd /c` with the
registry PATH did not find `sh`. A claim lasts 120 seconds: the same key (the conversation ID for
SessionStart, the conversation ID and `executionNum` for Stop) within that time is not handled again,
and an older claim is treated as stale. How agy numbers `executionNum` and whether reopening a
conversation fires SessionStart again are not documented and were not checked.

Antigravity CLI has no compaction or session-end hook event, so nothing is injected again after
compaction, and checkpoints are written on `Stop` with `fullyIdle` instead of on `PreCompact` and
`SessionEnd`. Whether agy keeps the executable bit of the package's files when it installs them was
not checked.

The deny-zone guard, the lesson cue hook and the Aside start hook are Claude Code PreToolUse hooks
and are not ported to the package, as for Codex; the Claude Code permission template is not
converted either, and the location of Antigravity's Project-scope permission file is not
documented. The Jarvis bridge generates only through the Claude CLI. `vault_doctor.py` does not
diagnose agy or the package; `--plugin-scope` reads Claude Code settings and `--session-evidence`
reads Claude Code transcripts only.

On a personal Google account Antigravity CLI collects interaction data unless the user opts out in
its settings (stored with the account); for business accounts that collection is always off. Vault
text that a session reads or that the hook injects goes to Google.

The engine, hook and asset copies in `antigravity/` are outside the repository's fixed-path copy
tests; the generator's `check` and the sync test that runs it are the only check that keeps them
equal to their sources. CI runs that test but not agy.

The package checks ran with agy 1.5.7 on one Windows machine only; earlier agy versions and agy on
macOS and Linux were not run. The full local suite and the probes run on one Windows machine; other
platforms are covered through CI only. Health check copies installed in a vault keep the old
behaviour until they are updated. Release publication, active plugin updates and vault upgrades are
separate operations.
