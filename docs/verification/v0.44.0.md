# v0.44.0 verification record

This is the verification contract. Measured results for the exact tagged source
are published in the release's `verification.json` asset, with CI run URLs and
explicit skips. This document alone does not establish that a gate passed.

## Release content and scope

Optional authored line/paragraph probes compare whole anchored records. Configured
revocation filters raw source context for Jev file-grounded judgments and Jarvis
generation, carrying the original policy/source bindings across dispatch. Existing
Hypothesis coverage is extended with relation and declared-derivative egress
sequences. Synthetic paired fixtures compare legacy literal and scoped record checks.

No model, live API, company input, production dependency, active installation update
or company-vault migration is part of the test scope. Default hook bindings and
configuration templates remain unchanged. The healthcheck version stamp changes;
unchanged rules and adapters keep their stamps.

## Evidence required from implementation

- Legacy checks and prompt bytes remain unchanged when the new option/configuration
  is absent. Compile/proposal manifests retain bounded reads, path policy and original
  and candidate hash checks.
- Record probes cover quantity swaps, appended negation, multiline exceptions,
  duplicated wording elsewhere, source/candidate ambiguity, unselected paths, malformed
  input and NFC versus meaningful Unicode case/unit distinctions.
- The two real consumers project complete UTF-8 source text before BOM/CRLF display
  normalization or truncation, bind excerpts to projection, and refuse stale source
  or policy between prepare/dispatch and after completion. Failure does not become
  an unfiltered fallback or fabricated success.
- Generated sequences observe benign retention, fresh reads and rebuilt declared
  derivatives, a simulated sink, stale evidence, missing observations and an
  unfiltered negative control. There is no persistent index or real outbox.
- Paired relation fixtures have independently authored expected outcomes, immutable
  pair/pack fingerprints and explicit limits; no model-score-as-truth is used.
- Native resource checks reject missing or changed new helpers, guides and
  evaluator/fixture assets in an isolated disposable installation.

Actual focused results, paired counts, generated runs, skips and independent review
must be read from evidence bound to the final source. Results from a superseded
candidate do not replace a run on the final source.

## Final release gates

Required before publication:

- Freeze the exact final source and annotated v0.44.0 tag. No old tag is rewritten.
- Run fresh focused and full local regression and independent feature/security review.
- Pass exact master and tag CI: nine OS/Python unit jobs and two required stateful
  jobs for each ref. Stateful jobs install `requirements-dev.txt` and explicitly run
  `tests.test_stateful_memory_lifecycle`, `tests.test_stateful_relation_probes` and
  `tests.test_stateful_revocation_egress`. Preserve actual attempts, logs and skips;
  advisory supply-chain results remain separate.
- Validate Claude manifests and isolated native Codex discovery, installed bytes and
  untrusted hook state with zero model turns. Live installations stay untouched.
- Verify the seven actual certificate-bound checker files and committed LF harmless
  corpus; record fresh fingerprints and harmless replay results.
- Build `agentic-vault-0.44.0.zip` with UTC0 timestamps and embedded rebuild spec.
  Independently verify L1 byte equality, L2 Git-blob/member checks and exact tagged
  source identity.
- Freeze sanitized LF `verification.json` and `SHA256SUMS`. Independently download and
  inspect the exact three draft assets before immutable GitHub Latest publication.
- Verify fresh anonymous public downloads, Latest/tag identity, checksums and release
  and asset attestations in a separate `post-publication.json`.
- Update Reference Atlas using pinned public evidence, canonical identities and
  explicit prior-use differences, then independently verify it.

## Evidence boundaries

Anchored literal preservation is not semantic truth, and a paraphrase can be flagged.
Unselected records and undeclared semantic copies are outside the scope. The two
configured consumers do not cover arbitrary programs. Already-sent information cannot
be withdrawn. A post-response rejection is not a reversal of a send. No-observation
is not a safe result; a simulated send is not a persistent outbox. Synthetic results
are not actual-model efficacy or real-world safety, and paper statistics are not
measurements of this plugin. General budget optimization remains exploratory.

Historical verification records retain their original scope and are not relabeled as
v0.44.0 results. Publication does not update installed caches or a company vault.
