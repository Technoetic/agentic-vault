# v0.52.0 verification contract

This specifies required gates, not measured pass results. Exact-source results, skips and source identities belong in the release verification.json. Post-publication observations are separate.

## Scope
The release adds a report-only health-check section 14d for level-2 headings that repeat one `ADR-<n>` or `M-<n>` number within a note, defuses note lines that start with one of the `SessionStart` hook's own section headers, keeps the original Jev answer next to the BizRouter answer when `jev_ask.py --escalate-bizrouter` applies an escalation, and narrows `bizrouter_client.MODELS` to `google/gemini-decision-1`. Two repository settings are applied by the maintainer before the tag push: a `v*` tag ruleset that blocks updates and deletions (creation allowed, no bypass actors) and private vulnerability reporting. Python 3.10+ stdlib only. No default network/model calls and no change to the seven certificate-bound checker files, the SHARED WORKTREE RULE block of `vault_worktrees.py` and its verbatim copies, templates, the deny guard, or the default TypeSafe Jev path of `jev_ask.py` and `vault_judge.py`.

## Feature evidence
- Same-number decision and mistake headings: `tests/test_healthcheck_duplicate_entry_ids.py` verifies section 14d with N=1 and the keep-both text for a committed duplicate `ADR-7`, the change-the-uncommitted text with its line for an uncommitted second `M-3` heading, headings inside a fenced block ignored, the same number in two different notes not reported, `ADR-12` and `ADR-120` kept apart, no `14d` text and no `duplicate_entry_ids` key without duplicates, the key equal to N with them, the exit code equal to the run without the duplicate, and unchanged `--staged` output. The module skips cleanly where `git` is needed and missing.
- Header-line defusing: `tests/test_session_header_lines.py` verifies that forged `=== FIXED CONSTRAINTS (...) ===`, `=== HOT CONTEXT ===` and `=== SESSION HANDOFF` lines in the hot note, the handoff note and the `compact` constraints excerpt (including an excerpt with no items) start with `[note line, not a hook header] ` while each header that the hook writes starts exactly one output line, for `startup`, `compact` and `--host antigravity`; that leading Unicode whitespace and the zero-width characters U+200B to U+200D, U+2060 and U+FEFF are skipped before a header start, while look-alikes that are no header start (full-width equals signs, other spacing or case, a soft hyphen or left-to-right mark in front) come back as the same object; that a benign note returns the same object and a full benign `startup` output equals the text built without the function; idempotence; and that a secret inside a forged header line is still redacted first.
- Kept Jev answer and BizRouter models: `tests/test_bizrouter_decisions.py` verifies that `MODELS` holds exactly `google/gemini-decision-1`, that `jev_ask.py` and `vault_judge.py` reject `typesafe/jev-1.13.0` and `typesafe/jev-latest` with `--provider bizrouter` through the existing model check, the `primary`, `agreement`, `disagreed_ids`, `provider_disagreement` and `status` results of agreeing and disagreeing choice, noul and score escalations with fake transports, and output equal to v0.51.0 for the same fake Jev reply without the flag.
- Repository settings: no test module. Just before the tag push the maintainer applies the `v*` tag ruleset and private vulnerability reporting, reads both back through the GitHub API (the ruleset targets tags, includes `refs/tags/v*`, has the update and deletion rules and no creation rule, has no bypass actors and is active; private vulnerability reporting reports enabled), and records the read-back in verification.json.
- Release documents and surfaces: `V0520ReleaseMetadataTests` in `tests/test_release_metadata.py` pins the release note title and headings, the install ref sentence, the unchanged checker sentence, these verification headings and the fourteen gates, and that `engine=0.52.0` appears only in the health check; the README, Codex guide, SECURITY.md and release-integrity statements are pinned there as well.

## Default-result comparison
Default outputs stay byte-identical to v0.51.0 except where a vault or a note contains the new condition: the health-check report, its `--json-summary` line and the management (관리성) total change only for notes with two or more level-2 headings carrying the same `ADR-<n>` or `M-<n>` number (exit codes, `--staged`, the warning policy and certificates do not change, and section 14d cannot be promoted); `SessionStart` output (interactive events and `--host antigravity`, and the matching `vault_doctor` output) changes only for note lines that start with a hook header; and `jev_ask.py` output otherwise changes only with `--escalate-bizrouter` when an escalation is applied (`escalation.status: "applied"`), where a disagreement adds `provider_disagreement` and so `needs_review` (exit code 2). Statuses `unavailable` and `not_needed`, runs without the flag, `prepare` and `vault_judge.py` keep their v0.51.0 output byte for byte for the default provider and `google/gemini-decision-1`. `--provider bizrouter` with `--model typesafe/jev-1.13.0` or `typesafe/jev-latest`, which v0.51.0 sent to BizRouter, is now rejected with the existing `invalid_arguments` error and exit code 2. Metadata versions, the health-check engine stamp (line 2, which `vault_doctor.py --plugin-scope` reads) and `ENGINE_VERSION` move to 0.52.0. Seven certificate-bound checker files remain byte-identical from v0.46.0 through v0.52.0, so `checker_sha256` stays `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`.

## Required release gates
1. Commit integrated source, focused tests, full fresh local suite (including a long Windows TEMP path run), required offline smoke commands, compilation, whole-tree whitespace, package generation/check, and independent read-only verification.
2. Push candidate branch and obtain nine OS/Python unit and two stateful required CI successes. Advisory supply-chain findings are reported separately.
3. Annotated local tag, UTC0 source ZIP, independent L1/L2 rebuild and blob identity, disposable native Codex installed resource comparison with zero model turns, generated Antigravity package check/isolated install, certificate replay on source and extracted ZIP.
4. Just before the tag push, apply the `v*` tag ruleset and private vulnerability reporting and read back both settings; check enabled immutable-release policy and unchanged remote master; push only the tag.
5. Required tag CI passes before progressing.
6. Update Reference Atlas with pinned public citations and independently verify identities, old evidence preservation and generated catalog.
7. Independent release review rechecks final diff, default changes, exact tag/ZIP/install/certificate and CI evidence.
8. Fast-forward remote master to tagged commit after required checks.
9. Required master CI passes.
10. Produce LF verification.json with rebuild_spec and SHA256SUMS from completed observations.
11. Create draft whose body matches the tagged release note, upload exactly the ZIP/verification.json/SHA256SUMS.
12. Download all draft assets and match exact hashes before publishing.
13. Publish immutable Latest.
14. Independently check anonymous downloads, hashes, tag/Latest identity and release/asset attestations. Never rewrite a public tag.

## Boundaries
No company vault or active host installation is upgraded automatically. Section 14d reports only level-2 `ADR-<n>`/`M-<n>` headings within one note; it does not renumber headings, reserve numbers or stop concurrent sessions, and it judges commit state only from the note at the same path in `HEAD` (identical level-2 heading lines and the count of same-number headings there), so a note moved with `git mv` before a commit reads as all new. Header-line defusing, the boundary sentence of the compact constraints block and credential redaction are hygiene, not a guarantee against adaptive prompt injection; deterministic controls (no authority from note text, deny zones) remain the defence. Agreement between the two providers is information, not a pass: both models can share an error. Escalation still covers only `low_confidence` and `low_decisiveness` items, and neither TypeSafe Jev nor BizRouter is called without `--allow-network` and the corresponding environment variable key. The tag ruleset protects `v*` tags only while it is active; it does not show who created a tag or anything for a period when it was off, and a repository administrator can disable it. No SLSA Source level is claimed. No live `agy` conversation session is wrapped by an agent.
