# v0.55.0 verification contract

## Scope

Release `v0.55.0` builds on published `v0.54.1` (`74a2776cec936cd2cce7274cc9f3cb29bacf0159`) by selectively adapting six non-redundant Python standard-library-only hygiene, egress, cloud-sync awareness, onboarding, and ADR improvements from `seulee26/stock-team-harness` (`v2.4.0`, commit `d3b716d1`, MIT; zero new runtime dependencies, no finance/trading/tax domain modules or multi-agent packs):

1. **Verification-date staleness and alias-collision lint (`vault_lint_extensions.py`, `vault_healthcheck.py`)**: adds opt-in `checked_at_stale_days` and `checked_at_annual_rollover` config keys (`KNOWN_CONFIG_KEYS` + `_validate_freshness_keys`), emits non-promotable `checked-at-stale` and `review-by-passed` warnings (with deterministic `today` injection for tests), and emits deterministic promotable `alias-collision` warnings when a note's frontmatter `aliases:` (flow or block list, NFC+casefold) collides with another allowed note's stem or alias.
2. **URL query-parameter secret/signature egress warning (`vault_egress.py`)**: parses `https?://` URLs with stdlib `urllib.parse.urlsplit` + `parse_qsl` (both raw and NFKC/invisible-stripped normalized text), emitting promotable `egress-url-secret` warnings without echoing URLs or secret values while excluding benign pagination keys (`page_token`, `next_token`, `cursor`) and template placeholders (`<...>`, `{...}`).
3. **Read-only cloud-sync destination guard and first-run capability summary (`vault_cloud_sync.py`, `vault_doctor.py`, `backup_vault.py`, `vault_okf.py`)**: adds lexical/env cloud-sync heuristics (`OneDrive`, `Google Drive`, `Dropbox`, `iCloud`) without echoing raw paths, usernames, or secret contents; adds opt-in `vault_doctor.py --cloud-sync` and `--summary` flags (exit code unchanged); emits non-blocking `stderr` advisories in `backup_vault.py` and `vault_okf.py` CLIs only when target destinations appear cloud-synced.
4. **ADR invalidation triggers and conclusion-reversal audit guidance (`assets/templates/decisions.md`, `commands/vault-lint.md`, `commands/vault-doctor.md`)**: adds optional pre-registered invalidation trigger bullet to the ADR template, adds unexplained conclusion-reversal and append-only history guidance to `/vault-lint` §4, and documents `--summary` and `--cloud-sync` in `/vault-doctor`.

Because `vault_lint_extensions.py` and `vault_egress.py` are two of the seven certificate-bound checker files, `v0.55.0` intentionally transitions `checker_sha256` from `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d` (`v0.46.0..v0.54.1`) to `ee421d6f8cc419f9d10017fe7fc3f52084dde4775e4a20ca5fe3271cb6691f98` while preserving the unchanged harmless corpus (`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`) with `false_positives = 0`.

## Boundaries

- `vault_cloud_sync.py` uses lexical path and OneDrive environment-variable heuristics only; it does not query OS sync daemons, detect arbitrary custom-named sync folders, or enforce filesystem blocks.
- `egress-url-secret` is best-effort static query-key coverage and not a guarantee against arbitrary vendor-specific URL tokens.
- `checked-at-stale` and `review-by-passed` depend on wall-clock calendar dates and remain intentionally excluded from `PROMOTABLE_CODES`.
- `alias-collision` checks exact NFC+casefold string equality on frontmatter `aliases:` and does not perform semantic deduplication.
- Live `agy` interactive sessions are not executed by automation.
