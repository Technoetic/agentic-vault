# v0.31.0 verification

This pre-publication document separates implementation evidence from final release
metadata, CI, immutable assets and installation checks. Pending gates are not passes.
See the [release notes](../releases/v0.31.0.md), [flip table and roles](../tower-reliability.md),
[ledger-table marking and period normalization](../hardening.md),
[session evidence](../reliability.md) and [request-body test servers](../evaluation-stability.md).

## Implementation evidence

The published baseline is v0.30.0 `452c5c0beb055320565eab39669e46ac6b18d075`. The reviewed
integration head is `169d8a66bb422bd0e07f8787e7d6340d75fb1624`: 22 files changed against the
baseline for five items (per-assertion flips and roles, period normalization, ledger-table marking,
request-body test servers, session evidence). The final release source is ⟦FINAL_COMMIT⟧.
Figures below come from the review and measurement records of 2026-10-24 and 2026-10-25 (KST) on
one Windows 11 PC (build 26300) with Python 3.12.10; release-time checks are recomputed in the
pre-publication `verification.json`.

These results describe `169d8a6` and the earlier review heads, not the final release source.
Release preparation changes the version surfaces (three manifests, the healthcheck stamp and

between `169d8a6` and ⟦FINAL_COMMIT⟧ with its checks.

## Final release gates

The pre-publication asset `verification.json` records the fixed final source SHA (⟦FINAL_COMMIT⟧),
actual commands, results and final gate status:

- the full local suite on the final tree (⟦TESTS_FINAL⟧) and the metadata, README truth, Codex
  verification and supply-chain tests;
- `checker_sha256` recomputed on the final tree and equal to the value stated in the release notes,
  README, `docs/codex.md`, `docs/hardening.md` and `tests/test_release_metadata.py`; the certificate
  matrix re-run if any of the seven bound files changed after `169d8a6`;
- default-output comparisons against v0.30.0 re-run on the final tree: `vault_ssot.py` `check`,
  `prepare` and `check-support` (only the two additive fields may differ), `vault_runs.py` with a
  fixed clock, doctor, healthcheck full and `--staged`, SessionStart and checkpoint hooks and the CI
  evaluation steps;
- `claude plugin validate .` and `claude plugin validate .claude-plugin/plugin.json`; a disposable
  Codex installation with `python scripts/verify_codex_plugin.py --codex PATH` (isolated `CODEX_HOME`,
  zero model turns, installed version 0.31.0, installed resources verified, including `vault_period.py`);
- master CI (⟦CI_MASTER⟧) and tag CI (⟦CI_TAG⟧) on the final commit: nine unittest cells
  (Linux, macOS and Windows with Python 3.10, 3.12 and 3.14), the two stateful jobs and the CI
  evaluation steps, with the advisory supply-chain audit status recorded separately;
- the ZIP built with `TZ=UTC0`, `core.autocrlf=false` and prefix `agentic-vault-0.31.0/`, its
  `rebuild_spec`, actual L1 byte equality and L2 Git-blob/member equality
  ([release integrity](../release-integrity.md));
- an independent read-only review of the frozen receipt and package before publication.

GitHub release immutability is checked before publishing. The draft release receives
`agentic-vault-0.31.0.zip`, `SHA256SUMS` and `verification.json` before it is published.
Release attestation, public re-download hashes, Latest/immutable state and final refs are checked
afterwards and kept outside the immutable assets in `post-publication.json`. Source-version
preparation does not update an active user plugin or an actual vault engine.

## Limits

Synthetic tests and probes do not measure false-positive or miss rates of period normalization
or ledger-table marking on real vaults. Session-evidence failure shapes and truncation notices come
from strings of the Claude Code 2.1.309 executable, not from observed transcripts. Flip tables and
role grades are descriptive host observations without p-values. All local runs used one Windows 11
PC with Python 3.12.10; other platforms and Python versions are covered by CI only.
