# v0.43.0 verification record

Status: preparation; final-source release gates are **pending, not passes**.

## Implementation evidence

The new optional surfaces are recall read settings and scope diagnostics, a capacity
report and staged growth check, handoff folding with an offline loss alarm, plugin
scope and session evidence values, lesson recurrence classes, a lesson cue compiler and
hook adapter, mutation fidelity and environment variation tools, linked worktree
handling, a declared-path commit tool and an item-by-item compact constraints note.
Default hook bindings, the configuration template and the seven certificate-bound
checker bytes remain unchanged. The engine, deny-guard and `vault-workflow.md` stamps
move to 0.43.0.

Focused evidence must cover the following.

- Recall: setting bounds, invalid configuration stops, unchanged matches and ranking
  by fixed digests, evenly spaced omitted paths and the derived answer state.
- State and capacity: distinct failure codes, hashing above 256 KiB under the 64 MiB
  bound, fixed hook stderr, exit code stability and estimates that decline to answer.
- Staged growth: `warn`, `block`, renames, new paths and an unreadable baseline.
- Handoff fold: byte-exact rebuild before writing, refused drift, unresolved lifting,
  archive framing, summaries bound to hashes and failure cleanup.
- Session evidence and plugin scope: closed output words, no command text, the
  `async_nonzero_exit` change, the lower-bound pairing and host failure paths.
- Lessons: optional `cues` keeping bytes when absent, `ignored_rows`, duplicate refusal
  and literal cue matching with one firing per session.
- Fidelity: the three `vault_compile_quality.py` fixes and the exact false alarm trade.
- Worktrees: real linked trees, submodules and foreign trees in walks and in the guard.
- Commit tool: hash refusal, in-progress states, lock retry, vanished stage entries,
  compare-and-swap `update-ref`, `pre-commit` on the proposed tree and shared-note
  refusal, including the multi-process cases on each platform.
- Constraints note: rendering by item, omitted count, budget fallback and no change
  without the key.

Native resource tests must reject missing or changed copies of new helpers, the lesson
cue adapter and guides. The handoff fold and verifier fidelity evaluators run in CI
without model calls. Local model use for the rule wording contrast is a preparation
note about synthetic scenarios only and is not repeated by CI.

Fresh focused results, independent review and final full regression counts are recorded
only after actual execution against the exact final source. Preparation text provides
no inherited test total or CI success.

## Evidence boundaries

A preview is not permission to apply. A fold's rebuild check proves bytes, not that the
remaining handoff is enough to work from. An estimate from recent commits is not a date.
A synthetic mutation rate is not real-world safety. A rule sentence that kept prohibition
answers on one small local model is not evidence of a gain, and it is not enforcement.
A lesson cue is advisory and its effect is unmeasured. A worktree host run is one run.
The commit tool cannot stop another session's plain `git commit`. Hashes bind bytes, not
identity or truth. Historical local, native and CI results are not relabeled as this
release's results. Publication does not upgrade installed caches or a company vault.
