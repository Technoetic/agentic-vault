# v0.59.0 verification contract

## Scope

Release `v0.59.0` builds on published `v0.58.0` (`34db74b437ddca715280f7d934d90204405f87c3`) and selectively adapts three Python standard-library-only artifact-governance and verification patterns from `openai/math` (`3344da59`, Apache-2.0) with zero new runtime dependencies, no automatic network or model calls, and no vault file mutation:

1. **Opt-in read-only note withdrawal & supersession lifecycle auditor (`skills/agentic-vault/scripts/vault_lifecycle.py`, `docs/note-lifecycle.md`, `skills/agentic-vault/scripts/vault_healthcheck.py`)**: validates `status: withdrawn | superseded`, non-empty `withdrawn_reason` (content-free: never echoed in diagnostics), pinned 40/64-char lowercase hex `withdrawn_revision`, `superseded_by` target resolution and cycle detection, active/draft stale citations (`cites-withdrawn-note` with fixed `withdrawal_scope: proof_or_evidence_only` and `cites-superseded-note` respecting direct and `terminal_replacement` citations), and bounded transitive dependent BFS cascade (`MAX_CASCADE_DEPTH=16`). Enforces `deny_zones`, `exclude_dirs`, runtime directory exclusion, registered linked worktree exclusion, and symlink/reparse refusal. Extends default `vault_healthcheck.py` `enums.status` with `withdrawn` and `superseded`.
2. **Exact bundle tree membership & required zero-count negative evidence (`scripts/verify_release_claims.py`)**: adds `check_exact_tree_membership()` (`agentic-vault/exact-tree-membership/v1`) rejecting missing files, unexpected extra files/directories, and symlinks/non-regular entries (`os.lstat`, `followlinks=False`), plus enforcing `required_zero_evidence` files (empty text or strictly zero-count JSON with no hidden non-empty lists) and optional `--bundle-dir`, `--expected-bundle-file`, `--required-zero-evidence`, and `--require-independent-review` CLI flags. Preserves existing 10-claim default behavior unchanged.
3. **Coverage review-status, immutable spec/solution separation, and permitted-gaps allowlist (`skills/agentic-vault/scripts/vault_coverage.py`)**: adds optional manifest v1 keys `review_status` (`unchecked` default vs `independent_reviewed`), `automation_methods`, pinned SHA-256 `spec_files` vs disjoint `solution_files` (`spec_hash_mismatch`, `spec_file_missing`, `spec_solution_overlap`, with full deny/credential pre-open guards and TOCTOU sweep), and explicit `permitted_gaps` allowlist (waiving only explicitly listed `gap` outcomes while still failing closed on `failed`, `regression`, missing checks, unlisted `gap`, and `unknown_permitted_gap`).
4. **Release-surface & generated `antigravity/` alignment**: aligns manifests, `vault_healthcheck.py` (`engine=0.59.0`), `vault_install_state.py`, `skills/agentic-vault/SKILL.md`, `skills/agentic-vault/references/codex.md`, `scripts/verify_codex_plugin.py`, generated `antigravity/` package (15 skills = 1 shared + 14 commands; 1 Codex required skill), and documentation to `0.59.0`.

None of the seven certificate-bound checker files (`vault_lint_extensions.py`, `vault_warning_policy.py`, `vault_provenance.py`, `vault_egress.py`, `vault_ssot.py`, `jev_client.py`, `vault_paths.py`) change in `v0.59.0`, so `checker_sha256` remains byte-identical from `v0.55.0` through `v0.59.0` (`3754f606efe8d48c55d5a835bf78552dc9deb6379673d883c5cb9eb56010e79d`) on the unchanged harmless corpus (`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`, `false_positives = 0`).

## Boundaries

- `vault_lifecycle.py` inspects only explicit frontmatter fields and literal wiki links; it does not resolve Git objects offline, detect unlinked prose references, or mutate vault files. `status: withdrawn` denotes retracted proof or evidence, not proposition falsity.
- `review_status`, `automation_methods`, and `--require-independent-review` enforce structured separation of caller-declared review metadata and do not cryptographically authenticate human sign-off.
- `check_exact_tree_membership()` checks exact filesystem tree membership and zero-count negative-evidence file contents; it does not prove correctness of the program that generated those files.
- Live `agy` interactive sessions are not executed by automation.
