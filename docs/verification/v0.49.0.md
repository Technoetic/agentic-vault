# v0.49.0 verification contract

This specifies required gates, not measured pass results. Exact-source results, skips and source identities belong in the release verification.json. Post-publication observations are separate.

## Scope
The release adds optional provenance-aware task contracts, staged evaluation over existing native evidence and coverage, and a read-only bounded cycle observer. Python3.10+ stdlib only. No default background execution, network/model calls, command runner, authorization, autonomous promotion or spending enforcement.

## Feature evidence
- Task contracts: exact selected source excerpts, declared source roles, consequential open questions, accepted goal/scope/AC readiness, immutable revision and old-contract invalidation, content-free unsafe input errors.
- Staged review: current native evidence and coverage mapping, every accepted AC, hard-fail veto, not-run/skipped/no-evidence, source hash mismatch, withheld semantic/independent reviews, optional independence requirement.
- Cycle observation: recomputed reports, fixed contract/AC identity, first/final allowed success, regression/repeated failure/oscillation, generation/cost exhaustion, unknown cost propagation and no writes.
- Source/policy tests: deny/excluded/secret/symlink/oversize and changed config/input/source, unknown/duplicate fields/IDs and bool-as-int values. Frozen receipt or passing check never authenticates a user or independently proves execution.
- Discoverability: shared skill/Codex routing, documentation, native install resource list and generated Antigravity sync.

## Default-result comparison
Old APIs and config schemas are unchanged. Metadata versions, healthcheck version/help information, routing descriptions and explicit package resource lists change as listed in the release note. New workflows require explicit selection. Seven certificate-bound checker files must remain byte-identical to v0.48.0.

## Required release gates
1. Commit integrated source, focused tests, full fresh local suite, required offline smoke commands, compilation, whole-tree whitespace, package generation/check and independent source review.
2. Push candidate branch and obtain nine OS/Python unit and two stateful required CI successes. Advisory supply-chain findings are reported separately.
3. Annotated local tag, UTC0 source ZIP, independent L1/L2 rebuild and blob identity, disposable native Codex installed resource comparison with zero model turns, generated Antigravity package check/isolated install, certificate replay on source and extracted ZIP.
4. Check enabled immutable-release policy and unchanged remote master; push only the tag.
5. Required tag CI passes before progressing.
6. Update Reference Atlas with pinned public citations and independently verify identities, old evidence preservation and generated catalog.
7. Independent release review rechecks final diff, default changes, exact tag/ZIP/install/certificate and CI evidence.
8. Fast-forward remote master to tagged commit after required checks.
9. Required master CI passes.
10. Produce LF verification.json with rebuild_spec and SHA256SUMS from completed observations.
11. Create draft whose body matches the tagged release note, upload exactly the ZIP/verification.json/SHA256SUMS.
12. Download all draft assets and match exact hashes before publishing.
13. Publish immutable Latest.
14. Independently check anonymous downloads, hashes, tag/Latest identity and release/asset attestations. Never rewrite a public tag.

## Boundaries
No company vault or active installation is upgraded. Model judgments are advisory. Source hashing is not execution/identity/truth certification; the cycle observer is not a runtime budget controller.
