# v0.50.0 verification contract

This specifies required gates, not measured pass results. Exact-source results, skips and source identities belong in the release verification.json. Post-publication observations are separate.

## Scope
The release adds a workflow-level `concurrency` block to the repository CI that cancels only a superseded pull-request run, and an opt-in, read-only `vault_healthcheck.py --worktree-heads` check (full mode only) with a guide section on landing linked-worktree work on master. Python 3.10+ stdlib only. No default background execution, network/model calls, hook, template, adapter or git-hook change, no path or branch filters, no job-level concurrency, and no change to the shared worktree rule block, its verbatim copies or the deny guard.

## Feature evidence
- CI concurrency: exactly one top-level `concurrency:` block between `permissions:` and `jobs:` whose two lines are the group expression `tests-${{ github.event_name == 'pull_request' && format('pr-{0}', github.event.pull_request.number) || format('run-{0}', github.run_id) }}` and `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`; no job has its own `concurrency`; the `on:` triggers are exactly `push`, `pull_request` and `workflow_dispatch` with no `paths`, `paths-ignore`, `branches` or `tags` filters. The existing workflow readers (release metadata, README truth, contributor guide) keep passing.
- Worktree HEADs: in a temporary vault repository, a linked worktree on a detached HEAD with a new commit gives section 14c with N=1 and that worktree's path; after a branch named `keep` is created at that commit N=0; a worktree on a branch is not listed; two flagless runs are byte-identical and contain no `14c`; `--staged --worktree-heads` exits 2; `--json-summary` carries `unreachable_worktree_heads` only with the flag. The module skips cleanly when `git` is missing.
- Shared blocks: the SHARED WORKTREE RULE block of `vault_worktrees.py` and its verbatim copies in `vault_healthcheck.py` and `deny-guard.py` stay byte-identical.
- Documentation: the `Landing work from a linked worktree` section of `docs/concurrent-commits.md`, the dated v0.50.0 decision bullet in `docs/release-integrity.md`, bilingual README sections, and generated Antigravity package sync.

## Default-result comparison
Without `--worktree-heads`, the healthcheck default report, `--staged` and `--json-summary` must be byte-identical to v0.49.0 except the version surfaces. `--help` also changes: argparse adds `[--worktree-heads]` to the usage block (one more usage line at the default width) and one option line, and realigns the six existing option lines by one column. Metadata versions and healthcheck version/help information change as listed in the release note. The repository CI cancels a pull request's older run when a newer commit arrives on that pull request; push and manual runs keep a group of their own. This concerns the repository's own CI, not the installed plugin. Seven certificate-bound checker files must remain byte-identical to v0.49.0, so `checker_sha256` stays `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`.

## Required release gates
1. Commit integrated source, focused tests, full fresh local suite, required offline smoke commands, compilation, whole-tree whitespace, package generation/check, flags-off comparison with v0.49.0 and independent source review.
2. Push candidate branch and obtain nine OS/Python unit and two stateful required CI successes. Advisory supply-chain findings are reported separately.
3. Annotated local tag, UTC0 source ZIP, independent L1/L2 rebuild and blob identity, disposable native Codex installed resource comparison with zero model turns, generated Antigravity package check/isolated install, certificate replay on source and extracted ZIP.
4. Check enabled immutable-release policy and unchanged remote master; push only the tag.
5. Required tag CI passes before progressing.
6. Update Reference Atlas with pinned public citations and independently verify identities, old evidence preservation and generated catalog.
7. Independent release review rechecks final diff, default changes, exact tag/ZIP/install/certificate and CI evidence.
8. Fast-forward remote master to tagged commit after required checks.
9. Required master CI passes.
10. Produce LF verification.json with rebuild_spec and SHA256SUMS from completed observations.
11. Create draft whose body matches the tagged release note, upload exactly the ZIP/verification.json/SHA256SUMS.
12. Download all draft assets and match exact hashes before publishing.
13. Publish immutable Latest.
14. Independently check anonymous downloads, hashes, tag/Latest identity and release/asset attestations. Never rewrite a public tag.

## Boundaries
No company vault or active installation is upgraded. The CI change concerns this repository's workflow only: a cancelled pull-request run is not a release gate, candidate-branch, tag and master push runs are never cancelled, and GitHub's actual cancellation is observed on a pull request after publication, not by the tests. `--worktree-heads` reads registered worktrees only; it does not prevent removal or pruning, create branches, or inspect uncommitted changes or unregistered copies. It consults only local branches and tags (`refs/heads/*`, `refs/tags/*`); remote-tracking refs (`refs/remotes/*`) are not consulted, so a commit only they hold is still listed. The guide section does not block plain `git merge`, `git cherry-pick` or `git commit`. Research is attributed to the video https://www.youtube.com/watch?v=iysCcCRKZA4 and the posts https://www.anthropic.com/research/redesigning-source-control, https://openai.com/index/scaling-git-at-openai/ and https://github.blog/engineering/infrastructure/inside-githubs-new-git-storage-architecture/; their server-side designs were not adopted and their measured benefits are not claimed.
