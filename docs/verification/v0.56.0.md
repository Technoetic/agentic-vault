# v0.56.0 verification contract

## Scope

Release `v0.56.0` builds on published `v0.55.0` (`ed6cc1362600f0edf44e6ab049705d9208c0f895`) by selectively adapting three non-redundant Python standard-library-only evaluation-rigor, manifest-integrity, coverage-matrix, and silent-noop-guard patterns from `ai3inc/foldboost` (`v0.3.0`, commit `ff7ad2208cf52d7692d5d016ba5b788d782256c7`, Apache-2.0; zero new runtime dependencies, no biomolecular/GPU/Triton adapters, no `.pth` interpreter gate, no Unix-socket resident server, no NumPy):

1. **Pre-registered evaluation plan seal and post-hoc amendment dual-verdict verifier (`scripts/verify_eval_plan.py`)**: adds `agentic-vault/eval-plan/v1` and `agentic-vault/eval-plan-verdict/v1` schemas with immutable `frozen_core_sha256` and whole-plan `plan_sha256` canonical digests, strict JSON parsing (duplicate keys and `NaN`/`Infinity` rejected), chronological amendment checks (rejects `pre_measurement` amendments dated after `observations.measured_utc`), and mandatory side-by-side `original_verdict` + `amended_verdict` + `post_hoc_rescued_failure` disclosure (with `--strict-original` failing unless original gates passed).
2. **Self-verifying install-state manifest digest, structured `near_misses`, and host/OS/adapter coverage matrix (`vault_install_state.py`, `vault_coverage_matrix.py`, `vault_doctor.py --coverage`)**: adds canonical `manifest_sha256` self-verification and duplicate-key rejection to `vault_install_state.py` (fail-closed `manifest_digest_mismatch` on `status` and `uninstall`, backward-compatible `unsealed_legacy` for unsealed v0.54/v0.55 manifests, structured `near_misses` drift diagnostics, and re-sealing on partial uninstall); adds read-only, no-leak `vault_coverage_matrix.py` (`agentic-vault/capability-coverage/v1`) and opt-in `vault_doctor.py --coverage` (exit code unchanged) classifying surfaces across Claude Code, Codex, Antigravity CLI, and Windows/Linux/macOS as `supported`, `opt_in_available`, `unsupported`, or `not_measured`.
3. **Treatment activation and control zero-leakage silent no-op guard (`scripts/eval_activation.py`, `--check-activation`)**: adds `agentic-vault/activation-audit/v1` with dedicated exit code `INACTIVE_EXIT = 70` to reject silent no-ops in treatment arms and unintended leakage in control arms; integrates via opt-in `--check-activation` into `scripts/evaluate_retrieval_backends.py` and `scripts/evaluate_tool_matrix.py` without changing default outputs or exit codes.

None of the seven certificate-bound checker files (`vault_lint_extensions.py`, `vault_warning_policy.py`, `vault_provenance.py`, `vault_egress.py`, `vault_ssot.py`, `jev_client.py`, `vault_paths.py`) change in `v0.56.0`, so `checker_sha256` remains byte-identical to `v0.55.0` (`3754f606efe8d48c55d5a835bf78552dc9deb6379673d883c5cb9eb56010e79d`) on the unchanged harmless corpus (`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`, `false_positives = 0`).

## Boundaries

- `scripts/verify_eval_plan.py` validates caller-supplied JSON plans and observation metrics only; timestamps are not cryptographically notarized and passing gates does not prove statistical generalization.
- `vault_install_state.py`'s `manifest_sha256` detects accidental corruption and casual edits rather than providing a cryptographic signature; defense-in-depth relies on `MANAGED_SURFACES`, engine stamps, and per-file SHA-256 verification.
- `vault_coverage_matrix.py` reports declared capability boundaries and static local file markers only; live host hook execution and interactive `agy` sessions remain explicitly marked `not_measured`.
- `scripts/eval_activation.py` verifies treatment activation and control zero-leakage only; it does not certify model quality or benchmark validity.
- Live `agy` interactive sessions are not executed by automation.
