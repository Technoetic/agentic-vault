# v0.46.0 verification contract

This document specifies gates, not measured results. Exact-source measurements
and explicit skips belong in the immutable release's `verification.json`; later
public-download/attestation observations belong in separate post-publication evidence.

## Release content and scope

v0.46.0 builds on published v0.45.1 at `7e463f5e8f57ce5aa01b32d54709e6778d81f2cc` and
fixes seven defects that an outside review of v0.45.1 found:

- F1, deny zones: every deny-zone and `exclude_dirs` decider compares path segments after
  one shared fold, Unicode canonical caseless matching returned in NFC
  ([release note](../releases/v0.46.0.md)). The fold lives in `vault_paths.py` with verbatim
  copies in the health check, the deny guard and `vault_lint_extensions.py`.
- F2, front-matter links: an iterative line scanner replaces the single-line rule for
  unquoted wiki links in both the staged gate and the full check.
- F3, unknown top-level configuration keys: advisory lines in report section 0, a count on
  the console line and doctor `config_warnings`; exit codes unchanged.
- F4, `hot_note` and `handoff_note`: configuration validation requires a `.md` note.
- F5, an explicit `--vault` that is not a folder: exit 2 in the health check and doctor,
  and the opt-in `--require-vault`.
- F6, the template's placeholder anchor `(없음)`: accepted; a git vault is told only after
  `anchor_drift_threshold` commits touched the vault folder.
- F7, the butler: the health check's opt-in `--json-summary` line, and a bridge that shows
  its check mark only for a complete clean check.

Several fixes change results without a new option; the release note lists each one under
`기본 결과 변경`. Manifests, install refs and health check identification advance to
0.46.0, and the deny guard and its PowerShell parser stamps move to `engine=0.46.0`
because the guard carries the fold. Rule templates, the Aside helper, the lesson cue hook
and the git hooks keep their stamps. The native Codex check byte-compares 129 installed
resources: `vault_paths.py`, `vault_healthcheck.py` and `jarvis_bridge.py` are added to
the 126 of v0.45.1.

## Required feature evidence

  the reverse, and that the default zones and other ASCII zones match as before (an ASCII
  zone that holds `;` or a backtick now also covers a folder spelled with the canonically
  equivalent U+037E or U+1FEF; a name that casefold alone compares as equal but that is not

## Final release gates

At documentation preparation time the following gates are pending; this document does not
assert they passed.

1. Full fresh local unittest on the final tagged commit, recording that the head is
   unchanged and the source clean afterwards; the focused phase modules; compile and the
   whole-tree whitespace check against the empty tree. The certificate migration exercise
   in both directions against v0.45.1: a temporary git vault that promotes a warning to
   `fatal` with a v0.45.1 certificate stops under v0.46.0 (health check exit 1, staged gate
   refusal, doctor `invalid_config`) and passes after the four steps, then the same back to
   the v0.45.1 sources. The flags-off comparison against v0.45.1 on fixed temporary vaults
   (ASCII defaults, the golden fixture vault, an NFD-zone vault, a template vault with and
   without git, a configuration with a key typo) for the health check full and staged modes
   and `--help`, doctor JSON, text and `--help`, recall and SessionStart; every difference
   must map to an item of the release note's `기본 결과 변경`. Independent feature and
   security review. Failures, fixes and explicit platform or dependency skips are kept
   rather than invented successes.
2. CI on the annotated v0.46.0 tag before master is pushed, then on the exact final master:
   nine OS/Python unit jobs and two required stateful jobs per ref. The advisory
   supply-chain job stays separate.
3. `claude plugin validate --strict` on `.claude-plugin/plugin.json`,
   `.claude-plugin/marketplace.json`, `commands` and `skills`. Actual disposable native Codex
   discovery from a clean detached worktree of the tag and from the extracted ZIP, the 129
   installed resources byte-compared with the source, hook trust status and zero model
   turns. Active installations and user vaults stay unchanged.
4. `vault_paths.py` and `vault_lint_extensions.py` changed; a fresh actual seven-file checker
   fingerprint equal to the value stated above, from the tagged commit and from the ZIP;
   corpus unchanged; LF harmless replay. The health check stamp changes with the version.
5. A UTC0 release ZIP built from the local tag before anything is pushed, its embedded
   rebuild specification, an independent rebuild from a separate clone (L1 bytes when the
   git build matches, otherwise L2 member/Git-blob identity), then LF `verification.json`,
   checked against the ZIP with `--spec`, and `SHA256SUMS`.
6. Confirm that release immutability is enabled before the tag push and the draft. Inspect
   the exact three draft assets before immutable Latest publication. After publication,
   verify anonymous downloads, hashes, Latest/tag identity and release and asset
   attestations. Never rewrite a public tag.
7. Reference Atlas: add canonical IDs, aliases and pinned current uses for the Unicode
   Standard 18.0.0 chapter 3 (D145), UAX #15 revision 58 and YAML 1.2.2 as this release
   cites them, keep the difference from earlier NFKC uses, then verify the catalog and its
   public source bindings independently.

## Limits

The fold uses the running Python's Unicode character data, so two Python versions can
differ for code points that only one of them assigns. The vault folder name itself is not
normalized, the staged gate's Git pathspecs stay byte- and case-exact, and the health
check's own folder walk and backups keep exact `exclude_dirs` matching. The front-matter
scanner is not a YAML parser; Obsidian and Dataview parsing were not tested, and an
unterminated quote or flow is not a finding of its own. In front matter that YAML cannot
load, the scanner's reading of where a quote, block scalar or flow ends can differ from a
YAML processor's, so a line v0.45.1 reported can go unreported there and a new line can
be reported; `tests/test_verifier_fidelity_evaluation.py` pins one such shape, the
unclosed-quote mutant, which moves the proposal gate's count for destroyed front matter
from 42 to 48 of 66. Folding a command or a zone name that holds a very long run of
different combining marks that must be reordered takes quadratic time. Without
`--json-summary` the
console line and report section 14 still count evidence byte-budget skips as read
failures. Health check, helper and deny guard copies installed in a vault, and a Jarvis
bridge started from an older plugin folder, keep the old behaviour until they are updated
or restarted. Release publication, active plugin updates and vault upgrades are separate
operations.
