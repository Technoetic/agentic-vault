# v0.34.0 verification record

## Release content and scope

v0.34.0 builds on published v0.33.1 at `4b213f3ed0a314595278adb7d70eb9a0c6fc61e5`.
The release candidate source is `67af284583c19b050ed93a1fc77a8cc7babb9086`; release
preparation adds version surfaces, documentation and contract tests on top of it.
Each of the five opt-in items was reviewed and fixed on its own branch before the
items were integrated:

- the `check-support --bind-subject` left edge for subjects that start with a
  non-ASCII letter, implemented at `ac96d3eaeb7414080a01b1c40395dee3aae9f4c7`
  ([support-row diagnostics](../support-row-diagnostics.md#subject-left-edge),
  [subject boundary note](subject-boundary-20261030.md)), with format guidance for
  `different_from` rows and no parser change;
- `scripts/evaluate_recall.py --abstention-calibration conformal`, with
  `--false-refusal-budget` and `--abstention-signal`
  ([guide](../memory-evaluation.md#답-없음-보정-문턱));
- `scripts/real_vault_audit.py plan`
  ([guide](../memory-evaluation.md#실제-볼트-표본-감사초기하-정확-상한));
- `vault_improvements.py inspect`/`compare --receipt-order`
  ([guide](../improvement-experiments.md#영수증-기록-순서-선택));
- `scripts/evaluate_tool_matrix.py --string-patterns`, with the schema B allow-list
  lint in `scripts/evaluate_tool_safety.py`
  ([guide](../evaluation-stability.md#문자열-인자-패턴-짝-비교)).

None is wired into hooks, CI gates or default runs. Current manifests, install refs
and healthcheck identification advance to 0.34.0; unchanged rule and adapter stamps
stay unchanged. The Codex verifier's installed-resource list is unchanged: it already
byte-checks `vault_ssot.py`, `vault_improvements.py`, `evaluate_recall.py` and the
improvement, support-row and hardening guides, but not `real_vault_audit.py`,
`evaluate_tool_matrix.py`, `evaluate_tool_safety.py` or the memory-evaluation and
evaluation-stability guides.

## Evidence boundaries

On one Windows 11 PC with Python 3.12.10, the full suite at the release candidate
source ran 2,626 tests in 1,578.457 seconds with 43 skips and no failures or errors.
Three of the skips are Aside helper tests, which skip while an Aside browser runs on
the machine. The same PC ran 2,543 tests with 40 skips at v0.33.1. Python 3.10 and
3.14 and Linux and macOS were not run locally; Python 3.10 compatibility of the new
code was checked statically only.

An independent read-only verification of the integrated items (six lenses) found no
blocks. Its flags-off comparison against an export of v0.33.1 found differences only
in documented places: help and argparse usage text, `--bind-subject` results, the
source and code SHA-256 values that some evaluators print, elapsed time and the
certificate's checker fingerprint. A second read-only verification (two lenses) of
the nine follow-up commits also found no blocks. Its remarks were applied afterwards
in `1228d4b` (tests), `66a395f` (documentation and a docstring in
`scripts/evaluate_tool_safety.py`) and `67af284` (documentation); the full suite
above covers them, but no further independent review did. Each item branch also
compared its own flags-off output with v0.33.1, including the `evaluate_recall.py --f`
abbreviation. These are release candidate observations, not results for the final
release source after metadata changes. The recorded measurements use synthetic data
and fixtures, and no actual-model `--string-patterns` run was made.

The certificate CLI on an LF export of the release candidate source returned checker
fingerprint `be02b141ffed91cbe34f8cb2317a790c60075740bfe5d8dc435ef202f113174f`,
21 cases, zero false positives, corpus
`38efaabde0ce1e1df4008276db9761ba1b88eff35ddd91cb8d4fc4899023d04a`
and result `2efeda6adfcbfd1b677159fa9ce59cb61fa011179168740f99bf9d20655dac59`.
Of the seven bound files only `vault_ssot.py` changed, at `ac96d3e`, so the
fingerprint differs from v0.33.1's
`af8f4c5ab9fc809a4998e55870e769d5f617d6742a53d0c5c2844df7ff3d7b92`, which the
unpublished v0.33.0 candidate also had. The healthcheck stamp and `ENGINE_VERSION`
are outside the bound files. The actual final certificate CLI must confirm this
declaration. Follow the
[upgrade and rollback sequence](../releases/v0.34.0.md#하위호환업그레이드):
demote promoted warnings, align every Claude Code/Codex/git-vault engine copy,
run harmless replay/certificate regeneration, then promote again. The published
[v0.33.1 release](../releases/v0.33.1.md) and [verification](v0.33.1.md) records
remain historical records with their fingerprint.

## Final release gates

At documentation preparation time the following gates are pending. The external
pre-publication `verification.json` records the final fixed source SHA, actual
commands, results and gate status; this document does not assert they passed.

- Final-tree full suite and focused metadata, README truth, Codex verification,
  feature and supply-chain checks; the certificate fingerprint re-run on the final
  source and the certificate migration in both directions against v0.33.1.
- Flags-off output comparisons against v0.33.1 on the final tree, and explicit
  opt-in CLI checks of the five items.
- Claude plugin validation and disposable native Codex installation/discovery with
  installed-byte resource checks, isolated `CODEX_HOME` and zero model turns.
- Master and tag CI across Linux, macOS and Windows with Python 3.10, 3.12 and 3.14,
  with actual test counts and skips recorded per job, including the Aside helper
  tests that skipped locally; stateful jobs and the advisory supply-chain job are
  recorded separately.
- Canonical LF source export, reproducible `TZ=UTC0` ZIP, `rebuild_spec`, L1 byte
  equality and L2 Git-blob/member equality; independent final source/package review.
- GitHub immutability check, draft assets `agentic-vault-0.34.0.zip`, `SHA256SUMS`
  and `verification.json`, then authorized publication. No old tag is rewritten.

Final asset review, public re-download hashes, attestation, Latest/immutable state
and final refs belong in external `post-publication.json`, since immutable assets
cannot record their own later review. The packaging and publication procedure is
documented in [release integrity](../release-integrity.md). Source-version
preparation does not establish completion of these gates or update active
installations or user vaults.

## Limits

The subject left edge approximates UAX #29 word boundaries and does not claim
conformance; same-line co-occurrence does not establish semantic attribution or
truth. The conformal threshold carries a marginal guarantee under exchangeability;
on recall_hard at α = 0.05 a threshold, where one exists, rests on the single
smallest calibration score, and the conditional Learn then Test version finds none.
Planned audit sizes are not guarantees. Receipt order is local-clock recording
order, not observation time or a signature. The string-pattern lint has documented
polynomial and alternation-group cost limits, and on the llama.cpp b10729
Qwen3-Coder XML path, inspected from source only, the B patterns reach the model
only as prompt hints. Scripted controls and synthetic fixtures are not actual-model
efficacy evidence. Release publication, active plugin updates and actual vault
upgrades are separate operations.
