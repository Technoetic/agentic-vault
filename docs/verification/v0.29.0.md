## First release CI and correction

The first release commit `4dfa87455f77916930c157e6c608c5fc916a6c4b` passed 11 of 12 jobs in each
of its three CI runs (master 39888137902, tag 39888138027, release branch 39888138805). The
`ubuntu-latest / Python 3.14` job (Python 3.14.8) failed the same existing test in all three:
`test_small_sample_stats.ExactPairedEvaluatorTests.test_cli_exact_paired_requires_compare_and_keeps_the_exit_code`
expected empty stderr and received `ResourceWarning: Implicitly cleaning up <HTTPError 502: 'CONTENT-SENTINEL'>`.

- Cause: on Python 3.14 an `HTTPError` that is garbage-collected without `close()` emits that warning,
  because it wraps a temporary-file object. Three `HTTPError` fixtures in `tests/test_jarvis_bridge.py`
  were never closed. The v0.28.0 ubuntu Python 3.14.8 log already shows the same three warnings, emitted
  outside any captured stderr. With the three new test modules, one of them was emitted inside the
  evaluator test's captured stderr instead; when a collection runs depends on allocations in earlier
  tests, so this placement is an ordering effect, not a change in the evaluator. Across all 36 job logs of the three runs
  these three warnings were the only Python warnings, and they appeared only on Python 3.14.
- Correction: the three fixtures are closed with `addCleanup(...close)`. Runtime code, the evaluator test
  and its assertion are unchanged. No GitHub release existed for the tag, so the tag moves to the
  corrected commit; the final CI and the pre-publication `verification.json` refer to that commit.
- Not changed in this release: the Jarvis bridge does not close an `HTTPError` it catches. In production
  that leaves the error response for garbage collection; it is a separate follow-up, not a test issue.

## Limits

- Answer rates and lower bounds describe the chosen evaluation results. Fixtures and
  deterministic controls do not measure real model or business performance.
- Lower bounds assume independent queries that share one rate and carry no multiplicity
  adjustment across summaries.
- `preserve-check` counts occurrences without positions: swaps or masking additions are
  not detected, rewording can look like a removal, and literal equality is not semantic
  preservation. Results never gate, apply or approve a proposal.
