# v0.52.1 verification contract

This specifies required gates, not measured pass results. Exact-source results, skips and source identities belong in the release verification.json. Post-publication observations are separate.

## Scope
The release publishes for the first time the changes of the unpublished v0.52.0 candidate and makes the full suite (`python -m unittest discover -s tests`) pass on Windows with `LongPathsEnabled` 0 when TEMP and TMP are a 150-character folder that `tempfile.gettempdir()` returns, with no test skipped because of the TEMP length. It adds a report-only health-check section 14d for level-2 headings that repeat one `ADR-<n>` or `M-<n>` number within a note, defuses note lines that start with one of the `SessionStart` hook's own section headers, keeps the original Jev answer next to the BizRouter answer when `jev_ask.py --escalate-bizrouter` applies an escalation, and narrows `bizrouter_client.MODELS` to `google/gemini-decision-1`. The two repository settings that the maintainer applied for v0.52.0 on 2026-11-16 stay in force and are read back just before the tag push: a `v*` tag ruleset that blocks updates and deletions (creation allowed, no bypass actors) and private vulnerability reporting. The long TEMP fixes are made where the failure is: the repository tools `scripts/verify_codex_plugin.py`, `scripts/verify_antigravity_plugin.py` and `scripts/build_antigravity_package.py` use the Windows extended-length form for a temporary workspace only where it would pass the plain path limit, test fixtures use `extended`, `plain` and `deep_path` of `tests/_winfs.py`, `make_junction` of that file creates a link whose path reaches the limit through the extended-length form, the cleanup wrapper of the test package (`tests/__init__.py`) is installed in every full discover run and keeps `tempfile`'s handling of read-only entries, `scripts/evaluate_improvement_experiments.py` checks a persisted record through `vault_evidence.fs_path`, and runtime modules change only where a real gap exists, through the existing `vault_evidence.fs_path` and `plain_path`. The new `scripts/long_temp_suite.py` runs the suite under a TEMP folder of a declared length that `tempfile` really uses. Nothing changes on short paths. Python 3.10+ stdlib only. No default network/model calls and no change to the seven certificate-bound checker files, the SHARED WORKTREE RULE block of `vault_worktrees.py` and its verbatim copies, templates, the deny guard, `hooks/hooks.json`, the CI workflow files, `requirements-dev.txt`, or the default TypeSafe Jev path of `jev_ask.py` and `vault_judge.py`. No test is deleted, weakened, skipped or marked as an expected failure to make a run pass. The public `v0.52.0` tag has no release and is not rewritten.

## Feature evidence
- Same-number decision and mistake headings: `tests/test_healthcheck_duplicate_entry_ids.py` verifies section 14d with N=1 and the keep-both text for a committed duplicate `ADR-7`, the change-the-uncommitted text with its line for an uncommitted second `M-3` heading, headings inside a fenced block ignored, the same number in two different notes not reported, `ADR-12` and `ADR-120` kept apart, no `14d` text and no `duplicate_entry_ids` key without duplicates, the key equal to N with them, the exit code equal to the run without the duplicate, and unchanged `--staged` output. The module skips cleanly where `git` is needed and missing.
- Header-line defusing: `tests/test_session_header_lines.py` verifies that forged `=== FIXED CONSTRAINTS (...) ===`, `=== HOT CONTEXT ===` and `=== SESSION HANDOFF` lines in the hot note, the handoff note and the `compact` constraints excerpt (including an excerpt with no items) start with `[note line, not a hook header] ` while each header that the hook writes starts exactly one output line, for `startup`, `compact` and `--host antigravity`; that leading Unicode whitespace and the zero-width characters U+200B to U+200D, U+2060 and U+FEFF are skipped before a header start, while look-alikes that are no header start (full-width equals signs, other spacing or case, a soft hyphen or left-to-right mark in front) come back as the same object; that a benign note returns the same object and a full benign `startup` output equals the text built without the function; idempotence; and that a secret inside a forged header line is still redacted first.
- Kept Jev answer and BizRouter models: `tests/test_bizrouter_decisions.py` verifies that `MODELS` holds exactly `google/gemini-decision-1`, that `jev_ask.py` and `vault_judge.py` reject `typesafe/jev-1.13.0` and `typesafe/jev-latest` with `--provider bizrouter` through the existing model check, the `primary`, `agreement`, `disagreed_ids`, `provider_disagreement` and `status` results of agreeing and disagreeing choice, noul and score escalations with fake transports, and output equal to v0.51.0 for the same fake Jev reply without the flag.
- Repository settings: no test module. The `v*` tag ruleset and private vulnerability reporting were applied for v0.52.0 on 2026-11-16. Just before the tag push the maintainer reads both back through the GitHub API (the ruleset targets tags, includes `refs/tags/v*`, has the update and deletion rules and no creation rule, has no bypass actors and is active; private vulnerability reporting reports enabled), stops when either is no longer active, and records the read-back in verification.json.
- Long TEMP run: `scripts/long_temp_suite.py` creates a TEMP folder whose path has the declared length (150 characters for gate 1), sets TEMP, TMP and TMPDIR to it and `AGENTIC_VAULT_REQUIRE_LONG_TEMP` to that length, and runs the suite from the repository root. Before the suite starts a child process must report that `tempfile.gettempdir()` is that folder; otherwise nothing is run and the exit code is 3. The exit code is otherwise that of the suite, or 2 for a usage error. The last line on standard error is a one-line JSON summary with `temp_length`, `tempfile_uses_temp`, `long_paths_enabled`, `returncode`, `python` and `platform`; the `LongPathsEnabled` value it reports is recorded with the run in verification.json. The run counts for gate 1 only on Windows, with `tempfile_uses_temp` true, exit code 0 and no test skipped because of the TEMP length.
- Long TEMP guard: `DeclaredLongTempTests.test_tempfile_uses_the_declared_long_temp` in `tests/test_000_environment.py` fails when `AGENTIC_VAULT_REQUIRE_LONG_TEMP` is set unless `tempfile.gettempdir()` is the folder named by TEMP (TMPDIR on other systems) and at least that long; without the variable it only checks that the temporary folder is usable. It is never skipped. The module sorts first in a discover run, imports the `tests` package before any other test module runs and pins that the cleanup wrapper of `tests/__init__.py` is installed. `tests/test_long_temp_suite.py` holds the tests of `scripts/long_temp_suite.py`.
- Release documents and surfaces: `V0521ReleaseMetadataTests` in `tests/test_release_metadata.py` pins the release note title and headings, the install ref sentence, the unchanged checker sentence, the statement that the v0.52.0 tag was not rewritten, the `scripts/long_temp_suite.py` usage line, these verification headings, the fourteen gates with the wording of gate 1, and that `engine=0.52.1` appears only in the health check; the README, Codex guide, SECURITY.md and release-integrity statements are pinned there as well. `V0520ReleaseMetadataTests` pins that the v0.52.0 release note and contract are marked as an unpublished candidate and keep the rest of their text.

## Default-result comparison
Default outputs stay byte-identical to v0.51.0 except where a vault or a note contains the new condition: the health-check report, its `--json-summary` line and the management (관리성) total change only for notes with two or more level-2 headings carrying the same `ADR-<n>` or `M-<n>` number (exit codes, `--staged`, the warning policy and certificates do not change, and section 14d cannot be promoted); `SessionStart` output (interactive events and `--host antigravity`, and the matching `vault_doctor` output) changes only for note lines that start with a hook header; and `jev_ask.py` output otherwise changes only with `--escalate-bizrouter` when an escalation is applied (`escalation.status: "applied"`), where a disagreement adds `provider_disagreement` and so `needs_review` (exit code 2). Statuses `unavailable` and `not_needed`, runs without the flag, `prepare` and `vault_judge.py` keep their v0.51.0 output byte for byte for the default provider and `google/gemini-decision-1`. `--provider bizrouter` with `--model typesafe/jev-1.13.0` or `typesafe/jev-latest`, which v0.51.0 sent to BizRouter, is now rejected with the existing `invalid_arguments` error and exit code 2. Metadata versions, the health-check engine stamp (line 2, which `vault_doctor.py --plugin-scope` reads) and `ENGINE_VERSION` move to 0.52.1. For a path below the plain path limit (240 characters, the margin `vault_evidence.fs_path` uses) the repository tools produce the same strings, outputs, reports and exit codes as at v0.51.0 (they did not change in the v0.52.0 candidate); the extended-length form is used only on Windows where a temporary workspace would pass that limit, and reports, messages and comparisons still show plain paths. Seven certificate-bound checker files remain byte-identical from v0.46.0 through v0.52.1, so `checker_sha256` stays `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`.

## Boundaries
No company vault or active host installation is upgraded automatically. Section 14d reports only level-2 `ADR-<n>`/`M-<n>` headings within one note; it does not renumber headings, reserve numbers or stop concurrent sessions, and it judges commit state only from the note at the same path in `HEAD` (identical level-2 heading lines and the count of same-number headings there), so a note moved with `git mv` before a commit reads as all new. Header-line defusing, the boundary sentence of the compact constraints block and credential redaction are hygiene, not a guarantee against adaptive prompt injection; deterministic controls (no authority from note text, deny zones) remain the defence. Agreement between the two providers is information, not a pass: both models can share an error. Escalation still covers only `low_confidence` and `low_decisiveness` items, and neither TypeSafe Jev nor BizRouter is called without `--allow-network` and the corresponding environment variable key. The tag ruleset protects `v*` tags only while it is active; it does not show who created a tag or anything for a period when it was off, and a repository administrator can disable it. No SLSA Source level is claimed. No live `agy` conversation session is wrapped by an agent. The long TEMP run of gate 1 is a Windows run with `LongPathsEnabled` 0 and a 150-character TEMP folder; it is not a claim for every TEMP length. Extended-length paths that the repository tools hand to the real `codex` or `agy` executables under a long TEMP are not verified. The lesson cue adapter (`assets/adapters/lesson-cues/lesson-cues.py`) keeps its session marks 92 characters plus the user name below TEMP; where that passes the plain Windows path limit no mark can be written and the documented fallback applies (a guard is delivered as a hint). The adapter is not changed. A single test module run in discover form (`-p "test_x.py"`) does not install the cleanup wrapper; the full suite and package-form runs do. The `v0.52.0` tag stays public without a release; results recorded for that candidate do not count for this release, and every gate is passed on the exact v0.52.1 source.
