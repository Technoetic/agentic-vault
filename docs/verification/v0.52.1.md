# v0.52.1 verification contract

This specifies required gates, not measured pass results. Exact-source results, skips and source identities belong in the release verification.json. Post-publication observations are separate.

## Scope
The release publishes for the first time the changes of the unpublished v0.52.0 candidate and makes the full suite (`python -m unittest discover -s tests`) pass on Windows with `LongPathsEnabled` 0 when TEMP and TMP are a 150-character folder that `tempfile.gettempdir()` returns, with no test skipped because of the TEMP length. It adds a report-only health-check section 14d for level-2 headings that repeat one `ADR-<n>` or `M-<n>` number within a note, defuses note lines that start with one of the `SessionStart` hook's own section headers, keeps the original Jev answer next to the BizRouter answer when `jev_ask.py --escalate-bizrouter` applies an escalation, and narrows `bizrouter_client.MODELS` to `google/gemini-decision-1`. The two repository settings that the maintainer applied for v0.52.0 on 2026-11-16 stay in force and are read back just before the tag push: a `v*` tag ruleset that blocks updates and deletions (creation allowed, no bypass actors) and private vulnerability reporting. The long TEMP fixes are made where the failure is: the repository tools `scripts/verify_codex_plugin.py`, `scripts/verify_antigravity_plugin.py` and `scripts/build_antigravity_package.py` use the Windows extended-length form only where a folder they read or write would reach the 240-character switch below the plain path limit of 260 characters (the temporary workspace; for the package builder also the repository, the output, the package folder it compares and link targets outside the source folders; for the Antigravity verifier also the package folder it copies), test fixtures use `extended`, `plain` and `deep_path` of `tests/_winfs.py`, `make_junction` of that file creates a link whose path reaches the 240-character switch through the extended-length form, the cleanup wrapper of the test package (`tests/__init__.py`) is installed in every full discover run and keeps `tempfile`'s handling of read-only entries, four evaluation scripts (`scripts/evaluate_improvement_experiments.py`, `scripts/evaluate_improvement_accounting.py`, `scripts/evaluate_memory_reliability.py`, `scripts/evaluate_task_workflows.py`) create the temporary folder that holds their vault in the extended-length form when that folder plus the receipt length they reserve below it reaches the switch, and hand the runtime modules the vault in plain form, and the memory reliability example and the improvement experiments example, whose check the accounting example reuses, reach records beyond the limit through `vault_evidence.fs_path`, three launch-path tests of `tests/test_vault_adapters.py` decide their browser skip when the test starts instead of when the module is loaded, and one runtime module, `vault_lesson_metrics.py`, which v0.51.0 had not moved to the long-path helper, reaches its observation store through the existing `vault_evidence.fs_path` and `plain_path` and walks a path that reaches the 240-character switch from the extended-length form of the vault, so that `resolve_note_path` sees links and reparse points at every depth. The new `scripts/long_temp_suite.py` runs the suite under a TEMP folder of a declared length that `tempfile` really uses. The default-result comparison describes what changes below the switch. Python 3.10+ stdlib only. No default network/model calls and no change to the seven certificate-bound checker files, the SHARED WORKTREE RULE block of `vault_worktrees.py` and its verbatim copies, templates, the deny guard, `hooks/hooks.json`, the CI workflow files, `requirements-dev.txt`, or the default TypeSafe Jev path of `jev_ask.py` and `vault_judge.py`. No test is deleted, weakened, skipped or marked as an expected failure to make a run pass. The public `v0.52.0` tag has no release and is not rewritten.

## Feature evidence
- Same-number decision and mistake headings: `tests/test_healthcheck_duplicate_entry_ids.py` verifies section 14d with N=1 and the keep-both text for a committed duplicate `ADR-7`, the change-the-uncommitted text with its line for an uncommitted second `M-3` heading, headings inside a fenced block ignored, the same number in two different notes not reported, `ADR-12` and `ADR-120` kept apart, no `14d` text and no `duplicate_entry_ids` key without duplicates, the key equal to N with them, the exit code equal to the run without the duplicate, and unchanged `--staged` output. The module skips cleanly where `git` is needed and missing.
- Header-line defusing: `tests/test_session_header_lines.py` verifies that forged `=== FIXED CONSTRAINTS (...) ===`, `=== HOT CONTEXT ===` and `=== SESSION HANDOFF` lines in the hot note, the handoff note and the `compact` constraints excerpt (including an excerpt with no items) start with `[note line, not a hook header] ` while each header that the hook writes starts exactly one output line, for `startup`, `compact` and `--host antigravity`; that leading Unicode whitespace and the zero-width characters U+200B to U+200D, U+2060 and U+FEFF are skipped before a header start, while look-alikes that are no header start (full-width equals signs, other spacing or case, a soft hyphen or left-to-right mark in front) come back as the same object; that a benign note returns the same object and a full benign `startup` output equals the text built without the function; idempotence; and that a secret inside a forged header line is still redacted first.
- Kept Jev answer and BizRouter models: `tests/test_bizrouter_decisions.py` verifies that `MODELS` holds exactly `google/gemini-decision-1`, that `jev_ask.py` and `vault_judge.py` reject `typesafe/jev-1.13.0` and `typesafe/jev-latest` with `--provider bizrouter` through the existing model check, the `primary`, `agreement`, `disagreed_ids`, `provider_disagreement` and `status` results of agreeing and disagreeing choice, noul and score escalations with fake transports, and output equal to v0.51.0 for the same fake Jev reply without the flag.
- Repository settings: no test module. The `v*` tag ruleset and private vulnerability reporting were applied for v0.52.0 on 2026-11-16. Just before the tag push the maintainer reads both back through the GitHub API (the ruleset targets tags, includes `refs/tags/v*`, has the update and deletion rules and no creation rule, has no bypass actors and is active; private vulnerability reporting reports enabled), stops when either is no longer active, and records the read-back in verification.json.
- Long TEMP run: `scripts/long_temp_suite.py` creates a TEMP folder whose path has the declared length (150 characters for gate 1), sets TEMP, TMP and TMPDIR to it and `AGENTIC_VAULT_REQUIRE_LONG_TEMP` to that length, and runs the suite from the repository root. Before the suite starts a child process must report that `tempfile.gettempdir()` is that folder; otherwise nothing is run and the exit code is 3. The exit code is otherwise that of the suite (a Windows status such as 0xC000013A after Ctrl+C is passed on), or 2 for a usage error or for a `--summary` file that cannot be written after a passing suite (after a failing suite the suite's code stays). After a run that created the folder, also when the suite was interrupted with Ctrl+C, the last line on standard error is a one-line JSON summary with `temp_length`, `tempfile_uses_temp`, `long_paths_enabled`, `returncode`, `python` and `platform` (a Ctrl+C during the `tempfile` check or the removal of the folder ends the tool without one); a usage error prints no summary and leaves an existing `--summary` file as it was (a missing one may be created empty); the `LongPathsEnabled` value it reports is recorded with the run in verification.json. The run counts for gate 1 only on Windows, with `tempfile_uses_temp` true, exit code 0 and no test skipped because of the TEMP length.
- Long TEMP guard: `DeclaredLongTempTests.test_tempfile_uses_the_declared_long_temp` in `tests/test_000_environment.py` fails when `AGENTIC_VAULT_REQUIRE_LONG_TEMP` is set unless `tempfile.gettempdir()` is the folder named by the first of TMPDIR, TEMP and TMP that is set (the order tempfile reads them) and at least that long; without the variable it only checks that the temporary folder is usable. It is never skipped. The module sorts first in a discover run, imports the `tests` package before any other test module runs and pins that the cleanup wrapper of `tests/__init__.py` is installed. `tests/test_long_temp_suite.py` holds the tests of `scripts/long_temp_suite.py`.
- Long-path fixes: `tests/test_long_path_helper_copies.py` verifies that the helper block is byte-identical in the three repository tools and how its functions behave at the switch, below it and on other systems. `tests/test_codex_verification.py`, `tests/test_antigravity_verification.py` and `tests/test_antigravity_package.py` run workspaces and folders beyond the plain limit whatever the TEMP is, and verify that the stand-in host receives plain paths while the workspace is short. `LessonMetricsLongPathTests` in `tests/test_windows_long_paths.py` records and summarizes observations in a vault of at least 172 characters whatever the TEMP is, which fails on Windows with `LongPathsEnabled` 0 without the `vault_lesson_metrics.py` change; it also records with the vault named in the extended-length form and leaves only the records behind, and on Windows it refuses with `unsafe_path` a junction placed at a record folder beyond the plain limit, as a short path does. `tests/test_improvement_accounting.py` runs the accounting example as a command under a temporary folder of at least 170 characters whatever the TEMP is, after a child process shows that tempfile uses that folder, and expects exit code 0 and an empty folder; `TemporaryParentTests` pins the folder decision that both improvement examples share, and the experiments example runs as a script smoke command. `tests/test_winfs_paths.py` verifies the fixture helpers and a junction link beyond the limit, and `tests/test_000_environment.py` that a temporary folder holding a read-only file beyond the limit is removed.
- Release documents and surfaces: `V0521ReleaseMetadataTests` in `tests/test_release_metadata.py` pins the release note title and headings, the install ref sentence, the unchanged checker sentence, the statement that the v0.52.0 tag was not rewritten, the `scripts/long_temp_suite.py` usage line, these verification headings, the fourteen gates with the wording of gate 1, and that `engine=0.52.1` appears only in the health check; the README, Codex guide, SECURITY.md and release-integrity statements are pinned there as well. `V0520ReleaseMetadataTests` pins that the v0.52.0 release note and contract are marked as an unpublished candidate and keep the rest of their text.

## Default-result comparison
Default outputs stay byte-identical to v0.51.0 except where a vault or a note contains the new condition: the health-check report, its `--json-summary` line and the management (관리성) total change only for notes with two or more level-2 headings carrying the same `ADR-<n>` or `M-<n>` number (exit codes, `--staged`, the warning policy and certificates do not change, and section 14d cannot be promoted); `SessionStart` output (interactive events and `--host antigravity`, and the matching `vault_doctor` output) changes only for note lines that start with a hook header; and `jev_ask.py` output otherwise changes only with `--escalate-bizrouter` when an escalation is applied (`escalation.status: "applied"`), where a disagreement adds `provider_disagreement` and so `needs_review` (exit code 2). Statuses `unavailable` and `not_needed`, runs without the flag, `prepare` and `vault_judge.py` keep their v0.51.0 output byte for byte for the default provider and `google/gemini-decision-1`. `--provider bizrouter` with `--model typesafe/jev-1.13.0` or `typesafe/jev-latest`, which v0.51.0 sent to BizRouter, is now rejected with the existing `invalid_arguments` error and exit code 2. Metadata versions, the health-check engine stamp (line 2, which `vault_doctor.py --plugin-scope` reads) and `ENGINE_VERSION` move to 0.52.1. The repository tools, the four evaluation scripts and `vault_lesson_metrics.py` (none of which changed in the v0.52.0 candidate) reach a path spelled in the plain form through the extended-length form only on Windows, where that path plus the length they reserve for the paths below it reaches the 240-character switch (the margin below the plain path limit of 260 characters that `vault_evidence.fs_path` uses). The reserve can be longer than the deepest path a run creates or reads: the accounting example reserves the length of a receipt that only the experiments example writes, and the package builder counts the longest entry below its source folders, files it does not open included. Reports, messages and comparisons still show plain paths, except where they quote a `codex` command line or its error output. Some results also change below the switch. A short path that the caller already spells in the extended-length form is in places handled in its plain form: the package builder shows and compares such an argument in plain form (v0.52.0 kept the spelling and skipped the git-mode comparison for such a path), the Antigravity verifier names such an `--agy` or `--package` argument in plain form in its error messages, and under a TEMP spelled that way the two verifiers build the paths they hand `codex` and `agy` in plain form and name the folder in plain form in their messages, and the four evaluation scripts hand the runtime modules a plain vault (v0.52.0 kept the spelling). The Antigravity verifier's failure text also shows the workspace as `<temp>` where the error output of `agy` spells it in the extended-length form (for a workspace in the plain form, v0.52.0 showed `\\?\<temp>` there). On Windows without long-path support, `vault_lesson_metrics.py` records and summaries that failed with `invalid_or_unavailable_input` from a 158-character vault root now succeed (no error code changed), a junction at a store folder beyond the plain limit is refused with `unsafe_path` as on a short path, and the four evaluation scripts end with exit code 0 under a long TEMP instead of 1. Seven certificate-bound checker files remain byte-identical from v0.46.0 through v0.52.1, so `checker_sha256` stays `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`.

## Boundaries
No company vault or active host installation is upgraded automatically. Section 14d reports only level-2 `ADR-<n>`/`M-<n>` headings within one note; it does not renumber headings, reserve numbers or stop concurrent sessions, and it judges commit state only from the note at the same path in `HEAD` (identical level-2 heading lines and the count of same-number headings there), so a note moved with `git mv` before a commit reads as all new. Header-line defusing, the boundary sentence of the compact constraints block and credential redaction are hygiene, not a guarantee against adaptive prompt injection; deterministic controls (no authority from note text, deny zones) remain the defence. Agreement between the two providers is information, not a pass: both models can share an error. Escalation still covers only `low_confidence` and `low_decisiveness` items, and neither TypeSafe Jev nor BizRouter is called without `--allow-network` and the corresponding environment variable key. The tag ruleset protects `v*` tags only while it is active; it does not show who created a tag or anything for a period when it was off, and a repository administrator can disable it. No SLSA Source level is claimed. No live `agy` conversation session is wrapped by an agent. The long TEMP run of gate 1 is a Windows run with `LongPathsEnabled` 0 and a 150-character TEMP folder; it is not a claim for every TEMP length. Under a long TEMP the Codex verifier hands the host an extended-length path only where that path itself reaches the 240-character switch, and the Antigravity verifier hands over the package copy and the home variables in extended-length form once its workspace plus the longest path a run creates below it reaches the switch (the start folder stays plain); neither was verified with the real `codex` or `agy` executables, and the tests use stand-ins. git keeps its own path limits (`git bundle create` refuses a target of 255 characters or more), which leaves the tests that use git about five characters of room at 150. On POSIX, when the suite itself ends on Ctrl+C (SIGINT), `scripts/long_temp_suite.py` records -2 in its summary and exits with status 254, not 130; gate 1 counts Windows runs only. The runtime modules that v0.51.0 moved to the long-path helper (for example `vault_state.py`) kept their path checks: where a vault root is so long (about 230 characters) that a runtime folder itself passes the plain limit, a junction placed at that folder is not seen by the link check and is followed (confirmed by the host at a 231-character root; refused at a 120-character root); this release changes only `vault_lesson_metrics.py`, and placing such a junction needs write access to the vault folder. Runtime paths that the 150-character run does not reach are unchanged where they do not use the helper (for example `vault_proposals.py` when it writes its receipts, and the checkpoint records that the opt-in drift check of `vault_healthcheck.py` reads). The workflow's 22 script smoke commands were also run as commands under a 150-character TEMP, outside the suite, and ended with exit code 0; other scripts were not run that way. A test that passes under the long TEMP can hold an assertion that is weaker there (an existence check on a plain path beyond the limit); only the failing tests and their surroundings were changed. CI runs under the default TEMP only, and GitHub's Windows runners enable long paths (`LongPathsEnabled` 1), so CI re-checks the extended-length form decisions, the plain messages and the helper copies, but not the outcomes that need `LongPathsEnabled` 0 (records, example runs and cleanups beyond 260 characters that failed before); only local runs on Windows with `LongPathsEnabled` 0 exercise those (gate 1's long TEMP run, the tests that build such paths whatever the TEMP is, and the 22 smoke commands run under a 150-character TEMP). The lesson cue adapter (`assets/adapters/lesson-cues/lesson-cues.py`) keeps its session marks 92 characters plus the user name below TEMP; where that passes the plain Windows path limit no mark can be written and the documented fallback applies (a guard is delivered as a hint). The adapter is not changed. On Windows, where the cleanup wrapper applies, a single test module run in discover form (`-p "test_x.py"`) installs it only if the module imports the `tests` package; the full suite and package-form runs install it. The `v0.52.0` tag stays public without a release; results recorded for that candidate do not count for this release, and every gate is passed on the exact v0.52.1 source.
