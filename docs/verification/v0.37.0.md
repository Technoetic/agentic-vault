# v0.37.0 verification record

## Source scope

The implementation checkpoint is `1f0d5a4015cc0b2cb9e72064192db68440218083`.
Its local module-sharded aggregate discovered and ran 2,731 tests: 2,685 passed,
46 platform-conditional skips, zero failures/errors. This is implementation evidence,
not a passing run of later release-preparation changes.

The release adds optional declared source-line/derivation revocation at documented
consumers and a deterministic two-case, 22-process lifecycle evaluation. Preparation
also addresses filesystem alias spellings on case-insensitive POSIX volumes and
extends isolated Codex resource verification to the new module, evaluator and guides.
The alias regression is reproduced with real guarded reads on a case-insensitive
fixture and a spelling-preserving resolver; that host experiment is not native macOS
execution. Native platform execution is a separate CI gate.

## Final release gates

At preparation time the following are pending, not passes:

- Freeze the exact release source and verify current manifests, install refs, safety
  documentation, historical records and focused behavioral/metadata regressions.
- Complete master and annotated-tag CI: all nine OS/Python full unit/regression jobs
  and two stateful jobs per run. The advisory supply-chain job and its step outcomes
  are reported separately; matrix totals are repeated executions, not unique cases.
- Validate Claude metadata and a fresh isolated Codex installation with both enabled
  skills and all required resource bytes. Do not modify an active host installation.
- Reproduce a source ZIP using `TZ=UTC0` and compare every archived member with the
  tag's Git tree/blobs. Independently verify L1 bytes, L2 members and bounded inputs.
- Bind final source, CI, native installation, certificate replay and independent
  archive review in UTF-8/LF `verification.json`; build `SHA256SUMS` from final bytes.
- Inspect an unpublished draft with exactly the ZIP, `verification.json` and
  `SHA256SUMS`; independently download and match the draft bytes before publication.
- After immutable publication, verify Latest, remote tag, anonymous fresh downloads,
  checksums and GitHub release/three-asset attestations. Record those later checks in
  `post-publication.json` outside the immutable pre-publication assets.

## Limits

Explicit physical spans and derivations only; no semantic equivalence, undeclared-copy
discovery or erasure of old external copies/Git/backups. Registry and source rechecks
are bounded point-in-time checks, not a filesystem freeze. Synthetic deterministic
controls do not measure actual model robustness or production efficacy. Publishing
does not activate a real-vault registry or update existing plugin caches.
