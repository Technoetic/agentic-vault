# v0.53.2 verification contract

This document specifies the required release gates for `v0.53.2`, not measured pass results. Exact-source test counts, skips, CI run IDs, rebuild hashes, isolated host install results and independent review outcomes belong in the release `verification.json`. Post-publication download and attestation observations are recorded separately.

## Scope
Release `v0.53.2` supersedes the unpublished `v0.53.1` candidate tag (`7a25c4c5a3880eb4dc2154d4209192fd3aeea47c`, which is never rewritten and has no GitHub Release) and publishes for the first time all seven findings from the external evaluation of `v0.53.0` (`c0f4a3cb4547897ad3e38a8a663e3aaa390db31a`), plus two CI stability fixes uncovered during `v0.53.1` Tag CI (`run #44514277999`):
1. `SECURITY.md` documents the opt-in BizRouter Decisions egress path (`bizrouter_client.py`, `https://api.bizrouter.ai/v1/decisions`, `BIZROUTER_API_KEY`, `google/gemini-decision-1` only, `256 KiB` / `1,000`-question cap), corrects the header-line defusing version reference from unpublished `0.52.0` to `0.52.1`, and aligns both English `Known limitations` and the Korean summary's Antigravity `Stop` dedup text with v0.51.0+ behavior.
2. `docs/antigravity.md` removes stale text claiming `Stop` checkpoints cannot deduplicate when `executionNum` is `0` or omitted, and aligns install URLs and version references with `v0.53.2`.
3. `skills/agentic-vault/scripts/vault_doctor.py` applies `SessionStart` credential redaction (`_redact_sensitive_lines`) before `_neutralize_header_lines` when estimating injection length, matching the actual `SessionStart` hook output on notes with secret lines.
4. `scripts/first_handoff.py` adds `argparse` handling for `--help` (exits `0` without creating any temporary vault) and `--dir DIR` (refuses an existing non-empty directory with exit code `2`), while preserving zero-argument tutorial output.
5. `tests/test_stateful_memory_lifecycle.py` and `tests/test_stateful_revocation_egress.py` wrap raw receipt `.read_bytes()` calls with `tests._winfs.deep_path` so Hypothesis stateful checks run cleanly under a 150-character Windows `TEMP` with `LongPathsEnabled=0`.
6. `skills/agentic-vault/scripts/jarvis_bridge.py` replaces author-local `D:/NS` usage examples with generic `/path/to/vault`.
7. `scripts/run_unittest_parallel.py` provides a Python stdlib-only parallel test runner (`--workers 4`) wired into `.github/workflows/tests.yml` without changing any of the 11 required GitHub branch-protection status check names or the `stateful` job.
8. `tests/test_vault_capacity.py` disables `maintenance.auto` and `gc.auto` in its temporary fixture repository to prevent transient `.git/objects/maintenance.lock` races, and `skills/agentic-vault/scripts/vault_state.py` (`_guard`) retries a vanishing regular guard entry (`S_ISREG`, `st_nlink == 0`, re-checked absent) during concurrent POSIX/APFS unlinks while continuing to reject symlinks, reparse points, and hardlinks (`st_nlink > 1`) with `unsafe_lock`.

Python 3.10+ standard library only for core and CI parallel test execution. No new runtime dependencies, no default network/model calls, and no changes to the seven certificate-bound checker files (`vault_lint_extensions.py`, `vault_warning_policy.py`, `vault_provenance.py`, `vault_egress.py`, `vault_ssot.py`, `jev_client.py`, `vault_paths.py`), templates, deny guard, `hooks/hooks.json`, or `requirements-dev.txt`.

- Hypothesis long-TEMP reads: `tests/test_stateful_memory_lifecycle.py` and `tests/test_stateful_revocation_egress.py` run cleanly under a 150-character Windows `TEMP` with `LongPathsEnabled=0` and `AGENTIC_VAULT_REQUIRE_LONG_TEMP=150`.
- Concurrent guard unlink retry & fixture git maintenance: `tests/test_vault_state.py` (`test_guard_retries_vanishing_zero_link_regular_entry_but_rejects_hardlink`) verifies retry on vanishing `st_nlink == 0` regular entries and continued `unsafe_lock` rejection on hardlinks; `tests/test_vault_capacity.py` disables `maintenance.auto` and `gc.auto` in `init_repo()`.
- Release surfaces and absolute links: `V0532ReleaseMetadataTests` in `tests/test_release_metadata.py` pins the `v0.53.2` release note headings, zero relative links in `docs/releases/v0.53.2.md`, unchanged `checker_sha256`, `SECURITY.md` BizRouter coverage, `docs/antigravity.md` updated `Stop` dedup text, `jarvis_bridge.py` absence of `D:/NS`, and `engine=0.53.2` appearing only in `vault_healthcheck.py`.

## Default-result comparison
Default plugin outputs remain identical to `v0.53.0` except where the documented changes apply:
- Metadata versions, install refs, `vault_healthcheck.py` line 2 (`engine=0.53.2`) and `ENGINE_VERSION` move to `0.53.2`.
- `vault_doctor.py` injection estimates change only for notes containing lines matching `jev_client.SENSITIVE` or PEM private-key blocks, now matching `SessionStart` output.
- `scripts/first_handoff.py` accepts `--help` and `--dir`; zero-argument behavior is unchanged.
- `vault_state.py` (`_guard`) retries only a vanishing regular guard entry (`S_ISREG`, `st_nlink == 0`, confirmed absent on re-check); symlink, reparse point, and hardlink (`st_nlink > 1`) rejections remain `unsafe_lock`.
- CI `unittest` runs `python scripts/run_unittest_parallel.py --workers 4` across the exact same `tests/test_*.py` module set; all 11 required check names stay unchanged.
- Seven certificate-bound checker files remain byte-identical from `v0.46.0` through `v0.53.2`, so `checker_sha256` stays `09642e7aa77d0b812f5afa646b491fe2d79d44104e399bea4a3001a6f2f1279d`.

## Boundaries
No active local installation or vault copy is upgraded automatically by release publication. `v0.53.1` remains an immutable unpublished candidate tag with no GitHub Release; results from `v0.53.1` do not count toward `v0.53.2` release gates. `scripts/run_unittest_parallel.py` runs each module in its own subprocess using only Python's standard library; module completion order varies with OS scheduling. GitHub Actions Windows runners enable long paths (`LongPathsEnabled=1`) and use default `TEMP`; `LongPathsEnabled=0` 150-character `TEMP` verification is a local Windows check recorded in `verification.json`. No live `agy` conversation is wrapped by an agent, and `vault_doctor` token estimates remain character-based approximations.
