# v0.47.0 verification contract

This document specifies gates, not measured results. Exact-source measurements
and explicit skips belong in the immutable release's `verification.json`; later
public-download/attestation observations belong in separate post-publication evidence.

## Release content and scope

v0.47.0 builds on published v0.46.0 at `e47d0a2cca599538bbe4351eba908e5fa4290fda` and
takes up eleven items of a review that compared the plugin with a vendor prompting
guide ([release note](../releases/v0.47.0.md)):

- Item 1, contributor guide: root `AGENTS.md` and `.claude/CLAUDE.md` (an import of
  `AGENTS.md`), and no root `CLAUDE.md`, for people and agents that change this repository; they
  ship in the tree and the ZIP and are not installed into vaults.
- Item 2, engine-copy ownership line: planned for `assets/templates/rules/vault-architecture.md`,
  tried with the rule-wording test and not shipped; the rule file is byte-identical to v0.46.0.
- Item 3: optional `jarvis.model` and `jarvis.effort`; empty or absent keys leave the bridge's
  claude argv byte-identical to v0.46.0, invalid values stop the bridge at start.
- Item 4: a scheduled briefing slot that fails 8 times in a row (generation failure, generator
  exception, send failure) is given up for the day and the owner is told once; refusals are not
  told apart from outages.
- Item 5: an optional reason and date on `RETIRE` in `vault_lesson_delta.py`, written into the
  ledger row's status cell; the retirement line of the mistakes template; scope, reason and source
  in promotion drafts; the ledger format line; writing guidance for `constraints_note`.
- Item 6: a completion condition for `/vault-process-inbox` with four hold reasons and a re-listing
  before the report.
- Item 7: a paragraph in `/vault-session-end` on who reads the handoff, hot note, log and report.
- Item 8: the remote-push line of `/vault-session-end`, the 500-word wording of the hot and handoff
  templates and `SKILL.md`, and the `gates.note_move` note of the configuration template.
- Item 9: the opt-in, engine-owned `/aside-repl` procedure command
  (`assets/adapters/aside/aside-repl-command.md`), its `adapters.aside_command` report entry, a
  clause line, measured rows for the operations guide skeleton, and the documented observation
  that shell commands injected by a command or skill body do not pass PreToolUse hooks.
- Item 10: the seed repository of `tests/test_vault_commit.py` switches git's automatic
  maintenance off.
- Item 11: dated errata appended to `docs/releases/v0.46.0.md` and `docs/verification/v0.46.0.md`.

Several changes alter results without a new option; the release note lists each one under
`기본 결과 변경`. Manifests, install refs and health check identification advance to 0.47.0;
the health check, the Aside clause begin marker and the new command asset carry
`engine=0.47.0`, and every other rule and adapter keeps its stamp. The native Codex check
byte-compares 130 installed resources: `assets/adapters/aside/aside-repl-command.md` is added
to the 129 of v0.46.0.

## Final release gates

At documentation preparation time the following gates are pending; this document does not
assert they passed.

1. **Local gates on the integrated tree and on the final commit.** Before the first
   candidate-branch push, again before any later candidate push whose tree changed since these
   gates last ran, and again on the final commit: full fresh local unittest (head unchanged, source
   clean afterwards), the focused item modules, compile, the whole-tree whitespace check against
   the empty tree, the workflow's smoke commands, `claude plugin validate --strict` on the two
   Claude manifests, `commands` and `skills`, the flags-off comparison against v0.46.0 on fixed
   temporary vaults with every difference mapped to an item of `기본 결과 변경`, the feature
   evidence probes with their v0.46.0 baseline, an independent source review, and one real
   `/aside-repl` run with the integrated command file (before the first candidate push, and again
   whenever that file changed since its last run). A failure is fixed with a failing regression
   first and the gate is repeated.
2. **Candidate-branch CI on the final commit.** Nine OS/Python unit jobs and two stateful jobs
   succeed; the advisory supply-chain job is recorded separately.
3. **Local tag, release ZIP, rebuild check, native Codex check and certificate.** An annotated
   local tag on the final commit; the UTC0 ZIP from the tag with its rebuild specification; an
   independent rebuild from a separate clone (L1 bytes when the git build matches, otherwise L2
   member and blob identity); disposable native Codex discovery from a clean detached worktree of
   the tag and from the extracted ZIP with the installed resources byte-compared and zero model
   turns; the certificate on the tagged commit and from the ZIP. No tag and no master push happens
   before this gate passes; only candidate branches have been pushed.
4. **Tag push.** Release immutability is confirmed enabled and remote master still at the v0.46.0
   commit; the tag alone is pushed.
5. **Tag CI.** Eleven of eleven required jobs on the tag.
6. **Reference catalog update and its independent check.** The Reference Atlas entries for the
   sources this release cites, pinned to the pushed tag, checked by a separate reviewer.
7. **Independent release review.** A reviewer who did not run gates 3-5 re-checks the tag, ZIP,
   rebuild, native Codex results, certificate, tag CI and the default-result list against the
   final diff and the flags-off comparison.
8. **Master push.** Master fast-forwards to the tagged commit; branch protection requires the
   eleven status checks for that commit.
9. **Master CI.** Eleven of eleven required jobs on master.
10. **Receipt.** LF `verification.json` from the runs above, checked against the ZIP with
    `--spec`, and `SHA256SUMS`.
11. **Upload.** A draft release of the tag whose body is `docs/releases/v0.47.0.md` as stored in
    the tag, with the three assets.
12. **Draft inspection.** The three draft assets are downloaded and compared by hash before
    publication.
13. **Publication.** The draft becomes the immutable Latest release.
14. **Post-publication checks.** Anonymous downloads and hashes, Latest and tag identity, release
    and asset attestations, in a separate record. A public tag is never rewritten.

## Limits

The contributor guide (`AGENTS.md` and `.claude/CLAUDE.md`, which imports it) was checked on Claude Code 2.1.252 in print mode with `--plugin-dir`, one run each: a session in another folder did not see it and a session inside the checkout did. A marketplace installation, the IDE extension and a turn that reads a plugin file were not tested, and Codex was not run. No `CLAUDE.md` is placed at the plugin root, because `claude plugin validate --strict` rejects one.
Claude Code reads the `.claude/CLAUDE.md` of a plugin checkout when a session starts in that
checkout, also when the checkout is kept inside a vault.

The engine-copy ownership line was not shipped: on one local model, with one pass per wording and
invented cases, every wording turned the explicit user requests to patch a vault copy from 3 of 4
carried out into 0 of 4. This measures neither hosted models nor real vaults.

The two bridge options were checked on Claude Code 2.1.252, one run per case: with `--bare` only up to option parsing (the release machine has no API key), and without `--bare`, logged in, with an answer. Generation with authentication in bare mode and whether bare mode applies the effort level were not run.
The bridge does not check that a model name is usable; a name the CLI does not accept makes every
question and briefing fail (seen without `--bare` for one name). An older claude CLI without
`--effort` can fail when a value is set. Response time and quality under other models or effort
levels were not measured.

The bridge reads only the CLI's text output and exit code, so it cannot tell a provider refusal
from an outage or an empty answer, and the output shape of a real refusal was not observed. With
`--bare` and no API key the CLI printed its not-logged-in line on standard output and exited 1
(one run); the bridge treats that as a failed generation and does not relay the output. The
attempt count lives in memory only and starts from zero after a restart; an undelivered notice is
not sent again; the first pass after midnight waits for a running backoff of up to one hour;
state-file write errors are not counted as attempts.

A retirement reason on a heading record (a mistakes entry) is written by hand. A reason records a
retirement; it does not approve it or establish that its cause is gone. Ledgers made with v0.8.3
or later keep their format line, because `/vault-upgrade` does not rewrite it. The texts of items
6, 7 and 8 do not enforce behaviour, and whether a model follows them was not measured.

The hook bypass of injected commands was seen on Claude Code 2.1.252 in print mode, one run per
case, with the hook log checked in two runs. The repl delivery routes were measured on Windows 11
with Aside CLI 1.26.916.1741 on 2026-11-12 and 2026-11-13; PowerShell 7, macOS, Linux and a Codex
session were not run. The `/aside-repl` run of gate 1 is one run on Claude Code 2.1.252 in print
mode on a public page; the IDE extension, a natural-language request without the slash command
and Codex were not run. A procedure text does not enforce behaviour.

The full local suite and the probes run on one Windows machine; other platforms are covered
through CI only. Health check copies installed in a vault, and a Jarvis bridge started from an
older plugin folder, keep the old behaviour until they are updated or restarted. Release
publication, active plugin updates and vault upgrades are separate operations.
