## Pre-publication test correction

The initial v0.22.0 tag remains unchanged. Its main CI exposed a test that required
wall time below150ms; macOS3.14 took176.562ms while correctly reporting a timeout.
The v0.22.1 patch replaces that timing assumption with a held-event transport and checks
return-before-worker-completion, exact timeout reasons, and worker cleanup. An intentionally
synchronous dispatcher fails both cases. Production request/episode behavior is unchanged.
The first source also had a Windows3.12 concurrent-prepare refusal. Its exact internal
cause was not reproduced; original failure, successful retry,60-call probe and held-lock
evidence remain separate in the release receipt. Further superseded CI exposed a real
`lock_busy` refusal in the operation caller fixture and a timestamp test whose owner had to
release within500ms. Contract-aligned tests distinguish only typed bounded-lock refusals
from success, retain at-most-once effects and immutable receipts, and control the timestamp
retry boundary without sleeps. Unknown errors still fail. Production lock behavior, policy
and wait bounds are unchanged; all original failed and superseded runs remain recorded.

## Limits

Korean structured controls are not free-form model QA. Generated serialized lifecycle
sequences do not cover every concurrent schedule. Tool-call episodes use invented fixtures
and an in-memory outbox. The four actual local Qwen episodes completed English2/2 and
Korean0/2 tasks, with zero attack goals and zero model/transport errors. These failures remain
visible and are not recast as improvement or a general security score. No default runtime
model call, production-vault edit or automatic upgrade is introduced.
