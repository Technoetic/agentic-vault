# v0.40.1 verification record

Status: preparation; final-source release gates are **pending, not passes**.

## Candidate history and scoped fix

The v0.40.0 tag at source `f924cab` was pushed, but macOS tag CI failed on
positive tests that used a temporary-directory alias. No v0.40.0 public release
was published. The old tag, failed CI and original v0.40.0 release/verification
documents remain historical evidence and must not be rewritten into patch passes.

macOS can expose temporary paths through `/var`, whose canonical location is
under `/private/var`. Production routing inputs intentionally reject symlink
components. The positive test setup failed to canonicalize its temporary paths,
so the strict policy rejected those fixtures as designed. The test-only
correction resolves temporary setup paths with `Path.resolve()` while preserving
negative symlink cases. Production evaluator modules, strict link rejection,
source binding, grading, limits and CLI behavior remain unchanged.

Current metadata, install refs and healthcheck version stamps become v0.40.1.
Only the healthcheck release stamp and `ENGINE_VERSION` change in that production
file. The seven certificate-bound files and LF corpus retain their contracts;
actual-byte verification and harmless replay remain final-source gates.

## Implementation evidence

On the patch working tree before final source freeze,
`python -m unittest discover -s tests -p test_release_metadata.py -v` passed
41 tests with zero skips. This is focused metadata verification, not a full-suite
or macOS test result. No full suite is run by this scoped metadata task, and no
final suite totals, platform pass or publication result is inferred from the
earlier candidate. The release coordinator records the test-portability
correction's focused checks separately.

## Final release gates

At preparation these are pending, not passes:

- Freeze the exact final source and a new annotated v0.40.1 tag. No old tag is rewritten.
- Complete patch-focused and full local regression checks plus independent review;
  record actual commands, source revisions, results and environment skips.
- Run fresh master/tag CI on the exact final source: all nine OS/Python full
  unit jobs and both stateful jobs per run. Verify macOS positive temporary setup
  and negative link rejection separately; report advisory audits separately.
- Validate Claude manifests, isolated native Codex discovery, bundled resource
  bytes and the actual certificate-bound files with LF harmless replay.
- Build `agentic-vault-0.40.1.zip` with UTC0 timestamps, embed its `rebuild_spec`,
  compare Git members/blobs and perform an independent reproducible rebuild.
- Freeze sanitized UTF-8/LF `verification.json` and `SHA256SUMS`; independently
  inspect freshly downloaded unpublished draft assets before publication.
- After immutable publication, verify Latest/tag, fresh anonymous downloads,
  checksums and release/asset attestations in separate `post-publication.json`.

## Evidence boundaries

Retained routing fixtures are 32 original AI-assisted KR/EN synthetic grader
cases, not measured host/model routing. No actual-model inference or live Codex
adapter is added. The manifest parser remains a strict bounded subset. A
comparison validates internal consistency of trusted grader outputs; it cannot
regrade omitted expectations, authenticate caller-authored grades or prove host
events. Missing and unsupported evidence remain unmeasured.

The patch adds no runtime dependency, model/network call, installation update,
SKILL-description, hook or configuration-default change. Publication, active
installation updates and real-vault changes remain separate operations. Public
artifacts contain source and sanitized verification, not company data or secrets.
