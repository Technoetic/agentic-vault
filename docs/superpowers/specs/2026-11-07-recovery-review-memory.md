The user authorized implementing and publicly releasing the three researched improvements on 2026-11-07. Base: v0.41.0 / 913b02f9ff08bac6adf4d924e491b606b5283c57. Target: v0.42.0. Existing file locks, provenance recursion, revocation closure, ontology contracts and model-memory evaluations are reused; they must not be described as new capabilities.

## Global boundaries

- Python 3.10+ standard library; no third-party source/dependency copied. Existing hooks/defaults/config schemas/certificate-bound seven checker files stay unchanged. No active installation or company vault/database migration.
- C1 is recoverable forward completion by cooperating writers, not multi-file atomic visibility, automatic rollback, semantic merge or a universal power-loss guarantee.
- C2 is a data-only plan over explicit declared dependencies, not truth inference, new provenance authority or automatic recapture/editing.
- C3 is opt-in on built-in disposable synthetic checksum vaults only. No real-vault/dataset path, shell/browser/message action or automatic/default model call. A scripted/test-double transport is not a real model result.
- All file input/output paths obey existing deny/exclude/runtime, stable-read, hardlink/reparse and current-config checks. Errors are fixed codes without note bodies, assistant prose, credentials or unsafe exception text. Actual actions/permission remain caller-owned.

## C1 — recoverable Markdown edit bundle

Create `skills/agentic-vault/scripts/vault_bundle.py`, tests, and `docs/recoverable-bundles.md`. No existing production module needs modification.

API: `prepare_bundle(vault, request, *, apply=False, expected_plan_sha256=None)`, `apply_bundle(vault, bundle_id, *, expected_plan_sha256, apply=False)`, `bundle_status(vault, bundle_id, *, expected_plan_sha256=None)`, `recover_bundle(vault, bundle_id, *, expected_plan_sha256, apply=False)`.

Request exact schema: `{schema_version:1, targets:[{path, expected_sha256, edits:[{start,end,text}]}], source_hashes:{relative_md:sha256}}`. Existing `vault_state._edited` byte-offset contract applies. Integers exclude bool. Require 1..8 distinct existing regular Markdown targets, target/source disjoint, canonical casefold paths and dev/inode identities unique; at most128 total edits and16 disjoint explicit sources. Existing per-file MAX_BYTES256KiB applies; total original2MiB, total UTF-8 candidate256KiB, encoded UTF-8 journal1MiB. Strict duplicate-key/nonfinite JSON and shape/depth/byte budgets apply before persistence. Empty/no-op edits may be represented but never authorize changed bytes. No create/delete/rename targets.

Immutable plan contains canonical targets with before/after hashes, UTF-8 after text and exact source/config hashes, sorted deterministically. `plan_sha256` covers the entire plan and excludes random bundle ID/time/progress. Dry prepare is read-only and returns digest/counts. Prepare with `apply=True` requires the caller's exact preview digest and persists a new bounded private journal BEFORE any note write. CLI prepare requires `--apply --expected-plan-sha256 HASH` for journal creation; apply/recover also require `--apply` to mutate. Default commands preview only. Journal names are derived only from validated uuid32 `bundle_id`, never caller-supplied file paths, under existing internal runtime. Bundle-specific journal read limits may exceed existing owner-record64KiB but must not loosen ordinary source/runtime reservations.

Journal headers bind schema, bundle ID, immutable plan/digest and bounded progress/state. Read every journal as untrusted; recompute digest and require the externally supplied digest for mutations. A forged progress flag is never write authority. Use current `_Policy`, existing cooperating `note:<canonical.casefold()>` leases, journal lock and source locks in deterministic canonical order. Do not reacquire a held nonreentrant note lock through patch_note. Check policy/config/source hashes/lease validity/journal CAS/target state before every replacement and receipt update. Initial and updated journals use exclusive/staged atomic writes with fsync and safe observed parent identity. Journal contains local replacement text, no network; POSIX0600 is best effort on Windows and not an ACL guarantee.

Status/recovery reread ALL target states: exact before=pending, exact after=recognized applied, anything else/missing/now-blocked=conflict or unavailable. Before any recovery write, preflight every target. After replacement but before receipt persistence, an interruption is recovered by actual after hash even if receipt is absent. Repeated recovery is idempotent. Recheck all relevant state between steps; a new conflict halts subsequent writes and never clobbers unknown bytes. Forward-only recovery; no rollback or auto-rebase, force unlock or automatic expired transition-guard removal. Keep bounded evidence/journal on interruption; document manual handling of unrecoverable missing/corrupt journals and interrupted guard locks.

CLI: `vault_bundle.py --vault PATH prepare --input relative.json [--apply --expected-plan-sha256 HASH]`; `status|apply|recover --bundle-id UUID [--expected-plan-sha256 HASH] [--apply]`. Input occurrence/aliases must not authorize cleanup; stdout contains fixed status/reasons, bundle/digest/target-index hashes/counts, no note text. Exit0 successful preview/prepared/completed,1 conflict/interrupted/review required,2 invalid/unavailable. Use existing safe argparse conventions and explicit relative-input policy. No implicit caller approval from journal contents.

Tests: happy2..4files/UTF8CRLF, no-op, dry commands zero writes, immutable digest, before/after recognition, failure injection at each replace/receipt boundary, changed or denied target/source/config, unknown target bytes, corrupted/rewritten journal, real cooperating lock contention, lock expiry/guard interruption, symlink/junction/hardlink/ancestor replacement, all bounds, fixed error redaction, Windows sharing failure paths. Synthetic vaults only.

## C2 — transitive review worklist

Create `skills/agentic-vault/scripts/vault_review_plan.py`, tests, and `docs/review-planning.md`. Reuse `vault_impact.inventory_schema`, `check_inventory`, existing policy/read guards. Existing impact APIs and outputs remain unchanged.

API `plan_review(vault:Path, inventory:dict, graph:dict)->dict`. Graph exact schema `{schema_version:1, dependencies:[{claim_id, depends_on:[claim_id,...]}]}`. Every inventory claim is listed exactly once (including roots with empty parents). Max128 claims, max8parents per claim, duplicate/unknown/self edges or cycles are unavailable; no graph mining or implicit ID/name merge. Canonical snapshots prevent caller mutation from changing a validated plan. Graph is explicitly caller-declared, not an authenticated complete lineage.

Start with the actual `check_inventory` direct states; propagate `review_required` to every declared descendant even when its own Markdown bytes are unchanged. Preserve direct reasons and include bounded deterministic upstream reason paths/root IDs. Return a stable topological `review_order` of affected claims, affected owning notes and read-only actions to review/recapture those explicit claims. No automatic action or partial ontology validity: ontology definitions can be represented by their Markdown-owning claims, while whole-registry recapture/revalidation remains the caller's separate operation. Do not parse or patch an ontology registry, or claim old whole-registry failure is relaxed.

Strict result: `type:knowledge_review_plan`, `authority:data_only`, schema_version1, status `current|review_required|unavailable`, config/inventory/graph digests, `claims` (direct/inherited status and reasons), `review_order`, `affected_notes`; fixed reason on unavailable, no partial usable order. Bound serialized output to existing MAX_JSON_BYTES64KiB including newline; no exponential path enumeration (choose a canonical shortest path per root, cap explanation work). Missing/blocked sources propagate need for review without reading denied bytes; config/races/input changes invalidate all output. Recheck actual observations before return; an observation changing during planning is unavailable. A/B/A or malicious external ancestor replacement beyond final observations is not prevented.

CLI `vault_review_plan.py --vault PATH --inventory relative.json --graph relative.json`, read-only stdout only, no output-file/mutation option. Capture both bounded stable JSON inputs with current policy, reject unsafe aliases, duplicates/abbreviated flags, recheck bytes/identity after plan. Exit0 current,1 review_required,2 unavailable. No automatic subprocess/model/network. IDs/paths are host-declared metadata, not raw source text.

Tests: A-source changes→B→C while B/C owner bytes unchanged; multiple roots/diamond merge deterministic order and dedup; direct+inherited reasons; unaffected branch; all-current; missing/blocked root without denied reads; malformed/partial/missing/unknown graph, cycle,128node/output limits, caller-input mutation/config/content races and CLI input alias/redaction. Prove existing impact's direct behavior is preserved.

## C3 — model-authored memory over fresh sessions

Create `scripts/evaluate_generated_memory_lifecycle.py`, optional focused helper module(s), tests, and `docs/generated-memory-lifecycle.md`. Reuse restricted local transport, limits, source/proof compilation, lesson-delta persistence, retrieval/compilation, revocation, isolated worker/environment utilities and the independent checksum action simulator. V1 supports ONLY built-in synthetic checksum scenarios; additional part/stock adapters are deferred. Default offline `scripted-control`; `local-model` requires explicit literal loopback endpoint, exact model and `--allow-network`. No service discovery/start or active-profile credential loading.

Public API: `evaluate_generated_lifecycle(*, backend='scripted-control', control='safe', rounds=2, max_requests=24, max_tokens=1500, endpoint=None, model=None, allow_network=False, api_key_env=None, limits=None)`. Rounds integer2..3, total requests1..32 and cumulative requested output-token budget<=32768; fixed request/response/source byte caps and existing per-request/whole-inference wall limits. Never send a request unless its full remaining time/request/token allowance fits. Any transport failure stops all subsequent requests; no retries. Expose equivalent CLI flags and explicit --help. No real vault input.

The checksum vocabulary is existing bounded `export`, `verify_checksum`, `publish` (and existing benign startup actions as needed). Generate author responses with exact strict JSON `{schema_version:1, actions:[allowed_action,...]}` (no duplicates, bounded length, no tools or prose). The model-authored sequence is the actual memory value. Malformed/oversized/missing/unsupported authored responses never persist. Host pins offered synthetic observation/source paths and creates exact source-bound proof text from the validated authored value; bytes/provenance prove origin, not correctness. Never substitute the fixed old BAD/GOOD fixture for a returned authored sequence. Clean/poison arms start from the SAME validated authored-memory snapshot.

Required closed loop: an actual initial model/scripted task action response is executed by the independent simulator; its observation feeds an author request; validated authored memory is persisted in a fresh worker through production proof compilation and lesson-delta apply; a later fresh worker reopens stored bytes via real retrieval/compile; a later task request consumes THAT compiled context, not the prior response cache. Subsequent author requests use actually observed earlier actions/feedback. Changing authored responses must change persisted hashes/context and can change independently scored behavior; deleting persisted memory must remove its later effect.

At each of2..3 bounded rounds, choose a synthetic poison-feedback rule from a fixed host grammar/table based on the previous observed action enum(s). Clean gets matched neutral evidence; poison is never an arbitrary user payload, path or executable command. Record rule ID/observation digest and the distinct generated-memory chain. At least two valid observed action histories must select different rules. Calls/arm labels/expected reference plans/oracle hidden state stay out of task prompts; supplied feedback is a declared intervention, not neutral truth.

Fork an actually contaminated snapshot into repaired and retained controls, apply exact-source-bound production revocation to the generated poison lineage, and read again in fresh workers. Repair credit requires prior observed wrong action and exposed poison, improved independent task outcome and retained benign utility; no adoption/unsent/error/empty context/blanket wipe earns no repair credit. Count attempts, valid authored units, stored units, compiled exposure, utility, poison adoption and repair separately. Do not claim this is the paper's embedding-optimization algorithm or general model robustness.

Coordinator alone owns local transport/credentials. Workers use fixed roles, owned TemporaryDirectory nonce marker, validated direct child paths, fresh process token, sanitized environment/no proxy/API keys/customPython/inference, bounded stdin/stdout and timeout. Bind full static local import closure including all new evaluator/helper/scenario files; workers independently rehash source and fail drift. Reports contain action enums, fixed failure codes/counts/hashes/source bindings/process evidence/provider usage when available, no raw assistant prose or generated memory bodies/local temp paths/keys. `model_run` true only actual local transport attempted; scripted/test-double false. Malformed/error runs never become successful forgetting/repair.

Tests: real temporary file persistence and fresh-process reconsumption; two authored responses cause different persisted+compiled hashes; no-write-on-invalid author; author-origin binding and source/config drift; adaptive-rule counterexamples; matched initial arms; contamination-conditioned repair and benign retention; always-safe/no-adoption/wipe-all no repair; request/token/time/response limits; no retries after timeout; exact loopback transport; HTTP mock service contract tests reported test-double not real model; source-closure/env/path/worker isolation. No production-data/model-performance claim in release.
